# 因子检验的预热历史与评价日期

**分级：普通任务。** 只扩展纯 `rquant.factor.result` 输入/输出合同与聚焦测试，不触及共享数据源、权限、数据库、Lab、Serving 或页面。风险是滚动因子在用户选择的首日因缺预热历史被错误判为缺值，或把预热日算入 IC/收益报告。

## 行为合同

1. `FactorTimeSeriesInput` 仍持有完整、递增的计算日历与每日 09:25 截止输入；允许调用者在 `FactorResearchRequest` 另列非空、递增、无重复的**评价日期**，必须是计算日历的子集。不指定时仍评价全部日期，保持当前调用者行为。此前的计算日期仅作预热/间隔上下文，不进入逐日覆盖、IC、分组收益或结果展示日期。
2. 后续收益网格只覆盖评价日期 × 固定股票池，每格恰一条；评估器仍先计算全部历史因子值，再取评价日期组装结果。窗口不重叠、同日终值一致、成熟时点与缺数规则仍按现有合同执行。内容摘要包含完整计算历史和所选评价日期；相同输入可复算，改变预热输入或评价日期会改变摘要。
3. 请求与结果明确保存 `holding_sessions`，只接受原型定义的 **1、5、10、20 个 SSE 开市日**，用于表示调仓与收益窗口；不能把“周/月”文字当作精确交易日口径。旧 `rebalance_frequency` 输入若仍需兼容，须明确映射或有版本化迁移，不得让同一结果同时声称不同周期。此处只描述周期，不自行推断真实日历；后续数据适配器负责核对第 h 个开市日。
4. 无报告样本时仍返回明确的覆盖状态；只有评价日期都具备全股票池有效因子和收益时才生成分组诊断。预热日期缺收益不能阻断评价日期完整的分组曲线。

## 红测与验收

- 用 3 股连续 4 个开市日的 `ts_mean(close, 3)`：前 2 日仅预热，评价第 3、4 日；手算首个评价日的因子、IC/覆盖、结果日期和分组曲线，确认预热日不需要收益行、不出现在结果里。修改第 1 日历史值会改变最终因子与摘要。
- 拒绝不在计算日历内、重复/倒序/空评价日；仍拒绝评价日期收益漏行、重复、跨股票池和重叠窗口。`holding_sessions` 接受 1/5/10/20，拒绝其他值；默认全日期的旧路径保持原有计算结果。
- 仅跑直接相关因子结果/时间序列/组合测试、Ruff、diff 和固定清单契约。更新进度台账，只称纯计算合同已具备预热与精确评价周期；来源/PIT、Lab 与页面仍未接通。最终候选做一次独立终审，按项目普通任务的一次定向修复上限处理。
