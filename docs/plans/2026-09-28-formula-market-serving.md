# 公式批量任务的 Serving 状态与产物索引

## 范围与分级

只建立从公式任务库和封存结果到 Serving 的只读投影，供随后 Web/React 查询。扩展稳定的 `research_artifact_index` 合同，首个产物类型为公式批量结果；避免在网页直接连接任务库或研究数据源。本片不改命令、HTTP、React 或生产配置。高风险：状态与文件错配、读取时竞态或 Serving 混代会使页面展示错误选股结果。

## 验收

1. 用只读 SQLite 一致快照读取有界近期任务（建议最多 100 条），核对状态、请求摘要、来源摘要和结果引用。缺任务库时明确不可用，空库明确为空；库损坏或越界不伪装为空。不得创建/修改任务库或其 WAL。
2. 成功任务只在对应不可变 JSON 结果经内容 SHA256、任务 ID、请求摘要、来源身份和计数守恒检查通过后，进入产物索引；失败/排队/运行不带成功索引。索引仅保存相对受控路径、摘要、字节数、类型/版本、任务关联和小摘要，不把命中全集塞进 Serving。破损文件、链接、错目录、超大内容均拒绝发布当前索引。
3. Serving 对任务状态和产物索引使用同一次来源快照与 `available_at`；合同限行限字节、任务顺序稳定，跨表引用和时间顺序可校验。没有来源时以明确 unavailable 状态发布，不回退读取其它代拼接成功。生成/验证的一致性测试覆盖成功、排队、失败、文件被改、数据库并发写、截断、旧成功与新排队共存。
4. 聚焦测试、Ruff、diff 检查通过，最终候选一次独立审查。既有 Serving 表可读、既有数据审计投影行为不变。

## 冻结失败模型

- 资产：任务状态、来源身份、成功文件身份、Serving 中可查询的产物索引。
- 边界：可信任务库/私有结果目录→只读投影器→单一 Serving 数据代。
- 路径：读取不完整 WAL 状态、索引指向另一个任务或旧文件、文件在读取中换代、空状态掩盖来源损坏、两表来自不同观察时刻。
- 不变量：每条成功索引指向一个可验证的完整文件；每条任务状态与该索引同次观察；失败与部分结果绝不有成功索引；投影器不写源。
- 排除：Web/React、池子保存、生产目录授权与部署、真实大库负载。
