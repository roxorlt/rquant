# 公式池定义与最近逐日结果的只读发布

## 范围与分级

把已验证的公式池定义和每只池**最近一个已成功交易日**的结果封入同一个 Serving 数据代，供后续 Web/React 读取。普通任务：新增只读数据合同与用户可见状态，不改写生产数据、执行或权限；主要风险是把伪造、错版或过期的池子结果显示成当前结果。本片不做网页接口、保存按钮、批量调度或生产配置。

## 验收

1. 显式配置才读取受控的公式定义目录、每日结果目录、原有公式任务库/产物及 PageControl 审计。复用既有只读 PageControl 审计快照，逐定义核对成功的 `save_formula_pool_v1` 命令、命令摘要与回执版本，并从成功任务和封存产物复核公式、语法合同及创建证据。目录不存在、文件不安全/损坏、数量超限或同名规则池冲突不得默默漏掉或伪称为空。
2. 每只池可显示「尚未运行」或最近成功交易日；最近结果要由精确的定义版本、任务及封存产物核验，包含目标日、两来源身份、命中/未命中/未知数及受控结果文件的路径/内容摘要。完整成员不复制进 Serving 表，后续网页按本代索引再读受控文件。失败或当日缺数据不沿用旧结果称作今天；最近成功日只能按其真实日期展示。可信零命中与未运行、未知数量不同。
3. 发布 `状态 + 定义 + 最近结果索引` 三表，三表同一数据代、同一可用时刻并相互核对；未配置则整组缺席，配置且无定义则明确为空。表名与字段有界、定义名称唯一、每只定义至多一条最近结果且版本匹配。Serving 发布/读取时拒绝残缺三表、跨代、摘要/数量/日期不一致。规则池现有投影和旧数据代兼容保持不变。
4. 用合成的保存命令→两日重算→只读投影→Serving 代完成聚焦验证；覆盖未运行、可信零命中、未知数、定义/每日文件篡改、任务或审计缺失、目录超限、跨代与混合表。Ruff、相关 pytest、diff 检查通过，最终候选独立终审一次。真实约 10 GB 数据与 Linux 权限留待单独验收。

## 边界

- 领域定义和每日结果继续由 `formula_pool_definition`、`formula_pool_daily` 负责；只读适配器核验证据并产出投影，Serving 只封存，不计算公式或猜测成员。
- 旧规则池 `RuleCall` 合同不接受公式的空规则或静态成员；后续页面以有类型的「公式池」读模型与规则池汇合。
- 缺来源时保持不可用或未运行的真实状态，不回退到创建日命中或前一日成员。
