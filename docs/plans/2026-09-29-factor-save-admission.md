# 因子新建与编辑：受信保存命令

接续 [定义与数据起日解耦](2026-09-29-factor-definition-availability.md)、因子仓库和已上线候选的归档准入。本片只接通**已认证 Web → 私有 Unix 准入 → PageControl → 因子仓库**的保存后端及只读字段能力；React 表单另片接入。Web 和 PageControl 均不直接读写因子仓库；PageControl 不解析表达式，领域层独占定义构造。新定义的日期是 `None`，直到具体冻结研究来源能够证明数据范围，网页不能传日期、字段目录、依赖列、历史窗口或版本。

**分级：高风险。** 本片开放新的已认证写面，并沿用跨进程、跨仓库的持久命令链。基线为定义日期可未知且合并后通过聚焦验证的本地集成提交；实现前记录该提交与干净 diff，后续只审这条链和直接依赖。

## 冻结失败模型

- **资产与信任边界**：登录代理身份、独立因子编辑者精确名单、同站/CSRF、同一已核验 Serving 因子库数据代及仓库实例、用户草稿与原命令身份、私有 socket 的 Web peer UID、PageControl owned actor/命令/效果、SQLite 仓库当前 head 与不可变版本。浏览器不能持有仓库文件身份或直接构造完整 `FactorDefinition`。
- **失败路径**：伪造或缺失代理身份，非编辑者借旧命令续查，跨站写入，浏览器注入特征目录/日期/版本，过期数据代改错 head，新建 ID 碰撞，同命令 ID 换草稿或换操作者，Web 超时后重复提交，PageControl/仓库写入之间崩溃，准入后换库或 head 竞争，已写入回执被误称已发布，Web/监听器配置只有一端开启。
- **必须保持**：浏览器只交中文名、分类、方向、受限表达式、创建/编辑选择、精确旧 head、原命令 ID/时刻和数据代；Web 从同一借用代校验编辑目标及 `registry_instance_id`，指针换代拒绝。服务端唯一 `HISTORICAL_DAILY_V1` 目录解析表达式并构造版本 1 或旧版+1 的定义，明确填 `earliest_available_date=None`；暂不可运行的行业/市值算子在入队前拒绝。新建稳定 ID 由已认证 actor 与原命令 ID 确定性生成，编辑沿用已核验 factor ID。监听器独立核对 peer UID、编辑者名单、仓库实例，入队前捕获完整仓库身份；PageControl 对**保存和归档**都在执行前复核该身份，旧命令只在原库按原回执恢复。把**完整原浏览器请求**（创建/编辑方式、目标 factor ID 或新建标记、expected head、command ID、requested_at、原 generation ID、名称、分类、方向、表达式）的规范摘要及原 generation ID 持久绑定 owned 命令；续查按 actor、命令 ID 和该完整摘要精确匹配，不能仅按公式文本，也不受后来代码目录版本或 Serving 换代影响。Web 提交超时后，lookup 暂无命令只表示**不确定**：保留原请求与原命令 ID，不允许页面清除并另发新 ID；可用同一原请求和原 ID 再试，后端重新核验当前 head/仓库实例，仍不明时继续等待，不把 lookup 未命中转换为“已拒绝”。只有原提交得到明确的入队前拒绝，或原命令取得可核验终态后，才可结束原操作。成功回执要核对命令、动作、因子 ID、版本及内容摘要；只有更晚且同实例的 Serving 数据代核验该 head 后才显示“已保存”。
- **排除与阻断**：不创建生产仓库，不改 systemd/nginx/UID/密钥，不运行真实因子检验，不把公式保存当成数据已覆盖或因子有效，不部署或停 Streamlit。监听器和 Web 写入口默认关闭，未同时配置双端授权不能开放保存。仓库、指针、权限或回执身份无法核验时 fail closed，保留可续查命令；不通过其他 TCP/HTTP 写路由补救。

## 合同与实现边界

1. `rquant.factor` 提供有类型的保存草稿和确定性定义构造：只接受六个已支持日线字段和可运行算子，服务端生成新 ID、版本、依赖和窗口。已有已知起日的定义保留原日期与哈希；**编辑得到的新版本起日未知**，不沿用旧快照日期作为新公式的可用性承诺。分类和中文名限制由领域校验负责，Web 只给简短中文错误。只读能力响应来自同一个 `HISTORICAL_DAILY_V1`，明确“不代表数据覆盖”。因子仓库在 `save` 的同一写事务中限制当前 head 最多 512 个：第 512 个新 ID 可写，第 513 个在事务内拒绝；已满库仍允许编辑已有 ID。不能只靠 Web/Serving 预检，因为并发新建会越过预检。
2. PageControl 为保存的 owned 命令持久捕获仓库完整身份、完整原请求摘要和原数据代；通用 parser、loopback HTTP、普通 service/outbox 仍拒绝因子写。定向 submit/lookup/resume 只推进这条命令，不顺带 drain 其他待办。不同 actor/原请求同 ID 拒绝，失联重启后在原仓库查原回执；缺库/换库/坏历史保持不确定，不向新库重复写。旧本地受信保存桥仍可读取/测试，不静默重解释历史 payload。
3. 已有 `factor_definition_admission.py` 的私有 socket 扩展保存动作，保持独立 UID、私有路径、大小与超时上限。监听器接收完整原请求而非全量定义；Web 只传已核验仓库实例 ID，监听器与 backend 当前身份核对后构造并入队。恢复只需原请求摘要和 owned actor，不根据新数据代重新构造旧定义。协议错误不泄露仓库路径。
4. Web 增加默认关闭的因子保存能力、只读字段目录和 `POST` 保存/续查。新建允许已核验空库或有定义库；编辑只允许当前未归档 head，必须精确匹配版本和内容摘要。新提交前刷新并借用同代，核对当前指针；续查只依赖原命令和 actor，不强迫沿用旧 Serving 代。lookup 暂未命中时返回不确定，若需要再送原请求则沿用完整原请求/命令 ID，并以当前核验数据代再次确认同一 head 和仓库实例；当前证据不足时继续不确定，不重新绑定旧请求摘要。Pydantic→OpenAPI→生成 TS；响应区分明确拒绝、处理中、已提交待更新、已发布和不确定。

## 红测与完成条件

- 用临时仓库、合成 Serving 数据代与私有 socket 测新建 v1、编辑 v2、从零库新建、保存后数据代确认、同命令跨换代续查、服务超时/重启原样恢复。原 submit 延迟入队、首次 lookup 未命中时仍保持不确定；同一原 ID 重试最多写一次，不能转成新 ID。仅改目标 factor、旧 head、请求时刻或原数据代的同 ID 续查须拒绝。第 512/513 个新建的事务内边界及满库编辑须验证。非法字段/算子、客户端日期/目录/版本、归档 head、错 head、换库、同 ID 换 actor/请求、无 CSRF、无名单、错误 UID、旧数据代和伪成功回执必须拒绝且不新增版本。PageControl 仓库提交后崩溃时只恢复原事务；相关归档路径仍可用。
- 只跑 PageControl/因子仓库/准入/Web 路由及生成契约的直接回归、Ruff 与 diff；不为本片跑全量固定清单。终审一次性覆盖冻结范围；阻断项只定向修复和复核。用户界面与文案另片验收，生产启用另行授权。
