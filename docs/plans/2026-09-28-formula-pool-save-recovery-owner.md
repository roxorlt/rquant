# 公式池保存请求的单一恢复入口

## 决策与范围

React 公式池候选 `6ef9d1c1` 在普通任务的一次定向修复与复核后，`FPR-001` 仍未关闭：恢复入口按“任务是否在最近列表”显示，普通保存入口却按“所选任务成功且结果可读”显示；两条件不互补，可能同时消失或同时出现。原候选冻结，不再做同一轮补丁。本片把**当前登录用户的一条未结保存命令**作为独立的页面交互状态，由一个始终挂载的保存区域呈现；最近任务列表只决定是否可发起新保存，不决定原命令能否续查。普通任务：改变 React 交互，不改命令、服务端判定或生产配置。

## 验收

1. 当前用户存在本地保存 journal 时，页面始终只出现一个保存状态区域；503/网络未知后刷新，无论该任务在最近列表中、暂时不可读、列表失败或被截断，仍可用**原 request 与 command_id**继续核对。切换选中另一项成功任务，不出现第二个重复的待确认卡，也不生成新命令。
2. 只有没有待核对 journal，且所选任务在当前 Serving 代中成功、结果可读并有完整摘要时，才显示新建保存表单。用户结束已完成的 journal 后，状态区域立即隐藏或切回当前可保存任务的表单，不留下空卡。查看另一用户时，不恢复上一用户命令。
3. `succeeded` 回执只证明保存；仍须同一或更新 Serving 代出现精确池名与版本才说可在画布查看。读失败、未发布、旧代都保持行动文案；冲突和明确失败允许改名重试，网络不明不换命令 ID。原公式结果和规则池行为不受影响。
4. 用同一组件级测试覆盖“最近列表缺失”“任务存在但结果不可读”“列表 503”“选 B 时 A 待核对”“保存完成后结束 journal”“切 viewer”，先复现再修复；跑相关 Vitest、类型/构建/产物检查、390px 与键盘路径。最终候选独立审查一次，只检查本片和直接回归。

## 边界

本片只调整保存交互的状态归属与渲染条件；保持 Web/PageControl 的幂等和 Serving 同代事实来源。未通过前不合入原 React 候选，不发布生产，也不把单次结果当每日公式池。
