# 加入盯盘：原型按钮与页面反馈

接续 [可信写入入口](2026-09-28-manual-watchlist-admission.md)。原型的个股抽屉「加入盯盘」和选股器结果区同名操作都须接真实名单；盯盘页可查看手动名单。只有名单读写与告警范围具备可验证端到端行为时才向正式用户开放，避免把“已入名单”误写成“正在告警”。

**分级：高风险。** 私有名单缓存、异步回执或批量部分成功若被误呈现，会让用户漏看应监控的股票；冻结下面的范围供后续实现与审查。

## 交互与文案

- 个股抽屉在概要附近提供清楚的「加入盯盘」/「移出盯盘」操作。已加入、已到期、尚未加入、状态暂不可用、请求待核对、权威已写但页面未同步分别显示；仅下一代按当前用户、同一代码与命令版本核对后才能显示「已加入盯盘」或「已移出盯盘」。缺数据时给「名单暂不可用，请稍后重试」，不猜测为空。
- 选股器对**当前已确认结果集合**提供批量加入：按钮与确认框明确只数、筛选日期和范围，不默默只处理当前 20 行或任意截断；按名单容量与逐只 CAS 反馈实际成功、已在名单、冲突、失败的数量和可重试对象。若当前 API 无法证明完整集合，就缩小文案为「加入本页 20 只」并在确认框说明该范围，不冒充全部结果。
- 盯盘页把手动加入的股票与自动池子来源说明清楚；仅手动成员可从此处移出。到期项不再列作有效盯盘，单股详情可重加。技术编号、服务名和内部数据代只放提示或日志；可见文案短、中文，价格两位小数、数量千分位，相对时间带悬停具体时刻。
- 请求排队/处理中只显示「正在处理」，回执丢失显示「状态待核对」并保留原请求供刷新后续查；PageControl 已成功而 Serving 尚未反映显示「已保存，正在同步」，不先写“已加入”。冲突提示刷新名单，容量提示移出其他股票后再试。

## 私有状态与验收

- React Query 的名单 key 必须包含可信 `/meta` 用户身份和数据代；身份变化、`/meta` 失败、抽屉换股时立即清除或隐藏旧私有数据，不能将前一用户/股票的状态短暂显示给下一位。不可用时按钮禁用且可重试；不缓存肯定状态跨过到期时刻。
- 桌面与 390px、键盘焦点/Enter/Space、触屏提示、等待/空/错误/冲突/部分成功均有行为证据。原型按钮不留下仅弹“示例成功”的路径。前端检查、构建产物与有针对性的真实浏览器路径通过后，再按正式 Serving 与生产授权条件决定发布及旧服务替代。

## 选股结果批量加入的冻结边界

- **资产与信任边界**：选股结果只是本次已核对的研究候选，不能充当手动名单权威。当前页最多 20 只；用户名、名单版本和有效成员只从私有同代名单读取，写入仍逐只走现有受保护命令与 PageControl CAS。按钮、确认框和最终摘要必须指明“本页”以及实际只数、筛选日期；翻页或改条件后不能沿用旧候选。
- **失败路径**：候选中有已加入、到期或墓碑成员；名单读取失败或换代；并发标签重复点击；第 N 只容量满或版本冲突；提交成功但响应丢失；PageControl 已保存而 Serving 仍旧；用户在处理中离开页面。这些情况下不能把整批描述为成功，也不能生成新命令来掩盖原请求。
- **不变量**：确认时固定一次有序、去重的当前页股票快照。逐只先核对认证用户、同一名单数据代和该股票当前版本；已有效加入的只计“已在名单”，不可用的只计“未处理”。提交前持久保存每只原请求，重试只续查原 ID 和内容；确认“已加入”须是原命令成功回执与后续同用户、同股票、匹配版本的新数据代同时成立。汇总分开显示已加入/已在名单、已保存待同步、待核对、冲突、容量和失败；所有计数之和等于确认的只数。不能把本页的 20 只称为全部命中结果。
- **排除项**：本片不改变筛选计算、PageControl 单只原子语义或生产监控范围；告警读取手动名单另行实现与验证。前端逐只请求不暗示服务端存在批量事务。
- **验收证据**：当前页少于/等于 20 只、总命中超过本页、换页/改条件、已在名单、墓碑重加、容量和冲突、响应丢失与刷新续查、部分成功与 Serving 延迟均有聚焦行为证据；桌面及 390px 浏览器里确认范围、进度和结果可读且键盘可操作。
