# 选股历史数据读取边界与迭代计划

> 2026-09-27。基于 `cdx/20260927-web-tdx-import` 的隔离分支。C4.1 仍为「部分」；本文件冻结下一增量的范围，不表示完整功能已经上线。

## 依据与任务分级

用户要让可点击原型的手工选股真实可用，最终补齐 26 条条件的参数、逐条命中、分页、排名和文案。当前 `nl_screen_universe` 只发布当日列，部分条件需要 T-30 的数据和最长 500 个交易日的窗口。把全部历史列放进现有 Serving 投影会超过 512 列与 6 MiB 的合同上限，也增加发布与网页常驻内存负担。

本增量定为**高风险**：网页新的只读数据边界会接触共享 DuckDB 副本；副本换代、来源不一致或查询过重可能造成错选或影响线上服务。代码实现前以本文件的信任边界和不变量为冻结范围。生产配置、主库写入、旧服务停用仍需另行授权。

## 第一性原理与模块边界

1. 股票筛选的权威是某个具体时刻的日线、指标、状态与交易日历的**同一份只读副本**。网页只负责输入/鉴权/响应；领域层复用 `screen.rules`、`screen.loader`、`screen.ranking`。React 只负责条件编辑、结果和状态。
2. 用现有 `rquant_ro.duckdb` 和 `.generation.json` 作为来源；**不回退连接生产主库**。副本必须是常规文件、不是符号链接或主库别名，sidecar 的副本指纹与当前文件一致，发布时的 `source_before/source_after` 一致。运行时身份再加入 ctime，防止同 inode、同大小且恢复 mtime 的原地改写。
3. 每次请求只借用一个已核验的副本连接。读取前后复核文件身份；更换发生在查询中则舍弃结果。分页游标沿用现有 HMAC 格式，但绑定副本身份、交易日、规范化条件、排名和排序；下一页若副本变化返回中文 409，页面保留条件并提示重新筛选。
4. Serving 数据代继续服务总览、全景与页面横幅；筛选结果明确展示自己的「数据截至…」和最近更新时间。不得把两个来源的字段拼为同一行结果，也不得把副本状态冒充 Serving 状态。同步文件短暂换代或损坏时用清楚的空/错误状态，不显示旧结果为新结果。
5. 只允许目录里的有界规则与字段，不执行任意表达式、SQL 或通达信源文本。保留 8 KiB 请求、26 条条件、8,000 只股票和单次并发门；按规则计算所需历史跨度，不无条件载入 500 日宽表。窗口聚合仍交给领域 SQL，缺失数据按原规则 fail closed。

## 冻结威胁/失败模型

- **资产**：生产主库完整性、同一请求的筛选事实、跨页结果一致性、网页 API 的内存/CPU、用户看到的数据时效。
- **信任边界**：浏览器输入是不可信的；规则注册表和 Pydantic 是唯一允许的计算入口；副本及 sidecar 由已有同步器产生但在读取时必须重新核验；Serving 与副本是不同发布链。
- **失败路径**：副本不存在、损坏或与 sidecar 不匹配；同步器在请求中原子换代；同 inode 原地改写；副本缺交易日历或某个事实表；状态在决策时点不可见；用户提交最大 offset/window 和重复条件导致资源膨胀；下一页使用旧数据身份；网页把内部代号或路径写进正文。
- **必须保持**：没有任何生产主库连接或写入；单次结果只来自同一已验证副本；未知/缺失事实不能变成命中；版本变化不能悄悄续页；无事实时不报「0 只符合」；超出预算的请求得到可理解的失败；页面正文无内部标识。
- **明确排除**：生产同步器/配置改造、数据修复、公式求值与保存、自然语言解析、盘中选股、用户池写入、旧 Streamlit 停服。

## 分步实施与验收

### A. 已有指标上的历史条件

- 将选股目录与执行统一切到受核验只读副本，按真实有数据的交易日列出最近日期；缺副本显示「选股数据暂不可用」。
- 用已编译规则的 `min_lookback` 与 `aggregate_requests` 算需求；支持 offset 0–30、量比 window 1–60、状态窗口至 500 交易日以及现有固定 MA/RSI 的交叉与比较。排名仍保留当前可用列的按需展示。所有 26 条规则的**已支持参数组合**须有真实数据行为证据；未支持参数不得被页面作为可运行选项。
- 验证 T-30、500 日窗口、缺一天日历、状态时点未可见、跨页副本换代、sidecar 错配、同 inode 改写、主库别名、请求并发限制，及 390 px/桌面条件与错误交互。至少对一个来自正式格式副本的样本作领域规则与 API 结果对照；无生产数据写入。

### B. 完整参数范围

现有日指标只存 MA5/10/20/60 与 RSI6/14，而注册表允许 MA 2–250、RSI 2–60。A 阶段不能以 26 条规则名称都可点选冒充参数完整。B 阶段需先选定与 `indicator.technical` 一致、可在副本上有界计算并验证的动态指标方案，再开放所有参数；以现有 MA/RSI 周期结果交叉校验。完成 B 后才把 C4.1 标为完整。基本面与盘中条件分别属于 C4.3/C4.4，仍按计划独立接入。

## 验证与发布边界

最终候选只对本增量 diff、直接依赖、相关聚焦测试和桌面/390 px 实际交互做一次独立审查；高风险修复至多三轮。服务性能以一只真实格式副本的最大合法请求测内存与耗时；若超过当前服务器可承受预算，先收窄请求并如实呈现，不能静默返回不完整命中。此分支本地验证成功也不等于线上切流或旧服务可停。
