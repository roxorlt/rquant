# 池子定义：权威发布与规则查看

**目标**：把内置池及 PageControl 已保存的自建池定义作为有界、可核验的只读 Serving 投影发布，再接到池子画布。命令成功表示“已保存”，同版 Serving 投影表示“规则已发布”；只有后续日终计算产物能证明使用同版定义时，页面才可显示“结果已按新规则更新”。本切片先建立读取事实，随后再接编辑提交。与[池子定义 v2](2026-09-27-pool-definition-v2.md)及[画布总计划](2026-09-27-pools-canvas-web.md)相邻实施。

**分级**：高风险。投影跨越可变 JSON、PageControl 审计和不可变 Serving 数据代；错误版本或伪造定义会使用户误判筛选规则。本文件是实现前的冻结失败模型。

## 资产与信任边界

- **内置定义**来自随代码发布的固定规则元数据，版本跟随代码；它们只可查看或复制，网页不能原地编辑。读取内置规则时不得隐式访问 `.env`、主库或动态用户目录。
- **自建定义**来自 PageControl 管理的 `user_presets`。投影只接受常规文件、受控目录、有限大小和规范字段，并在同一次稳定 PageControl 审计快照内核对最近成功的保存/删除命令、命令哈希、效果状态、文件内容及版本。文件里的 `command_id/hash` 自称不能单独证明权威。旧直接写入且无审计的文件保留明确的“尚不可编辑/待迁移”状态，不伪装为已核验规则。
- **数据代**单次原子发布定义、版本和可用状态；网页借用同一代获取画布引用、池子成员和规则定义，但同代不证明成员由当前规则版本计算。连接只来自已核验的 `depends_on`，不能从 `canvas.pool_refs` 推测依赖。用户看到的积木名称/参数由规则目录映射成简短中文，原始键/哈希仅用于请求或详情，不进正文。

## 失败路径与不变量

| 失败路径 | 不变量 |
|---|---|
| 文件被替换、软链接、过大、读取期间旋转 | 对该来源拒绝发布或标为不可用；不能沿用上一代当作当前规则 |
| 文件字段与成功命令不一致、审计中有未完成命令、删除后残留文件、旧版本回滚 | 不发布为“规则已发布”；版本只能对应当前权威定义 |
| 已保存但 Serving 尚未发布、Serving 发布了旧版本 | 页面区分“已保存，等待规则发布”与“规则已发布”，直到同版投影出现目标版本 |
| 同一 Serving 数据代含当前规则与旧筛选成员 | 不能暗示新规则产生旧结果；只有计算产物带定义版本凭据且匹配时才显示“结果已按新规则更新” |
| 旧 JSON 缺审计、父池缺失或环、内置规则元数据不可得 | 显示明确不可用/不可编辑原因；不绘制推测的依赖线或允许无证据保存 |
| 定义过多或规则过长 | 服务端有行数与总字节上限，超限显式失败，不截断成貌似完整的规则 |

## 验收

1. 合成 PageControl 文件与审计覆盖内置、旧审计、自建 v2、删除、冲突、部分写、软链接/轮换/过大和缺父池；不可信定义永不成为可编辑版本。已验证的 v2 精确 T-N 与旧窗口在投影里保留不同语义。
2. `pool_definition` 合同与数据代可用状态稳定；同一代 API 把已发布规则、依赖和成员对齐，空态/错误/待迁移说清原因。桌面、390px 和键盘能看规则及真实依赖，不显示技术键正文。
3. 直接相关 Python、OpenAPI→TypeScript、React 和浏览器聚焦验证通过；最终候选安排一次独立审查。此阶段不新增写入口、不修改生产配置、不切流或停用 Streamlit。
