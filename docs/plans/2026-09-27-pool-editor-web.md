# 池子画布编辑闭环

目标：把原型里的「添加条件节点」和既有自建池条件编辑接到 PageControl 权威命令，经过规则发布与下一次选股结果两道可见状态，再显示为画布上的真实节点。自然语言改池子沿同一预览与保存路径接入，但解析器属于后续独立切片。

**分级：高风险。** 网页将发起会改变日终筛选定义的命令；只在隔离工作树开发，生产权限、服务配置、部署与切流仍需项目要求的单独授权。

## 资产、信任边界与失败模型

资产是用户的池子定义、下一次日终筛选、已发布规则与可见成员。浏览器 → Web API → 本机 PageControl → 原子定义文件 → 只读 Serving 数据代是单向边界。网页不能写主库或定义目录，也不能把前端参数解释为已执行规则。

必须保持：只有已鉴权用户通过同源 JSON 写请求提交；Web 只转译受支持的池子字段并将请求交给固定 loopback PageControl 端点；PageControl 的规则编译、父池存在/无环、精确延后日、乐观版本与幂等检查仍是最终权威。重复提交相同命令不能重复生效，版本冲突不能覆盖别人的修改。旧 Serving 数据代没有可编辑定义时拒绝写入；旧内置池不可直接编辑，需要先复制为自建池。已受理、已保存、规则已发布、结果已按新规则更新是不同证据，页面只显示实际达到的状态。任何提交失败或发布滞后都保留原画布与可重试的草稿。

排除：实盘下单、生产迁移、自动删除池子、未确认的自然语言解析结果。父池删除时的依赖保护单列为后续权威命令切片；此片不显示删除入口。价格、收益及成员读取沿已有只读 Serving 路径，不由编辑命令推算。

## 实施边界

1. **只读编辑数据**：从一次借用的 Serving 数据代读取 `pool_definition` 的 `version`、`can_edit`、原始注册规则参数和父池/延后日，形成有类型、有限长度的编辑模型。画布正文继续只显示中文规则和状态；技术键只在请求体和必要的提示内。数据代不完整、定义不可用或版本未知时编辑按钮不可提交。选股积木目录复用现有有类型目录，不建第二套规则口径。
2. **写入网关**：新增限定为池子保存的 Web API，验证身份、同源与 CSRF、请求大小、命令标识和入参上限；把新建/更新映射成 `SaveUserPoolV2`，仅向配置中经过 loopback 校验的 PageControl `/v1/commands` 发送。客户端重试携带相同命令 ID、请求时间和载荷；超时状态显示待确认，不生成新命令猜测结果。PageControl 返回失败时映射为简短的冲突/规则无效/服务暂不可用文案，不把内部路径或异常输出给页面。测试用可注入传输，不访问在线服务。
3. **真实编辑交互**：桌面用聚焦侧栏或弹层，390px 用全宽表单；支持选择父池、精确延后交易日、一个或多个积木及其有类型参数，能预览将保存的中文条件与影响的池子。提交前明确目标池名、父池、规则，保存后先显示「已保存，等待规则发布」；刷新到同版本 Serving 后显示「规则已发布，等待下次选股」；有同版本结果回执后才显示「结果已按当前规则更新」。空态、错误、键盘、焦点归还和换数据代均有确定行为；不把旧成员冒充新规则命中。

## 验收与停止条件

- 用真实小型 PageControl outbox/消费者和合成 Serving 数据代串起新建、更新、重试、版本冲突及结果状态推进；验证旧定义内容在冲突/无效规则后不变。
- API 拒绝无身份、跨站、错误 Content-Type、非 loopback 配置、内置池直接编辑、旧/损坏的编辑数据和超限载荷。PageControl 不可用/超时不可提示“保存成功”。
- 前端验证桌面、390px、键盘、空态、离线、冲突、页面刷新与换代；正文无命令 ID、版本哈希、规则函数名或服务代号。提交时所有按钮确有后端行为。
- 只跑受影响的 PageControl、池子 API、前端与浏览器回归；最终候选一次独立审查。正式生产权限、资源和切流另做前置核验，不以本地测试替代。
