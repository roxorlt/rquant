# 池子画布编辑闭环

目标：把原型里的「添加条件节点」和既有自建池条件编辑接到 PageControl 权威命令，经过规则发布与下一次选股结果两道可见状态，再显示为画布上的真实节点。自然语言改池子沿同一预览与保存路径接入，但解析器属于后续独立切片。

**分级：高风险。** 网页将发起会改变日终筛选定义的命令；只在隔离工作树开发，生产权限、服务配置、部署与切流仍需项目要求的单独授权。

## 资产、信任边界与失败模型

资产是用户的池子定义、下一次日终筛选、已发布规则与可见成员。浏览器 → Web API → 本机 PageControl → 原子定义文件 → 只读 Serving 数据代是单向边界。网页不能写主库或定义目录，也不能把前端参数解释为已执行规则。

必须保持：只有已鉴权用户通过同源 JSON 写请求提交；Web 只转译受支持的池子字段并将请求交给固定 loopback PageControl 端点；PageControl 的规则编译、父池存在/无环、精确延后日、乐观版本与幂等检查仍是最终权威。重复提交相同命令不能重复生效，版本冲突不能覆盖别人的修改。旧 Serving 数据代没有可编辑定义时拒绝写入；旧内置池不可直接编辑，需要先复制为自建池。已受理、已保存、已加入当前画布、规则已发布、结果已按新规则更新是不同证据，页面只显示实际达到的状态。任何提交失败或发布滞后都保留原画布与可重试的草稿。生产入口沿用 nginx 覆写身份头和 loopback PageControl 的同机受信域假设；本片不把本机其他进程当作隔离用户。

排除：实盘下单、生产迁移、自动删除池子、未确认的自然语言解析结果。父池删除时的依赖保护单列为后续权威命令切片；此片不显示删除入口。价格、收益及成员读取沿已有只读 Serving 路径，不由编辑命令推算。

## 实施边界

1. **只读编辑数据**：从一次借用的 Serving 数据代读取 `pool_definition` 的 `version`、`can_edit`、原始注册规则参数和父池/延后日，形成有类型、有限长度的编辑模型。当前画布的已验证 `version_hash` 和成员引用也来自这一次数据代。画布正文继续只显示中文规则和状态；技术键只在请求体和必要的提示内。数据代不完整、定义不可用或版本未知时编辑按钮不可提交。选股积木目录复用现有有类型目录，不建第二套规则口径。
2. **写入网关**：新增限定为池子保存与画布挂接的 Web API，验证身份、同源与 CSRF、请求大小、命令标识和入参上限。新建/更新先提交 `SaveUserPoolV2`；所选保存画布还需提交新的幂等 `AddPoolToCanvas` 命令，由 PageControl 消费者读取当前已验证画布并追加引用，要求目标池文件仍是前一命令返回的确切版本。两条命令不伪装成单事务：保存成功而挂接失败时保留定义，显示「池子已保存，尚未加入当前画布」；画布当前版本变化时在权威侧重读、追加，不能用旧引用全集覆盖别人修改。默认全部池子视图无需挂接。旧 `SaveUserPoolV2` 合同与历史命令哈希保持兼容。Web 传输只直连 `127.0.0.1:8767/v1/commands`，不用环境代理、DNS 或重定向；HTTP 3xx 一律失败。测试注入传输，不访问在线服务。
3. **幂等回执协议**：首次发送前在同源 `sessionStorage` 写入该阶段的完整、不可变命令体（命令 ID、请求时间、载荷和阶段）；写入失败则不提交。超时、刷新或 `pending`/`processing` 只用原命令体再次 POST 续查，按有界退避等待，不生成新 ID；`ambiguous` 显示「状态待确认」并保留原命令供人工核对，不自动换 ID；只有 `succeeded` 且保存回执含有效版本（挂接回执可核对目标画布）才进入下一阶段。挂接命令终态 `failed` 后，用户可重试挂接：保留已成功保存的定义及其确切版本，先由新的挂接命令在 PageControl 内复核当前权威池文件和画布头，再用**新**命令 ID 进行幂等追加；绝不重做保存，也不能用旧失败 ID 期待消费者再次执行。保存命令终态 `failed` 则保留可修改草稿，修改或明确重试时再建新保存命令。提交回执不代表 Serving 已发布。浏览器时间偏差导致的权威拒绝显示时间校准提示。
4. **真实编辑交互**：桌面用聚焦侧栏或弹层，390px 用全宽表单；支持选择父池、精确延后交易日、一个或多个积木及其有类型参数，能预览将保存的中文条件与影响的池子。提交前明确目标池名、父池、规则。保存与挂接成功后仍须等同一 Serving 数据代中的目标池版本及当前画布成员引用均发布，才显示「规则已发布，等待下次选股」；只有现有池子 API 给出可信 `result.state == current_rules`（含谱系、日期、成员数和 `current_definition` 校验）且定义版本为本次保存版本时，才显示「结果已按当前规则更新」。其余状态不沿用旧成员。空态、错误、键盘、焦点归还和换数据代均有确定行为。

## 验收与停止条件

- 用真实小型 PageControl outbox/消费者和合成 Serving 数据代串起新建、更新、目标画布挂接、重试、版本冲突及结果状态推进；挂接响应丢失后以同命令续查，终态 `failed` 后以新挂接命令复核权威状态并重试，两个路径都不得重做已成功的池定义保存，新池最终出现在所选画布。冲突/无效规则后旧定义字节不变；两个画布编辑相邻提交不能丢引用。
- API 拒绝无身份、跨站、错误 Content-Type、非固定直连目标、代理环境影响、HTTP 重定向、内置池直接编辑、旧/损坏的编辑数据和超限载荷。PageControl 不可用/超时不可提示“保存成功”。
- 前端验证 `pending`、`processing`、`succeeded`、`failed`、`ambiguous`、响应丢失后刷新续查、浏览器存储不可用、桌面、390px、键盘、空态、离线、冲突及换代；同版本但谱系不完整的回执不得宣称结果已更新。正文无命令 ID、版本哈希、规则函数名或服务代号。提交时所有按钮确有后端行为。
- 只跑受影响的 PageControl、池子 API、前端与浏览器回归；最终候选一次独立审查。正式生产权限、资源和切流另做前置核验，不以本地测试替代。

## 下一片：新建画布的受控命令

旧画布服务还提供「新建画布」，因此池子编辑闭环完成后也不能直接停掉该服务。现有 `SaveCanvas` 会更新同名画布；网页如果只凭旧 Serving 列表判断名字可用，就可能在并发或发布滞后时覆盖已有定义。新建必须有独立的创建语义。

这一片按**高风险任务**实施。资产为已发布画布定义及其池子引用；浏览器、Web API、PageControl 和只读 Serving 的信任边界沿用上文。必须保持：创建不能覆盖同名画布或墓碑状态；同一命令重试只产生一次效果；另一命令抢先使用该名称时明确冲突；失败、超时和发布滞后不显示“已创建”；网页永不直接写定义文件。排除重命名、删除和任意重排引用，这些需要各自的权威命令。

推荐在 PageControl 单消费者互斥区内加入 `CreateCanvas`：核对权威 head 与目录均未占用名称，然后复用现有签名发布与原子写入；Web 只传有界名称、描述及幂等身份，初始引用为空，不把浏览器的引用全集交给 `SaveCanvas`。`SaveCanvas` 直接暴露给网页虽省代码，却没有创建冲突保护；仅在网页检查 Serving 列表也挡不住发布延迟和相邻提交，故不采用。成功回执带供内部匹配的发布身份；React 只有从同一 Serving 数据代读到对应身份和新画布，才显示“画布已可用”。技术身份不进正文。

验收用两个相邻创建命令、同 ID 丢响应重试、提交后消费者崩溃恢复、旧代未发布、损坏权威文件和同名已删除记录验证不覆盖；另测无身份、跨站、错误类型、超长输入、PageControl 不可用，以及桌面/390px/键盘路径。只做离线合成链路和聚焦回归；生产配置与停服仍按单独授权边界处理。
