# 数据中心财务概况：只读副本与可见范围

接续 [基本面每日状态与选股条件](2026-09-28-financial-derived-screen.md)。C1.4 的选股条件已经能读取经核验的只读副本；本片让数据中心的「财务」区域回答三件事：最近哪个决策日已有基本面状态、六个字段各有多少只股票可用、缺数主要因为什么。页面只显示有证据的记录数，不把“有记录”称为全市场覆盖。

**分级：高风险。** 财务状态和选股共用 PIT 证据。若概况读取旧 head、遗漏坏版本、把可用行数当覆盖率，用户会误以为回测和筛选已有完整历史。

## 资产与信任边界

- 权威输入是经 sidecar 核验的一代只读副本，内含 `fundamental_daily_head`、不可变 `fundamental_daily_version`、SSE 逐日历及日线；财报原始归档和主库不进入网页进程。边界为 `固定副本 → 专用汇总读取 → 有类型 Web API → React 数据中心`。目录里的静态字段说明不代表数据已采集。
- 与选股共用 head→version 和 T17 决策回执校验。汇总只读一条固定副本连接，完成前再核对副本身份；不能分别读取 head、版本、日历后拼接不同代，也不能用外层 Serving 代替财务来源代。
- 源身份、版本哈希和内部原因码只用于服务端核验与界面提示，不进入页面正文。页面显示中文字段名、单位、日期、记录数和简短原因。

## 不变量与界面口径

1. 查询开始时注入一次带时区的时钟，转换为 `Asia/Shanghai` 日期与时刻；不会在同一请求中跨过 17:00 重新选择日期。只选最近一个**已到固定 T17（当地 17:00）决策时刻**的 SSE 开市日作「本次核对日」：今日开市但尚未到 17:00 时，候选是前一个开市日，正文显示「等待今日 17:00」；17:00 起候选为今日；休市日候选为此前最近开市日。15:00–17:00 不把今日称为已完成决策日。候选和它之前一个开市日都须位于最多 32 个自然日的有界查找范围；从前一个开市日至当前上海日期的每个自然日必须各有一条 `source='tushare'` 的 SSE 日历记录，开闭状态与 `pretrade_date` 链须自洽。任何日期缺行（包括日历只到昨日）、日历来源或链不可信、尚无合格候选时，核对日及计数均为未知，不能回退到旧日或报零。不能因为候选日零行而自动退到有记录的旧日期。
2. 本次核对日的**全部** head 先用有界 `LEFT JOIN` 取最多 8,001 行，不以日线证券列表、非空字段或内连接预先缩小集合；第 8,001 行即拒绝。每个 head 必须一对一指向同证券、同日期、同修订的版本，且其修订号等于该证券/日期所有存储版本的最高修订号；较高修订即使坏掉也不能忽略并回指旧版本。无日线行的 head 仍须校验。版本身份、T17 决策时刻、六项字段 JSON 与数值列必须符合现有选股校验；任一记录失配时整次汇总不可用，不跳过坏行。校验逻辑从现有选股读取层抽取为一个共用函数，汇总与筛选不得各写一套 PIT 判断。若展示「最近有记录日」，须另外对那个日期的全部 head 做同样有界校验；不能用 `MAX(trade_date)` 冒充已核验记录。
3. 各字段分别统计「有值」和「未知」记录，六字段各自的两类计数之和必须等于已核验 head 行数。`pe_ttm` 等负盈利空值不补零；较新报告期缺值也不回退。未知原因只由服务端白名单映射为「尚无来源记录」「披露尚未可见」「字段缺值」「来源证据不足」「日历待核验」「候选数量超限」「数值不可用」「其他原因」；未识别码归「其他原因」。按数量降序、固定类别顺序排序；无截断时最多返回四类，截断时最多保留三类具体原因，余项（包括原有「其他原因」）合并为第四类「其他原因」。返回的各类数量之和必须等于该字段未知数；API 不返回原始原因串。统计只覆盖本次核对日已派生的股票，不声称其等于全市场股票数或历史数据的完整率。没有权威采集完成回执时，页面固定说明「全市场覆盖尚未核验」。
4. 当前表没有按日完成回执，因此核对日零 head 时只显示「该日暂无可核验记录」，计数保持未知，不称「可信零行」或零覆盖；即使旧日有记录也一样。没有配置副本、零 head、来源身份变化、校验失败分别显示可理解的不可用状态。API 返回财务副本身份、**副本同步时间**和已核验记录日期；同步时间不冒充财报日期，也不得使用旧 Serving 横幅时间。首次请求不带 `expected_identity`，获得身份 A 后后续请求带 A；若读前已换到 B，返回 409，读中换代或副本损坏则返回不可用且不携带旧计数。手动刷新一开始就隐藏旧卡片；409 时清除 A 身份与缓存，最多自动重新发现一次 B，确认 B 后才显示新计数；再次失败则保留错误与刷新入口。查询键由独立财务来源身份和刷新序号构成，不靠 Serving `/meta` 发现换代；Serving 代际变更不得把旧财务查询重新展示。刷新期间、错误时，即使 React Query 留有旧 `data` 也不得渲染；过期请求用取消或请求序号隔离。
5. 页面把「财务」放在数据中心现有导航/分类里，六字段只保留必要名称、单位、记录数和最近日期；字段定义、公告后可见时刻与缺数解释放在 hover/点按提示。390px、键盘焦点、加载和空态遵守 `web/AGENTS.md`。没有真实报告来源时不显示看似完整的覆盖柱图或样例值。

## 验收与发布边界

- 合成副本验证：注入时钟分别落在盘中、15:00–17:00、17:00 后和休市日；日历只到昨日、自然日中间缺行或链错误均拒绝。覆盖同日混合有值/未知、亏损空 PE、较新报告期全空、head 无日线行、A/B 两修订却回指 A、缺版本、版本身份改写、跨日期指针、T17 不符、第 8,001 行、核对日零 head、旧日有记录而核对日零 head、未配置副本及读中换代。坏证据不得返回部分计数；零 head 不返回数值零。
- 原因分类验证每种白名单、未识别码、超过四类合并以及每字段「各类之和 = 未知数」；正文不出现原始原因码。API 与 React 验证首次发现 A、空闲 A→B 手动刷新、读中换代、409 后一次发现、错误时清除旧卡片、六字段计数、中文文案、无内部标识、加载/空/错误、桌面和 390px；只跑直接相关的聚焦 Python/Web/浏览器路径，最终候选一次独立高风险审查。
- 真实 Tushare 权限与额度、正式采集、Linux 锁、主库迁移、生产副本负载和发布配置仍单独验收或授权。未完成这些条件前，数据中心财务概况只记本地候选，不作为 Streamlit 退出依据。
