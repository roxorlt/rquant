# 数据中心财务概况：只读副本与可见范围

接续 [基本面每日状态与选股条件](2026-09-28-financial-derived-screen.md)。C1.4 的选股条件已经能读取经核验的只读副本；本片让数据中心的「财务」区域回答三件事：最近哪个决策日已有基本面状态、六个字段各有多少只股票可用、缺数主要因为什么。页面只显示有证据的记录数，不把“有记录”称为全市场覆盖。

**分级：高风险。** 财务状态和选股共用 PIT 证据。若概况读取旧 head、遗漏坏版本、把可用行数当覆盖率，用户会误以为回测和筛选已有完整历史。

## 资产与信任边界

- 权威输入是经 sidecar 核验的一代只读副本，内含 `fundamental_daily_head`、不可变 `fundamental_daily_version`、SSE 逐日历及日线；财报原始归档和主库不进入网页进程。边界为 `固定副本 → 专用汇总读取 → 有类型 Web API → React 数据中心`。目录里的静态字段说明不代表数据已采集。
- 与选股共用 head→version 和 T17 决策回执校验。汇总只读一条固定副本连接，完成前再核对副本身份；不能分别读取 head、版本、日历后拼接不同代，也不能用外层 Serving 代替财务来源代。
- 源身份、版本哈希和内部原因码只用于服务端核验与界面提示，不进入页面正文。页面显示中文字段名、单位、日期、记录数和简短原因。

## 不变量与界面口径

1. 只选最近一个**已收盘且 SSE 日历完整**的交易日作「本次核对日」，不因为这天零行就自动退到有记录的旧日期。另列「最近有记录日」，两者不相同则说明数据尚未跟上。日历缺行、未收盘、来源损坏时保持未知，不能报零覆盖。
2. 本次核对日的每个 head 必须一对一指向同证券、同日期、同修订的版本；版本身份、T17 决策时刻、六项字段 JSON 与数值列必须符合现有选股校验。汇总沿用选股的 8,000 只股票上限；超过上限或任一记录失配时整次汇总不可用，不跳过坏行。校验逻辑从现有选股读取层抽取为一个共用函数，汇总与筛选不得各写一套 PIT 判断。
3. 各字段分别统计「有值」和「未知」记录，未知原因按用户可理解的类别聚合并限制返回条数；六字段各自的两类计数之和必须等于已核验 head 行数。`pe_ttm` 等负盈利空值不补零；较新报告期缺值也不回退。统计只覆盖本次核对日已派生的股票，不声称其等于全市场股票数或历史数据的完整率。没有权威采集完成回执时，页面固定说明「全市场覆盖尚未核验」。
4. 没有配置副本、该日期未派生、可信零行、来源身份变化、校验失败是不同状态。API 返回财务副本身份和更新时间；React 的查询键绑定身份，换代或错误时撤掉旧统计并给出可操作的刷新入口。不得将旧 Serving 横幅的时间写成财务数据更新时间。
5. 页面把「财务」放在数据中心现有导航/分类里，六字段只保留必要名称、单位、记录数和最近日期；字段定义、公告后可见时刻与缺数解释放在 hover/点按提示。390px、键盘焦点、加载和空态遵守 `web/AGENTS.md`。没有真实报告来源时不显示看似完整的覆盖柱图或样例值。

## 验收与发布边界

- 合成副本验证：同日混合有值/未知、亏损空 PE、较新报告期全空、旧 head、缺版本、版本身份改写、跨日期指针、T17 不符、应取日零行、较旧日有行但最新日缺行、日历缺失、未收盘、超过行数上限及读中换代。坏证据不得返回部分计数。
- API 与 React 验证同源身份、六字段计数、中文文案、无内部标识、加载/空/错误、桌面和 390px；只跑直接相关的聚焦 Python/Web/浏览器路径，最终候选一次独立高风险审查。
- 真实 Tushare 权限与额度、正式采集、Linux 锁、主库迁移、生产副本负载和发布配置仍单独验收或授权。未完成这些条件前，数据中心财务概况只记本地候选，不作为 Streamlit 退出依据。
