# 因子库定义的只读 Serving 来源

接续已审查的定义仓库与 PageControl 命令桥，为 C3.1 建立一份有界、可核验的因子库发布输入。**本片仅生成因子域的只读投影快照**，不改共享 Serving 发布器/表合同、不开放 Web/React、不配置生产路径、不让页面直读 SQLite，也不把空仓库误作已发布的正式数据代。

**任务分级**：普通任务。新增因子域到 Serving 载荷的只读适配与聚焦测试；不改变现有共享发布器、鉴权、生产数据或并发写入。主要风险是截断、换库或损坏历史被发布成看似完整的因子库，最终候选做一次独立审查。

## 合同

1. 调用方显式传入已初始化的 `FactorDefinitionRegistry`、预期 `FactorRegistryIdentity` 与发布时刻；投影只调用仓库公开只读 API。缺库、换 inode/实例、旧 schema、坏定义或命令回执时拒绝整份载荷，不创建或修复仓库。
2. 一份不可变状态与当前定义行成对生成；状态区分可信空库与有定义。当前定义含归档 head，按 `factor_id` 排序；每项带版本、内容摘要、中文名、分类、方向、表达式、最早可用日、依赖列、预热窗口和归档标记。Web 将来只需在列表展示用户可理解字段，技术 ID 与表达式只在详情/编辑或必要提示出现。
3. 最多生成 512 个当前因子。用 `list_current(include_archived=True, limit=513)` 检测溢出并整组拒绝，不静默裁掉第 513 项；定义与状态数量须一致，行键唯一。快照绑定预期仓库实例 ID、显式 `available_at` 和规范内容摘要；不把绝对路径泄露到输出。后续接入共享 Serving 时再定义精确表列、字节上限与同代发布约束。
4. 投影不推断检验结果、跟踪状态或可运行性；这些分别由后续 Lab 产物与跟踪权威发布。历史版本留在定义仓库和已封存结果中，本片只发布 current head。

## 执行与验收

1. 先写真实临时 SQLite 仓库用例：空、保存多个版本、归档、排序；核验字段、行数和稳定内容。模拟 513 项时整组拒绝。
2. 注入缺库/换库与历史损坏，确认不产生假空表；同一仓库重复读取相同，投影时间只由调用方提供。
3. 新模块只依赖因子仓库和规范摘要函数。运行直接聚焦测试、Ruff 和 diff；独立终审后由累计分支更新测试清单与进度文档。

后续接线：共享 Serving 发布器一次性纳入状态+定义表 → 同代只读 Web API → React 因子库/详情 → 已认证保存/归档命令及原命令恢复。生产配置与切流仍按仓库授权边界处理。
