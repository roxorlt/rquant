# 基本面每日状态与选股条件：PIT 派生方案

接续财务观察导入与专用 PIT 查询。目标是把已有证据变成 C1.4 的六个可筛选字段，并在数据中心给出可理解的财务数据状态；真实接口额度、生产主库迁移、正式任务与发布仍需另行验收或按项目规则单独授权。

**分级：高风险。** 这些字段将进入共享选股与回测结果。任一字段晚到却被写回历史日期、把空值补零，或把不同报告期混在一起，都能产生前瞻收益假象。

## 资产与信任边界

- 输入：经归档校验并由 `select_financial_fact` 裁剪的财务版本；**待补齐的** `daily_basic` 估值观察版本及其日面板 PIT 契约；SSE 完整日历；明确的决策时刻。现有 `daily_basic` 表只有换手、量比与市值，采集/运行时模型尚无三项估值，也没有历史观察时间，本片不能把旧行当作 PIT 输入。输出：每日基本面状态、每字段来源回执、选股可用列。
- 七个财报接口的响应不能直接绕过 PIT 查询；`update_flag` 不能证明修订的历史可见时刻。`daily_basic` 属于日线面板，不套财报公告规则，但也必须同时验证“上一开市日面板已可用”和“该版本首次观察早于决策时刻”。用唯一派生函数装配字段，存储、Serving、筛选积木与回测都不各自重新解释口径。
- 官方字段口径：[Tushare 财务指标](https://tushare.pro/document/2?doc_id=79) 含 `roe`、`or_yoy`（营业收入同比增长率）和 `netprofit_yoy`（归母净利润同比增长率），源值为百分比；[每日指标](https://tushare.pro/document/2?doc_id=32) 含 `pe_ttm`、`pb`（倍数）及 `dv_ttm`（百分比）。本片不将 `q_*` 单季度同比误作累计同比，也不从股价和可能不一致的股本/利润另算估值。
- 本地 Tushare Python 客户端将响应 `items` 直接构造成 Pandas DataFrame；同列混有数值时，原始 `null` 与 NaN 在浮点列里无法区分。日面板接入把这类 NaN 仅记为该字段未知，拒绝 ±inf；其他非法值由有类型事实模型拒绝。不能声称已还原源响应中的 `null`/NaN 区别，若以后必须区分，采集协议须提供转换前的可信原始值。

## 必须保持的不变量

1. 对一个选股日期 `T`，派生时固定上海时间 `T 17:00` 为决策时刻；即使任务后来补跑，也只能查询此刻已经满足公告后下一 SSE 开市日 09:30 且严格晚于首次观察时刻的财务版本。没有权威逐自然日日历、版本或来源就记未知。不得把今天新采集的过去财报倒填为过去可知。
2. `fina_indicator` 的三个字段取同一个目标报告期，且先依据**期间观察与公告证据**判定目标期，再在该期逐字段取值；不能从已有 `selected` 数值倒推“最新期间”。较新的期间已观察但三项全空、缺公告日或冲突时阻断旧期间回退，保留未知。目标期的 `roe`、`or_yoy`、`netprofit_yoy` 分别保留可用/未知状态与精确版本摘要；不能因为一个指标未知就编造另外两个值。
3. 先把 Tushare `daily_basic` 的 `pe_ttm`、`pb`、`dv_ttm` 接到有类型的采集请求、运行时事实、验证与追加式观察表，并给该内部表注册日面板加首次观察的 PIT 契约。旧 `daily_basic` 行没有首次观察证据，即使数值存在也只能记未知；今后每次修订另存版本，不以 `(ts_code, trade_date)` 覆盖证据。由 SSE 日历确定 T 之前**唯一应取的最近开市日**，不能从数据库里找最近一条现存行替代；缺整行时三项都未知。该日的版本还须在 T17 之前真实观察且已过下一 SSE 开市日可用门槛；三项取同一行版本，某项为空就该项未知，不退回旧版本或补零。亏损股票的空 PE 不变成 0。

   已有 `query_daily_valuation_pit` 把恰好 T17 的观察纳入候选（`observed_at <= as_of`）；基本面每日派生在专用选择器之后仍须拒绝 `observed_at` 或 `first_observed_at` 等于 T17 的整行，记明确未知且不回退旧批次，以符合本节“之前”的严格边界。
4. V2 说基本面列进入 `daily_state`；现有 `upsert_state` 使用无列名的整行替换，尾段回补会删行重建。为保持功能且避免旧写者擦除，物理实现改为**独立的不可变 `fundamental_daily_version` 表**与每证券/日期唯一的 `fundamental_daily_head` 指针；不扩充旧 `daily_state` 表。每项派生值保留决策时刻、来源数据集、证券、报告期或日面板日期、字段、版本摘要及可用/未知原因。以证券、日期与输入来源摘要为版本身份写入六项，并在同一 DuckDB 写事务中核对上次 head、分配单调修订序号、原子切换到新版本；重算相同输入不变。新输入须证明财务归档和日面板观察来源相对当前 head 没有回退，证明不了就拒绝切换，不按文件修改时刻猜新旧。选股在**同一个只读连接**按 head 的精确版本 ID 一对一关联，只命中当前一版；旧筛选结果保留原来源代和原版本，不被新 head 改写。日常 `upsert_state` 与历史尾段重算后，这两张表和已绑定的筛选结果仍完整。
5. 基本面条件明确走**只读副本选股**路径：目录在副本一代中宣告字段和 `ScreenCatalogData.source.identity`，运行请求须绑定这份身份，后端同一连接读该代的 `fundamental_daily_version` 并把身份写入结果与分页游标；换代拒绝旧请求或游标。旧 Serving 数据代仍可承载其他页面，但不能被当作这次筛选的数值来源：网页以 `ScreenRunData.source` 标示筛选数据时间，`Envelope.serving` 与 `X-Rquant-Generation` 只标外层 Serving，不能混入筛选行或给用户伪称同代。新副本加旧 Serving 的组合须证明页面只显示新副本筛选来源，若依赖旧 Serving 的财务数据则拒绝。旧 Serving 筛选模式和池子不开放未发布的基本面条件。
6. 选股 universe 只投影与其查询日期、固定决策时刻和同一副本来源代匹配的上述六项；缺来源或无数据不参与 `gt/lt/between` 命中，并显示“数据不足”而非 0 或假命中。只在这些列真实发布后开放相应基本面条件；条件目录、API 校验、中文名称、百分比/倍数显示和窄屏交互一致。
7. 数据中心“财务”分类展示可用范围、最近已观察日期与缺失原因的汇总，不展示归档 ID、哈希、任务内部名；明细可悬停或点击说明字段口径与可见时间。不能把接口返回非空、任务进程存活或可能截断的响应当全市场覆盖完整。

## 验收与发布边界

- 临时库构造：公告当日、长假、实际公告日晚于公告日、首次观察晚到、同期间修订、较新缺字段、新期间三项全缺或缺公告、日面板后到修订、旧面板无观察时刻、应取日缺整行、亏损空 PE；按 T17 重算后，历史决策没有未来值，三项财报同期间、三项估值同日期且逐字段未知。
- 新采集字段、模型、存储迁移和契约在假客户端验证；增量写入中途失败全回滚，同输入重放不变。A、B 两派生版本同在一份副本时 head 唯一指向 B，筛选无重复行；源身份回退不改 head，已生成的 A 结果仍绑定 A。日常状态写入、历史尾段重算不能擦除基本面证据。新副本/旧 Serving、目录/运行换代和分页旧游标不混用。页面在桌面、390px、键盘/触屏保持必要提示而不堆内部说明。
- 只运行直接相关的本地 Python/Web/浏览器验证与必要的独立高风险审查。生产主库写入/迁移、`rquant-fundamentals` timer 与云端部署须提交具体候选和验证证据后，按项目单独授权规则处理；未授权前不执行这些动作，也不停 Streamlit。
