# React 投研平台交付与 Streamlit 迁移决策

> owner 于 2026-09-25 决定建设新前端，2026-09-26 再次确认最终目标和旧页面投入边界。本文件记录长期有效的产品方向与迁移条件；具体排期可调整，不改变目标。

## 已确认的事实与方向

- 线上现有 Streamlit 页面占用较多服务器资源，其前端体验也不是 owner 想要的页面。今后不再为旧 Streamlit 页面开发新功能、打磨界面或扩容；过渡期只做维持现有使用所必需的故障与安全修复。可复用其后台能力，但新交互在 React 网页实现。
- 新网页采用 `web/` 的 React + TypeScript + Vite，入口 `/app/`。CC 的可点击原型是最终希望达到的页面与交互效果；所有可见功能和按钮最终要能实际使用，涉及危险操作的按钮保留必要保护。
- 最终范围还包括 CC 差距表中所有「部分」「缺」项，以及标为「已有」但仍有明确缺口的 M4 选股和 M12 监控告警。M11 实盘交易排除；高频、Tick 级微观结构和 Level2 仍不做。
- 当前新网页仍在分批开发，不能把第一批本地候选等同于完整原型已实现、正式 `/app/` 已切流或旧 Streamlit 服务已停用。

## 实施优先级与退出条件

1. 优先实现原型中能直接替代现有使用场景的功能，接通真实数据与操作，按 `web/AGENTS.md` 的界面与文案原则做细致设计：正文只给用户必要信息，文案简短，内部标识放在合适的提示或详情中。
2. 对每项迁移建立旧入口与新功能的对应关系；验证新页面功能、数据、异常和空状态，以及实际用户操作路径。完成对应能力并验收后，再迁移入口和书签；资源占用高的旧页面在满足这些条件后优先退出。
3. 每停用一个旧 Streamlit 单元，都记录替代范围、验证结果、受影响入口和回退方式。未覆盖的能力继续由旧服务过渡承载，不把“页面能打开”视为可停服条件。全部原型功能和上述差距补齐后，完成旧页面整体退役。
4. 生产切流、停服、nginx/systemd/sudoers 等基础设施变更继续遵守仓库生产规则，单独取得 owner 明确授权；本决策记录本身不授权这些操作。
