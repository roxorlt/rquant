# 因子检验：持久任务的单次 worker

承接因子专用 `FactorEvaluationJobLedger` 与冻结来源执行桥。本片让 Lab 进程**一次领取一条已提交任务并运行到可恢复终态**；另片再装循环守护、任务提交准入、Serving 与页面。策略 Lab 的 `ResearchRunSpec`/分片 worker 不接收因子作业。

**任务分级：高风险。** 计算可能长于租约；错误心跳、超时或竞态会把旧执行者产物挂到新任务，或把已成功的结果改成失败。冻结下述失败模型，先做 SPEC 独立审查，最终候选做一次独立审查。

## 冻结失败模型

- **资产与边界**：来自账本的当前 `FactorJobLease`、可信外部保存的 `FactorLedgerIdentity`、单次 `FactorSnapshotAdmissionRequest` 及只读元数据/湖文件、私有内容寻址产物根。账本在构造时注入其自身可信 UTC 时钟并在每次变更时取时；worker 给计算桥的显式 UTC 时钟只供计算期限检查，不能充当租约凭据。Web、任意动态路径及生产主 DuckDB 不进入 worker；未获授权的生产启动不在本片。
- **失败路径**：领取后进程崩溃；冻结来源或计算失败；计算时间超过初始租约；心跳在完成时仍写版本；心跳失联后旧执行者继续封存；worker 被终止后留下无法回收的运行态；产物已封存但 `complete` 未提交；`complete` 拒绝后旧 worker 改写 `failed`；过期规格仍起算或被标成功；异常信息含路径/内部 ID 被写入面向页面的失败字段。
- **必须保持**：入口只接收显式打开且身份固定的因子账本、元数据存储、湖根和私有产物根；调用账本自身计时的 `claim` 取得唯一令牌/版本后，仅把该租约中的原规格交给 `run_factor_evaluation_job`。计算期间按有界间隔续租，心跳与最终 `complete`/`fail` 串行化并使用最新版本；worker 不传缓存时间给账本判定期限。若心跳失败、时钟失效、租约/截止过期，停止任何终态写入，留下原任务供账本按租约与期限恢复。执行桥可能在失去租约后完成内容寻址产物，但 worker 不能报告成功或删除可信产物。计算异常时仅用有限安全原因码记录失败，原异常只留内部日志；若 `fail` 本身被 fencing 拒绝，不尝试另一路写。`complete` 仍由账本重读产物并复核规格/来源，worker 不用内存回执绕过。崩溃后下一次领取同规格可重复计算，内容寻址产物复用；不声称同规格计算 exactly-once。单次调用不自动提交新任务、不轮询等待 Web 命令，也不初始化/修复数据库。
- **排除**：无系统服务、启动参数/环境读取、生产资源限额与进程收容、任务取消/暂停、Serving/Web、真实数据规模验收。后续独立受控调度器安装和生产配置须按项目授权，现阶段本地临时目录与合成来源验证。

## 合同与实现

1. `factor/job_worker.py` 暴露 `run_one_factor_job(ledger, metadata_store, lake_root, artifact_root, runner_now, ...)`，先由账本自身时钟 `claim`，无任务返回类型化 idle；有任务则执行现有 `run_factor_evaluation_job`。`runner_now` 只传给执行桥，账本状态变更不接受它作期限证明。不直接打开 `ResearchRunSpec`、任意 DuckDB 或 PageControl 通用队列。
2. 心跳在同进程独立线程中使用固定租约和间隔（间隔明显短于租约，均有上限），只在已领取后运行。共享一个小的同步状态：当前 lease 版本、失联标记和停止事件；结束计算时先请求停止、等待心跳退出，确认没有在途心跳后再用最新版本写终态。等待退出超时或任何心跳异常即不完成；不得用过期版本重试。线程异常不吞掉后继续报成功。
3. 返回类型化单次结果（idle/succeeded/failed/lease_lost），成功仅来自账本 `complete` 的持久回执；失败仅来自账本 `fail` 的持久回执；`lease_lost` 不报终态成功。错误分类不包含路径或原异常文本。若执行桥的时钟/来源/产物异常发生在租约仍有效期内，选有限原因码；逾期时留给账本下次领取判定 `deadline_expired`。

## 验收

- 红测：冻结/计算抛错、跨初始租约的长计算、心跳和完成竞态、续租遭另一个领取者 fencing、心跳异常、完成前 deadline 到期、产物封存后账本事务失败、失败记录也被 fencing 拒绝；任何情形都不让旧 worker 写成功/覆盖新终态，不删除可信产物。
- 用合成冻结来源跑提交→领取→心跳→执行→持久成功，再重启用外部身份打开并读回同一结果；同规格重放只有同一成功索引。定向测试允许给账本构造器注入可信测试时钟、给 worker 注入调度与计算时钟以避免真实等待，且要证明 worker 的旧计算时刻不能延长租约；测试、Ruff、diff 集中于新 worker、账本和直接依赖，不跑无关全量或生产服务。
