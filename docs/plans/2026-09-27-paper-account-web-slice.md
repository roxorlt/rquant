# 模拟账户网页首个真实增量

> 对应 v2 C10.1 与可点击原型的模拟盘页。本增量先呈现已有 Serving 数据代能证明的账户与持仓；净值历史、当日指令、回测区间、对账和暂停另按 C10.1–C10.3 接通真实产物与命令，不以示例值代替。

## 分级与验收

**普通任务**：新增只读网页 API 和 React 页面，改变用户可见行为，但不修改模拟撮合、权威数据、发布器或生产契约。页面可从同一个已借用的 Serving generation 查看账户列表、选中账户的总资产、现金、持仓市值、浮动盈亏与持仓可卖量。来源未发布、无账户、表不可读、过期和请求失败须有不同且可行动的中文反馈；桌面与 390px、键盘和触屏能完成账户切换。技术账户 ID 不放在页面正文，需要时只在提示里查看。

## 服务边界

1. 网页 API 只借 Serving 中的 `paper_accounts` 与 `paper_holdings`，一次请求只用同一数据代；先验证 manifest 水位、表可读性、主子表关联和行数上限。没有发布的模拟盘是“暂无模拟账户数据”，不可伪装成零资产。换代后前端重新读取，不保留旧代详情。
2. 专属 Pydantic 响应输出页面所需字段、账户选择用的不透明身份、数据时刻与估值说明。金额来自已发布账户快照，持仓市值和浮盈以同代持仓核对；不在浏览器重算账户账本，不直连撮合 SQLite 或 DuckDB 主库。个股名称可复用现有 Serving 股票字典；缺名称时展示代码。
3. 页面沿用原型的信息层级和现有组件：账户选择、三项核心金额、持仓明细；时间用相对写法并可看准确时刻，金额千分位、价格两位小数。只在数据允许时显示收益率；没有初始资金、净值历史或订单时不推算累计收益、不画曲线、不展示无效的“对账”“暂停”按钮。
4. 合成 Serving generation 覆盖多账户、零持仓、缺表、不可用水位、估值降级、换代与主子表不一致；前端覆盖加载/空态/错误/账户切换及 390px。聚焦测试、类型合同、构建产物和浏览器路径通过后做一次独立审查。生产数据代、正式切流和 Streamlit 停用另按项目门禁验收。
