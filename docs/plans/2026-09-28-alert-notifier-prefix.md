# 告警来源证明：通知库核对路由前缀

接续 [路由循环链接](2026-09-28-alert-prefix-runtime.md)。本片只读核对总线→路由记录链接与通知库已复制的信号和路由回执，产出**历史前缀一致**证据；不声称上游生产者完整、当前告警覆盖或手机送达。

**分级：普通任务。**新增按需调用的只读核验器及类型化结果，不改常驻 notifier 循环、SQLite 表、Serving 契约、通知投递或生产配置。风险是把复制游标当成实际内容，或把两个时点拼成同一时点的完整性声明；验收以同一 SQLite 读取事务中的逐行核对和明确截止时刻为准。基准 `ccde6714`。

## 接口与约束

- 输入是实际 `ReadonlySignalRouteSpool`，核验器自己读取其 `bus_prefix_link()`；不得接受浏览器、普通 JSON 或未核验模型作为来源。链接读端已有当前 spool 指针、记录及摘要核验。通知库从一个只读 SQLite 事务读取复制游标、来源观察、状态修订以及最多 10,000 条完整信号和路由回执；不读取总线主库或 DuckDB。
- 只有通知来源代、起始序号和高水位与链接精确相同，复制游标已到该高水位，且通知进程对 spool 的观察时刻不早于链接的总线观察截止、又不晚于本次核验时刻，才可出具结果。逐条重建信号和路由回执，核对连续序号、完整信封哈希、回执哈希、接收/可用/路由时刻及链接的**路由行摘要**；仅比游标、信号 ID 或条数不够。空前缀必须有双方的明确空观察，不能因为无行就推断完整。
- 输出 Pydantic 结果包含原链接、通知观察时刻、同次状态修订与内容摘要，并明确 `upstream_complete=false`。它只证明链接截止点以前三个已观察副本的前缀一致；链接读取后来源可能继续前进，结果不能作为“当前无新信号”或过去 30 日完整的凭据。缺链接、代际或高水位不符、观察过早、行缺失/篡改、超上限返回不可用；不得修复数据、写入确认或吞掉正常通知错误。
- 后续单独把此核验按低频接入 notifier，再绑定 Serving 与上游生产者覆盖。直到三来源正面覆盖、确认起点及正式入口都核验通过，React 仍显示「确认状态暂不可用」，未确认数保持未知。

## 验收

1. 真实格式的 bus→spool→notification 合成链：一条、空前缀、重启重读均给出同一内容身份；重复调用没有 SQLite 或 spool 写入。
2. spool 落后或链接缺失、通知复制落后、来源换代、通知观察早于链接截止、链接后本地行/路由回执损坏、缺序号、超 10,000 条均不得给出可信结果；各分支有聚焦用例，不以旧结果代替。
3. 直接相关的信号链接、通知复制与新核验测试、Ruff、diff 检查通过；最终候选只做一次独立范围内审查。此片不改页面和 API，无需浏览器回归。
