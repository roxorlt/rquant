# 手动盯盘名单：按用户读取

接续 [同代只读发布](2026-09-28-manual-watchlist-serving.md)，对应 v2 C4.8。网页只从已校验的 Serving 数据代读取手动名单；本片提供单只股票状态及当前用户列表，不接写命令或按钮。

**分级：高风险。** 名单属于用户私有状态。身份错配、旧数据代或不可用状态误判，可能泄漏其他用户的股票，或把未确认的加入/移除显示成成功；以本节冻结审查边界。

## 威胁与失败模型

- 信任边界：nginx 认证并覆盖 `X-Rquant-User`，Web 必须要求有效身份，且仅在已配置私有 Web ingress 时开放私有名单读取；普通回环 TCP 入口上的可伪造身份头不能作为授权。请求参数里的 owner 不参与权限判定。Web 借用一次 Serving 数据代，只查询该用户；不得直连 PageControl 或主 DuckDB。
- 失败路径：未登录、伪造 owner、旧或校验失败的数据代、未激活投影、只存在状态表/成员表的一半、读取时跨代、到期时刻跨越发布时刻、删除后重加的版本误判、列表超限及错误消息暴露内部表或其他用户名。
- 不变量：读取结果只属于已认证用户；`unavailable` 与可信空名单严格区分。发布前的成对摘要校验与借代时的不可变整库哈希验证是完整性信任链；Web 再核对本代两表均可用、状态为 `ready`、全局行数与发布时间元数据一致，只按已认证用户过滤取行，不能为重算全局摘要而把其他用户行读进 Web 进程。`active/expired/deleted` 按请求时可信 UTC 时刻从事实计算。PageControl 命令仍以权威库 CAS 为准；网页读到的版本仅供发起命令，不保证即时成功。
- 排除：本片不提供写入口、前端按钮、告警范围或生产部署，不改变 nginx 信任链。

## 接口与验收

1. `GET /api/v1/watchlist` 返回当前用户有界的有效名单、可用性和简短中文提示；`GET /api/v1/watchlist/{ts_code}` 返回单只股票的当前状态及版本，缺项明确为 `absent`。两者都要求私有 ingress 与有效用户；无身份返回 401，未配置私有 ingress 返回 503，均不接受 owner 参数。
2. 已激活的可信零行显示空；未激活、数据代不可用/过期/降级、配套投影损坏或读取失败均不显示空名单或肯定的“未加入”。错误对用户只给行动提示，技术细节留服务端。
3. 列表只查询当前用户，最多 500 个有效成员；其余到期与墓碑行只在单只股票查询返回版本。页面可显示的价格档位保留十进制精度，以字符串传输。
4. 离线合成 Serving 数据代测试覆盖隔离、活跃/到期/墓碑/不存在、时钟推进、空与不可用、旧代及篡改配套关系、边界参数和有界读取；聚焦测试、Ruff、diff 检查通过。终候选做一次独立审查，台账仍标「部分且未发布」。
