# 盯盘事件进入 Serving：范围与失败边界

本文件冻结 C12.2 本增量的高风险边界。基准为 `268cf7e15f736096df663b50ba310b8e2946370f`；此前未提交的网页 API 草稿只由合成数据验证，不能证明生产供数。2026-09-27 核对确认：生产 `runtime_builder_signal.py` 构造 `SignalPageProjectionProducer` 时不传 `companion_projections`；该生产者默认继承旧投影，若没有旧值便发布空的 `monitor_event` / `surge_event`。现有网页 fixture 注入了合成事件，不能替代真实发布路径。

## 资产与信任边界

- 资产：旧监控的 `monitor_event`、爆量 `events-YYYY-MM-DD.jsonl`、只读副本的读取预算、通知权威状态、不可变 Serving 数据代及页面展示的事件时间与结果。
- 旧监控写主 DuckDB 和爆量 JSONL；本增量的 notifier 页面投影源只读取既有只读副本和已配置的 `surge_live_root`，再通过通知权威发布现有两张 Serving 投影。网页 API 只借用一代已校验 Serving，不直连旧库或 JSONL。
- 旧 `notification_log` **不是仍在写的 DuckDB 表**：v0.13.x 起实际来源是 `logs/notification_log.jsonl`。它含凭据前缀 `target` 和可能含敏感内容的 `error_msg`，不在本增量读取或发布。CC v2 的旧表来源描述按此事实更正；实际推送历史与确认命令另做。

## 必须保持的不变量

1. 不写旧主库、只读副本或爆量源文件；复用 notifier 现有受控的一次副本打开、时间窗和读取预算，不新增盘中抢锁或独立扫描进程。不得以合成 fixture 的事件当作生产可用证据。
2. 两类来源各有明确可见时刻。`monitor_event.trigger_time` 在旧库由上海本地无时区时间写入，发布前必须按 `Asia/Shanghai` 解释并转换为 UTC；爆量的 `trade_date` + `confirmed_at` 是上海本地日期与 `HH:MM`。不把无时区值当 UTC，不发布未来事件。
3. 本增量只发布观测时刻向前 30 个自然日的事件。读取受固定日期谓词、最多 10,000 行/表、Serving 既定 2 MiB/表和爆量文件累计 8 MiB 上限约束；超限或源损坏必须给出可观察的不可用/降级证据，不能静默截断成看似完整的列表。
4. 爆量文件仅从固定命名的受控目录读取；拒绝符号链接、目录置换、读中改动、非完整行和非法日期/时间。重复的 `(trade_date, confirmed_at, ts_code)` 按确定规则处理并留下质量证据，不随读取次序随机变化。
5. `monitor_event` 与 `surge_event` 继续使用现有 Serving 表契约和同一通知权威发布机制；来源不可读时不得继承上一次的事件冒充最新，也不得把空表标成已发布且完整。某日没有爆量文件可以表示该日没有事件，须与整个来源不可读区分。信号及回执现有语义保持：影子档和历史成功回执不能冒称手机送达，原始错误不进入网页接口。
6. 页面按真实事件时刻稳定混排与翻页，明确“最近 30 天”范围及源缺失/部分数据；非交易日显示历史，不虚构实时刷新、确认、规则开关或测试推送。

## 失败路径与验收证据

| 失败路径 | 聚焦验收 |
|---|---|
| 旧库无表、副本不可读或读取预算耗尽 | 不覆盖已验证的 Serving 数据代；状态说明源未就绪或降级，且可定位原因。 |
| 爆量目录不可读、JSONL 截断、超限、符号链接或读取时替换 | 不发布伪完整爆量列表；安全地拒绝该源并保留其他可用源。单日无文件与此区分。 |
| 上海本地时间被当作 UTC、跨日或同一时刻多事件 | 固定时钟样例核对 UTC 与页面上海时间；游标跨源不重不漏。 |
| 超过契约行数/字节、重复键、畸形记录 | 有界失败或确定去重并报告质量问题，不能静默少算。 |
| 数据代切换、通知权威发布中断 | 旧代可读且不混代；新代需完整校验；翻页游标换代返回 409。 |

完成本增量须有从**真实格式的本地只读副本和爆量 JSONL**到通知权威、Serving 数据代、网页 API 和 React 时间线的端到端合成回放；另跑聚焦单测与桌面/390px 浏览器检查，并由独立审查者在最终候选上审查一次。生产数据、服务配置、切流、停用 Streamlit 均不在本次授权范围。
