# 公式池保存的受控网页命令

## 范围与分级

将现有 `save_formula_pool_v1` PageControl 命令接入受保护的 Web POST，供后续 React 在已核验的成功公式任务上保存可重算定义。高风险任务：补齐跨鉴权边界的必填 actor 身份并新增用户可见写操作入口；真正的来源、同名及幂等裁决仍由已审查的 PageControl 后端负责。本片不加页面按钮、Serving 读取或生产启用。

## 验收

1. 浏览器只提交命令 ID/请求时刻、目标名称/显示名、成功任务 ID 及空的期望版本；禁止公式文本、命中代码、文件路径、浏览器 actor 和非空期望版本。Web 负责登录、同站请求保护、请求大小与有类型校验，并把可信登录用户填入 `SaveFormulaPoolV1` 新增的必填 `actor_id`。PageControl 命令摘要绑定 actor；原命令重试不得换人。网页不打开任务库或公式池文件。
2. 复用现有固定 loopback PageControl 网关。原请求重试始终使用同一命令 ID 和相同内容；响应不明、排队或处理中只显示“状态待确认/请用原请求重试”，不宣称保存成功。只在已完成且成功的回执精确包含 `pool_name` 与定义 `version`，且无错误时返回成功。命令冲突、失败、后端不可达、畸形回执分别有简短中文且不泄漏路径、公式或内部错误。
3. 路由、Pydantic/OpenAPI 与生成 TypeScript 类型一致；旧公式批量命令和其他 PageControl 网页入口保持行为不变。用假 loopback 与合成成功/失败任务验证授权、CSRF、额外字段拒绝、成功回执、原命令重试、不明回执、冲突及请求大小。运行聚焦 Python/Web 测试、Ruff、类型与产物校验，并做一次独立终审。

## 边界

- PageControl 是唯一的写入与来源裁决点；Web 是认证和有类型传输边界，React 后续只管原命令保存与用户状态。
- 页面保存按钮仍须等公式池逐日运行及同代只读发布接通后开放；本片只是受控命令能力。
- 不改生产配置、服务、数据库或 Streamlit。

## 冻结失败模型

- 资产：已认证用户身份、保存命令 ID/摘要、可信任务与公式定义。
- 边界：浏览器→Web 登录与 CSRF→固定 loopback PageControl→私有任务/定义。
- 失败路径：浏览器伪造 actor；未登录或跨站请求触发写入；原命令被另一身份改写重试；PageControl 回执不明却向用户宣称保存；原始错误或路径经 Web 泄漏。
- 不变量：进入 PageControl 的 actor 仅来自已认证 viewer，命令 ID 与包含 actor 的完整请求绑定；仅有核验成功的回执可称保存成功；Web 不读写私有文件。
- 排除：新增角色权限、生产入口启用、服务配置或旧命令批量迁移。公式池保存核心仅在显式私有配置下启用，尚无生产命令。
