# 每日池子排名结果回执

## 范围与分级

目标是让已保存排名定义的日终池子，把**实际入池成员的名次与分数**和价格、成员集合一起封存，供后续历史展示与按分回测核验。现有选股器的临时排名不等于日终事实，不能直接写为历史结果。本片只实现本地 DuckDB 写入、同事务回执及冻结只读核验入口；Serving、React 和回测权重接线留给后续增量，未接通前页面不展示可信历史分数。M11 实盘交易不在范围内。

**高风险**：新增持久事实会影响池子结果和历史回测输入，涉及生产数据完整性与共享回执契约。冻结基线 `59312a07`，范围限 `screen_result` / `screen_run_receipt`、日终排名流水线、同库只读核验及直接测试。生产主库迁移、云端执行、切流和停用 Streamlit 都须项目单独授权；本片不得做这些动作。

## 威胁与失败模型

- **资产/边界**：已保存的 v3 池子定义与日终写者提供排名计算；DuckDB 单写事务是结果权威；只读消费者必须用冻结文件上的回执核验，不能相信浏览器、临时 DataFrame 或未封存的 `extra` JSON。
- **失败路径**：排名在黑名单过滤前取前 N；只保存成员而丢失分数/名次；分数/名次只在内存与持久行不同；部分写入或零命中残留旧排名；重跑时旧成员/旧分数混入新结果；数值 NaN/Inf、重复或断档名次、重复代码、错误日期/池名进入可信回执；篡改结果行而旧回执仍被接受；旧 v1/v2 回执被误解为有排名。
- **不变量**：排名只对当前日已筛中且完成风险过滤的候选计算；分数和 1..N 名次与最终 `screen_result` 成员、价格在**同一事务**提交。写入后按持久行重读并封存排名摘要；可信读取须在同一冻结只读快照核对合同、成员摘要、价格摘要、排名摘要、连续名次及有限分数。任何缺列、缺回执、坏行或不一致均不给可信排名；旧无排名结果继续可读，且不能冒充新排名。零命中也必须有可区分的已完成 ranked 回执和空排名摘要。
- **排除**：不声称这是收益、可成交价格或可执行换手；不重算历史排名、不用当前定义覆盖历史、不把排名分数直接变成回测权重；不扩展到盘中/财务/自定义 RSI 等尚不能由日终复现的条件。

## 契约决策

1. `screen_result` 增加独立的 `rank_position`、`ranking_score`，不用自由 JSON 作为历史事实；旧行两列为空。`screen_run_receipt` 增加 `rank_digest`，新 ranked 合同须同时绑定原有成员和价格摘要。旧 v1/v2 的 `result_version` 计算和读取语义保持字节兼容。新 ranked 合同只给排名定义的日终运行，即使零命中也要封存空排名摘要；未排名运行仍用现有 v2。
2. 排名摘要按稳定的代码排序，对 `(ts_code, rank_position, ranking_score)` 作带域分隔的确定性编码；分数用持久化 `DOUBLE` 的 IEEE-754 位编码。无重复代码，名次恰好覆盖 1..N，分数有限且在 0..100；排名值必须与计算结果的最终前 N 行一致。不能通过仅修改哈希输入内存对象来证明数据库已写入。
3. 新旧表结构使用显式幂等迁移。旧库缺新列时无排名读取继续运行；请求可信排名时返回不可用。初始化/迁移发生在写者启动路径，本地测试可执行，生产主库迁移需另行授权。
4. 冻结只读核验入口复用现有 `backtest.screen_source` 的单连接事务/日期截止检查，不从另一文件或另一连接补齐字段。新 ranked 入口**必须接收可信的预期 `definition_version`**：调用者只能从与本次历史运行绑定并核验过的冻结定义产物提供；浏览器、当前池子定义和回执自身都不能充当预期版本。入口在缺少预期版本或与回执版本不等时拒绝，不能仅靠回执的自洽哈希放行。当前历史定义产物尚未接线时，此入口只供注入明确预期版本的离线验证，生产回测不得启用。入口明确返回已核验分数/名次或封闭拒绝，不能悄悄降为等权。

## 验收证据

1. 红绿样例覆盖 3 股手算分数/名次、并列、缺值、黑名单后 top N、零命中、重跑成员减少和从 ranked 改 unranked；读取结果与持久行、回执一致。
2. 篡改单股分数/名次、删列/删行、重复或断档名次、NaN/Inf、旧合同、错误日期/完成时刻均无法取得可信 ranked 快照；另用**两份各自自洽的不同定义**证明：只持目标池的预期定义版本才能读，传另一版本或不传均拒绝。事务中任一步失败时成员、排名、回执一起回滚。
3. 旧 v1/v2 既有测试与 `result_version` 固定向量仍通过；本地只运行直接相关 Python 聚焦测试、Ruff、固定清单契约及必要的 3.11 语法检查。最终候选一次独立高风险审查，仅限上述失败路径，阻断项按项目约定定向修复。
