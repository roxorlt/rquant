# 公式池每日任务的有界自动推进

## 范围与分级

把已验证的整日协调器和现有单任务 worker 组合成一个短命令：受信调用方给出私有配置与明确的交易日，命令先核对全目录，再有限次执行已经准入的任务，每次执行后重新核对整日状态。它不新建任务队列、计算器、日期权威或后台常驻服务。生产 timer、运行账号、路径配置和服务安装是后续独立发布事项。高风险：本片触及共享持久任务与并发准入；若把不同来源或未完成任务拼成“今日完成”，会污染公式池结果。

## 验收

1. 入口只接受现有 owner-private `FormulaPoolBatchPrivateConfig` 和显式 `trade_date`；worker 的四个来源/任务路径必须与该配置中的 `market` 完全一致。不给前端、环境变量、默认生产目录或未核验的当日日期推测路径。未收盘、非交易日、目录/来源不可信时拒绝启动任务且不输出部分结果。
2. 一次调用先运行 `run_day()`，随后最多调用 1–8 次现有 `FormulaMarketJobWorker.run_one()`；**每次调用后都重新运行 `run_day()`，包括 worker 返回 `None`**，因为它仍可能把过期租约改为失败。全部完成、worker 返回 `None` 后完成重核，或达到调用次数上限即返回。不能在进程内睡眠、无限轮询、直接重算公式或绕过 worker 的每任务预算。共享队列中的其他合法研究任务可以被 worker 消费，但不能计作公式池完成。
3. 本次返回有类型的完整目录状态与实际 worker **调用次数**。只有每只池在同一目录、名单和历史行情身份下拥有重读核验的封存逐日结果才报告 `all_complete`；等待、失败、可信零命中和空目录保持现有区分。首次与每次重核观察到的身份变化，或本次执行的公式池任务声明的身份不符，即整次失败，不输出局部 JSON。重复或重叠调用复用现有任务幂等键和 worker 租约；即使两个调用都尝试发布，最终也只能有一份证据一致的规范逐日结果，不能误称完成。
4. 用合成真实任务存储和 worker 验证两池的准入→执行→重核、调用次数上限、空目录、共享队列夹入其他任务、worker 返回 `None` 但耗尽租约、失败回执、同日重试、来源 A→B→A 落入观察点或任务执行窗口，以及并发调用收敛到同一规范结果；不要求证明任意两个观察点之间不可见的瞬时变化。先有可执行失败用例再实现。运行直接相关 pytest、Ruff、diff 自检；最终候选做一次独立高风险终审。生产数据、服务配置、真实约 10 GB 负载及 Linux 资源预算另行验收。

## 冻结失败模型

- 资产与信任边界：私有公式池定义、同日名单/历史投影、持久任务及封存结果；受信单步编排只通过现有协调器准入/发布、现有 worker 执行。
- 失败路径：单次运行中可观察的目录或两来源换代；其他任务的成功回执被算成公式池完成；worker 返回 `None` 却已将过期租约改为失败，入口不重核而输出过时的等待状态；任务失败或仍在等待时返回全日完成；worker idle 后忙等；两个入口重叠产生相互矛盾的逐日结果；达到调用次数上限仍继续工作；异常后输出已失效的部分状态。
- 不变量：编排没有第二套队列、计算器或结果权威；最终状态来自整日协调器的重新核验；每次调用的 worker 数量有界，失败不推进虚假的完成状态。
- 排除：生产定时器/systemd、自动选择最新交易日、账户与目录权限安装、正式 Serving 发布、Web 页面和 Streamlit 切流。这些需在各自增量完成并按项目生产规则授权。
