# 财务 PIT 第二片：有界采集与不可变观察记录

接续 [财务 PIT 基础](2026-09-28-financial-pit-foundation.md) 的第二片。目标是以七个 Tushare 财务接口取得**可追溯的观察记录**，为下一片主库表与 PIT 读取提供原料；本片只用注入的假客户端离线验证，不访问真实接口、凭据、主库或生产目录。

**分级：高风险。** 财报修订、供应商截断或系统时钟处理错误会污染历史选股与回测的共享事实。冻结范围是这七个接口的请求编排、响应校验、观察时刻和本地不可变记录；生产写入、迁移、服务与页面另行决策。

## 资产、信任边界与失败路径

- 资产：原始供应商行、接口与查询范围、股票、公告日和报告期字段、每次可信观察时刻、内容摘要、每次查询的响应状态。用户选择的证券与日期只是采集目标；供应商返回值、限额提示、时钟和文件系统均需校验。
- 接口适配器只按白名单调用七种方法，不做财务口径计算；采集核心以显式、有限的请求和注入的客户端/时钟运行；记录器只追加不可变整批文件，并以本地 SQLite 状态登记已提交批次。PIT 选择仍由 `rquant.financial_pit` 独占，后续主库与 Serving 不再复制公告日规则。
- 失败路径：按错日期字段查询导致漏行；单次返回达到上限却当作完整；返回股票或日期越界；NaN/Inf/非预期对象损坏摘要；相同内容重复采集抬晚首次观察；修订覆盖旧值；写入中断留下看似完成的记录；两个采集进程竞争同一记录；符号链接把文件写出目标目录。以上情况必须失败关闭，不发布“已完成”身份。

## 来源事实与请求边界

CC 的 v2 §4.1 指定 `fina_indicator`、`income`、`balancesheet`、`cashflow`、`forecast`、`express`、`dividend`。Tushare 官方接口文档为 [指标](https://tushare.pro/document/2?doc_id=79)、[利润表](https://tushare.pro/document/2?doc_id=33)、[资产负债表](https://tushare.pro/document/2?doc_id=36)、[现金流量表](https://tushare.pro/document/2?doc_id=44)、[预告](https://tushare.pro/document/2?doc_id=45)、[快报](https://tushare.pro/document/2?doc_id=46)、[分红](https://tushare.pro/document/2?doc_id=103)。

官方页面在 2026-09-28 核对的查询语义如下；响应仍须逐行核对，不能用请求成功证明没有漏行：

| 接口与官方依据 | 本片允许的请求 | 实际过滤语义 | 必须读取并核对的响应字段 |
|---|---|---|---|
| [`fina_indicator`](https://tushare.pro/document/2?doc_id=79) | `ts_code + period` | 单个报告期；文档的 `start_date/end_date` 也是报告期，**本片不用** | `ts_code,end_date,ann_date`，可选更新标识 |
| [`income`](https://tushare.pro/document/2?doc_id=33) | `ts_code + start_date/end_date` | 公告日区间 | `ts_code,ann_date,f_ann_date,end_date,report_type` |
| [`balancesheet`](https://tushare.pro/document/2?doc_id=36) | 同上 | 公告日区间 | `ts_code,ann_date,f_ann_date,end_date,report_type` |
| [`cashflow`](https://tushare.pro/document/2?doc_id=44) | 同上 | 公告日区间 | `ts_code,ann_date,f_ann_date,end_date,report_type` |
| [`forecast`](https://tushare.pro/document/2?doc_id=45) | 同上 | 公告日区间 | `ts_code,ann_date,end_date,type`；保留 `first_ann_date` |
| [`express`](https://tushare.pro/document/2?doc_id=46) | 同上 | 公告日区间 | `ts_code,ann_date,end_date` |
| [`dividend`](https://tushare.pro/document/2?doc_id=103) | `ts_code + ann_date` | 单个公告日；接口无区间参数 | `ts_code,ann_date,end_date,div_proc`；保留实施日字段 |

所有请求都指定单只 `ts_code`，拒绝全市场、无边界与跨接口暗换查询语义。单次响应只算“本次查询观察到这些行”，不证明公告窗口或历史数据完整；若真实接口行为与以上官方语义不符，停止采集并更新规格。
- 公告范围请求最多 31 个自然日且不晚于运行日；调用方显式提交有限的证券和请求清单，上限由配置固定，不按供应商返回自动无限分页。接口最低权限、频率与行数可能变化，生产启用前重核账号额度；本片不试探真实 token。
- `fina_indicator` 官方单次最多 100 行，`forecast` 3500 行，`dividend` 2000 行。任一接口响应行数达到**该接口明确上限**时，本次状态为“可能截断”，不得当作全部事实；其余接口也设本地硬行数/字节上限，超出直接拒绝。本片没有“覆盖完成”游标。空返回仅证明这次调用未观察到行，不证明公告历史完整。

## 必须保持的不变量

1. 每次调用只针对一种接口、一个证券和一个显式日期/报告期窗口；接口名、参数及响应中的证券、公告日或报告期一致。字段日期保持原始证据并严格解析；缺少 PIT 关键日期的行可以封存但必须标不可用于 PIT，不能补造公告日。
2. 响应在整批校验后、持久提交锁内，才从带时区的注入时钟取得**本次观察时间**；保守使用封存时刻，不把较早的供应商返回时刻当成首见。可见时刻不能取供应商 `ann_date`、`f_ann_date` 或 `update_flag` 代替。规范化内容、查询身份与时刻计算 SHA-256；浮点非有限值、无法序列化类型或超长字段导致整批拒绝，不落半批。
3. 同一封存根的 SQLite 提交事务串行读取并推进持久时钟高水位。新观察时刻必须**严格晚于**上一个已提交批次；时钟回拨或同刻一律拒绝，不能因重启或并发重新放行。相同请求 ID 重试只返回原已提交回执，绝不改早原时刻或追加重复批次；新的采集请求即使内容相同也有自己的观察记录。下片按同一逻辑键的有序记录，把**连续相同内容**的首条作为该版本的首次观察；A→B→A 的最后一条是新版本，不继承最早 A 的时刻。内容变化只追加，不覆盖旧值；同批同逻辑键内容冲突保留证据并标不可作为完整事实，由 PIT 返回未知。
4. 一次供应商响应是最小提交单元：整批行、查询、时刻、行数和响应状态写入**一个**有界规范文件，以安全相对路径经临时文件、fsync 与不可覆盖的原子链接发布；然后在**同一 SQLite 事务**写入批清单和时钟高水位。读取端只认已提交清单并核对文件格式、长度、摘要、查询、时刻、行数；只有文件而没有已提交清单的是孤儿，绝不能进入下片。已有请求 ID 须核对请求身份一致才可幂等返回。失败、中断、竞争或符号链接不能暴露半批。
5. 采集适配器不 import 配置以外的全局写者、不打开 DuckDB、不写主库；本片无调度、无自动重试风暴、无真实账户调用。下片主库导入只消费已提交并校验过的整批观察记录，不按扫描目录推断完整性。

## 首批验收

- 离线假客户端按上表真实过滤语义返回行：例如报告期在上一年的年报于本年四月公告，公告窗口查询仍得到并封存它；七种接口各自使用正确参数。日期边界、证券越界、错误字段、限额触顶、空响应及权限/网络异常不会被记成完整覆盖。
- 用公告后修订的 A→B→A 假响应证明三个观察版本并存、后到版本的首次观察时刻不会回到公告日或最早 A；相同请求 ID 再提交只得原回执。12:00 已提交后，11:00 的修订和重复响应不得推进或改早时刻。
- 两行响应在第一行之后中断，读取端看不到任何已提交批次；完整封存后读回摘要一致，篡改、截断、目标竞争和异常中断均被拒绝。
- 取本片封存的观察时间构造 `FinancialFact`，用第一片选择器证明历史决策时刻看不到晚采集的修订版；本片不自行计算 `next_open_at`。
- 聚焦单元与临时目录行为测试、Ruff；最终候选做一次独立范围审查。允许针对发现的一组阻断项一次集中修复并定向复核；上限遵守仓库高风险规则。
