# 分钟研究：三段日期口径

更新：2026-10-07。主代理在已授权的 R07–R09 范围内确定这项接线规则。

## 每段做什么

| 日期段 | 用途 | 是否参与选参数 |
|---|---|---|
| 训练 | 计算原评分并选择参数 | 是 |
| 验证 | 查看独立验证结果 | 否 |
| 最终测试 | 查看冻结参数的样本外结果 | 否 |

三段必须按时间排列，互不重叠。完整请求和结果保存三段的实际日期。
已有正式三段请求直接使用原日期。研究评分只取训练段；验证与最终测试分别保留。

交易必须在同一段内买入并卖出，才计入该段闭环交易评分。
跨段交易单独记录。净值使用原执行结果。没有闭环交易时，显示笔数 0、评分不可用，不补成零收益。
行情和候选仍按原事件可见时间读取。研究结果的可见时间使用实际封存和读取时间，不能改成历史开盘时间。

## 新滚动验证入口

旧滚动验证只有训练、测试两段。新三段入口使用独立、有类型的请求。

1. 请求必须明确给出最少训练天数和验证天数。验证天数为正整数，没有隐藏默认值。
2. 沿用原滚动分窗函数。传入的最少历史天数等于训练天数加验证天数。
3. 每窗历史段的末尾 N 天作为验证段；前面的日期作为训练段。N 等于请求中的验证天数。
4. 原函数返回的测试日期直接作为最终测试段。
5. 请求、原函数入参、实际分窗和完整身份一并保存。新模式的日期可以与旧两段模式不同。
6. 日期不足、日历不完整或任一要求窗口缺失时，结果为不可用，并给出原因。

原两段请求、默认值和分窗算法保持原行为。新入口不丢弃日期、不补造窗口，也不增加执行容量。
