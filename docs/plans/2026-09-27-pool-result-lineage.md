# 池子结果版本与父池谱系

**目标**：让“这批成员按这版规则产生”成为可验证事实，供池子画布区分“规则已发布”和“结果已按新规则更新”。当前 `screen_result` 只存命中行，没有定义版本；同一 Serving 数据代里的规则与成员可能分别来自保存前后，不能互相归因。

**分级**：高风险。该切片改变日终结果落库与父池零命中的判断，并增加生产 DuckDB 表。实现、测试和代码合入可先在隔离环境完成；生产建表、数据迁移或部署仍按项目规则取得单独授权。本文件冻结实现前的失败模型。

## 第一性原则与职责

- PageControl 的定义文件是规则权威；日终运行从同一次解析的规则数据构建可执行积木及 `definition_version`，不能另外从路径或当前文件重算版本。内置池的规则元数据也由日终与发布共用的纯注册表提供。
- 成员行与一条 `screen_run_receipt` 在同一 DuckDB 事务提交。回执记录交易日、池子、定义版本、父池所取的精确日期与父运行版本、成功命中数、按 `ts_code` 排序的成员集合摘要、完成时间和可重算的结果版本；结果版本绑定这些字段及成员摘要。零命中也必须有回执。旧结果没有回执时只可显示为“结果版本待确认”，不得按新规则归因。
- v2 精确 T-N 子池读取父池日的成功回执；父池确实运行且零命中才能判为零白名单。父池回执缺失、版本/行数不符或目标交易日行情缺失时，该子池不写新结果，也不把更早日顶替 T-N。旧 `offset_days` 的 T-1..T-N 行为保持兼容，但没有完整谱系的旧结果不能显示“已按当前规则更新”。
- Serving 后续只发布同一只读副本中校验过的定义与运行回执；网页 API 比较版本，React 只展示状态。不能由浏览器本地保存回执、同代时间戳或非零成员数推断计算生效。

## 失败路径与不变量

| 失败路径 | 必须保持的不变量 |
|---|---|
| 保存与运行交错，运行时文件又更新 | 结果只绑定实际编译的那版定义；新保存版本仍显示待重算 |
| 同日重跑从有命中变零，或落库中途失败 | 成员与回执一起替换或一起回滚；零命中不是“未运行” |
| 目标父池零行、回执缺失、历史无版本、父池被重跑 | 只有可验证的零命中回执能参与 v2 计算；缺证据不沿用旧结果 |
| 新规则发布快于日终结果，或回执与成员数量不合 | 规则状态和结果状态分开；不显示“已按新规则更新” |
| 旧版池和生产旧库没有新表 | 旧运行路径与旧结果仍可读取；新证明明确不可用，不凭空补历史版本 |

## 验收与分片

1. **日终核心**：先红测覆盖零命中回执、1→0 重跑、保存与运行交错、事务回滚、父池无回执/确实零命中、父池被重跑、旧 `offset_days` 兼容；再实现最小 `screen_run_receipt` 与原子替换。聚焦运行 PageControl、预设、流水线和存储测试，最终候选做一次独立审查。
2. **只读发布**：在核心过审后，把回执从只读副本有界投影进 Serving，与已核验的 `pool_definition` 同代；缺表或历史回执显示未验证，成员数或成员集合摘要校验失败不标为可信。API 和页面用两个版本比较状态；桌面、390px、键盘和换代路径聚焦验收。
3. 本切片不执行生产建表、不改 systemd/nginx/FRP、不切流或停止 Streamlit。规则保存页面的“已按新规则更新”须等两片都通过并验证真实数据代。
