# 公式批量运行的持久任务与结果

## 范围与分级

把现有离线 `run_formula_market` 包成可恢复的单任务工作流：可信调用方提交、独立 worker 运行、不可变结果文件、状态查询。此片只建领域侧任务与结果合同，不接浏览器、PageControl、Serving、池子或生产配置。高风险：异步重试、来源换代或结果损坏可能使网页以后展示错误的全市场命中。

## 验收

1. 提交请求使用受限公式、开市日期、带时区的执行时刻、两个 64 位来源摘要、由可信端配置的绝对来源根路径，以及 16–64 字符幂等键。浏览器不能直接调用此请求。重复键且请求相同返回原任务；重复键不同请求拒绝；任一时刻只允许一个排队或运行任务。接收仅做有界元数据操作，不在提交时运行公式或扫描大库。
2. SQLite 持久记录排队、运行、成功、失败、尝试次数和有限错误类别。worker 原子认领，有可续租 lease 和 token fencing；进程崩溃后过期任务可被重新认领。只在两来源身份仍与请求一致且运行器完成时成功；超时、容量或来源错误整次失败，不能给出部分结果。成功任务必须能在重启后读取。
3. 结果用严格 Pydantic 合同绑定任务 ID、请求摘要、公式摘要、完整 `FormulaMarketRunSummary` 和内容 SHA256；JSON 规范化、限长、私有目录、原子发布、不可覆盖。状态和读取成功结果时验证文件名、内容摘要、任务及请求/来源一致性；损坏、删除、链接或篡改必须 fail closed。结果保留三态计数与排序命中代码，供后续分页 Serving 使用。
4. 用合成名单/投影做红测：真实 worker 成功、提交幂等及冲突、并发只一活动任务、重启恢复、陈旧 worker fencing、来源换代、失败后无成功产物、结果损坏拒读。聚焦测试和 Ruff 通过，最终候选一次独立审查。

## 冻结失败模型

- 资产：公式、用户选定日期、名单和行情代、任务状态、可展示结果。
- 边界：可信控制端到 SQLite/worker；两个只读来源到离线运行器；worker 到不可变结果目录。网页以后只拿状态/结果，不传文件路径。
- 路径：幂等键重用改请求；两个 worker 争同任务；租约过期的旧 worker 覆盖结果；任务成功后产物失踪/变质；来源更新后沿用旧结果身份；运行器异常被误记为部分成功。
- 不变量：任务请求不可变；一个成功记录对应一个可校验的完整结果；陈旧认领不得改变任务终态；不在 Web 请求线程运行全市场扫描。
- 排除：PageControl/HTTP/React、保存池子、真实 10 GB 负载、生产调度/权限与 Streamlit 停用。
