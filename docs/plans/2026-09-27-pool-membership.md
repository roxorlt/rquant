# 池子成员进出记录

**目标**：补齐原型中状态池成员的入池日、入池价、入池后涨幅和日 K 标记。这里的“入池”指日终选股结果中的连续成员期；入池价采用入池日 `screen_result.close`，页面写成“入池日收盘价”，不暗示可成交价格或实盘买入。

**分级**：高风险。此切片给既有选股结果增加跨日解释，并新增 Serving 共享合同；缺日或旧结果没有运行回执时，错误推断会把历史成员伪装为新入池。本文件冻结实现前的失败模型。只做离线实现与审查，不改生产数据库、服务配置或切流。

## 权威与计算边界

- 输入只取同一份稳定只读副本中的 `screen_run_receipt`、`screen_result` 和交易日历。先复用[运行回执](2026-09-27-pool-result-lineage.md)的成员摘要、日期和父谱系校验，再比较相邻**成功运行交易日**的集合；没有成功回执的日子不能按零命中处理。
- 某只股票从上一可信运行日的不在池，到当前可信运行日在池，才生成入池日和当日收盘价。它持续在池时保留同一次入池日；离池后再入池开启新一期。上一交易日未运行、旧库无回执、校验失败、历史窗口截断或入池日价格缺失时，相关字段为“暂无可靠记录”，不把窗口首日冒充入池日，也不从最新价倒推入池价。
- 若定义版本改变，结果必须先与同一数据代的已发布定义版本匹配，才能把这期成员显示为当前规则的入池记录。计算保留结果版本关联；网页不能把另一个池、另一个交易日或旧定义的成员期拼进当前页。
- 发布有明确行数、时间窗口和字节上限；超限、日历缺失或副本换代时降级为没有可靠进出记录，原有成员查看继续可用。领域层负责纯成员期计算，Serving 负责核验与有界发布，API 只组织状态，React 只呈现。

## 失败路径与不变量

| 失败路径 | 必须保持的不变量 |
|---|---|
| 零命中、未运行、旧结果无回执交错 | 零命中是已运行的空集合；未运行或无回执切断连续性，不猜测入池/离池 |
| 同日重跑或成员行被改动 | 只接受与最新可信回执一致的集合；重新计算的结果代替旧成员期 |
| 休市、跨周末、交易日历缺口 | 相邻性按可信交易日历判断；无法证明相邻时返回未知 |
| 入池日 `close` 为空、非有限或后续复权口径变化 | 入池价与涨幅保持未知，不填 0 或用当前价格代替 |
| 窗口截断、定义换版、数据代切换 | 不把观察窗口首日当入池日，不跨版本/跨数据代拼接 |

## 分片验收

1. 先做纯领域算法与红绿测试：连续持有、离池再入、零命中、未运行、休市、同日重跑、缺价格、缺日历和窗口边界；输出有明确未知原因。
2. 再接同副本核验的有界 Serving 投影与 Pydantic→OpenAPI→TypeScript 合同，确保旧代缺表仍能读成员；最终候选按冻结范围独立审查。
3. 最后接 React 成员表与日 K 标记，桌面/390px、键盘和空态经浏览器验证；只在入池日与价格可信时显示入池后涨幅。各片都不把本地通过说成线上可用。
