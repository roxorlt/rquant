# 选股器一句话生成条件：下一片验收边界

本片接原型选股器的「生成条件」入口。复用池子修改所用的受控模型适配器与规则目录；选股器负责草稿、数据日期和真实筛选结果，不复制池子版本化保存逻辑。最终仍需补查询记录、保存预设，以及 AI 助手的「预览结果 → 一键回测」闭环。

**分级：高风险。** 解析可能消耗付费模型额度，用户文本离开本机；沿用池子修改已冻结的凭据、私有入口、限流与不可信输出边界。编码与测试使用离线替身，不调用真实模型。

## 用户路径

1. 在选股器输入至多 500 字，点「生成条件」。没有模型运行时就说明「暂不能生成，仍可手动添加条件」。正在生成时只锁住本次按钮，不清除当前条件或已有筛选结果。
2. 页面展示模型建议的**完整条件清单**，逐条用目录里的中文名称与参数值解释。建议不会立即替换手工草稿，也不会自动运行、保存池子或提交回测。含糊、无支持条件、超时和服务错误都保留原草稿，给出下一步。
3. 用户点「应用到条件」才替换条件行；可撤销本次应用并继续手工改参数。应用后旧筛选结果明确过期，用户点现有「运行筛选」获取同来源身份、同日期的真实命中数与分页。
4. 模型只生成过滤条件；排名权重、池子保存、查询历史及一键回测另按原型相邻功能接线，不能把此片称为 C14.1 完成。

## 服务边界

- 请求只含受信来源的数据代/副本身份、选中的交易日期和描述。Web 在一次借用中核对条件目录与来源，释放借用后解析，返回前重核来源身份。浏览器规则正文不能成为服务端验证基准。
- 输出先经 `ScreenPlan`、注册表参数模型和现有选股请求目录约束校验；最多 26 条，限制总 JSON 大小，拒绝未知积木、尚未开放字段、非有限数及不可用日期。模型改变日期或要求执行其他操作时不暗中照做。
- 前端保留一次候选与原草稿；数据来源换代或日期变化使候选失效。模型适配只做解析，选股计算仍由现有 `ScreenApplicationService` 完成。

## 聚焦验收

- 假解析器覆盖新增/删除/改参数、重复条件、含糊、空结果、非法字段/越界参数、迟到响应和来源换代；失败不会清空草稿或旧结果。
- 受保护 API 覆盖未登录、跨站、超长、高频、不可用模型与数据来源换代；零真实网络请求。
- 桌面、390px 与键盘路径可完成生成→预览→应用→手改→运行；页面正文无内部标识与虚构命中数。
