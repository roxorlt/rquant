# 因子定义与数据起日解耦

**任务分级：普通任务。** 现有 `FactorDefinition.earliest_available_date` 是必填日期，但网页新建因子时只有代码支持的六个日线字段，没有能证明该公式在特定股票池、冻结来源和历史窗口上从哪天起有值的事实。把浏览器选的日期或快照范围直接写成“最早可用”会制造错误承诺。本片调整尚未上线的本地候选合同，允许日期未知；不开放写命令、不修改生产数据或部署配置。涉及定义、Serving 与网页只读合同，最终候选做一次独立审查。

## 设计与验收

1. 因子定义的稳定内容保留 `earliest_available_date`，但允许 `None`。旧记录的具体日期和原内容摘要保持不变；新定义在没有可信逐因子来源证明时写 `None`。`None` 只表示**起日未知**，不是 1900 年、今天或来源 manifest 起日。`build_factor_definition` 可明确传 `None`，解析器仍从领域能力目录导出字段依赖和历史窗口。
2. `evaluate_factor_time_series` 对已知日期继续拒绝更早交易日；日期未知时按已有输入与时点规则计算，缺价格、缺预热、缺复权等仍保留缺数，不能把未知日期当作数据完备或跳过冻结来源准入。历史适配器和任务规格继续分别核验来源身份、区间和结果成熟；不改变收益或 PIT 口径。
3. 因子仓库读写、当前 head 快照、`factor_definition` 同代 Serving 投影、校验和 Web API 都能往返 `null`，且坏的非规范日期仍拒绝。物理 `DATE` 列可空，状态摘要和行数核验照旧；旧有日期投影与定义摘要不能漂移。生成 OpenAPI 和 TypeScript 类型，不手写接口类型。
4. React 因子详情对未知日期显示“待检验”，并用 `Tip` 说明“保存公式后，运行检验时核对实际数据起日”；已有日期仍显示日期，但标签改为“记录起日”，不把它当全市场覆盖保证。正文保持简短中文，390px 与键盘路径不退化。
5. 用一个无日期定义走完整的仓库→投影→物理 Serving→Web 只读链路，并用一个旧日期定义核对摘要和结果不变；覆盖非法日期、早于已知日期以及未知日期下的真实缺数。只跑直接受影响的 Python/Web 回归、Ruff、生成合同检查和前端构建/产物校验；浏览器只在详情文案或交互有实质风险时定向跑。固定 Python 测试清单由集成分支合并后更新。

## 后续接线

下一片的受控网页保存/编辑只接收中文名、分类、方向和表达式，服务端用 `HISTORICAL_DAILY_V1` 构造定义，日期填 `None`，不接收浏览器自报目录、依赖列、窗口或日期。真实检验任务以固定来源、股票池和日期区间单独准入；取得可核验的起日事实后，可在独立来源状态展示，不静默改写已保存的定义版本。
