# 告警确认与未确认数：实施边界

对应原型盯盘页的「确认」和总览未确认数，以及 v2 C12.2。本片只完成确认链路；规则编辑、测试推送和正式推送切换分别实现。旧推送记录的真实来源是 `logs/notification_log.jsonl`，不是旧版 DuckDB 表；它在时间线中表示一次通道提交，不能再当作第二条需要确认的告警。

**分级：高风险。** 确认会改变跨页面共享状态，并影响用户是否继续处理告警；错误计数或丢失确认会误导操作。实现前以本文件冻结失败模型，最终候选做一次独立审查，复核只限阻断项与修复回归。首次 SPEC 审查的 `ACK-SPEC-01..05` 已按下文修订，原审查者定向复核后全部关闭，SPEC 已通过。

## 资产、信任边界与不变量

- 资产：已发布的信号、盯盘触发和爆量事件；确认人的身份和时间；PageControl 命令回执；不可变 Serving 数据代；盯盘与总览的未确认数。
- 浏览器冻结 `command_id`、`requested_at`、`generation_id`、`alert_id` 的完整 JSON 请求，重试逐字使用原值。网页 API 要求 `current_user` 返回有效身份，否则 401 且不得入队；身份来自 nginx 覆写的头，浏览器不能指定确认人。每次写入执行同站 JSON/CSRF 校验，不能信任浏览器传来的事件内容或状态。
- PageControl 是唯一确认状态写者，使用其受控命令与持久 SQLite 状态；网页和 Serving 均不写 DuckDB 主库或确认状态。Serving 发布器从该状态读一份有界快照，与事件源一起生成新代。各层只传有类型的必要字段，不传原始推送目标、错误或凭据。
- **触发事件才计入待确认**：`signal`、`monitor_event`、`surge_event` 可确认；`legacy_notification` 和 `deliveries` 是投递事实，无确认按钮，也不重复计数。未来新增告警类型须显式加入可确认白名单。
- 稳定 `alert_id` 使用下表的 v1 字段；相同完整内容跨数据代身份相同，任何参与字段修订都得到新身份。生产者、Serving 读模型与网页 API 共用 `src/rquant/alert_ack.py` 的同一个规范化函数，不让三处各算一套。绝不以列表位置、页码、展示文案或客户端时间认定事件。
- 确认为全局处理状态，持久记录首位确认人、确认时刻和命令 ID；同一 `alert_id` 重复提交幂等，不覆盖首个记录。命令 ID 重放同一内容返回原结果，换内容拒绝。状态不得因来源短时缺失、Serving 换代或进程重启丢失。
- 正式启用时只设置一次不可后退的确认起点 `activated_at`。起点以前的历史事件可看，但没有确认按钮，也不倒灌到未确认数。配置缺失、确认投影未发布或源不完整时，不显示精确的 0，不提供貌似可用的确认按钮；说明「确认状态暂不可用」。首次启用时间与生产配置变更另走授权流程。
- 成功命令回执只证明确认已持久化，并返回实际生效的首个确认 ID；重复确认也返回该已有 ID。新 Serving 代按 `alert_id` 和实际生效的确认 ID 看到确认行后才显示「已确认」，不能等待重复请求自己的命令 ID。同步期间显示「已受理，正在同步」，不可把旧代的总览数当新数。浏览器失联或回执含糊时保留原命令 ID 重试，不生成新确认。
- 未确认数覆盖共同已验证截止时刻 `count_as_of` 所在上海自然日起最近 30 日、确认起点之后的全部可确认事件。只有三个来源和确认表都能正面证明从窗口起点到该截止时刻完整、同代且不过期，才返回精确数与「截至 HH:mm」；否则 `count=null`、标明来源不全，不把缺失当 0。时间线与总览复用同一读模型；截止时刻之后的条目不能被算入该数。
- 网页读取 `alert_event` 和覆盖摘要时，必须从同一借用代的 `signals`、`monitor_event`、`surge_event` 重新核对窗口内的事件身份与集合；投影表自称 `complete` 和它自己的摘要不能单独证明原始来源无遗漏。任一原始来源不可读、超限、身份不合法或集合不一致，确认和精确数一起关闭。

### v1 事件身份与数值规范

| 来源 | 参与 `alert_id` 的已发布事实 |
|---|---|
| `signal` | 经现有 `SignalEnvelope` 全量身份哈希验证的 `signal_id`。该哈希已经绑定策略与版本、参数/数据快照、事件与可用时刻、股票、动作、原因、证据及过期时刻；`global_sequence` 和投递状态不参与。若没有哈希验证的来源证明，拒绝计数和确认。 |
| `monitor_event` | `trade_date`、`trigger_time`、`ts_code`、`level`、`trigger_price`、`level_price`、`trigger_type`、`pool`；仅主键三元组不够。 |
| `surge_event` | `trade_date`、`confirmed_at`、`ts_code`、`name`、`theme`、`price`、`pct_chg`、`cum_amount`、`rel_cum`、`room_to_limit_pct`、`status`。 |

现有 Serving `signals` 小表未发布信封的全部身份字段，读端不能仅凭小表重算 `signal_id`。当前信任链是：发布器先通过 `ServingReadModelInput` 对完整 `SignalEnvelope` 做哈希验证，再生成受内容摘要保护的不可变数据代；网页与 PageControl 在该代中核对 `signal_id`、原始行集合和来源代。以后若信号改由其他路径写入，必须补等价的完整信封验证/来源证明；没有正面证明时该来源不完整，不能开放确认或精确计数。

哈希域为 `rquant-alert/v1` 加来源类型与有序字段。日期用 ISO 日期；时刻先按源约定解释（盯盘时刻在发布前按上海时间转 UTC，爆量日期加 `HH:mm` 按上海时间解释），再规范为 UTC 微秒；字符串按原已发布值作 NFC 规范化，不从页面文案逆推；浮点只接受有限 IEEE 754 值，以 `float.hex()` 表示并把负零归零；空值有独立标记。重复身份、非法时间或非有限数值令该来源不完整。新增或移除身份字段须升版本，不重解释历史确认。

### 重试、崩溃与来源完整性

1. 网页先在固定 loopback PageControl 以**只读的原命令查找**核对完整命令哈希及确认人；找到相同命令便返回原回执，即使浏览器持有的数据代已过期。若命令 ID 已存在但身份或内容不同，返回冲突，绝不泄露他人回执。只有查找结果明确为「不存在」时，才从一次当前 Serving 借用核对 `generation_id`、可确认事件和 `alert_id` 后入队；查找不可用时不盲目提交。PageControl 的 `requested_at` 参与哈希，重试不能重造时间。已有的仅 `POST /v1/commands` 接口不足以区分「原命令恢复」与「旧代新命令」；本片须补受控只读查找。
2. `ack_alert` 没有外部文件副作用。PageControl 在同一个 SQLite `BEGIN IMMEDIATE` 事务里核对命令租约/内容、首次插入或读回既有确认、记录首个确认 ID，并把该命令及效果记为成功；不把确认行和成功回执拆成两个可见提交。提交前崩溃时两者都不存在，原命令可重试；提交后崩溃时两者都存在，原命令直接取回首个确认 ID。双人竞争由唯一 `alert_id` 约束串行，第二人只收到首个确认 ID，不改确认人。不得出现确认已持久化而回执永久失败。
3. 新的有界 `alert_source_coverage` 投影为每个来源保存窗口起止、截止时刻、来源代/高水位、行数、行摘要和 `complete/unavailable` 状态；确认投影保存同一读取事务的起点、唯一行数与摘要。`signals` 需要权威连续序列及覆盖窗口证明；`monitor_event` 需要同一副本每个交易日的监控完成或明确零事件凭据；`surge_event` 需要每个交易日已核验事件文件或明确零事件凭据。交易日由同代 SSE 日历界定，目录存在或某日文件不存在不构成零事件证据。不能取得现有旧源的正面凭据时，该来源为不完整，页面可展示已观测事件但总览数保持未知；后续源写者/发布合同须补齐凭据，不能用推算代替。发布器核对覆盖行数/摘要与事件表，在共同截止时刻以前有缺日、超限、过期或来源换代均拒绝精确数。

信号总线现已能对**新建数据代**持久记录创建时刻，并在单个 SQLite 读取事务内核对有界的连续完整信封前缀，生成 `SignalBusObservedPrefixReceipt`。旧数据代缺少创建时刻时绝不追补；空总线的收据只说明总线当前为空，`upstream_complete=false`。这仍缺少全部上游生产者自窗口起点以来持续运行/完成的权威凭据，也未把同代总线、路由 spool 和通知复制进度合并为一个截止点。因此信号来源继续保持 `unavailable`，不能据此开放确认或显示精确零。前缀超过 10,000 条时当前实现也不出具收据，后续需要有界检查点或窗口归档合同。

路由进程现在有显式 `SignalRouteSpool.publish_bus_prefix_link`：它在总线同一截止时刻取前缀收据，逐条核对总线**路由回执**与 spool 的来源代、高水位、完整信封、路由内容及路由时刻后，连同路由行摘要原子写入有界 `bus-prefix-link.json`；落后、换代或总线路由账本不符时不会发布新链接。只读 spool 每次取链接均重新核对磁盘记录、当前指针和路由摘要，指针前进或内容改写时不提供旧链接；若总线已换代而旧 spool 尚未变化，旧链接仍只是**旧代历史证据**，只读端不能据此声称当前总线完整。**此 API 尚未接入路由的 2 秒热循环，也未接入通知复制或 Serving 发布**；后续应由受控低频触发，避免每轮扫描最多 10,000 条。通知进程还需把该链接与自身同截止点的完整复制前缀在一个 SQLite 快照内核对后才能形成总线→spool→通知的链式凭据。即使完成这一链，仍须另补全部上游生产者的正面覆盖证明；当前 `alert_source_coverage(signal)` 保持 `unavailable`。

### 新确认命令的跨进程准入

当前只读命令查找和确认状态落库尚未形成一条可提交新确认的链路。网页 API 先从当前借用的 Serving 代核实事件、来源覆盖、确认起点及登录人；PageControl 作为唯一准入和持久化写者，在受理新命令时独立复核这些已发布事实。浏览器提交的 `eligible`、事件内容或计数一律不可信。

- **Web 入口也是身份边界**：回环 TCP 端口不能证明请求经过 nginx；同机其他 UID 可直连并自填 `X-Rquant-User`。启用确认准入时，Web 只监听与 PageControl 确认 socket 分开的私有 Unix socket；同时配置 TCP bind 必须拒绝启动。Web 在启动 Uvicorn 前预绑定并以文件描述符交接，避免 Uvicorn 自行创建 socket 时使用 `0666` 权限。入口目录由 Web 服务 UID 所有、组为 nginx `www`、权限 `0710`，入口 socket 同属该 UID 与 `www` 组、权限 `0660`；其他 UID 既不能遍历目录也不能连接。`www` 组只能包含 nginx 与受信 Web 服务身份，其祖先目录须允许 nginx 遍历。nginx 完成认证并覆盖身份头后才代理到该入口；获得 nginx/Web 服务 UID 执行权已越过本期信任边界。旧回环 TCP 入口只在确认准入关闭时保留。生产 unit、nginx 代理、组成员、socket 权限及其他 UID 实测需单独获授权后验收，未验收不得启用确认。
- 新命令只走独立的本机 Unix socket 准入通道，socket 所在目录为服务用户独占，目录权限 `0700`、socket 权限 `0600`，且服务端从操作系统取得连接者 UID，要求与受信的 Web/PageControl 服务 UID 一致。其他本机 UID 直连必须在解析命令前被拒；原有 TCP loopback `/v1/commands` 仍不得接纳新 `AckAlert`，只读查找永不写入。生产中 Web 和 PageControl 以同一个受控服务用户运行；取得该用户执行权的代码本就能修改其 SQLite，本期不虚设共享密钥来冒充同 UID 进程隔离。对外边界仍由 nginx 身份和网页同站校验控制。socket 路径、目录权限及 Web 可连接性需在获得生产 unit 变更授权后另做验收。
- PageControl 自己打开当前不可变 Serving 代，核对该事件在原始来源及 `alert_event` 中身份一致、窗口来源证明完整、事件可确认，且其 SQLite 的受控确认起点与投影一致。完成这些核验后，**最后一次**读取 `current.json` 并要求它仍指向命令代号；这一次指针观察是新命令的资格判定点。该点之前换代为 G2，G1 新命令拒绝；该点之后即使发布器换代，仍允许把已判定合格的 G1 命令持久入队。无需假称 Serving 指针替换与 SQLite 入队可以原子化。
- 浏览器只有拿到持久命令回执才显示「已受理」；若资格判定后、入队前崩溃而没有记录，原命令再次尝试时须重新核验当时的当前代，可能因换代而拒绝并提示刷新。已持久受理的原命令无论换代都通过只读查找恢复；若其 `pending/processing` 续处理的私有通道失败或回执含糊，Web 再次只读查找并只返回这次核实的持久状态，查找失败则报错，不凭连接异常推断成功。准入失败、指针缺失、覆盖不足或起点未启用时，SQLite 确认状态保持不变；不得在 Web 进程直接写确认文件。
- 准入核验与网页的告警读模型共用不依赖 FastAPI 的领域读取器，避免 PageControl 和 Web 各自重新定义身份与覆盖口径。PageControl 只读已发布 Serving 代和自己的 SQLite 状态，不读取生产 DuckDB 主库。正式 Serving 路径访问权如需修改 unit，另走生产授权。

2026-09-28 定向修订：私有准入监听器按请求串行完成「原命令查找→资格判定→持久入队」，避免同一命令的并发请求在另一请求已通过资格判定、尚未入队时误判为不存在。网页在准入错误后再次只读查找原命令，找到则返回持久回执。只有私有准入明确因**已知当前代与命令代不同**而在入队前拒绝，且网页再次查找确定不存在时，409 才带 `stale_generation_no_effect`；当前代缺失、查找失败、普通 409 与失联都保留原请求续查。浏览器只在首次请求收到此明确语义时允许换代后新建命令。

## 失败路径与聚焦验收

| 失败路径 | 必须看到的行为 |
|---|---|
| 伪造事件、投递记录、旧数据代的新命令、缺失身份或跨站请求 | 网页 API 拒绝写入；无身份返回 401；PageControl 状态不变。 |
| 同一命令重试、两个用户确认同一事件、命令 ID 换内容 | 只有一个持久确认；重试取回原结果，冲突明确拒绝。 |
| PageControl 写后响应丢失、换代或事务前后崩溃 | 原请求逐字重试并核对确认人，仍取回首个确认 ID；确认行与成功回执同生同灭，页面不提前宣布「已确认」。 |
| 事件内容修订、Serving 换代、确认投影滞后 | 旧事件身份不错误确认新内容；新代未包含回执时保持同步中，数值不伪精确。 |
| 确认文件不可读、状态表缺失、来源缺日或空目录缺零事件凭据 | 盯盘和总览都显示来源/确认状态不完整，不给精确 0。 |
| 历史 30 日事件多于页面首屏 | 未确认数来自全窗口有界来源，不以当前页长度计数；分页稳定且不重漏。 |
| 三个覆盖行自称完整，但同代原始来源多出或少了事件 | 盯盘与总览均返回数量未知，所有新确认拒绝，不能显示 0。 |
| 网页核验后、PageControl 最后一次指针观察前换代；确认源表被省略；确认起点不一致 | PageControl 不入队；原命令只读续查仍可用。 |
| PageControl 最后一次指针观察后、入队前换代或崩溃 | 换代后仍可持久入队已验证的原命令；若入队前崩溃则无回执，重试重新核验当前代，不提前显示已受理。 |
| 其他本机 UID 直连 Web/新准入 socket，或从旧 TCP 端点提交新确认 | Web 入口配置或文件权限拒绝直连；PageControl 不解析或不入队，不接受伪造的确认人。 |

## 实施次序与接口

1. **身份与纯状态规则**：在 `src/rquant/alert_ack.py` 定义上表的规范化函数与确认窗口规则；用三种真实形状的触发事件、遗漏字段修订、时区、非有限数值和重复键测试。通知记录和投递回执必须被排除。
2. **唯一写者**：在 `src/rquant/page_control.py` 增加 `ack_alert` 命令、只读原命令查找和事务内幂等确认表；确认起点作为受控配置/状态，补查找失败、两处崩溃切点、响应丢失后换代及双人竞争测试。不得让网页直写状态文件或 DuckDB。
3. **发布与读模型**：在 Serving 契约和页面投影源新增有界确认投影、起点与逐来源正面覆盖凭据；核对状态行数、唯一性、行摘要及共同截止时刻。旧代无表明确为「尚未发布」，缺凭据不报告精确数。新旧投影在同一不可变数据代中消费。
4. **网页合同**：`POST /api/v1/monitor/ack` 接受冻结的 `command_id`、`requested_at`、`generation_id`、`alert_id`，身份由服务端追加；返回持久命令状态和实际首个确认 ID。GET 时间线增加每条可确认事件的状态和全窗口未确认数/完整性及 `count_as_of`，不暴露技术键于页面正文。总览复用同一读模型，避免另算一套。
