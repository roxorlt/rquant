# 旧通知记录进入告警时间线

> 2026-09-27。基于已审查的监控时间线 `96c2d4e0`。本增量只做只读展示，C12.2 的确认命令和 C12.1 规则配置仍未完成。

## 事实、风险与验收

旧 `rquant.notify.log` 在 v0.13 后将每次目标通道尝试追加到 `logs/notification_log.jsonl`；计划 v2 所说的 DuckDB `notification_log` 已弃用。JSONL 行含 `target`（推送 key/token 前缀）、`error_msg` 原文、`title` 用户或上游生成文本。这些字段不能通过 Serving、API、页面正文、提示或诊断日志泄漏。

本增量定为**高风险**：它把含敏感字段的文件跨入共享 Serving 和网页边界，且并发追加、时间解析或旧代继承错误会误报通知结果。以下信任边界和不变量在编码前冻结；不改通知发送行为、生产凭据、配置或部署。

## 信任边界与不变量

- 浏览器只读固定 Serving 数据代。旧 JSONL 是本地输入，不因位于服务目录就视为可信；通知发布者在独立源适配器里只提取白名单字段。源读取器使用常规文件、无符号链接、有界文件大小/行数，并在读取前后核对 inode/大小/mtime/ctime；并发追加或替换时本轮不发布它的旧内容。
- 只发布正规化后的 `sent_at`、白名单场景中文名、白名单通道中文名、布尔提交结果和不含原始输入的稳定行键。**绝不**把 `target`、`error_msg`、`title` 或完整原始 JSON 保存到投影、API、HTML、错误文本或日志。未知场景/通道不猜测含义，不显示原始代码；可跳过但须有明确来源不完整状态。
- 原日志时间是无时区的本机时间：按现有生产约定解释为 Asia/Shanghai，再转成 UTC 用于排序与最近 30 个自然日窗口。无效/未来时间、部分行、超限文件不得形成“已发送”假象。多通道同一事件只表示各通道的提交尝试，**不能**与某只股票的触发/新运行时回执自动配对，不能将 API 成功写成手机已送达。
- 若已发布过记录的来源随后缺失、损坏或正在改写，新通知权威须显式撤销这一投影并更新来源状态；新的 signals authority→Serving 代不能悄悄保留旧推送行。其它信号、触发和爆量记录继续显示；页面用一句短中文解释该来源暂不可用。
- 同一 Serving 代中按时间倒序合并、分页与 HMAC 游标绑定；换代继续用现有 409 重新查看行为。页面正文不显示服务代号、原始 scene/channel、token 前缀或内部行键。

## 失败路径

文件同 inode 改写并恢复 mtime；追加中读到半行；超限或异常 JSON；重复时间、多通道与重复行；30 日边界时区错误；来源撤销后 Serving 仍继承旧行；用户把“提交成功”误解为“送达”；前端窄屏裁字。源目录无法读或尚未配置时页面不能把“没有记录”说成“没有发生过推送”。

## 实现与验证范围

1. 在现有通知页面投影来源增加可选的旧日志路径，复用有界/稳定文件读取与权威发布链；不从网页直接读 `logs`，不引入新常驻服务。注册最小 Serving 契约。生产路径配置另行 review/授权，此分支仅在离线夹具注入路径。
2. 网页 API 将旧日志作为独立「通知记录」时间线项，写明通道与「提交成功 / 提交失败」，不冒充某条触发的回执。React 按原型时间线风格呈现，短文案与 tooltip、桌面和 390px 都可读；旧日志缺失时只提示确切缺口。
3. 用带合成秘密 canary 的真实格式 JSONL 走源→通知权威→signals authority→Serving→API→React；断言全链输出和错误路径都无 canary、无内部代码；测试并发追加/同 inode 置换/半行/超限/时区边界/撤销旧行/多通道独立状态，并跑聚焦页面与 390px 浏览器验证。

独立审查只覆盖本 diff、直接依赖和以上冻结不变量；高风险定向修复最多三轮。此增量通过也不等于旧推送、确认、规则引擎或正式模式已切流。
