# 研究任务队列网页增量

> 2026-09-27，基线 `d46c345f`。对应 v2 C13.1 的研究任务队列部分。原型的 systemd 定时任务、资源卡片、日志和操作按钮继续留在 M13 台账；本增量不以演示数据或无效按钮填充。

## 分级与验收

**普通任务**：只读展示已发布 Serving `lab_jobs`，改变网页可见行为和 API 合同，不触及生产写入、权限或服务配置。验收是 `/tasks/jobs?cursor=` 与任务页在同一 Serving 数据代下提供稳定分页、状态计数、任务进度和预计结束时间；来源未发布、空队列、过期、加载失败、数据换代与 390px 均有正确中文反馈。任务名称/类型与状态面向用户；内部 job ID、状态枚举、服务代号不在页面正文，必要时放悬停提示。没有接通的暂停、重试、日志、立即运行按钮不出现。

## 数据与模块边界

1. API 只借用一次 Serving generation 游标，检查 `projection_status` 与 `lab_jobs` 水位；已配置但未发布时明确不可用，不把缺表当空队列。固定上限读取、按 `updated_at DESC, job_id ASC` 排序；游标绑定 generation、排序键与查询条件，换代返回中文 409。现有发布表字段足够展示状态、分片进度、资源档位和 ETA；不查询主库、Lab SQLite 或生产运维服务。
2. Pydantic 响应只输出页面需要的字段与有限的技术身份（供未来操作与提示）；把 job type、resource class、status、ETA 状态显式映射为简短中文，未知枚举保守处理，不把原始错误或 spec hash 暴露给网页。状态计数按同一份已发布数据计算，不使用原型的虚构计数。
3. React 任务页复用现有表格、状态、相对时间和空态组件；桌面显示任务、进度、状态、更新时间，窄屏仍能看主要信息并翻页。刷新从第一页开始，换代时不沿用旧游标或旧计数；技术编号仅在 hover/tap 的详情里。定时任务及写操作在后续接通真实服务后再显示。
4. 聚焦 API、OpenAPI 快照、前端状态与分页测试；`pnpm -C web check`、构建/产物校验和桌面/390px 浏览器行为。最终候选做一次独立审查；只有可复现违反本次验收的 P2 才阻断，一次定向修复/复核为上限。生产 Serving 数据代与正式切流仍是独立门禁。
