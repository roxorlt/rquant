# 研究任务队列网页增量

> 2026-09-27，基线 `d46c345f`。对应 v2 C13.1 的研究任务队列部分。原型的 systemd 定时任务、资源卡片、日志和操作按钮继续留在 M13 台账；本增量不以演示数据或无效按钮填充。

## 分级与验收

**原定普通任务，现升级为高风险**：只读展示已发布 Serving `lab_jobs`，改变网页可见行为和 API 合同，并按下文证据修复共享构建器的一处 ETA 序列化错误。验收是 `/tasks/jobs?cursor=` 与任务页在同一 Serving 数据代下提供稳定分页、状态计数、任务进度和预计结束时间；来源未发布、空队列、过期、加载失败、数据换代与 390px 均有正确中文反馈。任务名称/类型与状态面向用户；内部 job ID、状态枚举、服务代号不在页面正文，必要时放悬停提示。没有接通的暂停、重试、日志、立即运行按钮不出现。

### 范围升级：Serving ETA 序列化

真实 ETA 红测发现 `LabEtaEstimate.status` 是经 Pydantic 验证的字符串，而共享构建器 `build_serving_read_models` 在写入 `lab_jobs.eta_status` 时调用 `.value`，使任何带 ETA 的任务无法发布。本任务仅授权把该已验证字符串投影到现有字段，分级因此升级为**高风险**；不改变字段、状态定义、发布流程或发布门禁。

- 资产与信任边界：研究任务源模型由 Pydantic 验证后进入 Serving 构建器；构建结果才可被原子发布、供只读 API 借用。浏览器只能读借出的数据代，不接触研究队列 SQLite、主库或发布器控制权。
- 失败路径：构建器错误访问 `.value` 会阻断整代发布；网页若把不可读表、缺水位或未发布状态当空队列，会虚报“没有任务”；换代后旧游标若继续使用会混合两代计数和任务。
- 必须保持：ETA 状态值只能来自已验证的 `LabEtaStatus`；其余 `lab_jobs` 列、签名/水位/数据代机制不变；一次 API 响应的计数、分页和内容来自同一借出的只读数据代；API 不泄露原始错误、spec hash，不执行写操作。
- 排除项：其他 Serving 构建/发布逻辑、运行时作业/命令、数据库迁移、运维服务、生产数据与部署。本次仅用合成数据和聚焦回归核验。

## 数据与模块边界

1. API 只借用一次 Serving generation 游标，以 manifest 中 `lab_jobs` 根数据集的水位/状态及实际表可读性判断可用性；`projection_status` 只列页面派生表，不包含 `lab_jobs`。已配置但未发布时明确不可用，不把缺表当空队列。固定上限读取、按 `updated_at DESC, job_id ASC` 排序；游标绑定 generation、排序键与查询条件，换代返回中文 409。现有发布表字段足够展示状态、分片进度、资源档位和 ETA；不查询主库、Lab SQLite 或生产运维服务。
2. Pydantic 响应只输出页面需要的字段与有限的技术身份（供未来操作与提示）；把 job type、resource class、status、ETA 状态显式映射为简短中文，未知枚举保守处理，不把原始错误或 spec hash 暴露给网页。状态计数按同一份已发布数据计算，不使用原型的虚构计数。
3. React 任务页复用现有表格、状态、相对时间和空态组件；桌面显示任务、进度、状态、更新时间，窄屏仍能看主要信息并翻页。刷新从第一页开始，换代时不沿用旧游标或旧计数；技术编号仅在 hover/tap 的详情里。定时任务及写操作在后续接通真实服务后再显示。
4. 聚焦真实 ETA 发布构建、API、OpenAPI 快照、前端状态与分页测试；`pnpm -C web check`、构建/产物校验和桌面/390px 浏览器行为。最终候选按根 `AGENTS.md` 做一次独立高风险审查，仅在上文冻结的失败模型范围内检查；P0/P1 阻断，P2 仅在可复现违反本次验收或冻结不变量时阻断，最多三轮定向修复/复核。生产 Serving 数据代与正式切流仍是独立门禁。
