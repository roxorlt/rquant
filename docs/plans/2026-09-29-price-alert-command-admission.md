# 价格提醒规则：受信命令与原请求恢复

接续 [规则事务权威](2026-09-28-price-alert-rule-authority.md)。本片把价格规则的保存、启停与删除接入 PageControl 原命令机制；只形成 SQLite 权威与终态回执，不发布 Serving 数据代、不开放 Web API、不评估行情或发送通知。页面看到“已生效”仍必须等后续同代发布证明。

**分级：高风险。** 错认用户、规则版本或名单版本会让他人的提醒被改写，或让已移出的股票重新触发。

## 冻结边界与不变量

- **权威与信任边界**：认证用户来自受信私有入口，外部命令体不得自称 owner；受信提交端把 owner 注入规范化的**持久命令**，并使其参与命令摘要、原命令精确查找和恢复身份。PageControl 是规则写入的唯一执行者，借同一个 SQLite 事务调用 `PriceAlertRuleRepository`。现有普通 `submit` 和公开 TCP 入口不得受理价格规则命令。命令 ID、内容摘要、权威写入、效果记录与终态回执必须同事务一致；相同 ID 即使业务字段相同，只要认证 owner 不同，也不得看到前一用户的回执。
- **协议激活**：价格规则默认关闭。单独显式激活须在一笔事务内安装规则 schema 和版本 marker；未激活或 marker/表不一致时，受信 submit、claim 和 complete 都失败关闭，不得隐式建表或创建待处理命令。lookup 是只读操作，只有已存在且认证 owner、ID 与完整原命令内容均匹配时才返回回执；resume 只继续这个已存在原命令。查无原 ID 返回 missing，不得借 lookup/resume 入队或写规则。
- **失败路径**：重复命令 ID 换内容或换用户、旧规则 CAS、同股另一用户、名单删除/到期或版本更新、并发启停/删除、SQLite 锁或进程在提交前后中断、规则表缺失或损坏、未来时间及超容量。失联只允许用原命令 ID 和原内容恢复查询；不得把未知回执重新生成新命令，或把“已保存”显示成“已触发告警”。
- **必须保持**：新建及启用在执行事务内核对 owner、代码和当前有效名单版本；停用与删除可在名单失效后执行。所有修改要求预期规则版本，删除写单调墓碑，同 ID 重建基于墓碑版本。成功回执的规则版本须等于事务后仓储版本；拒绝或异常不能留下部分规则变化。旧 monitor、手动名单和现有通知路径不因本片改变。
- **排除项**：本片不改 Web 路由、React、Serving、报价源、通知、systemd/nginx/sudoers 或生产库；不访问 `.env`、真实凭据或网络。私有 UDS 准入、同代读取、告警评估及正式投递按后续切片完成。

## 验收

1. PageControl 有明确的保存、启停、删除规则命令类型与受信提交路径；普通入口拒绝。受信 owner 进入持久命令和摘要；相同 ID/owner/内容幂等，相同 ID 的不同内容或 owner 在 submit、lookup、resume 均拒绝且不可见他人的回执。
2. 合成 SQLite 验证显式激活、规则写入、效果与终态同事务；未激活或 marker/表损坏时不写入。未知 ID 的 lookup/resume 不产生命令；提交前失败可用原 ID 续跑而不产生半写，提交后重试返回原终态且不重复效果。两用户同股、旧名单版本、过期恰在执行时刻、CAS 冲突、删除后重建及容量边界均有聚焦用例。
3. 手动名单和 PageControl 既有直接回归通过；本片不运行真实告警，不触碰生产状态。
