# 池子画布：已发布规则只读页

**目标**：用真实 `pool_definition` 数据在 React 画布展示条件、规则与池子依赖。此阶段只读取，不提供编辑或模拟成功；后续写入、运行回执和入池记录按相邻计划推进。

**分级**：普通任务。改动涉及网页 API、OpenAPI 类型和 React 可见行为，但只读取已核验的 Serving 数据代，不新增写入、权限或生产基础设施路径。

## 数据与交互

- API 一次借用同一 Serving 代，分别读取规则定义和选股结果；两个状态独立。缺少 `pool_definition` 时保留现有成员查看，并显示“规则暂不可查看”。缺少当天成员时，仍可查看已发布规则。
- 只有 `state=available` 的定义能生成条件节点及 `depends_on` 连线。依赖端缺失、待迁移、不可用或被列表上限隐藏时，不画推测连线，并在列表或详情解释。画布引用只决定筛选范围，不表示规则依赖。
- 每个可用池用条件节点汇总其真实规则，再连接到该池。存在可用父池时画“父池 → 条件 → 子池”；无父池时画“条件 → 池子”。节点与旁边等价列表都可用键盘选择；点条件看规则，点池子看成员与来源。
- 规则详情由服务端把全部已登记积木及参数映射成短中文，字段名或技术表达式只放在提示或详情的辅助信息中。规则名称、阈值、日期偏移必须来自实际定义；没有逐条件命中证据时不显示逐步人数。无效 JSON、未知积木或超限规则不伪装成可用规则。
- 页面把“规则已发布”与“上次选股结果”分成两块。即使它们出现在同一数据代，也不能宣称成员按当前规则计算；只有 [运行回执](2026-09-27-pool-result-lineage.md)接入且版本吻合后才能写“结果已按新规则更新”。
- 页面正文用简短中文，长说明进 `Tip`；技术键、命令哈希与数据代标识不进正文。空态说明原因与下次会怎样；桌面和 390px 宽度均可选节点、看规则和成员。

## 验收

1. 合成发布代覆盖内置、自建、旧文件待迁移、损坏文件、缺父池、无当天成员、规则表缺失、跨代更新及数量上限；同一响应不混用数据代。API 返回 Pydantic 类型，OpenAPI 和生成的 TypeScript 类型一致。
2. React 的真实依赖线、条件列表、规则详情、无结果提示、键盘选择和 390px 页面经聚焦组件及浏览器验证；不得把画布引用、规则发布或旧成员误写成已按新规则生效。
3. 聚焦 Python、前端检查、构建及 `web/dist` 校验通过；最终候选独立审查一次。此阶段不修改生产配置、不切流、不停止 Streamlit。
