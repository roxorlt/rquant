# 模拟盘和组合风控：剩余功能与现有入口

状态：已核对需求和直接代码入口，尚未开始实现。
本文件是下一项任务的准备资料。它不是已通过审查的实现方案，也不表示功能完成。

## 要完成什么

范围来自 CC 的 `frontend-plan-v2.md` 第 4.9、4.10 节、差距表和模拟盘原型。

| 功能 | 用户应能完成的操作 |
|---|---|
| 目标仓位 | 选等权或按排名分加权。单票、行业、持股数、现金和最小金额限制同时生效。模拟盘按目标仓位运行。 |
| 组合回撤 | 设置回撤阈值。触发后降仓或停止开新仓。回测和模拟盘使用同一规则。 |
| 行业暴露和归因 | 查看持仓与基准的行业权重偏离，以及行业配置、选股贡献。现金单列。 |
| 完整账户记录 | 查看账户状态、运行天数、逐日净值、收益、最大回撤、持仓、当日指令及完整历史。 |
| 回测区间对照 | 将模拟净值与对应策略版本的回测抽样区间放在同一图中。区间为 5%–95%，区间外显示“需要关注”。 |
| 对账和暂停 | 提交原研究任务做只读对账。两步确认暂停账户。暂停后停止新开仓，已有持仓照常按规则退出。 |

## 已核实的缺口

1. 模拟盘买入仍读取固定股数。`paper_signal_worker.py` 的两处准备路径尚未接目标仓位。
2. 原 `paused` 配置会在消费和执行之前返回，因此也会停止退出。它不能直接作为新“暂停账户”按钮的实现。
3. 账户页目前用最近成交价估值，并明确标为降级。不能把这份估值存成每日收盘净值。
4. 指令页已验收的是最近最多 200 条记录。它不是完整历史。
5. 行业暴露、归因、权重和回撤的纯计算已存在。后续应接真实输入、持久状态和页面，复用这些计算。
6. v2 计划要求的暂停命令和操作员控制通道尚未实现。后续采用原 PageControl 命令入口，按序号和命令摘要让服务每轮读取控制状态，并在运行事实中显示已应用的状态。

## 实现时必须证明什么

- 目标仓位、回撤限制、费用和整数手规则同时生效。重复处理同一信号不重复交易。
- 重启后保留回撤前态和已确认的账户暂停状态。暂停期间可执行减仓和退出；恢复后不补买已被暂停拒绝的新信号。
- 暂停命令的接收、应用和页面显示须能对应同一序号与摘要。控制状态尚未应用时显示等待，不能先显示“已暂停”。
- 每日净值有真实估值输入及可信账本来源。缺行情或历史证据时显示原因，不能补零或倒推旧资产。
- 完整历史的分页覆盖范围、账户和数据版本可核对。跨账户或跨版本的详情不能混用。
- 对照区间绑定同一策略版本、成本口径、日历和已封存回测。抽样结果可重算；缺证据时不显示“符合预期”。
- 对账任务只读比较原账本，并产生可下载结果。它不能修复或重写生产账本。
- 页面有加载、空态、失败、键盘和 390px 行为证据。正文短而明确，内部身份和计算细节进入提示或详情。
