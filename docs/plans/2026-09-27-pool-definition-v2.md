# 池子定义 v2：写入与运行语义

**本次范围**：先把可编辑池子的权威命令、依赖和延后天数接到现有日终筛选。页面编辑、Serving 发布和入池记录在后续相邻切片接入；这一步不把 PageControl 的“已受理”误作数据代“已生效”。

**分级**：高风险。命令会改动下一次生产筛选的池子定义，且依赖关系与重复执行会影响候选结果。本文件冻结本切片的失败模型和验收标准。

## 第一性原则与边界

- 池子定义的唯一可写来源是 PageControl 管理的 `user_presets/<name>.json`；前端不能直接写文件或 DuckDB。旧 `save_user_pool`、`save_nl_preset` 继续可读可执行，新命令使用独立 `save_user_pool_v2` 种类。
- v2 定义包含规则、展示名/描述、父池 `depends_on` 和**精确**延后天数 `delay_days`。父池指向一个现存内置池或用户池；有父池时只取 T-N 交易日的父池结果，N 限于 1–252 个交易日；无父池时延后天数必须为 0。原型将“延后 2 日”解释为“2 日前的父池”，因此不能把现有 `offset_days=2`（合并 T-1 至 T-2）的旧回看窗口冒充精确延后。旧命令、内置池和旧 JSON 的 `offset_days` 行为保持兼容，运行模型要显式区分两种语义。
- 保存时以已知文件版本为前提，检查依赖存在、自引用与跨用户池的环。拒绝后保留旧定义；命令 `command_id` 幂等重试只能得到同一结果，不能用相同 ID 换载荷。规则必须能由现有积木注册表编译。
- 保存文件后，PageControl 回执仅表示该命令已经写入权威定义。日终筛选重载该定义并产出结果才算计算生效；Serving 发布相同定义版本后，网页才可显示“已生效”。

## 资产、边界和失败路径

| 资产或边界 | 失败路径 | 必须保持的不变量 |
|---|---|---|
| 用户池定义文件 | 两个编辑者基于同一旧版覆盖、进程半途退出、重试重复写入 | 乐观版本不匹配拒绝；原子替换；同一命令重试恢复同一文件效果 |
| 日终筛选结果 | 父池不存在、自引用、A→B→A、非法延后值、错误规则、把 T-1..T-N 误作 T-N | 保存前拒绝；加载时不把坏定义变成有效规则；v2 仅用精确父池日，旧池维持原窗口；未影响的旧池可继续执行 |
| 画布和网页 | PageControl 已写入但 Serving 未发布，或发布了旧定义 | 分开“已受理”和“已生效”；不能用浏览器本地状态冒充发布证据 |
| 既有命令 | 旧版 JSON 缺少新字段、旧命令继续保存 | 旧定义默认无依赖和零延后；旧命令保持原语义与审计恢复路径 |

**本次排除**：不修改线上数据库、systemd/nginx/FRP、部署器和运行中的服务；不停止 Streamlit；不实现自然语言解析、入池价、前端可视化编辑或多父池。用户可见保存闭环须等后续 Serving 与 React 切片一并验收。

## 可执行验收

1. 红测覆盖：新建/更新时版本匹配与冲突；缺失父池、自引用、两/三级环、非法延后天数、未知规则均拒绝且旧文件字节不变；同一命令在原子写后中断并恢复不会改写第二次。
2. 兼容测试覆盖旧 `save_user_pool`、`save_nl_preset` 与旧 JSON 仍加载；v2 定义重载后，真实日终筛选只按精确 T-N 交易日的父池命中作为白名单，T-1 的额外命中不能混入 T-2 的结果；旧 `offset_days` 回看窗口不变，多级依赖得到稳定拓扑顺序。
3. 聚焦运行 PageControl、preset 和 pipeline 相关测试及 Ruff；变更到共享契约时补足直接受影响的验收。最终候选由独立审查者一次集中检查本文件的不变量。
