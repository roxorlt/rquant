# 盯盘页推送通道状态：第一片

**范围与分级：普通任务。** 这次只把原型的两张推送通道卡接到已有旧通知记录；跨只读网页 API 与 React，但不写生产状态、不发送消息、不修改推送模式。基线为 `f75405d5`。C12.3 的测试推送、精确重试次数和新运行时通道统计另按真实来源接通，不能在这一片用旧记录推算。

## 行为与数据口径

- 新增只读 `GET /api/v1/monitor/channels`，从**一次借用的 Serving 数据代**读取 `legacy_notification_status` 和 `legacy_notification`。它独立于信号时间线：即使信号源暂不可用，也应准确显示已经发布的旧通知记录状态。API 使用已有 Pydantic→OpenAPI→TypeScript 合同链。
- 只展示 PushDeer、PushPlus 的中文用户可读名称。记录中的 `submitted` 表示通知接口是否接受提交，**不表示手机收到**。只统计截至本次请求时刻的上海自然日「今日」和含今天的最近 7 个上海自然日；百分比以最近 7 日成功提交数 / 提交尝试数计算。零次尝试时百分比为未知。最近成功时间只从已发布的 30 日窗口内取，不编造更早历史。
- 状态表缺失、标记 unavailable/partial、记录表缺失、坏行或 Serving 数据代不可用时，整块显示「推送记录暂无法核对」和稍后刷新入口；不显示看似精确的 0 或 100%。完整来源中真实零次提交才显示「近 7 日无提交记录」。API 不向页面传目标设备、凭据或原始错误。
- 页面在盯盘页时间线之前放两张紧凑卡片；每张只放今日提交成功数、近 7 日提交成功率和最近成功时间。解释「提交成功不等于手机送达」放提示。数据代更换或请求失败时先清旧卡片，不沿用上一代数值。桌面、390px、触屏和键盘可读。

## 实施

1. 在 `src/rquant/web/models/monitor.py` 增加有类型的通道统计模型；在 `src/rquant/web/routes/monitor.py` 增加独立只读路由与聚合。复用 `readers.table_states`、`serving_meta` 和现有标签，不重复解析原始 JSONL。
2. 从后端模型重新生成 `web/src/api/openapi.json`、`schema.d.ts`；在 `web/src/api/endpoints.ts` 增加查询封装。`web/src/pages/monitor/` 展示真实状态与加载、缺失、失败、换代状态；不加假的测试推送按钮。
3. 聚焦验证：完整来源中两个通道、今日与 7 日上海时区边界、成功/失败与真实零、来源不完整、信号源缺失、换代；前端文案、缺失态和窄屏。运行相关 Python/Web 测试、类型与产物检查、目标浏览器路径、Ruff 和 diff 检查。最终候选仅做一次独立范围内审查。

**完成边界：** 本地页面能从真实形状的已发布通知记录展示提交状态。C12.3 仍未完成测试推送、重试来源、新运行时通道状态、生产数据代与切流。
