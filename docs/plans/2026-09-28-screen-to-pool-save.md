# 选股结果保存为每日池子：设计与实施计划

> 来源：CC 可点击原型的「选股器 → 保存为池子」和新前端计划 v2 §4.4、§4.17。该按钮最终要保存可继续运行的筛选与排名定义，而非只保存当前股票名单。

**目标：**用户在选股器核对最新结果后，给条件命名并保存为自建池子；下一个日终运行沿用相同筛选、加权排名和前 N 规则，池子画布能读取、编辑且不会丢失排名。

**架构：**选股器只组装与展示规则；PageControl 接受有类型、可审计的定义命令；日终流水线复用 `rquant.screen` 的规则编译与纯排名函数；Serving 从命令和结果回执发布定义与成员；React 从同代读回保存状态。网页进程不接触主库或自写定义文件。

**技术：**Python/Pydantic、DuckDB 日终写者、PageControl、Serving 固定数据代、React/TypeScript。旧 `save_user_pool_v2` 的模型、序列化和哈希保持原样；带排名的池子走新 `save_user_pool_v3` 命令。原型按钮仍保存到同一类自建池子，命令版本仅为内部契约。

## 决策依据

这是高风险任务：保存的定义会改变每日池子成员及依赖池结果，属于生产数据完整性与共享契约。快照边界为本计划创建时的 `a44efce05e187b700e899fc8756b42a477239284`；实现、审查限于下述定义、日终、Serving、网页编辑/选股及直接依赖。

比较过三种做法：只存筛选条件会让页面排名和日终池成员不一致；只存当前名单无法每天重算；持久化完整定义并在日终复用同一排名算法，才符合原型里的「条件 + 排名」语义。选择第三种。v2 计划中「保存为池子」仍是 PageControl 普通操作；v3 只在有排名时使用，旧 v2 命令完全不变。

## 风险模型与不变量

- **资产和边界：**浏览器请求不可信；PageControl 定义文件与命令审计是写入权威；DuckDB 的 `screen_result` 与 `screen_run_receipt` 是日终结果权威；Serving 只读发布，不能代写主库。
- **失败路径：**伪造指标/权重、重放或失联命令、编辑时静默丢失排名、日终缺指标却按股票代码凑满前 N、黑名单在截取前后口径不一、同一日部分写入、旧定义或旧 Serving 代误当新结果。
- **必须保持：**规则和排名在写前按同一目录/数值边界校验；排名只对已确认筛选且风险过滤后的候选计算；缺失指标遵守现有排名规则，全部无可信数据时明确失败；前 N 成员与现有成员/价格回执同事务；旧 v2 命令哈希、恢复与定义路径不变；网页编辑/复制既要显示也要保留排名，不能隐式删除；提交后的读回区分命令成功、定义已发布和日终结果已刷新。
- **可信结果边界：**本片持久发布排名定义与经现有回执证明的前 N 成员；排名分数和名次只参与运行时计算与合成验证，不写入供页面/回测消费的可信结果，也不在池子成员页声称已发布。日后需要按分数回测或展示历史排名时，单独扩展持久结果字段、回执摘要和 Serving 同代复核后才启用。
- **明确排除：**本片不部署、不迁移生产库、不停 Streamlit、不接实盘下单，不把当前页结果直接冒充日终权威结果。盘中条件、财务条件和自定义 RSI 若尚不能由日终写者按相同可见时点复现，保存时给中文说明并阻止；后续专片打通后解除限制，仍在最终目标内。

## 验收

1. 当前 Replica 选股来源也提供同身份、同日期的 20 日复权涨幅目录和运行列；默认原型式「基础条件 + 20 日涨幅/换手率/流通市值排名 + 前 N」可预览并保存。次日日终用合成完整 21 个交易日和复权价得到与手算一致的运行时名次、分数及持久成员；并列、缺值、黑名单、零命中、旧定义有定向证据。成员页不把未封存的名次/分数当成可信历史显示。
2. 保存请求带最新成功筛选的条件快照；条件、来源或日期改变时禁用保存并提示重跑。名称可编辑，错误、失联续查和保存成功各有明确反馈；桌面、390px 和键盘可用，正文无内部代号。
3. 池子画布能看到排名摘要和定义版本状态；从池子编辑保存不会删除原有排名。未发布或日终尚未执行时明确提示，不编造当前结果。
4. 不兼容条件不会形成一个表面成功但日终无法复现的池子。非法排名、失联重试及版本冲突无法绕过 PageControl 校验；旧 v2 的排队、处理中恢复、已完成重试和发布身份不受 v3 影响。
5. 相关 Python 与 Web 聚焦测试、OpenAPI 生成物、前端构建与产物校验通过；候选浏览器走一次实际保存或受控合成命令流。最终候选接受一次独立范围内审查；只复核阻断项。

## 实施顺序

1. **定义与日终核心：**在 `src/rquant/page_control.py`、`src/rquant/presets.py`、`src/rquant/builtin_presets.py`、`src/rquant/pipeline.py` 和直接相关测试中新增 v3 排名定义；保留旧 v2 模型原样。抽出可复用的 20 日复权涨幅取数；日终先风险过滤再排名，持久写入前 N 成员及原有成员/价格回执，不把运行时名次/分数写进可发布事实。旧定义和在途命令恢复回归保持不变。
2. **同来源预览与发布：**在 `src/rquant/web/screen_service.py` 的 Replica 目录/运行接入同日期 20 日复权涨幅，保持来源身份和 21 个开市日完整性验证，不回退另一来源。扩展 `src/rquant/pool_definition_projection.py`、`src/rquant/serving_read_models.py`、`src/rquant/web/models/pool_editor.py`、`src/rquant/web/pool_editor_read.py` 及相关路由，验证 v3 审计命令与定义字段一致，发布有界排名定义；不认识的排名定义拒绝可编辑状态。重生 OpenAPI 与 TypeScript 类型。
3. **React 用户流：**在 `web/src/pages/screener/` 增加最新结果的保存对话框与持久命令续查，使用 `@/api/*` 受控接口；在 `web/src/pages/pools/` 的编辑表单显示并保留排名，保存带排名池子必须用 v3 命令，不能用 v2 隐式抹掉；完成中文错误/空态、键盘、390px。
4. **验证与收敛：**跑上述直接相关回归、生成合同、`pnpm -C web check`、`build`、`verify:dist` 和目标浏览器路径；一次独立终审。只修复本次验收的可复现阻断项，更新进度台账。生产数据与服务验证等待相应单独授权。

## 后续关联

日终尚不能复现的盘中、财务和自定义 RSI 条件按 C4.3/C4.4 的数据与时点契约继续补齐；「回测」「加入盯盘」分别走 Lab 和手动盯盘命令，不复用池子保存命令冒充完成。
