# 私有网页操作的认证身份边界

接续 [价格规则私有准入](2026-09-29-price-alert-private-admission.md)。本片先解决 nginx 认证用户进入 Web API 时的身份证明，再开放新的价格规则读写入口。代码可先本地完成；nginx、systemd、凭据安装及生产启用分别按项目规则单独授权。

**分级：高风险。** Web 的 `current_user()` 目前仅取 `X-Rquant-User`。普通回环 TCP 可被本机进程直连；即使改用私有 Web socket，现有共享 `www` 组也不足以证明请求确实经过 nginx Basic Auth。伪造该头可能读取或修改另一人的名单、确认和价格规则。

## 方案与选择

1. **只靠 loopback 或 Unix socket 权限**：改动小，但同机进程可直连 TCP；共享 `www` 身份的其他进程可访问 socket。不能证明用户身份，排除。
2. **Web 再验证一次 Basic Auth**：能独立证明用户，却需要 Web 读取密码哈希、实现并长期维护 nginx 的哈希算法与账号配置。两层认证容易漂移，排除。
3. **受信代理凭据（选择）**：nginx 在同一个受 Basic Auth 保护的 `/app/api/` 位置覆写用户头和一个随机代理凭据头；Web 从独立的只读运行时凭据文件取得预期值，对每个用身份判断权限的请求做定时安全比较，再接纳用户头。凭据不进仓库、URL、日志、页面或 `.env`。Web 只依赖一个窄的“代理已认证”证明，PageControl 仍只依赖 Web 的专用内核 UID。此方案的生产前提是代理运行身份和凭据均与其他本机服务隔离；当前共享 `www` 身份不满足前提，不能启用私有身份能力。

## 冻结边界与失败模型

- **资产与主体**：浏览器和本机其他进程均不受信；nginx 完成 Basic Auth 并覆写两头；Web 验证代理凭据后才产生 authenticated owner；PageControl 只信专用 Web UID，不直接接触代理凭据。Web 的运行 UID、PageControl UID、处理 `/app/api/` 的 nginx worker UID 均须专用且互不共享，不能与其他应用进程共用。代理凭据所在文件及每层父目录均须由 root 控制，文件最多 `0640`，可读组仅限专用代理身份；Web 通过另一份 `0400` 只读运行时凭据取得同值。任何其他本机 UID/GID 均不得读取凭据、访问代理进程内存或在其身份下运行。当前共享 `www` worker 和组不满足此条件；即使 socket 是 `0660`，也不得启用。
- **准入规则**：所有用 `current_user()` 产生身份、过滤私有数据或判断权限的路由共用一个受信身份依赖；先盘点实际调用点，逐个归类为公开、私有读或受保护写，并记录归类。请求必须经显式启用的私有 Web ingress，且原始 ASGI headers 中恰有一个合法用户头和一个有界代理凭据头；重复、空值、坏编码、错凭据、配置缺失均拒绝并不得产生 owner。公开且完全不用身份作门禁的只读路由可保持现有行为，但任何用户专属数据、管理员能力与写命令不能降级为仅凭用户头。Web 不从 JSON、query、cookie 或 `X-Forwarded-*` 取 owner。常量时间比较只比较固定长度的高熵凭据。既有 CSRF、同源和业务 CAS 是额外条件，不替代身份校验。
- **启动与轮换**：私有身份能力默认关闭；只允许显式绝对路径的只读凭据文件，拒绝符号链接、过宽权限和空/短值。凭据缺失或权限异常时，私有身份能力不可用，不回退 loopback 或裸用户头。轮换采用有界的明确重启/版本切换，避免同时接受无限旧凭据。生产凭据生成和安装另行授权。
- **部署不变量**：实现和测试阶段不改变 `deploy/nginx`、`deploy/systemd`、sudoers、真实凭据或生产库。未来启用前须静态和 Linux 实机验证 nginx 同一受保护位置覆写两头、专用 worker UID/GID 只运行该代理、其他本机进程无法读取代理配置/凭据或进入该身份、Web 只监听受控入口、两份凭据文件及父目录权限、不同 UID 的 PageControl 通道、默认拒绝的直连请求。任一条件无法证明就保持私有身份能力关闭，不以共享 `www` 组或本机 loopback 代替证明。旧版 Streamlit 和通知链不随本片切换。

## 验收

1. 用实际本机 Web 入站 socket 与合成高熵凭据，证明正确认证代理请求可以取得身份；直接连接并伪造用户头、错/缺代理凭据、重复头、坏编码、未启用配置均拒绝。其他用户的私有 GET 和 POST 不能借伪造身份访问；拒绝不写 PageControl。
2. 完整盘点 `current_user()` 的调用路由并用一份可复核清单分类；名单、确认、池子编辑、公式任务与保存、回补/审计命令、管理员日志、任务操作及其余任何以用户为过滤或权限条件的 GET/POST 都须共用受信身份依赖。逐类验证缺少有效代理证明时无法读取他人的内容、取得管理员能力或写入。公开且不使用身份作门禁的只读路由可保持原状。CSRF、原命令续查和失败状态保持原语义。
3. 直接相关安全/Web 回归、OpenAPI 合同和至少一个浏览器经代理的正常路径通过。Linux 实机的 nginx、专用身份和凭据交付属于生产启用门禁，不以合成测试代替。
