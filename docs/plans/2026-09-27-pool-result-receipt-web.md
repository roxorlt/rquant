# 池子结果回执：网页可信状态

**目标**：画布准确回答“这批成员是否按当前显示的规则选出”。只读网页从同一 Serving 数据代读取已核验的 `pool_definition`、`screen_run_receipt` 和成员；状态由 API 计算，React 只展示。此计划依赖 [日终回执与发布](2026-09-27-pool-result-lineage.md) 先通过最终审查。

**分级**：普通任务。这里只改只读网页合同和页面行为，不新增生产写入、权限或基础设施路径。验收重点是结果归因；若上游回执发布契约变化，先同步本计划的字段和状态，再编码。

## 数据与状态

- 现有池子列表仍可在旧 Serving 代查看。`screen_run_receipt` 缺表、旧结果无回执、校验不可信或成员与回执不一致时，成员可以按原有来源展示，但结果版本显示“待确认”，不得归因于当前规则。
- `pool_definition` 只证明规则已发布。回执必须来自同一借用代、通过发布端的成员数/集合摘要校验，且 `definition_version` 与该池已发布规则版本完全一致，才可说“结果已按当前规则更新”。版本不同则显示“规则已更新，等待下次选股”；不能用保存回执、时间接近或同代存在两表代替版本比较。
- 回执记录当天零命中时，该池显示“今天没有符合条件的股票”，成员数为 0；不得沿用上一日成员。只有其他池运行的全局最新日期不能证明本池已运行，本池日期须取本池自己的可信回执。
- 父池日期/版本不完整时保留“结果版本待确认”，不画虚构的逐条件人数或成员来源。真正可信的旧日结果可以显示其具体交易日，并与当日未运行区分。
- API 只返回 UI 必需的状态、日期、计数及安全标签，版本摘要和技术键仅用于后台比较或提示/详情；页面正文不用哈希、服务代号、数据代编号。状态和文案要能在 390px 与键盘列表中读懂。

## 验收

1. 合成 Serving 代覆盖版本相同/不同、零命中、其他池今日运行而本池旧日运行、旧库无回执、回执校验失败、缺定义、父谱系不全及跨代切换；API 响应来自单次借用且有界，Pydantic→OpenAPI→TypeScript 一致。
2. 画布节点、详情和等价列表显示一致的规则与结果状态；保存后仅“规则已发布”，版本匹配才显示“结果已按当前规则更新”。零命中和未运行不同；旧成员不被冒充新规则的结果。桌面、390px、键盘、加载/空态/错误经聚焦组件与浏览器路径验证。
3. 聚焦 Python、前端检查、构建、`web/dist` 校验通过；最终候选做一次独立审查。本切片不修改生产配置或数据库，不切流、不停止 Streamlit。
