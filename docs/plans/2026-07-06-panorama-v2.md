# 盘中市场全景 v2：屏效 + 性能 + 合表联动 + 个股图表

**日期**：2026-07-06　**分支**：feat/panorama-v2　**执行**：Opus 4.8 subagent（coding）/ Fable 5（规划·测试设计·验收）

## 需求（用户原话映射）

| # | 需求 | 方案 |
|---|------|------|
| P1 | 布局浪费空间，减少滑动/切 tab | 单屏两栏布局 + CSS 压缩 + 消灭 tab |
| P2 | 切选项/查询等待太久 | 聚合结果缓存（键=快照时间戳）+ 消重复聚合 + 排序走客户端 |
| P3 | 资金流/成交额/涨停数合一张表 | `build_board_overview` 一表全列，列头点击排序 |
| P4 | 板块下钻与总表选中行联动 | `st.dataframe` 行选择事件 → 下钻 |
| P5 | 个股分时/5日/日K级联 | 下钻行选择 → 图表区（segmented_control 切周期） |

## 现状根因（P2 性能）

1. `aggregate_board_amount` / `aggregate_board_limit_ups` / `board_constituents` **零缓存**，任何控件交互→fragment 整体 rerun→全部重算；
2. 涨停排行 3 个 tab **急加载**（Streamlit tabs 不懒渲染）= 每轮 3 次全市场聚合；
3. 成交额排行与下钻**重复**同一聚合（各算一次）；
4. 快照 TTL 30s < fragment 60s，交互常撞缓存过期 → 阻塞在 sina 全市场拉取（数秒）；
5. 排序 radio 触发整页 rerun（本可零成本客户端排序）。

## 架构方案

### 数据层（src/rquant/panorama_data.py，新增/改造）

**A1. 资金流保留板块码**：`_normalize_em_flow` 保留 `f12` 为 `board_code`
（东财 BK 码；`f"{f12}.DC" == dc_board.ts_code` 可精确 join）。ths 兜底路由无码
→ `board_code=None`，join 降级 board_name。

**A2. 合并总表构建器**（pinned 签名）：

```python
BOARD_SYSTEMS = ("东财行业", "东财概念", "开盘啦题材")

def build_board_overview(
    snapshot: pd.DataFrame,        # add_limit_prices 后的快照
    members: pd.DataFrame,         # load_board_members 输出
    kpl_members: pd.DataFrame,     # load_kpl_concept_members 输出
    flow: pd.DataFrame,            # fetch_sector_fund_flow 输出（对应体系；kpl 传空表）
    system: str,                   # BOARD_SYSTEMS 之一
) -> pd.DataFrame:
    """列：board_code, board_name, amount(元), main_net_amount(元|NaN),
    main_net_rate(%|NaN), pct_chg_median(%), limit_up_count, broken_count,
    stock_count, limit_up_ratio_pct, leading_stock(str|None)。
    默认按 amount 降序。涨停数为 0 的板块也保留（成交额仍有意义）。
    资金流 join：东财路由优先 board_code 精确 join（f12+'.DC'），
    ths 路由按 board_name；kpl 体系资金流列全 NaN。
    快照或成分为空 → 空 DataFrame。"""
```

涨停/炸板判定复用 `aggregate_board_limit_ups` 同口径（price_tol=0.01），不另造。
内部实现允许复用/改造既有两个聚合函数，但**一次 merge 出全列**（不做两次大 merge）。

**A3. 个股图表数据**（pinned 签名）：

```python
def fetch_intraday_trend(ts_code: str, ndays: int = 1) -> pd.DataFrame:
    """分时/5日线。列：dt(datetime), price, avg_price(float|NaN), volume。
    路由：东财 push2his trends2 直连 → SOCKS 出口 →
    ak.stock_zh_a_minute(period='1') sina 兜底（无均价线，avg_price=NaN）。
    df.attrs['route'] ∈ {'em_direct','em_socks','sina','none'}。全失败→空表。"""

def load_daily_kline(ts_code: str, n: int = 120,
                     store: DuckDBStore | None = None) -> pd.DataFrame:
    """日K（只读副本 daily_bar 最近 n 根）。列：trade_date, open, high, low,
    close, volume, ma5, ma10, ma20（MA 就地滚动计算，不足窗口为 NaN）。
    副本不可用→空表。"""
```

东财 trends2：`https://push2his.eastmoney.com/api/qt/stock/trends2/get`，
secid=`{1|0}.{code6}`（sh=1/sz=0/bj=0），fields2 含 f51(时间) f53(价) f56(量) f58(均价)，
`ndays=1|5`、`iscca=0`。直连/SOCKS 超时与 `_em_fetch_rows` 同参。
当日 K 线补充：盘中副本缺今日 bar，UI 层用快照行 (open/high/low/price/volume) 拼一根
临时当日 bar append 到日K 尾部（仅当快照该票 open 非空且 trade_date > 副本最新日）。

**A4. Fake 模式（e2e 可测性）**：环境变量 `RQUANT_PANORAMA_FAKE=1` 时，
`fetch_market_snapshot` / `fetch_sector_fund_flow` / `load_board_members` /
`load_kpl_concept_members` / `load_pool_flags` / `load_liquidity_baseline` /
`fetch_intraday_trend` / `load_daily_kline` 全部返回**确定性 fixture**（模块内
`_fake_*` 函数，seed 固定）：
- 快照 ≥30 只票、跨 3 个板块，含 ≥2 只涨停（price==limit_up_price）、1 只炸板；
- 东财成分含行业+概念两个 idx_type；kpl 成分含板块名「人形机器人」（≥5 只成分）；
- 资金流含与成分板块可 join 的行（board_code 精确 join 路径被覆盖）；
- 分时 240 根、5日 1200 根、日K 120 根，数值平滑可画图。
fake 分支放在各函数入口（`if _fake_enabled(): return _fake_xxx()`），不碰真实路径。

### UI 层（src/rquant/dashboard/market_panorama.py 重写）

**B1. 缓存矩阵**（全部 `st.cache_data`，大 DataFrame 不做缓存函数入参——以
`as_of` 时间戳字符串作键，函数内部再调上游缓存函数取数）：

| 函数 | 键 | TTL |
|---|---|---|
| cached_snapshot | — | **60**（对齐 fragment，消除交互撞过期） |
| cached_fund_flow | sector_type | 60 |
| cached_members / kpl / pool / liquidity | — | 300 |
| **cached_overview** | (system, as_of) | 120 |
| **cached_constituents** | (board_code, as_of) | 120 |
| **cached_trend** | (ts_code, ndays) | 60 |
| **cached_kline** | ts_code | 600 |

**B2. 布局**（单屏，1440×900 基准）：

```
┌ 脉搏行：5 个紧凑 metric + 涨/跌家数 ─ sparkline 收进 st.popover("📈") ┐
├───────────────────────┬──────────────────────────────┤
│ 板块总表 (52%)          │ 板块下钻 (48%)                 │
│ 体系 segmented_control  │ 「{板块名}」成分 · 强度分默认序    │
│ 一张 dataframe          │ dataframe h≈250 行选择→图表     │
│ h≈560 列头排序 行选择    ├──────────────────────────────┤
│                        │ 个股图表 {名称}                 │
│                        │ 分时|5日|日K segmented_control  │
│                        │ altair 图 h≈300                │
└───────────────────────┴──────────────────────────────┘
```

- 全局 CSS：`.block-container{padding-top:1.2rem;padding-bottom:0.5rem}`、
  metric 字号压缩、`st.subheader` 全部换 `st.markdown("**…**")` 小标题；
- st.divider 全删；标题区与"立即刷新"按钮同行（columns）；
- 60s `st.fragment` 自动刷新保留。

**B3. 联动逻辑**：
- 总表 `st.dataframe(key="board_tbl", on_select="rerun", selection_mode="single-row",
  hide_index=True)`；选中行→`board_code`（注意：selection.rows 是**传入 df 的位置索引**，
  客户端排序不影响该索引语义——用 `df.iloc[idx]` 取）；未选中→默认第一行（成交额最大）。
- 下钻表同款 single-row 选择→`ts_code`→图表区；未选中→提示「点选个股查看图表」。
- 体系切换后 board 选择自动失效回退默认（board_code 不在新体系内时）。
- 显示列（总表）：板块 | 成交额(亿) | 净流入(亿) | 净流率% | 涨跌中位% | 涨停 | 炸板 |
  占比% | 成分数 | 主力流入最大股；kpl 体系隐藏资金流三列。
- 下钻列沿用现状（代码/名称/现价/涨幅%/成交额(亿)/强度分/换手强度/相对放量/涨停/池内）。

**B4. 图表（altair）**：
- 分时/5日：价格线 + 均价虚线（有则画）+ 底部量柱（独立 y 轴，`alt.vconcat` 或
  layer+resolve）；5日在 x 轴按日分隔；
- 日K：`rule`(high-low) + `bar`(open-close)，**红涨绿跌**（A 股口径），MA5/10/20 线，
  底部量柱；当日临时 bar 拼接见 A3；
- 空数据→`st.info` 灰态提示（不炸）。
