# 模拟盘和组合风控：实现方案

## 目标和范围

完成 v2 的 C9.1–C9.4、C10.1–C10.3。页面按原型提供目标仓位、回撤限制、行业暴露、账户详情、逐日净值、完整指令历史、回测区间对照、只读对账和暂停。模拟盘继续只做模拟成交。

本项是高风险任务：新增控制影响模拟账本的订单准入，涉及账户归属、顺序、重复执行和重启恢复。审查只覆盖这些新增边界及直接改动。已有撮合、费用、T+1、账本签名和纯计算不重新设计。

需求来源是 CC 的 `frontend-plan-v2.md` 第 4.9、4.10 节、差距表及原型模拟盘页。现有入口及已核实缺口见 `2026-10-05-paper-portfolio-remaining-entrypoints.md`。

## 复用和职责

- 仓位继续调用 `allocate_target_weights()`；回撤继续调用 `evaluate_drawdown()`；行业计算继续调用 `calculate_industry_exposure()`、`attribute_brinson_fachler()`。
- 原 `PaperBrokerStore` 负责资金、订单、成交、T+1 和费用。新增准备逻辑只产生有来源的目标与数量，不写另一套账本。
- 原信号总线、路由、消费游标和队列继续负责一次处理及恢复。新模式通过可选的有类型依赖接入；未启用时保持旧行为。
- 原 PageControl 负责命令身份、用户核验、顺序和原请求恢复。控制文件只传递已确认的操作，不替代命令日志。
- 只读 Serving 发布同一代账户、历史、净值、暴露、区间和已应用控制事实。Web 不直连模拟主账本。
- 原 Lab 运行 `paper_reconcile` 和收盘后的区间研究。对账只读，不能修复或重写账本。

## 资产、来源和排除项

保护账户资金、原订单身份、信号游标、精确策略版本、成本口径、控制序号和每日净值来源。浏览器只能提供受限规则、已展示账户及期望版本；不能提供可信 owner、路径、撮合结果或“已应用”标志。

用户和账户归属来自原已核验身份及受信账户目录。运行时角色、账户、策略版本和账本来源来自精确 manifest 与原登记事实。未知账户、角色或版本在副作用前拒绝。控制路径只能从受信目录构造。

本项先在私有临时数据中完成代码和验收。生产安装、运行时切流、现有生产账本变更及 Streamlit 停用继续按既有单独授权执行。它们不能由测试或普通代码发布代替。

## 仓位和回撤合同

1. 账户配置固定原仓位模型及可选回撤模型，绑定精确策略版本和成本版本。配置变更形成新版本；旧指令和结果保留原版本。最多持股数沿用模板上限 500。
2. 目标输入包含决策前可用的完整候选、排名分、申万一级行业、当前资金、已有持仓及估值。行业上限开启时不能将缺行业的股票归入虚构行业。缺必要材料时拒绝本次新入场，保留可核实的退出路径。
3. 先用原纯函数计算连续目标，再按原价格、费用和 100 股整数手向下取整。实际买入不得突破资金、现金保留、单票、行业或总风险上限；剩余资金保留为现金。约束无解时给出原因，不换成固定 100 股。
4. `prepare` 和 `refresh_prepared` 两条路径必须使用同一有类型数量依据。依据绑定账户、原信号、配置版本、决策时点、原资金与持仓来源、目标摘要和报价。不能接受调用者裸数量作为可信目标。
5. 原退出数量依据继续有效。减仓及退出受原可卖数量、T+1、停牌和涨跌停约束。不能为了达到目标伪造成交。
6. 回撤前态持久保存，绑定同一账户、配置和净值序列。重复观测返回原结果，倒序或同刻异值拒绝。配置改变须明确开启新序列或按原历史重算，不能沿用不同规则的峰值。
7. 回撤触发后按原模型停止开新仓或降低总风险仓位。需降仓时产生可追踪的原模拟指令；被交易约束阻止时显示未完成，不能先宣布已降至目标。退出和减仓不被回撤限制拦截。

## 操作员控制合同

新增 `set_paper_account_paused`，复用原命令网关、已核验身份和 CSRF。暂停采用两步确认；恢复也核对当前账户、配置及控制序号。原请求先 lookup，再检查新鲜度与期望状态。

控制文件采用 v2 要求的 `data/runtime/control/operator/<role>.json`。每个文件只作用于该角色 manifest 固定的账户。正文有固定合同版本、角色、账户、精确配置、递增序号、原命令摘要和期望暂停状态。正文有界，拒绝额外字段、未知版本、链接、替换后的来源和损坏内容。

PageControl 先持久确认操作，再按原安全文件发布方式原子更新控制文件；中断后只恢复原正文。文件不是“已应用”回执。角色每轮验证控制，并将同一序号和摘要写入实际应用事实及心跳。页面区分“等待应用”“已暂停”“运行中”和不可用。

实际应用的暂停只阻止新开仓。角色继续消费并终结被暂停拒绝的买入信号，继续执行减仓及退出；恢复后不补买这些信号。暂停前已准备但尚未提交的买单，在真正提交前也须核对当前准入。已提交订单沿用原恢复路径，不创建第二笔订单。

新模式不能直接复用原 `settings.paused` 的提前返回：它会阻断退出。原硬停止配置和旧默认保持。启用新控制后，缺失、损坏、倒序或账户不符的控制不能默认为恢复；新入场保持关闭，仍使用可核实的原退出路径。

应用事实与订单准入有明确顺序。只有实际关闭新入场后才能发布“已暂停”。重启须保留已应用序号，不能接受更旧文件回滚。并发命令核对同一前序，最多一项成功；未知回执保留原命令身份供恢复。

## 净值、历史和行业视图

- 每日净值绑定账户、交易日、精确策略与成本、原账本序号，以及决策前可用的收盘估值与交易状态。缺材料时发布缺口，不以最近成交价冒充收盘价，不补零或倒推旧资产。
- 净值、收益、最大回撤和运行天数来自同一已核实序列。交易日按原日历计数。页面继续展示已有资金、持仓及拒单原因。
- 完整历史按原不可变序号分页，每页最多 200 条。游标绑定账户和 Serving 代次；换账户或代次须重新开始。覆盖范围和未发布记录有明确状态，不能把最近窗口称为全部历史。
- 行业暴露使用有来源的持仓及同期基准行业权重。归因采用原 BF 形式、无交互项、现金单列。缺行业、基准或期间收益时显示原因，不能补估计贡献。
- 现有旧账户 API、近期历史和关闭证据保持原合同。新增视图不扩大旧窗口或改变旧返回正文。

## 回测区间和对账

区间只使用该账户精确策略版本、成本和日历的已封存回测日收益。使用固定 seed 的有放回日收益抽样，生成与模拟交易日数相同的路径，计算逐日 5% 和 95% 分位。算法、seed、路径数、输入摘要和分位规则全部进入可复算产物；不能从当前模拟净值调节区间。

首次合同固定 2,048 条路径，最多 2,520 个交易日；输入与工作集须在既有研究任务预算内预检。缺对应回测、非有限收益、错误成本、日期对不齐或超界时拒绝。区间内只标“在区间内”，区间外标“需要关注”。提示说明这是回测抽样对照，不能证明未来结果或自动晋级。

`paper_reconcile` 通过原 Lab 只读核对同一账本序号的资金、持仓、订单及成交，封存差异与来源。无差异有实际结果后才显示完成；未知、未运行或缺输入不能显示“一致”。下载复用原可信产物读取，不能接受浏览器文件路径。

## 失败模型和验收

| ID | 必须证明的行为 |
|---|---|
| PP-01 | 无效规则、非有限数、未知账户、他人账户、错版本和任意路径均在副作用前拒绝。 |
| PP-02 | 等权、排名权重及所有上限同时生效；手算参考一致；约束无解有明确失败。 |
| PP-03 | 目标数量的首次准备和刷新一致；费用、整手、现金及已有持仓共同约束；原重复信号不重复交易。 |
| PP-04 | 原回撤边界、恢复边界和重启前态一致；限制只阻止新入场，原合法退出继续。 |
| PP-05 | 原命令恢复不重复控制；并发前序最多一个成功；发布中断恢复原序号和摘要。 |
| PP-06 | 真实角色应用前显示等待；应用后新买入及未提交买单被阻止，减仓和退出继续；恢复不补买。 |
| PP-07 | 错角色、倒序、损坏、缺文件和来源替换不能恢复买入；重启不回滚已应用控制。 |
| PP-08 | 净值、行业暴露和 BF 归因绑定同一账本与材料；缺输入不补假值；原小样例和独立参考一致。 |
| PP-09 | 超过 200 条的真实历史可完整分页；账户与代次变化不能混读，旧窗口合同保持。 |
| PP-10 | 固定分布、固定 seed 和边界参考可重算 5%–95% 区间；错版本、成本、日历或无回测拒绝。 |
| PP-11 | 原 Lab 实际完成只读对账和产物下载；差异如实展示，账本字节不被修改。 |
| PP-12 | 原实际信号、队列、撮合、控制、权威发布及私有 API 连成一条路径；实际应用状态与同序号回执一致。 |
| PP-13 | 1440px、390px、键盘、两步确认、未知回执恢复、换用户、换代次及加载/空态/失败有真实行为证据。 |

高风险红测集中覆盖 PP-01、PP-03–PP-07、PP-09 和 PP-12；原纯计算的有效证据继续使用。新增研究统计有独立参考；容量边界只运行一次，实际失败或来源变化时才补测。
