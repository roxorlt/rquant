# 数据审计报告与页面接线

对应 v2 C1.2。现有数据中心能查看旧 `data_audit_run` 的尝试和问题；新日线月度覆盖与单日质量规则已有同副本取证函数，但还没有任务报告、发布表或页面结果。本片要把这些证据接成可追溯的研究报告，再作为有界只读数据发布。它不执行回补，也不以空问题列表表示健康。

**分级：高风险。** 报告会成为跨任务、Serving 与页面共享的健康判断；错误的完成标记或零异常可能掩盖数据缺口。实施前冻结下列失败模型；每个可独立合入的候选只在最终版本做一次独立审查，定向修复按根 `AGENTS.md` 的高风险上限处理。

## 资产与信任边界

- 资产：固定的只读副本及其身份、明确完成的 SSE 交易日、交易日历、日线与停牌证据、月度覆盖/质量结果、不可变报告、Serving 数据代和页面状态。
- 研究任务只接受已由调用方固定并核验的只读连接、不可变副本身份、审计区间和采集完成凭据；不得由系统时钟猜测「今日已完成」。现有 `DailyPipelineRunReport` 只有 `run_id`、日期及回执 ID，不能单独证明原始来源或已写入的副本。生产凭据必须以 `run_id` 联结并核验同一生产 namespace/profile 的成功 `DailyRunRecord`、其 `DailyRunSpec` 的原始 `source_generation_id`/`source_content_hash`、完整阶段回执，以及与该 run 绑定的日线入库提交凭据。入库凭据须由权威写者在提交后产生，至少绑定交易日、run、源身份与已提交内容身份；没有这条桥接时只能写「采集完成未确认」。`shadow`/开发测试身份、旧 legacy daily timer 的“运行成功”或表内有行均不得冒充生产完成。
- 同一只读连接须核验副本生成元数据与入库凭据，取得由副本生产者封存的不可变 `replica_generation_id`；审计前后重新核对固定连接对应的文件与生成身份。该身份是实际 DuckDB 副本的身份，**不得**把原始行情 `source_generation_id` 或任意调用方字符串直接当成副本身份。Serving 使用自己的固定副本读取同一封存身份并与报告比较；若当前副本缺入库回执、生成身份或中途换代，拒绝“本次数据已审计”。现有副本元数据只有文件水位，没有贯通入库回执的身份链，因此这条桥接是实施前置工作，不是已有能力。`data_audit_evidence.py` 在固定连接取证并调用纯计算；不能混用主库、副本、不同数据代或不完整日历。
- 离线合成测试可注入显式测试凭据，但其 namespace/mode 必须与生产严格隔离，报告标记测试来源；Serving 的生产入口拒绝测试报告。若真实生产仍由旧日线任务驱动且缺同等正面凭据，允许展示已取证的历史覆盖事实，但报告与页面均保持「采集完成未确认」，不得发布当期健康结论。
- 报告拥有自己的版本化契约和内容摘要，不复用旧 Stage-1 `data_audit_run` 的完成状态，不直接写生产主库。研究任务以临时文件写入、校验后原子发布；失败不得覆盖上一份成功报告。正式任务调度、生产目录权限及数据库写入另行授权。
- Serving 仅从显式配置的有界报告产物读取，验证契约、大小、摘要、审计范围和源身份后纳入新数据代；旧数据代无报告表时返回「尚未发布」。网页 API 从一次借用的 Serving 数据代取报告，React 只展示其证明过的事实。

## 必须保持的不变量

1. 报告分开记录**运行状态**、**覆盖结论**与**质量规则覆盖**。每条质量规则都记录审计区间内应评估的日期集合、实际评估的日期集合、未评估日期及原因、问题总数；集合可用可验证的有界日期范围/位图表达，但数量必须可复核，不能只存最后一天。单日取证仅证明该日，跨日运行须逐日调用并汇总。日线整日有记录不等于每只股票完整；价格上下限没有独立权威来源时，越界规则为「未评估」；停牌快照缺完整凭据时零成交量规则也为「未评估」。仅最后一天零问题或只跑了部分日期，不得汇总为整段质量正常。
2. 完成日须由上述生产凭据、入库身份和报告来源副本的完整链证明，且不晚于副本所含已提交交易日；`replica_generation_id`、原始 source 身份、run/提交凭据身份、起止日、规则版本、完成日、月度分母/分子、连续缺口、休市日脏行、逐规则已评估范围、问题和未评估原因进入报告与摘要。相同输入及版本得到相同内容身份；不同来源或内容不得共用身份。
3. 报告最多覆盖现有取证函数允许的 3,660 个自然日，每日质量最多 10,000 行；发布表与 API 另设明确行数/字节上限。报告损坏、字段不完整、重复日期或摘要不匹配时整份拒绝，不静默丢掉坏行。旧成功与最新失败可同时可见，但要分别标明时间，不能把旧成功冒充当前结果。
4. Serving 用报告中的 `replica_generation_id` 与本次发布所用副本的封存身份比较，并复核生产 mode/namespace、入库提交链。全部相同时才可说「本次数据已审计」；不同只说「上次审计」并标明截止日，缺任一凭据视为未确认。相同交易日但不同副本也不得复用当前结论。
5. 页面图表和问题列表取同一报告；换代时撤掉旧图表和筛选状态，加载/空态/失败/未评估分别反馈。覆盖图可显示完整已取证区间，质量摘要必须注明各规则实际检查的日期或范围及未检查数量；只有全区间所需规则均已评估、无问题且来源链闭合才展示绿色健康。正文不显示摘要、路径、服务代号或原始错误；详情与悬停只显示对用户有用的来源时间与规则说明。

## 失败路径与验收

| 情况 | 应有结果 |
|---|---|
| 副本换代、日历缺日、完成凭据缺失、读到不同来源 | 研究任务失败或报告标未评估；不得发布完成/零缺口。 |
| 同交易日不同副本、生产报告混入测试凭据、原始行情身份误作副本身份、入库提交凭据缺失 | 生产报告不得标完成；Serving 不得标本次已审计，旧可信结果仅作上次审计。 |
| 质量事实缺独立权威涨跌停价或完整停牌快照 | 对应规则保留未评估原因；其他已证实的覆盖结果仍可展示。 |
| 仅最后一日做质量取证、区间其余日期无质量结果 | 页面明确写实际检查日期与未检查数量，整段质量状态为未评估。 |
| 任务写入中断、同名报告损坏、Serving 读取中途变更 | 上一份成功产物不被覆盖；新代拒绝坏报告并说明审计暂不可用。 |
| 新尝试失败但旧成功存在、报告与当前副本身份不同 | 显示最新失败和上次成功；旧结果不标当前健康。 |
| 30 日以上缺口、跨月、休市日脏行、问题超过首屏 | 月度分母和缺口来自完整有界报告，不从页面分页数量推断。 |

实施顺序：先做生产完成→入库提交→副本生成的身份桥接与纯报告契约，并在合成固定只读 DuckDB 上逐日完成覆盖和质量取证；再接可选 Serving 小表与 API；最后接数据中心图表、问题列表和受控任务入口。身份桥接没有真实凭据前，离线研究报告可继续开发，但一律呈现完成未确认。端到端在桌面与 390px 验证真实小库→报告→Serving→API→React，并分别验证缺凭据、测试身份混入、同日不同副本、仅末日质量检查、失败和换代。正式约 10 GB 副本的耗时、RSS、页缓存、生产调度与入口切换是独立门禁，不能用小样本代替。
