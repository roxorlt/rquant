# Serving 交易日历完整性边界（AUD-CAL-01）

## 资产与信任边界

- 资产：网页展示的交易日、市场阶段、最新已收盘日，以及审计日期选择。错误地把开市日说成休市会让监控状态和审计范围失真。
- `MarketCalendarAuthority` 是已校验哈希的 SSE 日期权威，含 `coverage_start`、`coverage_end` 和开市日集合。只读 DuckDB 是一次固定读所见的数据证据；Serving 投影和网页请求是下游，不能补猜权威没有明确给出的每日事实。
- Serving 数据代的签封证明字节未被替换，不证明投影构造时没有漏行。网页每次只借用一代并核对投影状态与行数。

## 已复现的失败路径

旧投影只列 `is_open=true` 的日期。构造阶段漏掉 2026-09-28 后，首末日期、行数与 manifest 仍可彼此一致；网页把列表中没有的 09-28 推断为休市。中秋 09-25 的真实休市与漏掉 09-28 的错误在旧形状里无法区分。

## 必须保持的不变量

1. 新投影在一个有界的自然日区间中，每日恰有一条 SSE 记录，明确记录 `is_open=true/false`，且与权威开市集合一致；超出行数或字节预算时选取最近且完整的不超过 3660 天窗口，无法安全发布则拒绝。
2. 同一次固定 DuckDB 读取若取得日历证据，覆盖内的逐日记录与权威日期集合必须一致；冲突拒绝发布。
3. 共用网页日历读取及审计日历接口只有在投影已发布、逐日连续、日期唯一且包含服务器上海今日时，才返回开市或休市及可选审计日期。旧的仅开市日数据代、内部漏行、损坏或换代一律关闭相关选择，不能把缺失当休市。
4. 审计范围不超过 3660 个自然日，结束日期不得晚于上海时钟最近已收盘交易日；同一响应的数据与 generation 标记来自同一借用代。

## 排除项与阻断边界

- 不修改生产数据库、服务配置、鉴权、审计命令提交或 React 表单；不借此重构其他 Serving 表。
- 无法证明权威覆盖内的每日事实、超出资源上限或发现来源冲突时，本片只返回不可用或拒绝发布，不回退到工作日规则或旧开市日缺席推断。
