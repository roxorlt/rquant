# 将已完成的公式筛选保存为可重算池子

## 决策与范围

公式池子保存的是**公式定义及其重算规则**，不是某日命中代码的静态名单。现有 `SaveUserPoolV2`/`user_presets` 只认识注册表 `RuleCall`；把公式硬塞成空规则或固定命中会让池子每天运行出错误结果。因此建立独立的有类型公式池子版本，并在后续读模型中明确区分规则池与公式池。用户希望保存后按已有自建池节奏逐日运行；首个保存命令只在已完成、已核验的批量任务上开放。

高风险：保存的公式、任务来源或定义版本错配，以及把历史结果冒作新日期运行，会误导后续池子、回测与盯盘。

## 分段验收

1. **定义与可信保存**：定义含名称、显示名、公式原文与语法合同版本、创建时间、来源任务 ID/结果摘要/当日来源身份、定义版本；创建证据与未来重算输入分开。PageControl 接受有界保存命令，只从可信任务库和封存文件验证成功任务及公式摘要，按全局 `user/` 名称检查现有规则池冲突，使用原命令幂等与期望版本保护原子保存。公式定义单独落盘且有可审计的版本，旧 `SaveUserPoolV2` 文件和解析器保持兼容。Web 只转发有类型命令，不得接收浏览器提供的文件路径或“命中股票名单”。
2. **逐日重算**：收盘后以新的逐日 A 股归档名单和独立历史投影执行该定义；每次结果绑定定义版本、交易日、两来源身份与完整的命中/未命中/未知计数。缺当日名单/行情、公式版本不支持、运行失败时不发布该日池子结果，也不延用前一日名单。成功结果可进入同一池子成员与入池时间/价格证据链，但未知数量须随结果展示。
3. **只读与页面**：Serving 发布定义和每日运行事实，Web 从同一数据代读取；池子列表、画布和公式运行结果中的「保存为池子」入口都指向同一定义。保存按钮只在第 1、2 段的可重算合同与真实运行路径验证后开放，失败保留当前结果并给出下一步。页面以简洁中文显示「公式池」、最近运行日和数据状态，技术来源在详情/提示中。

## 冻结失败模型

- 资产：用户池子名称、公式文本/语法版本、可信来源任务与结果、每日成员事实、定义版本。
- 边界：浏览器→Web→PageControl→私有任务与定义；离线名单/行情→重算器→封存每日结果→Serving→页面。
- 失败路径：保存未完成/损坏任务；命令重试覆写另一版本；同名规则池与公式池冲突；语法升级静默改变已保存公式；把创建日命中静态复用到新交易日；缺数据仍显示成功池子。
- 不变量：每个公式池子都保有可再次求值的定义；每个交易日成员只来自该定义某个固定版本在同日两来源上的完整成功运行；旧规则池行为不变；失败或未知不能冒充确定未命中。
- 排除：实盘下单、生产数据库迁移/写入、systemd/nginx、正式切流与停用 Streamlit。生产动作仍须单独授权。
