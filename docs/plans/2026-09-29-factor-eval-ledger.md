# 因子检验：持久任务与结果身份账本

承接已完成的 `FactorEvaluationJobSpec`、专属冻结来源执行桥和内容寻址结果产物。因子检验是研究诊断，不具备策略 `ResearchRunSpec` 所要求的成交与实验语义，因此由 Lab 拥有独立的因子任务账本；后续用统一只读投影汇入研究任务页。本片只建立可恢复的任务与同规格唯一结果索引，不开放网页提交，也不运行生产任务。

**任务分级：高风险。** 幂等写入、租约恢复和结果索引影响研究结论的完整性。冻结下面的失败模型；实现前由独立审查者核对本 SPEC，最终候选再做一次独立审查。

## 冻结失败模型

- **资产与边界**：规范 `FactorEvaluationJobSpec`、调用方命令 ID、私有 SQLite 账本及其固定文件身份、由构造/重启打开边界注入的可信 UTC 时钟、单次 worker 租约、已封存且可重读的因子产物。Web 请求和任意传入文件路径都不进入本账本；实际计算只由下一片独立 worker 调用已审查的 `run_factor_evaluation_job`。
- **失败路径**：同命令 ID 被换内容重放；两个命令提交同一规格却生成两个结果；SQLite 文件被替换或只读操作意外建库；worker 崩溃后任务永远停在运行；过期 worker 晚到覆写新租约或成功结果；调用方传入旧时刻让实际已过期的租约继续成功；产物已封存但成功事务未提交；失败或过期任务被显示为成功；伪造的完成回执绑定另一份规格、定义、来源、代码版本或结果；超限/损坏的持久行被当作可信任务。
- **必须保持**：仅显式初始化空账本，不隐式迁移或修复；`initialize()` 返回账本外保存的可信身份（实例 ID、规范绝对路径、设备与 inode），重启时 `open_existing(expected_identity, clock=...)` 必须从独立受信配置取得该身份，绝不能从当前路径的文件动态重建预期值；时钟由账本构造/重启打开边界注入，默认使用系统 UTC 时钟。预期身份丢失或文件换代时拒绝接管，恢复配置另走人工决策。所有变更使用短 SQLite `BEGIN IMMEDIATE` 事务，读写前后均按预期账本实例与文件身份拒绝换库，并在事务内取账本自身时钟；调用方不得用传入的旧时间作为租约权限凭据。命令 ID 唯一绑定规范规格摘要，规格摘要唯一绑定一条任务；相同命令与规格重放返回原任务，内容冲突拒绝。领取/续租/完成/失败都需要当前随机租约令牌，且检查期限和版本；回收过期租约只旋转令牌，不在旧令牌下完成。成功写入前按摘要重读私有产物，逐项核对规格、定义、快照 binding、代码版本、来源摘要、结果摘要和产物回执；完成事务只写一次，后续相同规格只能取得同一成功身份。封存成功但事务中断时，不删除产物；重领任务可重算并复用同一内容寻址文件。所有读取重新验证规范规格、行摘要和状态组合，损坏时拒绝，不推断成功。将内部失败归为有限原因码，后续页面给中文行动文案。
- **排除**：本片没有运行 daemon、自动心跳线程、Web/React、Serving 表、任务取消/暂停、正式研究结论或真实数据负载；不改策略 Lab 的存储或任务协议，也不创建/迁移生产 SQLite 文件。后续 worker 再处理长计算期间续租及失败记录。此账本只提供持久能力，不等于原型「运行检验」已经可点击。

## 合同与实现顺序

1. 独立 `factor/job_ledger.py`：私有 SQLite v1 账本，显式 `initialize()` 返回 `FactorLedgerIdentity`，`open_existing(expected_identity)` 强制核对账本外的可信预期身份。任务模型包含 UUID、完整规范规格、规格摘要、状态（排队/运行/成功/失败）、单调版本、尝试次数、UTC 时间、可选安全失败码及成功回执。命令表保存 `command_id → spec_sha256 → job_id`；任务表对 `spec_sha256` 唯一。读取有上限，不返回任意 SQL 或文件路径。
2. `submit(command_id, spec)` 在事务内先判同命令重放与冲突，再复用同规格任务或插入排队任务；新任务必须在规格截止前。`claim(lease_seconds)` 只领取最早的可运行任务，回收过期租约时轮换随机令牌和递增尝试数；已到规格截止的候选改为失败。`heartbeat` 只允许当前未过期租约、延长期限不超过规格截止。有限租约下不承诺计算本身中断，只保证过期执行者不能封存成功。
3. `complete(job_id, lease_token, expected_version, completion, artifact_root)` 先用已有产物读取器校验封存事实，再在同一账本事务内核对当前租约和完整规格绑定后写成功；同规格的成功身份不可覆盖。`fail` 只接受安全原因码和当前租约。`get`/有界 `list_recent` 为后续 Serving 提供类型化状态；成功结果下一片发布前还须重读产物，不能因为索引存在就相信文件仍在。
4. 保持依赖方向：账本依赖因子纯规格与产物读取器；计算 runner 不依赖账本；后续 worker 在外层编排两者。策略 Lab 引擎和 Web 不直接依赖此账本实现细节。

## 验收

- 先写失败用例：同命令异内容、双命令同规格、双 worker 竞争、租约过期旧令牌晚到、期限过期、封存后事务失败再重领、错规格/来源/结果/代码修订完成、产物缺失/损坏、进程重启前把 A 库换成同路径合法 B 库后仍持 A 的外部身份打开、运行时账本替换、状态行篡改；任一失败均不得显示成功或删除可信产物。
- 用临时私有目录和小型合成产物走提交→领取→完成→重启重读、同规格重放、一次租约回收；验证恰好一个持久成功索引、命令回执稳定、时间与状态有界。聚焦测试、Ruff、diff；不运行生产数据或无关全量测试。
- 本片通过后按顺序接独立 worker、同代结果 Serving、React 只读结果和有认证的「运行检验」入口；跟踪功能另按真实任务/指标来源接线。
