# 因子编辑：可信可检验字段目录首片

**任务分级：普通任务。** 现有 `FeatureCatalog` 能校验表达式引用的名字，但网页尚无可编辑字段目录，历史日线适配器又独立写死六个允许字段。本片只把“代码确实能从当前历史来源读取并计算什么”变成因子领域的唯一、有类型能力目录；不开放保存命令、不查询生产库，也不把源码支持误写成数据已覆盖。

## 合同

- `rquant.factor` 拥有一份冻结的 v1 日线能力目录：`open/high/low/close/vol/amount`，每列有短中文名、可读说明与稳定内部列名。目录构造现有 `FeatureCatalog`，历史适配器从同一常量核对允许列，消除两套名单漂移。目录给出当前可运行的表达式算子集合；`industry_neutralize` / `size_neutralize` 因缺历史行业、市值事实，明确标为暂不可检验，不能通过“表达式可解析”推断可运行。
- 目录只表示**实现支持**，不含“最早可用日期”“全市场已覆盖”“今天可运行”等数据事实。`FactorDefinition.earliest_available_date` 的可信来源要在后续保存入口由固定、已核验的研究来源证明；浏览器不能自报该日期或整个 `FeatureCatalog`。生产未配置因子来源时，网页不得显示这些字段已可用于正式检验。
- 从该目录生成的可运行定义须与历史适配器接受的字段/算子一致；加入分钟、竞价、VP 或行业/市值字段时，先扩展真实来源和时点合同，再扩目录版本。旧定义自带的历史 `FeatureCatalog` 保持可重读，不被当前目录静默改写。

## 验收

1. 同一字段名单与算子能力由因子领域导出，`FactorDefinition` 构造和历史适配器使用它；合成冻结来源对每个宣称可运行的字段完成求值，未知列和行业/市值上下文在执行前拒绝。旧定义和已有研究产物摘要不变。
2. 聚焦用例证明目录声明、解析器、历史适配器一致，且“代码支持”不会生成伪造的最早日期或数据覆盖率。只跑直接相关因子测试与 Ruff；最终候选一次独立范围审查。后续片再做受控 Web 保存/编辑与 UI 字段提示。
