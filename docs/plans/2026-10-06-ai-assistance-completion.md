## 2. 风险与边界

本任务为高风险任务：涉及共享调用预算、私有研究内容和封存产物完整性。范围只包括下列边界。

| 资产或边界 | 失败路径 | 不变量 |
|---|---|---|
| 私有身份与研究内容 | 伪造用户、换账号、读他人缓存 | 身份来自原私有入口；缓存和读取绑定原用户 |
| 原条件和执行命令 | 模型输出命令、路径、未知字段 | 模型不拥有身份、日期、来源、UUID 或执行权限 |
| 调用预算和用量 | 并发超额、重启丢记录、失联重调 | 调用前持久记账；同请求先查原记录；失联保留未知 |
| 回测产物 | 错数字、错结果、旧缓存 | 绑定原产物摘要；引用和数字逐项核验 |
| 公告和研报 | 错股票、错日期、伪造引用、任意 URL | 原采集事实先保存；引用必须存在；源域和读取大小受限 |

不改回测数学、原来源权限、原交易日判断或生产配置。不新增实盘下单。Linux 安装、生产入口、付费数据权益和停用 Streamlit 继续按已有授权边界处理。

## 4. 实施顺序

### 4.1 调用记录和结构化建议

新增 `src/rquant/ai_assistance_contracts.py`、`src/rquant/ai_usage.py` 和聚焦测试。用原 PageControl 所属状态记录调用，不开第二套任务队列。每日上限用配置；调用前在同一事务核验和预留。相同请求恢复先查原记录，不再次收费调用。

模型适配器返回建议和实际 usage。没有 usage、超时和断连都保留未知。所有错误转为简短中文；密钥、提示上下文和原始响应不进入页面或普通日志。

### 4.2 助手三步和池子修改

新增 `web/src/app/AiAssistantDrawer.tsx`；从 Topbar 打开。修改原网页模型适配器、增加 Pydantic DTO 和 API 路由。先校验条件和排名，再送入原选股编辑页；预览使用原真实执行记录。

“一键回测”打开已填好的原日线组合配置，用户确认后提交原命令。没有真实来源或完整模板时，说明缺项并保留草稿。池子修改复用原 diff 和人工保存，不另存一份池子。

### 4.3 回测解读

新增 `src/rquant/ai_interpretation.py` 和聚焦测试。读取原封存结果，提取有限的指标、过拟合检查和分年事实。模型只能引用这些事实；每个展示数字必须匹配原事实。拒绝错数、缺引用、错产物和多余字段。

模型返回事实引用，页面从原产物填入数值和单位。自由文本中的数字也须核验；不能只校验一个指标表，留下正文里的错数。

固定输出四节。缓存绑定原用户、产物摘要和模板版本，保存为不可变产物。结果页增加“AI 解读”；未知数据仍显示未知，不生成缺失指标。

### 4.4 公告与研报摘要

新增 `src/rquant/stock_news_digest.py`、来源适配器和聚焦测试。批处理接入原研究调度，仅采集原池子和盯盘名单所需股票。默认固定来源、有限页数、有限字节、有限时间；不调用 SDK 的无界翻页路径。

公告、新闻和研报分别保存原记录。来源发表时间、正文时间和本次首次采集时间分开记录。新闻关键词命中不能代替股票归属。新采到的旧文不能用于证明过去某日已知。摘要引用先核存在和原文匹配，再发布 `stock_news_digest`；个股和总览读同一批事实。

正文只读已许可的固定来源；不接受模型给出的任意地址。原文和摘要的缓存分开记录，日期不一致时保留两者，不改写为同一天。

Tushare 公告与新闻当前实测无权益。保留明确不可用状态，继续使用已预检的现有公开来源。近期没有研报可以显示“暂无近期研报”，不得用旧文冒充近期内容。

### 4.5 用量、页面和验收

通过 Serving 发布 `llm_usage`，页面显示本月实际 token 和未知调用数。新增“查看用量”入口，功能未配置时说清原因，不显示假数字。

先运行直接相关红绿测试，再生成真实 OpenAPI 和 TypeScript。最终构建后验证桌面和390px：三步完整操作、池子确认、错数拒绝、来源引用、换账号、超限和失联恢复。所有模型和来源响应使用明确的离线测试材料；真实权益和安装单独记录。

## 6. 2026-10-06 直接来源核对

当前核对基线为 `641875a7eff873297177280cabd9841786400c5c`。这是实施准备，不是 SPEC 接受或功能通过。M1、M13 合版后，只刷新实际改变的直接依赖。

- 原 SQLite 状态是 `PageControlOutbox`。在它所属文件及事务中保存新调用状态；网页不能直接写此库。原 effect journal、身份、队列和恢复规则继续有效。
- 原网页模型是固定官方 OpenAI 入口：12 秒、0 次 SDK 重试、4096 输出 token。16 KiB 仅限制工具参数，不能当作整个响应大小证明。新适配器还须限制完整输入和响应，并返回真实 usage。
- 原 `parse_new` 不生成排名。新助手加独立排名输出方法，再用当前目录和原排名模型校验。旧方法仍只生成条件。
- 旧选股和池子自然语言接口只有进程内限流。助手、这两个旧入口、解读和夜间摘要必须共用原 PageControl 所属的持久预算。未配置预算时关闭真实调用；仍可手动编辑。
- 相同请求先查原记录。调用已发送但没有可靠结果时，记为未知；继续查询原请求。停止页面等待不能证明供应商调用已取消。
- 单日预览不能作为整段回测来源。确认回测前，原制备入口须按全部交易日生成完整候选、排名和行情证明，再提交原组合命令。来源不全时保留草稿，不能偷偷改用别的来源。
- 默认配置必须来自原模板或原已验证 `default_config`。原策略、仓位、退出、成本、基准和来源版本不能由模型填造。转换只做接线，原计算函数不变。
- 原绩效有已知指标、月度/日度事实，过拟合状态为“未评估”。分年派生只用原绩效函数和封存源行，记录函数版本及源行引用；材料不全时仍为未知。
- 原 Serving 没有 `llm_usage` 和 `stock_news_digest`。新增投影遵守原单格 64 KiB、每归属方合计 7 MiB；不能用新增投影扩大总限额。私有用量和名单按原身份过滤。
- 公告、新闻、研报使用已有预检。六次有限请求和缓存 PDF 核对不代表正文工件、完整历史或安装已通过。开发仍离线，不再重复请求这些来源。

来源、风险和验收候选保存在本工作树的 `data/verification/ai-assistance-completion-20261006/preparation-impl-01/`。
