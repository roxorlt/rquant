# 告警来源证明：路由循环发布信号前缀链接

> 接续 [告警确认与未确认数](2026-09-27-alert-acknowledgment.md) 中已实现但尚未接入运行循环的 `SignalRouteSpool.publish_bus_prefix_link`。本片只接通总线与路由记录的同截止点证据，不把它误称为完整告警来源覆盖。

**目标：**正在运行的信号路由器在路由记录追平总线后，按受控低频自动发布可重读核验的总线→路由记录链接。路由正常处理不等待这份附加证据；通知复制、上游生产者覆盖、Serving 计数与确认按钮仍须后续接线和验证。

**分级：高风险。**此改动触及共享常驻路由服务及其证据写入；基准为 `9007f9d2`。实现与审查限于路由 builder、链接调度和直接相关测试，不改生产 manifest、systemd、通知模式或页面。

## 风险模型与不变量

- **资产与边界：**`SignalBusStore` 是信号与路由回执权威；`SignalRouteSpool` 是只读消费者的不可变路由来源。路由进程是两者的唯一写者，通知进程只读。运行时 manifest/clock 可异常，不能让浏览器或 Serving 生成来源证明。
- **失败路径：**每 2 秒全量扫描 10,000 条引发资源负担；总线已前进、spool 落后时发出虚假完整链接；暂停时仍生成新覆盖；换代/文件损坏后沿用旧链接；链接写失败使主路由停摆；时间倒退/重启造成无限重试或长时间不更新。
- **不变量：**仅在最终 `publish_signal_bus_prefix` 已追平本次可观察总线高水位后调用现有 `publish_bus_prefix_link`；链接自身仍须核对同代同截止点路由回执与全部记录，不新增第二套计算。相邻**尝试**至少间隔 60 秒，成功、返回 `None` 与抛出普通异常都消耗一次尝试；空闲的 2 秒循环不扫描前缀或改写链接。间隔用单调时钟计，不受墙上时钟回拨影响；若注入的单调时钟自身倒退，重置锚点并允许一次立即尝试，随后重新限流。每次进程冷启动允许一次立即尝试，不跨进程持久化限流。新路由记录出现时旧链接由现有只读核验自然失效；旧代链接只保留历史证明，本片没有将它消费为当前覆盖。暂停或待追平时不发布新链接。附加证据不可用时不声称覆盖完整、不阻塞既有路由；真实路由故障仍照原路径报告。
- **排除：**不把 `upstream_complete` 设为真，不显示精确未确认数或启用确认，不改变通知投递，不部署或修改生产配置。正式正面覆盖需生产者生命周期、通知复制和 Serving 三段后续接通。

## 验收与顺序

1. 先用现有真实格式的 bus/spool 合成源写红测：首次追平发链接；2 秒空闲不重复扫描/改写；满 60 秒可刷新；连续 `None` 和连续异常均每 60 秒最多核验一次；墙上时钟回拨一天仍按单调时间刷新，注入的单调时钟回拨后能恢复，冷启动可立即尝试；spool backlog、paused 和 source 换代或损坏时无新可信链接；链接失败不改变已提交的路由游标和发件箱。
2. 在 `runtime_builder_signal.py` 的路由 step 末尾复用现有链接 API，单一闭包持有上次**尝试**的单调时钟刻度，不引新轮询服务或跨进程共享状态。现有可注入墙上时钟只用于链接的 `observed_at` 截止点，单独注入单调时钟用于 60 秒调度；在调用链接 API **前**记下尝试刻度，保证异常与 `None` 都限流。异常隔离须限于附加证据，不吞掉正常路由错误；无时区墙上时间或观测时间早于已路由记录，由现有链接核验拒绝，不产出虚假覆盖。
3. 跑 `test_runtime_builder_signal.py` 与 `test_signal_bus_spool_prefix_link.py` 的直接相关用例、Ruff 和 diff 检查。最终候选一次独立范围内审查；只对阻断 finding 定向修复及复核。进度台账继续写明信号覆盖不完整。
