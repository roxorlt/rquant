# 数据审计结果页：设计与实施边界

**目标**：让数据中心能查看最近一次真实数据审计的状态与问题，并从同一个 Serving 数据代取得可核对的记录。此增量接通 C1.2 的审计结果查看路径；月度覆盖率、审计调度和手动运行随后接入，不把它们标为完成。

**等级**：高风险。新增 Lab 权威来源的 Serving 表，改变共享发布契约；错误会把未运行或失败的审计展示为正常，或把不同数据代的记录混在一起。

**基线**：`601eb68c`；独立工作树 `cdx/20260927-data-audit-web`。开始时已有的覆盖率和质量纯函数测试 37 项、数据中心前端测试 2 项通过。仅本工作树写入；不修改主库、生产配置、线上服务或旧 Streamlit。

## 方案选择

1. **推荐：研究元数据库 → Lab 来源投影 → Serving → 网页 API → React。** 复用现有 `data_audit_run` / `data_quality_issue` 和 `DuckDBLabPageProjectionSource` 的稳定只读快照，发布紧凑、有限的状态与问题行。网页服务只读已验证的数据代，发布与展示边界清楚。
2. 网页 API 直接查约 10 GB 只读副本：实现少，但会把审计数据库查询放进 640 MB 网页进程，并可能干扰盘中与日终流水线；不采用。
3. 网页 API 读一个独立 JSON 报告：避免大库查询，却形成第二套发布、换代和权限语义；现有 Serving 已能承载小表，不采用。

## 冻结的威胁与失败模型

- **资产与边界**：研究元数据库中的审计运行/问题是来源；Lab 来源发布为权威；Serving 数据代是网页唯一的运行时读面；浏览器请求与筛选参数不可信。
- **失败路径**：正在运行或失败的最近一次尝试被当作完成；上次成功报告与后来问题状态被误称为同次审计；来源文件换代；记录超量或超长；原始 `scope_key`、证据 JSON、路径或服务代号进入页面正文；切换 Serving 数据代后沿用旧分页。
- **必须保持**：只有 `completed` 的运行能作为已完成审计；最新尝试失败/运行中须单独显示；每次读取稳定元数据库快照并经同一 Serving 数据代发布；严格限制行数和字节，超额明确不可用或标明只展示前 N，不静默丢失；API 输出中文可用的标签和动作提示，原始证据不进入浏览器；无运行记录显示“尚未审计”，不得显示绿色健康结论。
- **排除**：新建生产审计定时器、主库修复/回补、PageControl 写命令、全表历史日线扫描、月度覆盖率曲线。这些属于后续 C1.2/C1.3 增量，现有纯计算逻辑保持可复用。

## 可验证验收

1. 最近一次尝试和最近一次成功分开；无记录、运行中、失败、有问题、无问题各有真实且简短的中文状态。成功审计的日期范围与完成时刻可见。
2. 数据中心可按数据集看最近一次审计的问题摘要、严重程度和当前处理状态；显示数量及是否仅展示部分。无数据集/无审计/来源不可用/换代有明确反馈。桌面和 390px 可操作，键盘可达，说明放 Tip。
3. 来源只查询既有审计元数据，不读取 `evidence` JSON 或暴露原始路径/内部 ID；有界查询在稳定只读快照内完成。异常、换代、行数不符或超限不得显示“正常”。
4. `GET /api/v1/data/health`、`GET /api/v1/data/issues?dataset=` 使用 Pydantic 契约、OpenAPI→TypeScript 生成；只读同代 Serving，响应保留数据代可用性。测试覆盖运行状态与最新成功、问题归属、限制/换代、API/前端空态和错误态，并运行相关回归、Ruff、web check/build/dist。

## 实施步骤

1. 在 `serving_read_models.py` 定义紧凑审计状态和问题表（Lab 来源、固定列、稳定排序、行/字节预算）；先给来源状态和混代/超限写可执行失败用例。
2. 在 `serving_page_projection_source.py` 使用现有 `_StableReadonlyDuckDB` 从研究元数据库读取最近尝试、最近成功及有界问题，建立类型化投影；扩展 `LabPageProjectionSnapshot` 的完整性验证。复用现有发布流程，不开第二套文件通道。
3. 在 `web/routes/catalog.py` 或同一 `data` 路由包内增加只读端点和 Pydantic 响应；校验 Serving manifest/表行数，过滤参数白名单；把技术字段映射为短中文，不回传原始 `message`/`evidence`/`scope_key`。
4. 在数据中心为选中数据集加“审计”区域：状态、日期范围、问题数、可筛选问题表；新增源不可用、尚未审计、运行中、失败、无问题等反馈。沿用现有 `Panel`、`EmptyState`、`StatusBadge`、`Tip` 与窄屏样式。
5. 重生 OpenAPI、TS 合同和 `web/dist`；用同源合成研究元数据库→Serving→API→React 夹具验证桌面与 390px。最终候选只安排一次独立范围审查；高风险最多三轮定向修复与复核，范围外问题进后续台账。
