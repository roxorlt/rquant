# 因子检验：结果发布与只读网页入口

## 范围与选择

**任务分级：高风险。** 研究结果跨越私有 Lab 文件、持久任务账本与用户可见的 Serving 数据代；错误的身份绑定会把伪造或过期曲线标成可信检验。本片只把已完成且可核验的检验状态和紧凑展示产物发布到现有 `lab_jobs` Serving 来源，并提供只读 Web API。React 图表、任务提交、调度和生产配置分片接续。

使用现有链路：因子账本和私有产物根 → Lab 所属的有类型结果投影 → `lab_jobs` 来源双读比对 → 固定 Serving 数据代 → Web 只读 API。Lab 不在网页请求时扫描研究数据；Web 不接触账本、DuckDB 主库或私有研究产物，也不把 128 MiB 完整原件复制进 Serving。结果与当前定义各有单一权威；网页仅在因子 ID、精确版本和**定义内容摘要**都相等时关联两者。即使 ID 和版本相同，摘要不同也须显示为历史定义不可用，不能把旧曲线标在当前定义下。

## 冻结失败模型

- **资产与边界**：外部钉住的 `FactorLedgerIdentity`、账本任务状态及完成回执、内容寻址的紧凑展示文件、完整原件摘要、Lab 投影、同一 Serving generation 和登录用户的只读请求。只有 Lab 能持有账本和私有文件句柄；浏览器、Web 与通用 Serving 读者均不决定研究值或完成状态。
- **失败路径**：浏览器提交 job ID 或因子名诱导 Web 直读私有路径；成功状态与另一任务/因子版本/定义摘要/来源的曲线混接；旧成功回执缺紧凑产物却被显示为有效；文件被替换、截断、符号链接化或内容篡改；读取中账本换代；Lab 两次读取间任务变化；按观察时刻反复发布相同事实；单格超过 64 KiB 或 Lab owner 总量超过 7 MiB 时使发布失控；缺数点被转成零；回溯检验被文案写成真实当时可交易业绩。
- **不变量**：Lab 仅从已钉住身份的账本取最近任务；成功记录只有在新展示回执完整时才按摘要和大小重读紧凑文件，并核对 `job_id` 对应的规格、定义版本、代码、结果、来源、完整原件摘要和紧凑文件自身摘要。旧成功回执显示 `display_unavailable`。任何新回执或文件核验失败都使本次发布失败，保留上一可信 Serving 代；不得改成空结果或取内存旧值。状态、索引和展示表作为一个全有或全无的可选组，在 Lab payload、Serving 输入及固定 generation 读取时重复核对；同一组的 `available_at` 和 owner generation 必须一致。两次来源读取的规范内容不同则拒绝发布。
- **排除**：本片不让 Web 运行研究、不开放账本写入、不迁移旧回执、不自动补建旧产物、不改调度或部署、不接入完整原件文件。没有正式 Linux UID、数据量和 Serving 资源证据时不声称上线，也不停 Streamlit。

## 发布契约与验收

1. Lab 投影提供三张有类型表：一行 `factor_result_state` 说明可信空队列/任务数与账本实例；`factor_result_index` 收最近至多 50 条任务，按更新时间及 job ID 稳定排序，包含任务 ID、完整规格摘要、精确因子版本、状态/安全失败码、来源与研究时间、完成摘要和展示可用性；`factor_result_display` 只含可核验的紧凑产物。仅成功且有新展示回执的任务能进入展示表。状态与索引可覆盖运行、失败和旧成功任务；旧成功任务明确说明“历史结果暂无图表”。
2. 研究结果可能有 1,024 个日期，Serving 先给最近至多 4 个可展示任务分配总计 **4 MiB 原始 JSON** 的展示预算；单条超出总预算或其余较旧任务在索引中明确标为 `not_published`，不截断曲线、不伪造空值。选择顺序确定，优先新完成任务，不能因为文件损坏而跳过它去显示旧结果。`factor_result_display` 按每片至多 **32 KiB 原始字节**切分紧凑产物的规范 UTF-8 JSON，行键为 `(job_id, chunk_index)`，字段含 `chunk_count`、整体文件 SHA 和该片的 base64 内容。每格经过 Serving 自身的 JSON 字节计算仍须低于 64 KiB；重组必须验证连续索引、唯一总数、解码后总体大小、整体 SHA、规范 JSON 和有类型产物，再与索引及完成回执身份逐项比对。选择时还须核对包含既有 Lab 表在内的 `lab_jobs` owner 实际编码总量不超过 **7 MiB**；空间不足的任务标 `not_published` 并重新构造、核验整个投影，既有必需表自身超限则拒绝该次发布。超过索引 50 条的分页和所有历史结果访问另片完成，因此这一步仍属部分实现。网页返回结构化字段，不把路径、私有身份、租约令牌或内部服务代号暴露给用户。
3. `LabPageProjectionSnapshot` 与 `ServingReadModelInput` 接入结果三表的全组与交叉校验；`lab_jobs_state_identity` 只剥除观察时间及随之变化的展示快照摘要，保留任务、状态、产物和曲线内容，因此无变化不重新发布，有完成或变化则换代。Web 用固定 Serving generation 提供 `GET /api/v1/factors/results` 和 `GET /api/v1/factors/results/{job_id}`；换代沿现有 409 契约，未发布、可信空队列、旧回执、缺图、完整结果分别返回明确状态。API 不查询账本或计算 IC。
4. 聚焦红测用合成账本和双产物覆盖成功闭环、旧成功/运行/失败、同 ID 与版本但不同定义摘要、不同来源、替换/缺失/篡改、双读变化、合法大于 64 KiB 而小于总预算的完整曲线分片重组、缺片/乱序/重片/越界拒绝、owner 预算、新旧 Serving generation、零数据与换代 409；直接相关 Python 回归、OpenAPI/TS 合同生成与构建通过。候选做一次独立终审，发现阻断项只做定向修复和复核。真实 10 GB 副本、生产 UID/资源和切流另行验收。
