# 午间战报题材连续梯队与脉搏格式设计

## 目标

改善 PushDeer 手机上的扫读体验：将午间战报原本分离的“连板梯队”与“最强题材
Top5”合为同一个按题材展示的连续梯队；将 30 分钟脉搏的题材热度升级为 Top5
题材摘要，附最高板标的及相对上一脉搏的排名变化；将下午候选观察池从横向 Markdown
表格改成逐票三行的纵向卡片。

本次只改变 `morning-pulse` / `midday-report` 的内存计算和 PushDeer/Markdown 正文。
不改 CLI、通知场景、调度、落盘目录、外部实时数据路由或 systemd unit。

## 现状与问题

- `theme_map_from_kpl()` 为每个股票只保留第一个开盘啦题材；这会错误丢弃一票多题材
  的归属，因而无法按真实题材关系构造梯队。
- 午间 `compute_board_ladder()` 按全市场板高聚合，而 `compute_top_themes()` 只列主题
  排名。手机上必须来回对照两节才能知道某题材的最高板与梯队构成。
- 脉搏的 `_theme_heat()` 只输出“题材：涨停数（增量）”，无法看到龙头和排名变化。
- 候选池的六列表格在窄屏横向拥挤，字段边界不稳定。

## 数据口径与模型

新增 Pydantic 跨层模型 `ThemeLadderRung` 与 `ThemeLadderSummary`，并让 `PulseView`
和 `DigestView` 都消费 `list[ThemeLadderSummary]`。旧的 `LadderStock`、`ThemeRank`
以及分离的 `ladder` / `top_themes` 输出将被该统一模型替代。

`ThemeLadderSummary` 至少携带：题材名、当前涨停数、半日成交额、按高度从高到低的
`rungs`、上午四槽涨停数序列，以及脉搏专用的排名变化标记。`ThemeLadderRung` 携带
板高和该高度的全部同高标的（代码及名称），所以渲染层可以按不同媒介决定截断，而不
会在计算层丢失信息。

题材统计以 `kpl_concept_member(board_name, con_code)` 的真实多对多关系为准：把成员表
与当前快照按 `con_code == ts_code` 连接；同一股票命中多个题材时，在每个题材内都参与
涨停数、半日额和板高统计。这些题材之间的金额/股票数不得再求全市场总和。没有当前
涨停的题材不进入 Top5，也不进入午间梯队。

今日板高沿用既有口径：只有当前涨停的股票才有梯队高度，`T-1 limit_times + 1`，昨日
不在涨停榜的股票为首板。对每个题材，从它的最高板连续展开到首板；中间缺少标的的
高度也保留为“0档”（例如 `4板：0`），以便手机上一眼看到断层。这里的“0档”是某一
**板高无人**，不是“0板股票”。

题材排序稳定为 `limit_up_count DESC, amount DESC, board_name ASC`，与现有排序兼容并
消除同值时的非确定性。午间显示排名前五个 `ThemeLadderSummary`；每项保留涨停数、
半日额及上午四槽的涨停走势。

## 脉搏排名变化

脉搏同样显示排序后的 Top5。每项包含题材、涨停数、当前最高板，以及最高板标的名称。
最高板并列的全部标的保存在模型中；手机渲染只显示前两只，第三只起写为“等 N 只”（N
为该高度总数），避免单条通知失控。只有一个或两个同高标的时全部显示。

排名变化按“上一脉搏 Top5”比较：同题材的变化为 `上一名次 - 当前名次`，正数显示
`↑n`、负数显示 `↓n`、零显示“持平”；本次进入 Top5 而上一脉搏未在 Top5 的题材显示
“新晋”。10:00 是当天首个脉搏，绝不显示任何排名变化。若上一槽 parquet/板块帧不存在，
按首槽语义省略变化，而不是错误标为“新晋”。

示例（仅展示形态）：

```markdown
## 题材 Top5
- AI硬件：涨停10 ｜ 最高3板：甲、乙等3只 ｜ ↑2
- 商业航天：涨停6 ｜ 最高2板：丙 ｜ 新晋
```

午间复用同一 `ThemeLadderSummary`，但展示完整连续梯队而非脉搏的两只名称截断：

```markdown
## ② 题材连续梯队 Top5
1. AI硬件 涨停10 半日额12.3亿（上午 5/7/9/10）
   3板：甲、乙、丙
   2板：0
   首板：丁、戊
```

## 候选池手机排版

候选筛选条件、排序、top20 截断及量纲完全不变。仅把每只候选渲染为三个 Markdown 行，
相邻标的空一行：

```markdown
- 创A（300001.SZ）
  题材：存储 ｜ 半日量比：2.10
  涨幅：+8.0% ｜ 距涨停：5.0%

- 科B（688002.SH）
  题材：— ｜ 半日量比：1.35
  涨幅：+5.2% ｜ 距涨停：7.8%
```

## DuckDB 与降级边界

任何数据库读取仍只能经 `open_readonly_store()`，不得新增裸 `duckdb.connect()`、默认
`DuckDBStore()` 或写库路径。`run_morning_pulse()` / `run_midday_report()` 在网络快照读取前
用一次短生命周期的只读 store 复用 `load_prev_limit_list(store)`、
`load_avg_amount_20d(store)`、`load_kpl_concept_members(store)`（午间再读持仓），读取后立即
关闭，不能持锁跨越网络调用；东财板块成员同样在该 store 内读取，空时以同一 store 查询
行业兜底。原始东财/KPL 成员均传入 `fetch_slot_frames()`，KPL 也传入后续视图，避免同次通知
重复查询。fake 模式传 `None` 给各 fake-aware loader 以保留离线演示数据。

打开只读 store 或任一查询失败时均 fail-soft：记录 warning，返回空 T-1 表/空均额/空
成员；脉搏仍正常发送市场温度和可得的内容。没有 T-1 涨停榜时当前涨停按首板；没有
成员时题材节省略；没有均额时放量异动节省略。快照三路失败的既有降级短讯保持原样。
午间已经采用一次 store 复用的方式，重构后继续将成员、昨日涨停榜、均额和持仓读取放在
同一受控只读连接中。

## 非目标

- 不改变开盘啦题材采集、成员表 schema 或日终同步。
- 不改变题材涨停判定、实时快照、资金流、候选池筛选阈值、推送渠道或标题摘要。
- 不修改 systemd/CLI/notify 直通配置，不触发生产部署。

## 验收要点

- 一个涨停股归属两个开盘啦题材时，两个主题均得到该股票及其板高。
- 每个主题的梯队从最高板连续到首板，缺档明确为 `0`；同高标的不会在模型层截断。
- 10:00 无排名变化；之后能正确覆盖 `↑n`、`↓n`、“持平”和“新晋”。
- 午间使用同一摘要对象且保留涨停数、半日额、四槽走势；候选池无 Markdown 表格。
- 只读库不可用或查询异常时不阻塞脉搏/午间报告，也不连接主库写模式。
