# 池子入池价的不可变运行凭据

**目标**：把“这只股票的入池日收盘价属于这次选股结果”变成可复核事实，再向原型的成员表和日 K 提供入池价、可比较的涨幅。

**分级：高风险。** 新切片改变生产选股回执、DuckDB 迁移和共享 Serving 合同。只先在隔离工作树实现与验证；生产建表、迁移、配置、部署和页面切流仍按项目规则单独授权。

## 失败模型与不变量

资产是已发布的成员期、入池价、结果版本与用户看到的涨幅。信任边界依次是日终输入、主库事务、只读副本、Serving 数据代、Web API 和页面。现有 v1 回执只绑定成员集合；事后同时改写 `screen_result.close` 与 `daily_bar.close`，会让两表仍然相等，却把新价格错误归到旧结果版本。单独比较两张当前表不能跨越这个边界。

必须保持：新价格凭据与成员行在同一事务生成；同成员重跑但价格改变时，价格凭据与结果身份改变；旧回执、缺价、价格/因子口径不明、摘要不合、跨数据代与副本换代只给未知，不从当前价倒推。真实零命中仍是成功运行。仅价格证明失败时保留**已由连续回执证明**的入池日与结果版本；日历缺失、窗口截断、成员或回执不可信时，日期和版本也未知。原有画布成员读取不依赖价格证明。排除实盘成交价、分红现金流入账和跨源推测；入池价文案固定为“入池日收盘价”。

## 方案选择

可选独立价格事件账本、发布后封存整个选股结果文件，或给现有原子运行回执增加价格摘要。选择第三种：它与已有成员摘要处在同一事务，Serving 可在同一副本复核，无需让网页读取主库。旧 v1 回执按旧字段和旧哈希规则保持可解读，但**绝不能**从现在的历史行情补造 v2 价格证明。新 v2 摘要以同一事务中**已持久化并读回**的 `screen_result.close` 为准，按 `ts_code` 排序：字节流以固定版本域开头，先编码行数，每行编码 UTF-8 代码的字节长度与内容，再用单独的 NULL 标记或完整 8 字节 IEEE-754 binary64（大端）编码价格。不得按显示精度取整；非有限价格也参与字节摘要但不可显示。新 `result_version` 包含 v2 合同与价格摘要，验证方按同样规则重算。

字段状态矩阵：连续性与 v2 价格摘要均可信时可给日期、价格；连续性可信但仅有 v1、价格缺失或摘要不合时只给日期/结果版本，价格与涨幅未知；连续性不可信时日期、版本、价格与涨幅都未知；可信零命中是成功运行但没有成员字段。

## 分片验收

1. 扩展 `ScreenRunReceipt` 的版本化模型、原子写入、DDL/迁移和研究同步。用手工构造的结果验证成员不变而价格微变也会改变版本、零命中、同日重跑、事务失败回滚、旧 v1 读取及同步降级；持久化前后浮点转换与 NULL/非有限值单独覆盖。生产迁移只记录待执行步骤，不在本地开发阶段执行线上操作。
2. Serving 从同一稳定副本重算新摘要，并核对入池日 `screen_result.close` 与 `daily_bar.close`。匹配才发布 `entry_close`；v1、改写单表或双表、缺价只使价格未知；缺日历、窗口截断和成员连续性失证连日期也未知。用真实发布器和网页 API 的合成链验证跨代不串价。
3. 网页成员表显示“入池日”和“入池日收盘价”；有证据时在同数据代日 K 标记入池日与价格线。入池后涨幅以最新**已收盘**且经 v2 价格摘要及日线核对的日期为右端，使用同副本 `adj_factor` 的入池日因子 `F_entry` 与右端因子 `F_current`：`同口径入池价 = 入池日原始收盘价 × F_entry / F_current`，`复权涨幅 = (右端原始收盘价 / 同口径入池价 − 1) × 100%`。两端代码、日期、结果代必须相符，两个因子都要有限且大于零；缺因子、缺收盘价、停牌或仅有盘中报价时显示“暂无可靠涨幅”。页面文案称“入池后复权涨幅”，不把它称为现金分红再投资或实盘收益。桌面、390px、键盘、空态与换代路径验证。

上述同口径换算与 [Tushare A 股复权行情说明](https://tushare.pro/document/2?doc_id=146) 的前复权公式 `当日收盘价 × 当日复权因子 / 最新复权因子` 一致；右端必须是本次固定副本中选择的已收盘日期，不读取页面打开时的实时因子。

## 分片 3 的发布与展示口径

入池后涨幅由独立的纯 Python 计算函数给出。右端固定为该池**当前可信运行回执的交易日**，并同时要求其 v2 价格摘要、同代码 `screen_result.close` 与 `daily_bar.close` 一致，以及该交易日已收盘；不从未运行的较新日线或盘中快照延长收益区间。入池端继续使用已验证的入池价。两端 `adj_factor` 必须来自同一固定副本、日期和代码精确匹配，收盘价及因子均有限且大于零；右端 `daily_bar.vol` 不大于零或不可用时不计算。价格或因子缺证只撤去涨幅，不能撤去独立证明的入池日期与价格。原始涨幅与复权涨幅不可混称，展示保留右端日期。

Serving 以**新增可选的有界 `pool_member_return` 投影**发布收益事实，不给已有 `screen_run_receipt`、`pool_membership` 投影增加必填列，以免旧已发布 authority 在升级时失效。投影每行绑定池名、当前运行日与结果版本、股票代码、入池日与入池结果版本，给出可信时的 `gain_pct`；因子相同时才给出可画在原始 K 线上的 `entry_line_price`，否则为空。网页 API 在同一次借用的数据代中与入池投影按这些键核对，缺表、行缺失、重复或跨版本时仅隐藏涨幅。网页成员表显示“入池后复权涨幅”，池子汇总同时给出已核验人数与总人数，不能把部分样本均值写成全池均值。图表的日 K 仍是原始价格：只有入池日和右端复权因子相同时才在原始 K 线上画“入池日收盘价”水平线；因子不同则保留入池日标记、隐藏水平线，并在悬停提示解释原始价格不可直接横比。该规则避免把复权参考价画在原始 K 线上。页面正文不显示回执版本、因子或内部状态代号。

聚焦验收要覆盖：复权因子变化使原始跌幅与复权涨幅方向相反、同日入池为零、缺一端因子/价格、旧 v1、价格事后双表改写、停牌或盘中、跨代换表、旧 authority 无新投影、部分成员可算时的均值覆盖数，以及桌面/390px、键盘和空态。最终发布前还须在约 10 GB 正式副本与 Linux 资源限制下验证投影的耗时和峰值内存。

每片只做一次最终候选独立审查；发现问题按冻结失败模型定向修复。正式约 10 GB 副本负载与生产资源限制须在切流前实测，不能由小型合成库通过推断。
