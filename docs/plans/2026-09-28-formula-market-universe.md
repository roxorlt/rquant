# 公式运行的逐日市场名单：采集与封存

## 决策

C4.5 的下一增量建立独立的、收盘后采集的逐日 A 股名单。现有公式历史投影的 `stock_basic` 是累计表，不能作某日完整市场分母；参考慢源虽每天读取 L/D/P 全表，但只将全部名单的摘要带入其快照，不保留可供公式运行的全表事实。修改其现有内容哈希契约会牵动生产发布与旧记录。因此新名单由独立采集者封存，公式计算只消费有类型的只读快照，不从网页请求现场调用 Tushare。

任务分级：高风险。名单漏项或跨日会直接改变选股分母；第三方接口截断、重复和发布竞争可能产生看似完整的错误结果。本切片只交付离线采集与可核验归档，不接生产调度、PageControl、Serving、React 或 Streamlit 切换。

Tushare [官方 `stock_basic` 文档](https://tushare.pro/document/1?doc_id=25)说明单次最多返回 6,000 行，可按交易所和上市状态查询；该接口返回的是查询当时的状态，不能拿今天的返回值回填过去某日的“当时名单”。本增量只在目标交易日收盘后封存当天实际观察，不倒填旧日期。

## 合同与验收

1. 在现有 Tushare 适配器增加可选交易所参数，默认行为保持；离线采集者只请求 SSE、SZSE、BSE × L、P 六个分区。每分区必须返回要求的列，行数达到 6,000 即视为可能截断并整体拒绝；请求异常、重复代码、同代码跨分区、交易所后缀不符、状态或日期矛盾也整体拒绝。B 股、基金等非 A 股需明确排除并计数；沪深遵循现有 A 股前缀，北交所保留 4/8/9 前缀。每个已采集 A 股必须有可信上市日期，暂停上市者留在名单，缺当日日线由后续公式运行记“未知”。
2. 只接受权威 SSE 日历确认为开市日，采集开始和完成均在目标日 17:00 之后且未过午夜；日历生成时间不得晚于采集。快照包含目标日、开始/完成时刻、日历摘要、六分区原始行数及排除数、按代码排序的有类型名单、内容摘要。分区数与名单数必须守恒，不能以空结果假装完整上市市场。
3. 离线归档使用显式绝对根目录，不读取 `.env`、主 DuckDB 或网络（测试以假适配器）；每个内容代为不可变文件，单日指针原子替换。读者按日期和期望摘要固定同一代，验证普通文件身份、大小、内容摘要与日期，换代或损坏拒绝，不回退旧结果。相同内容重试幂等，不同内容保留旧代供追溯；写临时文件失败不改变当前指针。
4. 聚焦红绿测试覆盖六分区、边界 6,000、漏列/重复/跨交易所/错日期、B 股排除、空上市名单、休市、时间跨日、同日重试/更正、指针换代/损坏。Ruff、差异检查通过，最终候选一次独立审查。正式源接入与 Linux 路径权限仍待后续环境验收，不声称线上已采集。

## 冻结的失败模型

- 资产：目标交易日 A 股名单、来源分区、观察时刻、归档代。边界：第三方表格输入不可信；采集者规范化并封存；后续公式运行只能读取归档，不自行推断目录。
- 失败路径：接口 6,000 行截断、某交易所漏请求、B 股占分母、跨状态重复、昨日结果充当今日结果、指针覆盖半成品、内容被替换后仍沿用旧摘要。
- 不变量：六个分区都成功且未达上限；每个纳入的代码只在一个分区；每日快照内容与唯一摘要相符；读取者不能把未归档日期当零股票。采集没有来源完整回执以外的外部总数证明，因此页面应写“当日已采集名单”，并在真实源负载验收前保持未上线。
- 排除项：现有参考慢源快照契约、历史倒填、公式批量运行接线、正式任务调度、生产配置与数据库写入。
