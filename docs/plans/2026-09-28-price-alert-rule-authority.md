# 价格提醒规则：事务内权威状态

接续 [手动名单范围证据](2026-09-28-manual-alert-scope.md)，对应新前端计划 C12.1 的第一种规则。先建立用户可配置的单股到价提醒权威状态；名单的 `price_levels` 只是用户保存的参考价位，不能自行变成告警规则。26 条条件、分钟特征、频率选项和旧 monitor 规则迁移留给后续独立切片。本片只实现 PageControl 所在 SQLite 事务可调用的领域仓储，不开放外部写入口、不执行或投递。

**分级：高风险。** 错误的用户、股票或名单版本绑定会导致错发或漏发提醒。实现前冻结以下边界。

## 威胁与失败模型

- **资产与信任边界**：`manual_watchlist` 的 `(owner_id, ts_code, version)` 是有效作用范围的写入权威；价格规则独立保存 `(owner_id, rule_id, rule_version)`、股票与名单版本、名称、P0–P3 级别、`gte`/`lte` 阈值、上海时间窗口及启用状态。仓储借用 PageControl 的同一个 SQLite 连接和调用方事务，不能自己提交、访问 DuckDB 或发送通知。未来网页 owner 只能由受信入口注入。
- **失败路径**：跨用户绑股、过期/已删名单、旧名单版本、规则并发更新、规则删除后同 ID 重建、启停与删除竞态、超容量、无效价格/时间、读到损坏行。移出再加入会产生新名单版本；旧规则即使仍标启用，也不能自动恢复作用范围。
- **不变量**：创建、修改、启停和删除都要求期望规则版本的 CAS；删除保留递增版本的墓碑，同 ID 重建只能基于墓碑版本。每个 owner 最多 100 条未删除规则。创建/重新绑定/启用时在**同一事务**核对该 owner 的手动名单仍有效且版本准确；同股其他 owner 的名单无效。停用和删除仍可在名单已移出时完成。规则读取必须携带绑定版本，后续评估仍须在每轮的可信 Serving 范围里再次核对，不能仅凭规则表中的 enabled 触发。写入前后不会隐式推送；未激活及损坏状态不推断为空规则。
- **排除项**：本片不改 PageControl 命令适配、Web API、React、Serving 发布、行情源、通知通道、systemd/nginx/sudoers 或生产库；不读取 `.env`、凭据、真实数据。正式规则启用、按用户通道映射与旧 monitor 迁移需另外验证和授权。

## 本片验收

1. 有类型规则与事务仓储独立于 Web/运行时；仅在调用方已有事务中建表和写入，回滚连同名单修改一起生效。最大规则数明确有界；有效零行与未建表分开。
2. 离线 SQLite 测试覆盖两位用户持有同股、绑定版本过期、已删/到期、创建/修改/启停/墓碑 CAS、同 ID 重建、容量边界、非法阈值/窗口、坏行和事务回滚。规则版本单调递增，旧绑定不会因名单重新加入而复活。
3. 现有手动名单与纯价格求值的直接回归通过；此片不产生告警事件或网络调用。
