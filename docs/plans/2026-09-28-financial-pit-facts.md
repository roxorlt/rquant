# 财务 PIT 第三片：封存观察到本地可查询事实

接续 [PIT 基础](2026-09-28-financial-pit-foundation.md) 和 [有界采集](2026-09-28-financial-pit-acquisition.md)。本片只在临时 DuckDB 与假采集客户端验证：把已提交归档中的观察记录导入新表，并由唯一的财务 PIT 选择器回答某字段在指定历史时刻是否可用。**不接真实 Tushare、生产主库、正式定时任务或网页，也不声称 C1.4 完成。**

**分级：高风险。** 导入丢失修订顺序、把不完整观察当完整事实，或让通用数据查询绕开日历门槛，会污染历史选股与回测。生产迁移和写入仍需项目规定的单独授权。

## 资产、信任边界与失败路径

- 资产是归档身份、已提交批次及其校验过的内容、观察时刻、原始行和异常状态、SSE 逐自然日日历、导入游标、每次 PIT 选择的来源版本。
- `FinancialArchive` 是唯一可信的归档读取入口。封存目录中的路径、文件和外部字段仍是不可信输入；导入器只能接收同一把归档锁下取得、逐批校验过的有界快照，不能自己读批文件或绕过清单。DuckDB 是本地派生索引，不能反向改写归档。
- 生产者是采集归档，消费者是导入器、专用财务 PIT 查询、后续派生/选股/回测。`DatasetContract` 只能声明 `FINANCIAL_PIT`，不得把原始 `ann_date` 当 `PANEL_CLOSE_NEXT_SESSION`，也不得把 `first_observed_at` 单独当 `MINUTE_AS_OF`。通用 `is_visible`、`evaluate_visibility`、`query_visible_rows` 对此规则必须明确拒绝，避免返回貌似已裁剪的原始行。
- 失败路径：归档被换根或回滚；批次在游标推进前后崩溃；重复请求、跨页同值重采与 A→B→A；同批同键内容冲突；缺报告期/类型/公告日/数值；触顶可能截断；日历缺日；修订晚于历史决策时刻。

## 不变量与实现边界

1. 归档增加只读的**有界已提交批次页**：在单次 `_state()` 锁内给出 `archive_id`、归档高水位、严格按 `observed_at` 排序的回执与经现有 `_load_batch` 校验的批次，以及是否还有后页。按显式游标读取，单页上限固定；不返回未提交的孤儿文件。导入游标同时保存已接受的 anchor generation 与记录哈希；每次分页都在归档锁内证明这个记录仍是当前 anchor 哈希链的前缀。仅有相同 ID 或更高高水位不够：整根回滚再分叉为另一条更晚历史也必须拒绝。
2. 追加式 schema migration 新建批次导入账本、原始观察行表和单一归档游标。批次账本保留请求、状态（含 `empty`/`possibly_truncated`）、时间、内容摘要与行数；观察行保留原始 JSON、公告日、实际公告日、报告期、报表类型、行摘要、`pit_usable`/`conflicted`。所有行包括不可用于 PIT 的行都留证据，绝不静默丢弃。唯一身份包含归档、请求及原始行序号；事务内检查已存在记录完全相等，再推进游标与已验证 anchor 身份。重放相同页不重复写，差异、换归档、游标倒退或 anchor 非后继失败且事务整体回滚。
3. 导入只记录观察，不在写入时假定公告可见。查询先取同一证券、接口、期间与类型的**所有相关行**，不能按目标字段是否存在预过滤；另取报告期或类型缺失、无法归键的同证券/接口异常行。按原始观察顺序对目标字段独立生成版本：版本内容由该字段的值、公告日和实际公告日决定，完整行其他字段变化不改变该字段的首次观察；缺字段、空值、不可用或冲突行是阻断版本，打断连续同值。跨查询页延续此前字段版本状态，A→B→A 的最后 A 取得新首次观察时刻。全部按字段版本规则放在一个纯函数中，采集层现有整行 `observed_versions` 仍只用于整行观察，不得冒充字段 PIT 规则。候选过多时返回显式未知，不截去早期版本后继续计算首见。
4. `FinancialFact` 的报表类型：利润表/资产负债表/现金流量表取 `report_type`，业绩预告取 `type`，其他接口使用固定的非空默认值；不得把空类型混同为已知类型。证券、报告期或类型缺失导致无法定位的行，在其观察时刻之后阻断相关证券/接口的 PIT 查询，直到有明确处置机制；可定位但缺公告日、字段或值的较新版本返回未知，不能回退到旧值。应修改**唯一** `select_financial_fact` 的异常优先级：已观察的较新阻断版本遮挡旧值；较晚且已满足公告与观察双门槛的完整版本可以解除较早异常；查询较早时点仍保持未知。不能让早期异常永久污染后来时点，也不能因最新版本尚未可见而提前选它。
5. 只从主库现有 `trade_calendar` 的 SSE 每个自然日记录构造 `SSECalendar`，覆盖候选公告日到决策日；不能自行补周末或把缺行猜为休市。结果保留 `selected/unknown`、原因、字段来源接口/期间/版本摘要和首次观察时刻。`possibly_truncated`、`empty` 仅为采集观察，均**不证明全市场或该接口覆盖完整**；字段不存在只能返回未知，不能据此推断为零。
6. 本片注册 `financial_observation` 的**内部**数据契约，但不把原始观察表纳入面向用户的数据目录；目录构建须显式排除这项契约，验收目录产物不含归档 ID、请求 ID、哈希等内部字段。下一片只发布经 PIT 裁剪后的用户字段，并用短文案说明“财报公告后下一开市日开盘，且实际采集后才可用于历史研究”。财务字段使用来源文档的原口径，暂不生成 PE/PB/ROE 等派生列。官方 [每日指标](https://tushare.pro/document/2?doc_id=32) 才提供 `pe_ttm`、`pb`、`dv_ttm`；后续派生不得假设七个财报接口直接返回它们。

## 首批验收

- 离线临时库测试：七接口、空响应和可能截断响应可入账；重复导入不改账本；坏摘要、换归档、游标倒退或同键不等数据失败且无部分写入。归档批次页保持边界与安全读取。
- PIT 测试：公告当天、下个开市日 09:30 前后、首次观察晚于公告、公告日至决策日缺历、同值重采、同一行其他字段变化但目标字段不变、A→B→A、同刻冲突、旧值之后的行缺目标字段、较新空值/缺公告、异常后恢复及恢复前时点。特别验证 9 月 24 日公告但 10 月 1 日才首见的数值在 9 月 28 日不可见；分页不能重置字段首次观察。
- 通用数据契约查询对财务规则拒绝；新迁移在空库和已有迁移库只追加成功；目录产物不出现内部财务观察表或其标识字段。运行直接相关 Python 测试、Ruff；最终候选由独立审查者一次覆盖本次 diff，按高风险最多三轮定向修复复核。
