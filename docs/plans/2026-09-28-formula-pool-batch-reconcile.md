# 公式池逐日批量协调

## 范围与分级

把已验证的「单池单日重算」组成一个有界、可重复调用的日终协调器：从私有定义目录列出要运行的公式池，按目标交易日给共享公式任务队列准入；已有成功任务则发布不可变逐日结果。任务执行继续由现有一次性 worker 负责。本片提供本地受信入口与可核对的运行摘要，不新增常驻进程、生产定时器、数据库迁移或网页按钮。

高风险：批量重试、共享队列及来源换代可能使未完成或错日期的结果被冒称已运行，或漏过池子。

## 验收

1. 入口只接受显式、owner-private 的绝对配置和已收盘的目标交易日；配置固定市场名单、历史投影、任务库、封存产物、公式定义、规则池与逐日结果根。目录扫描有上限（最多 512 个定义），文件名、权限、版本、语法与规则池同名冲突在任何新准入前验证；非法文件、丢失配置或阶段文件不得当作「没有池子」。不读取 `.env`、浏览器参数中的路径或生产隐式默认值。
2. 一次调用最多处理有界数量的定义，按稳定池名顺序并返回明确续页位置；下次从该位置继续，不因前面一个失败池子永远饿死后面池子。每只池固定定义版本和目标日两来源身份，复用 `FormulaPoolDailyRecalculator.admit/read_exact/publish`；创建日成员不作为后续日成员。共享队列中的其他任务由独立 worker 处理，协调器不假设 `run_one()` 领取的就是当前池子任务。
3. 只把已封存且重读核验成功的每日结果计作「已完成」；`queued/running` 显示「等待运行」，失败保留安全错误类别且不写逐日结果。既有同身份结果幂等，错定义版本或来源变更与同日文件冲突明确拒绝。一次调用的部分进度不能伪装成全日完成；摘要有已完成、等待、失败及未处理数，并保留确切交易日。
4. 用两只公式池、两日合成来源，跑批次准入→现有 worker→批次发布，验证重试、分批续页、单池失败不饿死后续、未收盘日、目录污染/超限、来源换代、同日冲突和坏封存结果。运行聚焦 pytest、Ruff、diff 自检；最终候选做一次独立终审。真实约 10 GB 性能及 Linux 权限另行验收。

## 冻结失败模型

- 资产：私有配置、全部公式池定义及版本、目标日两来源身份、共享任务状态、不可变逐日结果、批次进度摘要。
- 边界：受信本地入口→定义目录和目标日来源→共享持久任务；一次性 worker→封存结果；协调器→逐日结果。
- 失败路径：目录坏文件被忽略；分页或单池失败导致后续池永远不运行；重试重复写入；共享 worker 执行了其他任务却误报当前池完成；来源换代或前日成员被当成目标日成功；配置错误写进真实路径。
- 不变量：报告为完成的池在精确目标日有可重读、版本和双来源一致的逐日结果；等待/失败/未处理可区分；批次有界且可从续页继续；坏目录和坏配置在新写入前拒绝。
- 排除：修改现有任务 worker 的租约与执行合同、正式生产调度/路径/权限、Streamlit 切流或停服。上述生产动作按项目单独授权。
