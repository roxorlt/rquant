# 价格提醒：带源端时间的分钟行情候选

接续价格规则配置和离线批次求值。本片只把现有 `TushareAdapter.rt_min` 返回的 1 分钟行情转换为有来源时间的价格证据；不获取真实行情、不写信号或通知、不改变默认新浪报价提供器，也不把页面改成“正在提醒”。任务定级为普通：只读适配与领域校验跨两个模块，但不修改生产权限、并发写入或发布契约。

Tushare 官方 `rt_min` 契约提供 `ts_code`、`time` 和 `close`，其中 `time` 是交易时间，单次最多 1,000 行（[官方说明](https://tushare.pro/document/2?doc_id=374)）。仓库现有适配器把它标准化成 `trade_time`。这是一分钟 K 线的源端时间，精度只有分钟；把它作为保守的报价年龄起点，不用请求或收到响应的时间冒充行情时间。实盘启用前仍须核验真实响应、权限、延迟和时间标记语义。

## 验收

1. 新增独立的纯适配函数，接收现有 `rt_min` 标准化结果、明确的上海交易日、收到时间和有界目标代码；只产出 `PriceQuoteEvidence`，不调用 `rquant.web`、通知或生产网络。
2. `trade_time` 按上海时区解释；缺失、无效、未来、错交易日及会话外的时间拒绝成为可触发证据。`close` 须为正的有限数。重复代码或非请求代码拒绝整批，避免任取一条；请求内缺行保持缺报价，由下游三态求值解释，不伪造零价。
3. 每条证据保留源端分钟时间，使用 `provider_source_timestamp`；`received_at` 仅用于拒绝未来数据和审计，不替代源端时间。接上现有纯批次求值时，跨午休、过期和时间回退仍由既有规则拒绝。
4. 聚焦测试覆盖上海时区、合法多股/同股多用户复用、缺行、坏价、重复/越权代码、未来/错日/会话外时间和原有批次求值。没有真实凭据或生产采集测试。

## 后续接线边界

`rt_min` 是需单独开通权限的实时分钟接口，当前生产监控虽有旧适配器，但新告警运行链路尚未取得真实响应证据。后续 runtime 必须有独立限额、采集超时、报价单调性记录、当前 PageControl 权威复核、频率与持久去重，完成后才能写信号总线。此片 `delivery_eligible` 仍为 `False`。
