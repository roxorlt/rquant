# 财务数据 PIT 基础：可见时刻与版本

对应新前端计划 v2 的 C1.4，并为基本面选股、因子检验和回测提供同一份时点规则。此处先冻结数据语义，再分片接采集、存储、派生和页面；代码仍是本地候选，不读取真实凭据，也不写生产主库。

**分级：高风险。** 历史财报的后来修订若按旧公告日回填，会让选股与回测看到当时尚不存在的数值，污染共享研究结果。正式写入主库、迁移、定时任务及发布另走项目单独授权。

## 资产与边界

- 资产：每个财务数值、对应证券和报告期、原始公告日期、实际公告日期、报表类型、采集观察时刻、来源与内容摘要；完整的 SSE 开闭市日历；衍生选股字段及回测结果。
- 外部 Tushare 响应是输入证据，不是可直接用于历史决策的权威状态。适配器只取数与归一化；PIT 纯函数只接收有类型的事实和显式日历；存储保留版本；`daily_state`、选股和回测只消费已经通过 PIT 裁剪的视图。
- Tushare 官方文档列出利润表与现金流量表的 `ann_date`、`f_ann_date`、报告期及报表类型，并说明普通接口按单只股票取历史、全市场季度接口另有积分门槛：[利润表](https://tushare.pro/document/2?doc_id=33)、[现金流量表](https://tushare.pro/document/2?doc_id=44)。接口有 `update_flag`，但该字段只说明供应商当前更新状态，不证明某个值在过去何时可见。[财务指标](https://tushare.pro/document/2?doc_id=79)也包含报告期、公告日与更新标识。

## 必须保持的不变量

1. 日期只有日精度时，取 `ann_date` 与非空 `f_ann_date` 中较晚的一日；该事实最早在**严格晚于该日**的下一 SSE 开市日 09:30（上海时间）可用于研究。缺日期、无覆盖下一开市日、日历缺口或冲突时为未知，不能自行猜工作日。
2. 每次供应商返回保存内容摘要和首次观察时刻；同一证券、报告期、报表类型出现不同内容时保留版本。没有可核验的独立修订公告时，新内容不能沿用旧版本的历史可见时刻，最早还须晚于首次观察时刻。`update_flag=1` 不得追溯改写过去的结果。
3. 同一决策时刻只从已可见的版本中选择，若同一时刻存在内容冲突而缺少明确顺序则返回未知。用于计算 ROE、营收/净利同比或估值的组成字段必须采用同一决策时刻的已可见值，并记录各自来源版本；缺一项就保留缺失，不补造零。
4. PIT 规则由一个纯领域模块负责；采集、存储、任务、Serving 和 React 不得各实现一套公告日计算。页面只展示用户可用的财务字段与可见时间说明，原始哈希和内部任务标识留在诊断层。
5. 首次观察晚于历史公告日时，不能仅凭当前供应商返回的修订值为过去构造“当时已知”历史。若以后接入能证明原始公告内容和修订时刻的来源，可逐版本扩大历史可用范围，且保留既有结果的来源版本。

## 首批验收与明确排除

- 第一片仅实现有类型的财务事实、SSE 日历输入与纯 PIT 选择器：覆盖周末/节假日、公告当天、下一开市日开盘前后、实际公告日晚于公告日、缺日历、缺公告日、同期间修订、同刻冲突和首次观察晚于历史查询。不得读数据库或调用 Tushare。
- 第二片才接七个接口的有界增量采集与不可变原始版本；第三片接新表、数据契约、正式任务与派生；第四片接目录、基本面条件和真实页面。每片在本地聚焦验证和独立审查后合入。接口权限与额度只影响真实采集验收，不阻断离线纯函数。
