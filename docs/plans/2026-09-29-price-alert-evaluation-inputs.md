# 价格提醒：同代评估输入

接续已完成的价格规则配置候选。本片只建立可复用的只读评估输入与离线求值批次；不写信号总线、不发送通知、不启用页面“正在提醒”状态。任务定级为普通：跨 Serving 读模型和规则领域函数，但没有权限、生产数据、并发写入或发布变更。

## 验收

1. 价格规则与手动名单从同一个已核验 Serving 数据代、同一个借用的只读连接读取。读取器先核对两份来源状态、行数、摘要、唯一键与来源代，再按 owner 过滤。可信零规则返回 ready 空集；未激活、缺表、坏行、来源失配、过期数据代和指针变化返回不可用，不把未知解释为零。
2. 把现有 Web 规则读取的通用部分移到 `serving_` 领域读模块；Web 保持原 API 行为并复用它，不维护第二套规则与名单摘要校验。
3. 纯批次适配器把有效的 owner、股票、规则版本、名单版本与明确的交易日和报价证据交给现有 `evaluate_price_rule`。删除、禁用、过期或版本不匹配的规则不触发；缺报价、错日、午休或陈旧报价保留不可用/未触发原因，不生成告警事件。
4. 报价输入必须保留来源观测时刻及来源类型。现有盯盘网关的 `response_received_at_fallback` 不能证明价格新鲜，批次适配器必须拒绝把它当成可触发报价。本片仅接受 `provider_source_timestamp`；其他有来源时刻的通道须单独核验。当前默认报价提供器不提供该字段，因此本片不会让价格提醒上线。
5. 聚焦回归覆盖同股多 owner、可信零行、数据代或来源代切换、损坏摘要、名单版本变化、旧规则、过期成员、休市/午休、缺报价、来源时间回退，以及 Web 原有读写路径。保持核心模块不依赖 `rquant.web` 或通知通道。

## 后续接线前的硬边界

Serving 是已发布快照，可能晚于刚刚禁用或删除的 PageControl 规则。后续任何信号总线写入必须在提交点再次核对最新权威规则版本和名单版本，证明报价来源时间，并完成频率/去重的持久协议；本片的离线结果不具备投递资格。正式运行与旧 monitor 对照、生产权限、切换通知通道及停用旧服务另行验收。
