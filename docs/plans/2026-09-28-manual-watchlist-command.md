# 手动盯盘名单：PageControl 原子命令

接续 [名单领域首片](2026-09-28-manual-watchlist-authority.md)，对应 v2 C4.8。目标是在 PageControl 已有的命令库中，同一 SQLite 事务完成名单变化、效果记录和最终回执。本片仍为内部候选；网页写入口、Serving 发布、React 按钮和告警消费留到后续接线，不能据此宣称已加入盯盘。

**分级：高风险。** 命令重放、崩溃或身份注入可能使未来监控范围错乱。实现前冻结以下边界，并在最终候选做一次独立审查。

## 威胁与失败模型

- 资产与边界：PageControl 私有 SQLite 中的每用户名单、命令原文、处理租约、效果与终态回执。现有 loopback TCP 接口不证明网页用户身份；未来受保护的网页入口须注入可信 `owner_id`，本片不能让泛用 TCP `submit` 接受名单命令。
- 失败路径：相同 `command_id` 用不同内容重放；同一命令在事务提交前/后崩溃；租约过期后旧消费者完成；旧名单版本覆盖新版本；用户身份或容量越界；缺少显式功能激活时仍执行写入。
- 不变量：只有显式激活可创建名单表和启用写命令，不因普通服务构造自动迁移生产库。新增/移出均在单次 `BEGIN IMMEDIATE` 事务中执行领域 CAS，并把效果与命令终态一并提交；失败回执不得伴随名单变化，成功名单变化不得缺最终回执。原命令重试只返回同一持久结果；异内容同 ID 冲突；陈旧 claim 不能写。身份只能来自后续可信准入，不能从网页请求体直接采信。
- 排除：本片不新增 HTTP/Unix 网页写入口、Serving 表、React 按钮、行情/通知消费或生产激活；不使用 `.env`、真实凭据、网络或生产数据测试。生产数据库迁移、服务配置和切流仍须单独授权。

## 验收

1. 有类型的 `add_watchlist_item` / `remove_watchlist_item` 命令携带服务端身份、A 股代码、预期名单版本和必要的来源、价格档位、到期时间；重用领域契约，不复制验证规则。现有普通 `PageControlService.submit` 与 loopback TCP 对它们保持拒绝。受信内部提交入口须显式激活且保留同 ID 原命令恢复能力。
2. PageControl 使用现有命令库连接，在同一事务调用名单仓储并写效果及终态回执；不另建第二个数据库或做跨库双写。并发、旧版本、超容量产生明确可区分的失败状态；成功回执包含代码、动作、版本与当前状态，不把“命令已排队”写成“已加入”。
3. 离线聚焦测试覆盖激活前无迁移/拒写、成功新增/更新/移出、墓碑再加、不同用户隔离、同 ID 重试/异内容冲突、租约失效、旧版本与容量失败、提交前回滚和提交后响应丢失恢复。验证 Ruff、diff；只对本片代码与直接依赖审查，不扩为全仓审计。
