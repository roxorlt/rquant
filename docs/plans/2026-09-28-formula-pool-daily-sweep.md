# 公式池每日全目录协调入口

## 范围与分级

现有 `FormulaPoolBatchCoordinator.run()` 每次只处理至多 64 只池，操作员必须手动逐页、等 worker 完成后重新逐页核对。本片在同一受信批处理模块增加有界的整日协调入口：一次遍历完整目录、汇总精确状态，并提供供调度器反复调用的单次命令。它继续复用现有单池任务、独立 worker 和不可变逐日结果，不新增计算器或第二份队列。高风险：该入口会批量准入任务，错误汇总可能把部分完成说成全日完成。

## 验收

1. 在一份私有配置及显式交易日下，最多处理 512 只定义，按现有稳定分页走完整目录；全程绑定同一目录版本、逐日名单与历史行情来源身份。目录、来源或光标中途变化时本次整日运行失败，不返回局部“完成”。无已完成可信来源、尚未收盘或非交易日不能准入任务。配置加载仍使用当前 owner-private、规范路径入口，不从环境或网页请求推测生产路径。
2. 返回有类型、尺寸有界的整日状态：总数、已核验完成、等待共享 worker、失败，以及每只池的安全状态与逐日证据摘要。`all_complete` 仅当本次覆盖整个目录且所有定义对应版本、目标日期与双来源身份均有已重读的封存结果；可信零命中算完成，空目录在来源可信时明确为空且完成。失败与等待绝不折算成完成。
3. 同日重复调用幂等：首次可准入任务；worker 独立完成后后续调用发布并核验结果；跨页超出 64 池或共享单活动任务时仍覆盖全部目录并如实给出等待状态。异常终止后无需额外游标库，重跑即可收敛。一次命令不在进程内轮询或拉起 worker，不跨交易日，也不绕过现有 10,000 股票/120 秒单任务预算。
4. 用合成来源做红绿用例：跨页 65/512 池、空目录、首轮等待→worker→次轮完成、失败任务、源/定义换代、坏目录、结果损坏、末页/中途异常及命令输出/退出码。聚焦 pytest、Ruff、diff 自检；最终候选做一次独立高风险审查。

## 冻结失败模型

- 资产与边界：受信私有定义目录、名单/行情双来源、共享任务状态、封存逐日结果；批处理入口只负责协调，不重新计算公式。
- 失败路径：分页之间目录或来源变化；单活动任务导致后页未准入却被计完成；一次调用的本页计数误当全目录计数；旧版本/旧交易日结果复用；坏目录先创建任务状态；输出过大或无限循环。
- 不变量：整日状态绑定同一目录和双来源；已完成逐条有精确证据；单次执行和输出有上限；失败不推进虚假的“全日完成”。
- 排除：生产定时器、systemd 单元、正式私有路径/权限、真实数据负载、Serving 发布器和 React 页面。后续生产调度与部署仍须单独授权。
