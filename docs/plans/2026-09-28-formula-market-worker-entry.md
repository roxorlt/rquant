# 公式批量任务的一次性 worker 入口

## 范围与分级

把已有租约隔离的 `FormulaMarketJobWorker.run_one()` 接成可实际执行的一次性本地命令，让 PageControl 已排队的任务能完成。本片不新增定时器、常驻进程或生产启用。高风险：worker 会写任务状态与不可变结果，错误配置或重复执行可能破坏结果与来源绑定。

## 验收

1. 一次性命令只接受显式绝对路径的 owner-private 本地配置，不从 `.env`、浏览器、任务内容或当前目录推断数据路径。PageControl 与 worker 共用同一四路径配置合同和安全加载器；其代码放在中性的配置模块，避免 worker 依赖页面命令实现。缺参、宽松权限、符号链接、非规范 JSON/路径在打开任务库前拒绝。
2. 每次启动最多领取一个任务；无任务正常退出。执行前核对任务中固化的名单/投影根与当前可信配置一致，来源代仍由已有离线运行器复核；不符记明确失败，不读取任意旧路径。执行成功后任务与受控 0600 不可变产物可由 Serving 投影器验证；失败保持失败状态，不产生成功索引。输出有界的任务 ID/状态/错误类别，不打印公式全文、路径或内部栈到正常输出。
3. 同一队列的两次调用、任务中途失租约、结果文件预先存在/损坏均沿用已有 fencing 与失败语义，不增加重复成功或覆盖文件的路径。命令没有无限循环；实际调度、Linux 资源限制和生产目录权限留待部署阶段。
4. 使用合成名单和历史投影，从真实命令入口排队→一次性 worker→只读 Serving 任务/结果核验完整跑通；无任务、坏配置和错根有聚焦用例。Ruff、聚焦 pytest、diff 检查通过，最终候选独立审查一次。

## 冻结失败模型

- 资产：可信四路径配置、持久任务/租约、来源代、封存结果。
- 边界：本地私有配置→worker；PageControl 已排队请求→worker；worker→任务库/结果目录；Serving 只读验收。
- 失败路径：通过任务 JSON 中的旧/恶意根读错数据；错误权限配置启动后建库；两个 worker 同时完成同任务；失租约者发布结果；结果文件损坏仍标成功。
- 不变量：只运行与当前可信配置相同根的任务；一个任务至多一个完整成功产物；失租约与失败不显示成功；启动前拒绝坏配置无状态写入。
- 排除：生产配置与 systemd、真实 Tushare、约 10 GB 压测、Web/React 读取、保存池子。后续分别验收或单独授权。
