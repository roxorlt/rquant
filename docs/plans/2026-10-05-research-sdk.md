## 设计

- SDK 只组合现有模块。特征使用已核验的封存来源及原有有界 reader，检验调用现有因子库，结果使用已有产物 reader。不得复制指标、统计或来源校验算法。
- 入口放在 `rquant.research_sdk`。库及跨层请求、结果使用现有 Pydantic 模型；确有需要才新增小模型，不搭框架。
- 读取根和来源文件由调用者显式给出，不读 `.env`、主库或凭据，不默认搜索用户目录。不能用直接连接主库替代已核验来源。
- 特征目录来自实际来源；未知字段、越界日期或代码明确拒绝。遵守现有批大小和读取容量，不能静默截断。
- 保留原值、单位、缺失状态和原因。市场日值只有一份；需要表格时只在当前有界请求内展开，不另算全市场指标。
- Notebook 用户可直接调用已有因子检验库入口。不为同名转发新建计算层。
- 结果读取核对原有内容地址和模型。说明实际校验范围，不把展示文件读取称为完整重放验证。
- 读取采用上下文管理，成功、失败后关闭句柄。SDK 不启动后台服务，不写来源或产物目录。

## 实施顺序

1. 读现有公开 reader、模型及因子库接口，确定最小可用入口。
2. 聚焦验证：真实结构的封存包取值与原 reader 相同；缺失、0/100 和共享日值保留；非法请求拒绝；产物字节校验及失败收尾有效。
3. 增加 SDK 与简短本机 Notebook 示例。示例只使用显式测试资料，使用生产的同一库入口。
4. 实际运行示例和相关测试，记录 Python 版本、命令、结果及资源收尾。复用仍有效的因子统计证据，不重跑全仓。
5. 最终候选做一次集中独立审查；必要修复仅覆盖原 finding 及直接回归。由根任务安排合版和进度更新。
