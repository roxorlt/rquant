# 公式批量选股的网页闭环

## 范围与分级

在已校验的离线公式任务上接通网页闭环：可见数据日期、提交运行、恢复状态、查看命中及未知、保存为池子。批量计算始终由离线 worker 完成，Web 只做鉴权、查询和转发有类型命令。高风险：错误来源绑定、成功结果错配或保存池子时丢失公式语义，会产生误导性的选股结果。

## 分段验收

1. **可信提交**：新增 PageControl 公式运行命令，包含操作者、公式、所选交易日和命令 ID，不含浏览器指定路径。控制端从固定配置绑定名单归档、历史投影、任务库与结果目录，通过名单模块的安全只读指针探测取得当前摘要，校验两个当前来源代及日期后提交持久任务；命令重试恢复原任务。Web 仅接受同源 CSRF JSON，通过现有 loopback 命令网关转发，轻量请求限长；回执区分已排队、冲突和状态待确认。控制进程不做批量计算。
2. **可核对读取**：Serving 从任务库只读快照提取任务状态和已封存产物索引，验证任务与结果身份后原子发布；网页只按同一 Serving 代获取状态与结果。成功时分页展示命中代码、市场总数、命中/未命中/未知及具体缺失原因。任务排队、运行、失败、过期数据、来源缺失和结果损坏均有明确状态，绝不把部分结果当成功。正文只显示中文结果和时效，摘要与技术代号放详情提示。
3. **React 交互**：保留现有单股预览；增加“运行所选日期全市场”及较重任务确认、离开再回来可恢复的进度、失败重试、结果分页。不能运行时显示原因，不显示假成功。桌面与 390px 实走路径；检查、预览和批量运行各自只在输入/来源仍匹配时显示结果。
4. **保存池子**：先定义公式池子的有类型条件及日后重跑语义，再允许保存；保存必须绑定公式文本/语法版本与已成功任务来源，不把当日命中静态名单伪装成可重算条件。若现有 `SaveUserPoolV2` 不支持，添加专用版本合同及相容读取；失败时保留未保存的结果和可执行下一步。

## 冻结失败模型

- 资产：公式、提交者、两个来源代、任务/产物、可重算池子定义。
- 边界：浏览器→Web→PageControl→任务库→worker→封存产物→Serving→Web；文件路径和写权限不出可信控制/worker，Web 不读主库或副本。
- 路径：篡改来源 ID 或路径；命令重复排两个任务；过时 Serving 状态覆盖新回执；损坏产物标成功；只保存命中名单而丢公式；UI 用旧输入显示新结果。
- 不变量：展示的每个结果可追溯到同一任务和一对来源代；只在完整成功时允许保存；任务/结果与池子版本可明确区分。
- 排除：生产权限、systemd/nginx 修改、正式切流、Streamlit 停用、真实大库压测。它们需要单独验收和授权。
