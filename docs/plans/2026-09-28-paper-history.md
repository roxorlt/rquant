# 模拟盘指令与成交记录实施计划

**分级：高风险任务。** 这项只读功能跨越模拟盘受信账本和冻结的 Serving 共享契约；错误关联、截断或跨代读取会让用户误判订单与资产。它不提交新指令，也不改变账本撮合。

## 目标与边界

从真实 `PaperBrokerStore` 发布最近指令及对应成交，在 `/app/#/paper` 查看当日指令、最近记录和成交详情。账户、持仓与历史记录通过同一借用的 Serving 数据代读取，但分别显示实际更新时间；不把它们称作同一时刻的账本快照。首次仅发布一个有界最近窗口，明确显示覆盖范围和是否截断；完整历史查询、净值曲线、对账及回测区间对照仍属 M10 后续范围。

采用三个同属 `paper_accounts` 数据集的只读投影：窗口元信息、指令、成交。候选方案还有网页直接读 broker SQLite，或把记录塞入账户对象。前者打破网页只读 Serving 边界并可能碰常驻写锁；后者改动基础账户契约且难以独立标注窗口。因此选择投影，并保持旧数据代账户/持仓可读、历史显示“尚未发布”。

## 失败模型

- **资产与信任边界：** `paper_broker` SQLite 是指令和成交权威；SourceReadResult 及其签名来源、Serving 固定代是网页唯一读取入口。浏览器不能指定源数据库路径、账户权限或发布代；技术 ID 不放页面正文。
- **可能的失败：** 账本被篡改或处于未受信旧版本；跨账户混入指令；订单累计成交量与成交行不符；投影超额后静默裁剪；发布时 writer 正在更新订单；旧 Serving 代没有新投影；前端换代后继续展示旧详情。
- **必须保持的不变量：** 只在 `require_trusted_ledger` 成功后读取；一次 SQLite 只读事务形成窗口；所有行账户一致，成交只指向窗口内指令；每条指令经 `PaperOrder` 校验，每条成交经 `PaperFill` 校验，窗口内可见订单的成交数量与价格摘要可核对。所有时间不得晚于本次源读取截止；超容量、损坏、关系不一致时拒绝历史发布，绝不将其显示成零记录。窗口的 `has_more` 由总数与保留数计算，不由 UI 猜测；同一 Serving 数据代中元信息与数据表必须成套。缺旧代投影时保留账户页，同时说明历史未发布。
- **明确排除：** 实盘下单、模拟盘新指令写入、账户历史净值、完整历史分页、推断手机推送送达、生产数据写入与发布切流。
- **阻断范围：** 仅上述权威取证、投影边界、同代 API 与页面行为；不借审查扩大到整个 broker、全部 Serving 表或其他模块。

## 实施与验收

1. **账本读取。** 在 `src/rquant/paper_broker.py` 增加有界只读历史快照，先写聚焦失败用例，再写实现。截止时间来自发布步骤时钟；按 `updated_at, order_id` 稳定降序选最近最多 200 条指令，取这些指令的全部成交，最多 1,000 条，容量超限明确失败。读取在一个 SQLite 事务内，验证账户、时间、状态、已成交量和成交与指令关系；不可把损坏数据、失效信任或截断解释为零记录。保留总指令数和窗口截断事实。
2. **同代发布。** 在 `src/rquant/serving_read_models.py` 注册三张有界投影；由 `src/rquant/runtime_builder_paper.py` 在现有 `PaperAccountsPayload.projections` 发布，不重建第二套账本。`src/rquant/runtime_serving_snapshot.py` 的 owner 绑定继续保护投影。旧 payload 缺投影仍合法。新增聚焦用例验证空窗口、部分成交、拒单、跨账户、篡改、超容量和读写竞争边界。若现有 `PaperOrder` 平均价的存储精度无法与逐笔精确相等，验证应使用与 broker 相同的计算口径，不引入第二种价格算法。
3. **网页 API。** 扩充 `src/rquant/web/routes/paper.py` 与 `models/paper.py`，在现有一次 Serving lease 中校验三表和 manifest 行数/状态及关联，再返回短中文状态、最近指令与成交。缺三表为“未发布”，可信空表为“没有记录”，损坏或不成套为 503。限制响应行数；详情含订单/成交精确数字，内部 ID 仅作为机器身份或 tooltip。重新生成 OpenAPI 与 TypeScript schema，并跑网页 API 聚焦测试。
4. **React。** 在 `web/src/pages/paper/` 添加“今日指令”和“最近指令”视图、状态/方向/时间及成交详情；选账户和 Serving 换代后清理旧选择。窄屏保留代码、方向、状态与股数，次要信息进入展开详情；拒单原因用面向用户的短中文，技术原因放提示。旧代、真空、加载、失败、窗口截断均有诚实文案。使用已有 `DataTable`、`Tip`、`RelativeTime` 和统一格式器。焦点、390px 和按钮可操作性由聚焦 Vitest 与浏览器路径验证。
5. **终验。** 每一步采用相关红测到绿测或等价行为证据；运行直接受影响的 Python 测试、`pnpm -C web check`、构建与 `verify:dist`、聚焦 Playwright。候选版本只安排一次独立高风险审查，针对本计划失败模型集中给出发现；修复和复核遵守根 `AGENTS.md` 的三轮上限。更新 React 进度表，保持 M10 “部分且未发布”。正式服务器数据代、发布及 Streamlit 停用另行验收与授权。
