# 策略模板、版本与详情

## 目标和风险

完成 v2 的 C5.1、C5.2：新建策略、保存新版本、归档、查看规则和版本历史，并关联同版本的最近回测。原型和差距表已授权这项工作。

本片是高风险任务。新入口涉及用户隔离、不可变版本、并发保存和中断恢复。风险只限这些新增边界及执行绑定；不重新审查已有回测计算、定义登记或撮合规则。

## 复用和边界

- 版本正文使用原 `ImmutableDefinitionRegistry` 和 `StrategySpec`。登记的版本不可改写，也不创建另一套定义登记。
- 原 PageControl 记录保存、归档和原请求恢复。版本名称、改动说明、归档状态和用户归属是附属元数据；它们不能替代原定义正文或执行绑定。
- 受控模板只引用已有池子、筛选条件或已有信号，配置退出、仓位、调仓和指数过滤。计算和参数校验复用已有领域模型，不接受任意代码、路径或可执行对象。
- 模板有自己的精确执行绑定和完整输入，复用组合回测的原队列、worker、成本和研究账本。`portfolio_backtest@1` 的定义和输入保持。保存时固定完整规则；运行时绑定实际来源、区间和成本。缺少所需数据时可保存，但不能运行。
- 新网页与只读 API 消费同一份版本事实。共享命令、注册、接口类型和编译产物由 root 串行接线。
- C5.3 的证据评估及手动晋级属于下一片。不得把原实验登记的自动 `approved` 当成用户手动批准。

## 资产和信任边界

保护原不可变定义、用户所属策略、版本 head、命令回执和精确回测引用。浏览器只提供受限模板、显示名称、改动说明、期望版本及原命令身份；不能提供 actor、可信执行绑定或文件路径。

用户身份沿用私有代理核验及 CSRF。配置默认关闭。保存服务从原受信目录解析引用，在写入前核验所有参数和模板能力。归档只关闭新操作，已封存的旧版本和结果继续可读。

## 模板字段和范围

只提供一个完整受控模板。入场来源从池子、条件、信号中选一种。所有数值必须有限；整数不接受布尔值。完整保存正文不超过 32 KiB，名称为 1–80 字，改动说明不超过 1,024 字。

| 字段 | 固定合同 |
|---|---|
| 池子入场 | 原池子精确 key、version 和正文摘要。用户池子须核对所属用户；不按当前同名池子猜配。 |
| 条件入场 | 1–26 个原筛选积木，按 AND 合并。名称、参数和上下限由原受控目录校验；拒绝额外参数、任意表达式和代码。 |
| 信号入场 | 原受信目录的精确策略 ID、版本、信号动作和来源摘要。只消费已确认且在决策前可用的信号。 |
| 止损 | 可关闭；开启时收益阈值为大于 0、小于 1 的 Decimal 比例。达到阈值退出全部可卖数量。 |
| 止盈 | 可关闭；开启时收益阈值为大于 0、不超过 10 的 Decimal 比例。达到阈值退出全部可卖数量。 |
| 移动止盈 | 可关闭；开启时从持仓后已知最高决策价回落的比例大于 0、小于 1。不能读取尚未发生的日内高点。 |
| 最长持有 | 可关闭；开启时为 1–2,520 个交易日，按原交易日历计数。 |
| 定时退出 | 可关闭；开启时为上海时间 09:31–11:30 或 13:00–15:00 的整分钟。必须有该时刻的分钟价、交易状态和观测证据；不能用日线开收盘代替。 |
| 仓位 | 原 `PortfolioWeightRule`；等权或排名权重，最多 500 只，单票和行业比例大于 0、不超过 1，现金比例为 0–1，最小金额精确到分。 |
| 调仓 | 每日、每周、每月或每 N 个交易日；N 为 1–252。 |
| 指数过滤 | 可关闭；开启时使用原六种基准之一、1–250 日均线、线上或线下。原始收盘和均线窗口须在入场决策前可用。缺窗口拒绝该运行。 |

退出每个决策点先核对原可卖数量及停牌、涨跌停。多个退出同时触发时按止损、移动止盈、止盈、最长持有、定时退出的顺序记录一个原因。退出先于新增仓位；同一决策点已退出的股票不能立即买回。指数过滤只限制新入场，原退出继续生效。

## 版本到执行的精确路径

1. 服务端为新策略生成逻辑 ID `template_<uuidhex>`。浏览器只能提供原命令身份；同一原请求恢复时使用第一次固定的逻辑 ID。显示名称不能作为执行身份。
2. Compiler 校验上述完整正文，生成该逻辑 ID 的 `StrategySpec`。版本由原 head 的下一版本确定；完整入场、五种退出、仓位、调仓、指数过滤及模板合同版本进入不可变 `parameters`。名称和说明不替代正文。
3. 服务端构造 concrete `TrustedStrategyImplementation`。逻辑 ID 必须精确相同；入口、退出和运行函数是 `strategy_template_execution.py` 中固定的顶层函数，语义版本固定为 `strategy-template/v1`。候选模型摘要和退出规则随固定合同登记。调用方不能提供 callable、模块名或 resolver。
4. 模板使用原登记器中的独立固定 FeatureContract `strategy-template-entry/v1`，绑定入场判定、指数判定和原持仓生命周期字段。判定来自受信输入生产者对完整规则的实际计算，不接受浏览器提供的通过标志。固定函数声明由服务端生成，原 registry 发布协议及任意 resolver 禁令保持。
5. 保存附属事实只引用原 registry 的精确回执：owner、逻辑 ID、version、spec/record hash、父版本和完成状态。一个逻辑 ID 的不同版本使用同一固定函数族，各版本读取自己的完整不可变参数。归档不能改写旧正文。
6. 原 PageControl 对精确已保存版本核验 owner、head 和归档状态。受信准备固定 `FrozenStrategyTemplateInput`：原日线材料、完整模板、精确定义回执、所需入场/指数证据及定时退出分钟证据，再绑定来源、成本、日历、代码和配置摘要。
7. 新 `StrategyTemplateRunInput` 的 task strategy_name 等于原登记逻辑 ID。服务端只为已核验的逻辑 ID 构造一个精确 adapter；adapter 身份含该逻辑 ID，计划和输入另外绑定精确 version/hash。原 adapter registry 按完整名称和 job_type 查找；禁止前缀匹配或通用放行。
8. 原 Lab、实验登记和 worker 执行新 adapter。模板执行器消费每项完整规则，并调用原权重、风险、成本及 `PaperBrokerStore`。它只写本次私有研究账本；不新建撮合或实盘能力。C6 原日线 runner 和输入不接受模板别名。
9. 封存结果同时绑定 template input hash、精确定义身份、来源和原账本结果。列表及每版最近回测按这些精确引用读取；不同版本即使参数或名称相近也不能共用结果引用。

模板执行器负责新入场和五种退出的决策。原 broker 继续负责 T+1、数量、资金、成交和费用；原绩效模块继续负责结果计算。若确需复用原 runner 的决策钩子，root 先记录有类型最小 diff 和直接失败用例；原默认调用、旧正文和 C6 固定身份必须保持。

## 保存、恢复和归档顺序

原请求先 lookup，再检查当前目录和来源。新保存先冻结完整候选及期望 head，再通过原 registry 发布，最后提交附属 head 和回执。附属写入在私有单事务中核对 head；中断后只恢复第一次固定的正文和精确登记结果。已发布但未提交附属事实的版本不能进入可运行目录。

归档与新保存、运行共享策略级准入顺序。归档先提交时拒绝后续新操作；新命令先受理时可恢复该原命令。只读列表、详情和 versions 使用同一份有界附属事实，不扫描 registry 中的孤儿版本。S4 `strategy_definition` 发布这些已确认版本，不能从正文目录自行推断 owner 或归档状态。

## 必须保持的不变量

| ID | 要求与失败用例 |
|---|---|
| ST-01 | 任意代码、未知模板、越界参数、额外字段及非有限数在写入前拒绝。合法编译结果与手写等价 `StrategySpec` 一致。 |
| ST-02 | actor 来自已核验身份。其他用户的定义、引用和命令不能读取、修改或恢复。普通 TCP 和裸用户头不能写。 |
| ST-03 | 只有原登记确认的正文和可信绑定可保存。模板名字或 ID 不能自行获得执行权；不放宽原 registry 的 allowlist 或版本合同。 |
| ST-04 | 新版本只追加，期望 head 必须匹配。同一 head 的并发修改最多一个成功；失败不会改旧版本。 |
| ST-05 | 原命令重试先核对已存请求。相同命令同正文返回原结果，换正文拒绝；后续目录变化不能使已成功原请求再次写入。 |
| ST-06 | 定义发布与附属元数据之间中断时，原命令能核对精确正文后续完。未确认版本不能显示保存成功或进入可运行列表；孤儿版本不靠目录扫描自动放行。 |
| ST-07 | 归档要核对 head。归档后新保存和新回测拒绝，原版本、命令回执和已封存结果保持可读。 |
| ST-08 | 列表、详情、版本和最近回测引用同一策略版本及内容摘要。缺回测显示空态，不套用其他版本或原型示意绩效。 |
| ST-09 | 页面换用户或数据来源后清除旧详情和可写状态。未知回执保留原命令供恢复，不重复创建。 |
| ST-10 | 受控模板回测复用原队列、worker 和账本。完整结果绑定原定义精确版本；保存不会启动监控或写模拟盘。 |

## 使用路径

策略页点「新建策略」后按入场、退出、仓位和调仓填写。必要说明放提示；桌面可悬停或聚焦，手机可点按。保存前显示可读的规则摘要。编辑只新增版本，并填写改动说明。

列表显示名称、阶段、当前版本和最近回测。详情显示完整规则、参数范围、版本历史和各版本最近回测。无来源、无回测、已归档、加载、失败和权限失效分别给出短文案。阶段先读已有证据；没有事实时不补示意数据。

390px 不横向溢出。键盘可选择策略、完成向导和关闭抽屉，关闭后返回原入口。归档用既有确认框，未知回执明确等待确认。

## 执行顺序与验收

1. 按上面的固定模板和精确版本路径实现。任何必要的共享适配先记录明确 diff，并在写入前补对应失败用例；不能为了展示按钮放宽能力。
2. 冻结受控模板、命令和有类型响应。按 ST-01 至 ST-10 先做红测，再补编译、原保存/恢复及版本读取。
3. 接同代目录与 React，验证实际保存、编辑、归档、旧版本查看、最近回测和未知回执恢复。
4. 用独立临时环境走新定义到原生 worker、原账本和封存结果的精确版本路径。完整规则与手算参考核对：三种入场、五种退出、指数过滤、仓位、调仓均有实际案例。仅退出参数改变须改变相应决策；未来观测、错版本和缺定时分钟材料须拒绝。原撮合和成本有效证据继续使用。
5. 验证 1440px、390px、键盘和换用户。一次集中最终独立审查；原作者修复，原审查者定向复核。有效结果继续使用。

正式权限安装、生产目录更新和 Streamlit 停用继续按既有发布边界。验收资料保存在项目内，原失败与冻结记录保留，自有进程和临时数据清理。使用既有任务工作树，不新建仅供审查的工作树。
