# 通达信公式导入实现计划

**目标：** 让用户粘贴常见通达信选股公式，看到可解释的解析结果，在同一数据日期预览命中股票，并将验证过的公式保存为可重复运行的池子。此项对应 v2 C4.5；原型未画出导入入口，放在选股器的条件区，不占用页面正文的长篇说明。

**架构：** `rquant.screen.tdx` 只负责受限语法、类型/窗口检查和纯向量求值；网页 API 负责输入边界、当前数据代和响应；持久化由 PageControl 管理。公式求值与内置积木共用一个有时点约束的历史数据视图，绝不让浏览器、网页 API 或公式语言执行任意 Python，也不把公式文本直接插入 SQL。当前 `save_user_pool` 只接受内置 `RuleCall`，不能用它假装已保存通用公式；待 C4.6 的版本化命令扩展后接通保存。

**技术栈：** Python 3.11+、Pydantic、pandas、已有 `mytt` 依赖、FastAPI、React/TypeScript；生成接口类型仍走 Pydantic → OpenAPI → TypeScript。

## 事实与依赖

- `src/rquant/llm/registry.py` 的 26 条积木不是通用公式 AST；`src/rquant/page_control.py:SaveUserPool` 仅保存 `RuleCall`。
- 公式支持 `MA`、`EMA`、`SMA`、`REF`、`HHV`、`LLV`、`CROSS`、`COUNT`、`SUM`、`IF`、`BARSLAST`、`EVERY`、`EXIST`、`AND`、`OR`、`NOT`，以及 `CLOSE`、`OPEN`、`HIGH`、`LOW`、`VOL`、`AMOUNT`。不支持项逐个报告，不能忽略后继续执行。
- 当前 Serving `nl_screen_universe` 只有当日宽表；规则偏移最多 30 日、窗口最多 500 个交易日。其 512 列、6 MiB/表上限不容纳直接展开所有历史值。C4.1 的有界历史读取设计是公式**预览与保存后日常运行**的前置条件；解析器本身可先独立落地，但页面在历史输入就绪前不得展示可执行的导入按钮。

## 冻结的风险边界

**资产与边界：** 用户提供的公式是未信任文本；数据代与池子定义是可信的只读/受控权威；研究副本、主库、通知和生产配置不由解析器访问。公式 AST 从网页进入纯计算函数，保存只能经 PageControl 的版本化命令，旧 `save_user_pool` 的语义保持。

**失败路径：** 任意代码/文件/网络访问、无限递归或超长窗口、未来数据引用、除零和非有限数、缺失历史数据、不同数据代混用、解析通过却因不支持函数而假装可运行、保存后版本漂移、同名池子被覆盖。

**不变量：**

1. 不使用 `eval`、`exec`、动态 import、表达式字符串 SQL 或用户可选 Python 函数。词法仅接受白名单标识符、数字、括号、运算符、赋值和分号；每个 token 保留源位置用于短错误提示。
2. 限制公式 UTF-8 字节数、赋值数、token 数、AST 深度、节点数、历史回看和一次求值的股票×日期预算；超限显式拒绝，不截断。
3. `REF` 的偏移、时间窗和均线周期只能是经静态检查的非负/正整数，并受统一上限约束；输入数据晚于决策时刻或来源缺失时不求值。布尔结果须按股票、日期对齐；NaN 不当作真。
4. `POST /screen/tdx/parse` 只返回规范 AST、翻译计划、错误位置和不支持项，不写池子、不调用 LLM。`预览` 明确绑定数据代和交易日；换代后旧游标/结果不可复用。
5. 保存时由受控命令重解析并固定语法版本、规范 AST 哈希、数据依赖和用户填写的名称；命令未成功时页面不得显示“已保存”。既有内置池子与 v1 用户池子继续可读。
6. 生产数据写入、服务配置、部署、切流和停用 Streamlit 不在本增量范围。

## 实施步骤与验收

### 1. 受限解析器（可独立交付的第一增量）

- 新建 `src/rquant/screen/tdx/{tokens,ast,parser,validate}.py`，用带位置的 token 和显式优先级解析；变量赋值只在公式内引用，最后一个输出表达式必须是布尔值。AST 用 Pydantic 判别联合并固定语法版本；无调用外部系统的入口。
- 新建 `tests/unit/test_tdx_parser.py`：先写常见公式、嵌套函数、优先级、赋值复用、不支持函数逐项报告、未来偏移、越界与恶意文本的红测，再实现到绿。命令：`uv run pytest tests/unit/test_tdx_parser.py -q`。
- 在 `src/rquant/web/models/screen.py`、`src/rquant/web/routes/screen.py` 添加只解析的 `POST /api/v1/screen/tdx/parse`；输入与错误均给简短中文可操作文案。生成 `web/src/api/openapi.json` 和 `schema.d.ts`，以 `tests/unit/test_web_screen.py` 验证接口及错误。此时不在页面放可执行按钮，也不宣称 C4.5 完成。

### 2. 纯函数求值器（依赖 C4.1 历史输入契约）

- 新建 `src/rquant/screen/tdx/evaluate.py`；把规范 AST 编译为受控的 pandas/MyTT 运算，按股票、交易日期分组，统一定义 MA/EMA/SMA/REF 等边界与缺值，输出布尔序列及所需最早日期。不得在求值器里读库或调用网络。
- 新建 `tests/unit/test_tdx_evaluate.py`：先用手算 OHLCV 和现有 MyTT 固定参考值验证所有白名单函数，再测未来数据不可见、缺值、零除和大输入预算。与内置规则等价的公式应在同一历史样本上命中同一股票。
- C4.1 的历史输入实现须先给出固定数据代、覆盖范围、可见时刻、行/字节与耗时上限的真实格式回放；再接 `POST /screen/tdx/preview`，响应含数据日期、命中数、前几只和不可用原因。聚焦测试要证明当前日与历史日无穿越。

### 3. 保存与 React 导入交互（依赖版本化池子命令）

- 在 C4.6 的 `save_user_pool_v2` 中添加公式定义类型；PageControl 重新解析、校验语法版本及哈希后原子保存。旧命令与旧池子不改，保存后日常池子运行读取同一规范 AST。测试同名冲突、幂等重试、坏版本和恢复。
- 在 `web/src/pages/screener/` 添加「导入公式」对话框：粘贴 → 解析错误定位/不支持列表 → 预览命中 → 输入池子名并保存。帮助放在 `Tip`，页面正文只显示动作和结果；按钮的加载、失败、空数据、换代与 390px 状态均有行为证据。
- 聚焦验证：Python parser/evaluator/API/PageControl 测试、`pnpm -C web check/build/verify:dist`、桌面与 390px 浏览器走通粘贴到保存并在池子列表复见。最终候选一次独立审查，阻断问题按根 `AGENTS.md` 的高风险轮次上限处理。

**停点：** 本计划允许先交付解析 API 作为基础能力，但必须在页面与进度台账标为“部分”；完整 C4.5 验收以预览及持久化都真实可用为准。任何需要变更生产服务、主库或部署配置的步骤先独立准备可审查的改动，再按仓库授权规则执行。
