# 日线回补计划与受控执行

对应 v2 C1.3 和数据中心「生成回补计划」。先交付只读计划、产物与网页预览；写入生产主库、systemd 回补单元和开关是另一个需单独授权的实施片。2024-09 至 2025-04 的空洞是优先核对的目标区间，实际缺日必须以当时同一只读副本的 SSE 日历与日线证据重算，不复制原型里的演示数字。

**分级：高风险。** 计划会指向后续生产写入；过期或错误的日期、来源与成本估计可能导致覆盖正确数据、耗尽接口额度或与日常写者争锁。本文件冻结资产、失败路径和验收边界；本地只读片可先实现，生产执行前再核验实际运行环境与单独授权。

## 资产与信任边界

- 资产：权威 SSE 交易日历、已封存的只读副本及其身份、`daily_bar`/`daily_basic`/`adj_factor` 与派生 `daily_state`、Tushare 配额、不可变计划产物、PageControl 命令回执、执行日志与生产 DuckDB 主库。
- 浏览器只发起计划请求和展示结果，不读主库、不提交日线或自行估算缺日。Lab 任务在固定只读副本上取证；计划产物内容寻址并经 Serving 小表/有界预览供网页读取。网页与 Serving 不打开生产 DuckDB 主库。
- 计划只说明「这份副本在这些历史已收盘交易日没有任何日线行」。某日有一行不证明全市场每股完整；此类逐股缺口须另有完整名单与来源凭据，不能由本片计划推断。截止日由请求明确给出并按上海交易日收盘核验，不能取当前未收盘交易日；采集完成凭据缺失时，计划可作为待核对建议，但不能自动进入可执行状态。目前审计报告的生产来源模式仍是 `production_unverified`，其人工 `snapshot_label` 不是已验证的副本身份。
- 生产执行由受控运维服务启动新的**精确日期批次执行器**；现有区间式 `market-daily-backfill` 只提供可复用的取数与重算逻辑，不能原样用作计划执行器。Lab/Web/PageControl 不直接写主库。策略开关默认关闭，且执行要求本次明确授权、精确计划哈希、允许时间窗及唯一在运行实例。任何生产 unit、sudo、数据库写入或权限变更按项目规则另行授权。

## 必须保持的不变量

1. **只读计划身份。** 计划绑定 `dataset=daily_bar`、审计区间、已收盘截止日、SSE 日历证据、固定只读副本文件的可复核身份、缺失交易日的完整有序集合、取证代码版本、所用来源接口、预计逻辑调用量与估时假设，并显式标记采集完成证据是否可核验。相同输入及规则得到相同内容哈希；日期、来源或假设变更产生新哈希。人工 `snapshot_label` 不可冒充生产身份链。计划最长覆盖现有审计上限 3,660 自然日，不能吞掉超限日期、缺日历日或重复日期。
2. **缺口与估计分开。** 缺失日期由同一固定副本的逐日日历与行数取证，不用网页筛选结果、缓存的月度比例、当前时钟或计划列表推算；复用 C1.2 的同连接覆盖取证，不从缺口起止日期直接展开自然日而误纳休市日。计划按**一次精确日期批次**估算：每目标日 `daily`、`daily_basic`、`adj_factor` 各一次逻辑操作，`namechange` 上下文整批预取一次，`stock_st` 按逐日上限单列；本执行器不再远端请求 `trade_cal`，以已核验的 SSE 日历为准。各项耗时、节流与重试假设分列，页面只写「预计」。这些是可观测的适配器逻辑操作，内部重试/真实 HTTP 次数与 Tushare 实际扣额不可由当前适配器证明；额度未知显示「待确认」且生产执行拒绝，不偷偷远程探测，也不把估计写成承诺。
3. **计划不可变。** Lab 原子发布计划文件与摘要；失败不覆盖旧产物。Serving 读取前后核对文件与摘要，网页从同一 Serving 数据代读取不可变计划概要/逐日任务和单独的任务进度投影；进度变更不改写计划哈希。旧计划可看但须标出源副本时间；副本换代、审计过期或完成凭据不充分时撤去新执行的「可执行」提示。已受理的同一任务按持久回执续做，另按第 6 条核对剩余目标。
4. **互斥与时间窗。** 生产前须将所有会写或复制云端主库的受控入口纳入同一个新增的回补排他锁：`rquant-daily`、常驻 `rquant-monitor`、备份、只读副本同步及其手工脚本持**共享锁**贯穿整个进程；回补执行器持**独占锁**贯穿整批取数、逐日写入和恢复。现有 `rquant-workload-arbiter maintenance` 的共享锁不提供这层互斥，不能直接复用为证明；安装后须核对线上实际 unit/脚本清单和锁路径，缺一个入口便保持执行开关关闭。回补在上海时间工作日 17:50 后或周末才可争锁，等到 daily/备份结束才进入；每个工作日上午 08:20 前停止接新日期并释放锁，08:30 是硬截止。08:29 请求、截止前不足以完成一个有超时界限的日期、跨窗阻塞或失去锁均暂停/拒绝，不能拖到盘中；跨夜/周末计划以同一任务恢复。锁、unit 和生产策略实施需单独授权。
5. **执行重新取证与写集。** 取得独占锁后，从主库重新核对计划哈希、SSE 日历、截止日、来源身份和全部目标日期；不能只信取锁前的只读副本。仅处理计划列出的稀疏日期，逐日期在同一主库事务内再次核对 `daily_bar`、`daily_basic`、`adj_factor`、`stock_status` 当前键集和已提交回补回执。没有本任务有效回执的 `daily_bar` 目标必须为零行；关联表已有键只读保留，缺键才可插入，抓到与新源冲突的既有行则阻断该日，不允许沿用当前 `INSERT OR REPLACE` 覆盖。计划显式声明受影响股票自目标日起的 `daily_indicator`/`daily_state` 尾段会失效并重算；重算完成前不发布健康结论，不能静默删除或改写计划外的源表。零日线但关联表已有行的合成用例必须证明原行字节不变。计划来源代已过期、出现外部新日线、任一副本/主库身份不符或锁不可用时，不受理新任务；已受理任务按下一条的回执恢复，不能把外部写入误当本任务成果。现有区间 CLI 会处理整段交易日并改写关联表，不能直接调用。
6. **持久进度与结果。** 新执行器按上面的一次批次策略预取共用上下文，逐日期以 `(plan_hash, task_id, trade_date)` 记持久回执。事实写入与该日 `facts_committed` 回执在**同一个 DuckDB 事务**提交；回执绑定来源与目标键/内容摘要。崩溃后只有回执存在且主库内容仍匹配的日期可跳过，回执不存在却已有日线视为外部/不明提交并拒绝自动续写。跨夜恢复允许副本因本任务已提交日期和常规新交易日而换代，但必须用回执解释本计划中已有行、重新核对剩余目标与日历；不能把旧来源代直接当新任务许可。派生尾段另有待重算/已核验阶段，恢复时先补该阶段；只有全部日期、派生重算、刷新副本及新审计均核验通过才显示「回补完成」。记录每日期成功/失败与已观测的**逻辑适配器操作数**，不称真实 HTTP 次数或实际配额扣额。部分日期失败、跨窗暂停、派生失败或未发布新审计均保留同任务身份与准确状态，不生成新计划来掩盖部分成功。
7. **页面状态。** 数据中心提供计划列表、缺口日期、预计耗时、当前任务状态和有界日志；没有计划、生成中、失败、过期、跨窗暂停、部分完成分开显示。高风险执行按钮只在生产开关与授权条件满足时出现，并用服务端预览票据作两步确认。正文文案短，技术哈希、路径、服务名与原始错误只在必要详情或提示中出现。

## 失败路径与聚焦验收

| 情况 | 必须看到的行为 |
|---|---|
| 副本中有 2024-09 至 2025-04 的部分缺日、休市日、区间中途断档 | 只列历史已收盘的 SSE 缺失交易日；休市日不计任务，缺口段数与逐日集合一致。 |
| 区间没有整日空洞 | 显示「这段时间没有整日缺失」，任务数与估计请求数均为 0；不据此断言每只股票完整或采集已核验。 |
| 同日有少量日线，但可能缺股票 | 不把该日称全市场完整，也不把逐股缺失隐式加入本计划；标明本片只能检查整日空洞。 |
| 日历/副本身份不一致、截止日无采集完成凭据、产物损坏或换代 | 拒绝可执行状态；网页保留准确的未知/过期原因，不显示成功。 |
| 估时依赖限流、权限或额度而无可信输入 | 显示估算假设和「配额待确认」；不远程探测、不虚报可执行。 |
| 开关关闭、窗口外、计划哈希不符、日期已有新数据或写者正在运行 | 生产执行请求拒绝，主库与 PageControl 命令状态不发生错误变更。 |
| daily 持续到 18:00、备份与回补争锁，或 08:29 请求、任务跨过截止 | 回补等全部共享锁退出后才取独占；截止前停在日期边界并释放，次窗持同任务恢复；安装入口缺锁则始终拒绝。 |
| 日线整日为空，但关联表已有正确行；或某现有键与新源不同 | 正确现有行保持原样，缺键按明确写集补齐；冲突日拒绝，不把区间 CLI 的替换行为带入。 |
| 日期 A 已原子提交、B 失败，或提交后进程立即崩溃 | A 有同事务回执且内容一致则跳过，B 仍可在同任务重试；无回执的新行被视为外部/不明提交并停住。 |
| 逐日执行会重复公共预取、适配器内部自行重试 | 使用一次精确日期批次，估算与观测只计逻辑操作，页面不称实际 HTTP 次数/配额。 |
| 写入中断、部分日期失败、派生状态重算失败、回补后审计未通过 | 记录可恢复进度与实际结果，页面不宣布完成；未重新核验的数据不标健康。 |

## 实施顺序

1. 固定只读副本与 SSE 日历，复用 C1.2 的逐日取证形成缺日集合，再用纯计划函数形成接口步骤与显式估算；合成小库验证边界和重复运行。沿用现有 `market_backfill.py` 的日线接口语义，但只读计划不调用 `TushareAdapter` 或写者。现有 `market-daily-backfill --dry-run` 仍会调用 `trade_cal`，因此不能作为离线计划接口复用。
2. Lab 任务封存不可变计划，Serving 发布有界索引与预览，网页 API/React 接通「生成回补计划」及列表、进度、日志的只读路径。此片不提供可点击的生产执行假按钮。
3. 取得生产基础设施与写入授权后，再实现运维策略、精确哈希预览票据、systemd 单元、写者串行及故障恢复；在云端核验 unit 语法/权限和真实配额、约 10 GB 副本负载、生产回退路径。获得新审计结果并核对用户路径后才宣布回补完成。

## C1.3 只读计划任务契约（2026-09-27）

「生成回补计划」使用独立的 Lab 数据维护任务队列，不伪装成策略回测任务。受信任的服务端装配固定副本路径、O(1) 捕获的文件指纹（设备、inode、大小、mtime、ctime）、审计区间、已收盘截止日、来源标签、取证代码版本和估时假设；浏览器只提交幂等键与用户可选的有界日期，不提供文件路径或身份。提交路径不扫描约 10 GB 的副本，也不打开 DuckDB。worker 领取后由产物函数首次流式计算 SHA256，并在取证后第二次核对摘要；首次摘要在建立固定硬链接之前写入有租约保护的任务记录，供崩溃重试使用。硬链接固定本身会改变 inode 的 ctime；有持久摘要的重试允许仅 ctime 改变，但仍核对设备、inode、大小、mtime 和完整 SHA256。该指纹与摘要仅固定取证输入，不能冒充副本来源或采集完成证明。单份请求最长 3,660 天，队列总记录有硬上限。提交成功只表示已排队。

队列状态写在专用 SQLite 文件中，和计划文件不同位置。任务领取有持久租约、定期续租及 fencing token；进程在原子发布计划后、写回成功前崩溃时，过期任务可按原请求重做，内容寻址发布保证重复结果一致。成功状态写入前和读取成功状态时都复验不可变产物的文件名、内容摘要与请求身份。副本变更、产物损坏、取证失败只呈现有界失败类别，不把原始错误或路径送到页面，也不把未完成任务显示为成功。失败任务只能按原请求显式重试；换副本必须提交新任务身份。此任务不调用远端数据源、不写生产主库，也不运行回补执行器。

服务端接线须先按浏览器稳定请求 ID 续查已受理的完整请求，再决定是否装配新任务。相同 ID 的重试不可重新绑定当前时钟、副本代、文件指纹或估时假设；否则合法重试会被任务队列判为不同请求。新副本或新截止日由新的请求 ID 明确表示。完整请求的幂等比对保留在队列内。

PageControl 的 `submit_backfill_plan` 命令只含稳定命令 ID、请求时间、操作者及有界审计日期。其私有后端先按 ID 查任务队列；已受理命令直接恢复原任务 ID，再由 PageControl 的完整命令哈希校验操作者与日期。新命令才从本机受信配置绑定主库与只读副本的不同文件身份、队列路径、计划目录、取证代码版本和估时假设；提交不连接 DuckDB 或读完整副本。PageControl 的成功回执只表示「任务已排队」，计划是否生成由独立任务状态说明。缺后端、缺副本、主库别名或 WAL 一律拒绝受理。
