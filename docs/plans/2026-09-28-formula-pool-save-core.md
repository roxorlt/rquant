# 公式池子的可信保存核心

## 范围与分级

只实现[公式池子语义](2026-09-28-formula-pool-definition.md)的第一段：有类型定义、PageControl 保存命令、持久化与读取验证。暂不加 Web/React 保存按钮或每日运行。高风险：写错定义或错误复用任务结果会让以后池子逐日运行失真。

## 验收

1. `save_formula_pool_v1` 只接收目标名称/显示名、已成功任务 ID、幂等命令 ID 与期望定义版本；不接收浏览器传来的公式、命中名单或路径。可信后端从任务库同一任务读取公式请求、封存产物与来源摘要，确认结果完整、公式摘要/日期/两来源身份一致，再生成 `schema_version=1`、明确公式语法合同版本和创建证据的定义。创建证据不是未来重算的固定来源。
2. 本段只创建新定义，`expected_version` 必须为空；编辑旧公式定义另设后续版本命令。使用单独受控的公式定义目录与原子私有文件；全局 `user/` 名称不得与现有规则池重名。名称冲突、非空期望版本、已存在文件损坏或链接均拒绝覆盖。既有 `SaveUserPoolV2`、规则池加载/发布行为不变。定义含稳定内容版本，可按版本重读核对。
3. PageControl 原命令重试恢复同一版本，不能重复创建或覆盖；命令失败不产生“成功定义”。若定义写成而回执未完成，恢复路径可核对文件与原命令身份。对任务排队/运行/失败、产物损坏/丢失、公式摘要错配与目录不安全均拒绝。
4. 用合成公式任务真实排队→一次性 worker 完成→PageControl 保存→定义读取走聚焦测试；并测试改名/覆盖、幂等恢复、同名规则池与坏结果。Ruff、聚焦 pytest、diff 检查通过，最终候选独立终审一次。不改生产目录/部署。

## 冻结失败模型

- 资产：公式原文与语法版本、目标名称与定义版本、成功任务/封存结果、两个来源身份。
- 边界：受信 PageControl→只读任务事实/封存结果→受控定义目录；浏览器未来只能提交标识与名称。
- 失败路径：选择另一任务的结果；解析版本升级后静默改语义；同名覆盖旧规则池；写文件后回执丢失再重试造成不同定义；坏文件/链接被当成旧版本覆盖。
- 不变量：每份保存定义可重算且有经核验的创建证据；同名冲突不隐式覆盖；一次命令最多形成一个确定版本；旧规则池合同不变。
- 排除：Web/React、每日重算、Serving 定义投影、生产配置与切流。保存核心未接重算前，页面不得展示可用的「保存为池子」。
