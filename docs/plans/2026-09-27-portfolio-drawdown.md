# C9.2 组合回撤控制：纯领域增量

> 2026-09-27。普通任务；只新增 `src/rquant/portfolio/drawdown.py`、直接测试和必要的包导出。没有账户、订单、存储、网页或生产契约变更，C9.2 用户功能仍未完成。

## 决定与合同

- 输入为当前时刻已知的正净值、带时区观测时间、不可变规则和上次返回的状态。状态保存历史峰值及发生时间、上次观测净值与时间、触发锁存位和规则。无状态首次调用以当前净值建峰，不能回推历史；调用方必须逐次保存状态，规则变化须从历史重算或显式开新序列。
- 当前峰值为 `max(旧峰值, 当前净值)`；同值重访保留第一次峰值时间。当前回撤为 `(峰值 - 当前净值) / 峰值`。只用本次及此前观测，不读未来数据；规则比较使用精确数值，展示用回撤小数保留 18 位。
- 规则包含触发回撤 `0 < trigger < 1`、恢复回撤 `0 <= release < trigger`（默认 0）、动作 `block_new_positions` 或 `cap_total_risk_weight`。第二种动作要求风险仓位上限 `0 <= cap < 1`，第一种动作不接受该参数。
- 未锁存且回撤 **达到**触发阈值时锁存；已锁存且回撤 **降至或低于**恢复阈值时解除。触发期间，`block_new_positions` 仅返回“不得开新持仓”；`cap_total_risk_weight` 返回配置的总风险仓位上限。解除后不加限制。退出或降低已有持仓始终由调用方允许，函数不执行交易或改变持仓。
- 非正/非有限净值、同一或倒退观测时间、无时区时间、非法阈值/上限、前态峰值小于末次净值、峰值时间晚于末次时间、规则中途变更，均显式拒绝。状态无法证明未提供的更早历史，调用方负责提供完整且按时序的 NAV。

## 实施与验收

1. 先写手算红测：`100 → 90 → 80` 的峰值/10%/20%，触发点等号，两种动作；恢复阈值两侧、连续调用、创出新高；观测输入顺序反转的拒绝。
2. 新增 Pydantic 规则、状态和决策模型及一个纯函数；规则比较用精确分数，状态不读写外部系统。
3. 红测覆盖 0/负/非有限 NAV、时间不前进或无时区、非法参数、峰值状态不一致与规则变化；补聚焦回归、Ruff、diff 检查。只提交干净候选，交一次独立审查。

本增量不接 C9.1 分仓函数、回测撮合、模拟盘或页面；后续接入方需要提供当前可见 NAV，并对返回的开仓许可或总风险上限自行执行。
