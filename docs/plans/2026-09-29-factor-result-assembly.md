# 因子检验结果组装：真实产物链的第一片

**目标**：把同一份冻结因子输入与完整的后续收益事实交给现有因子计算，得到可复算、有缺数说明的结果对象。它是 C3.2 从离线算子走向 Lab 产物和 React 页面所需的应用层边界，不是页面上线证明。

**任务分级**：普通任务。只在 `rquant.factor` 中增加有类型输入、组装函数与聚焦测试；不改 Web、Serving、PageControl、生产数据库、Lab 队列或现有信号 `FactorSpec`。主要风险是不同池子、时间或收益口径被误拼，生成貌似可信的 IC/收益曲线，因此最终候选做一次独立审查。

## 方案选择

- 直接在浏览器或 Web 请求中算因子，会让展示层持有研究数据、长任务与计算状态，且无法保证同一冻结来源；不采用。
- 把当前几个纯函数各自的输出直接放进页面，会漏掉共同的池子、时点、收益窗口和缺数合同；不采用。
- **采用**一个 `factor` 应用层组装器：只接受调用方已冻结、带来源身份的输入；验证每个股票 × 决策日的收益事实，调用现有表达式、IC、统计和分组组合函数，返回单一不可变结果与内容摘要。后续 Lab 适配器只负责读取/封存输入和产物，Serving 只发布已封存的摘要和表，React 只展示。

## 输入和输出合同

1. 新 `FactorForwardReturn` 包含股票、决策日/时刻、收益结束时刻、收益值或封闭缺失原因、首次可用时刻。每个请求日 × 固定股票池必须恰有一条；不允许额外、重复或漏行。可用收益必须有限、不得小于 -100%，结束时间晚于决策且不晚于结果的 `as_of`，首次可用不早于收益结束；未成熟的窗口只能给明确缺失状态。组内同一天使用同一结束时刻，相邻提交日期的收益窗口不重叠。
2. 新 `FactorResearchRequest` 包含冻结的 `FactorTimeSeriesInput`、后续收益集合、`as_of`、两份非空来源身份、收益价格口径和调仓周期。`factor_input` 已包含唯一、排序的股票池、交易日及决策时刻；组装器不得重新查询行情或推断缺行。
3. 每日输出覆盖率：应有/有效/因子缺失/收益缺失数量与封闭原因；原始缺值不填零。IC 只基于该日实际成对有效样本，保留有效样本数和无法计算的状态。若全区间无有效成对样本，返回明确的“无可检验样本”，不构造假统计。
4. 分组累计收益与目标权重变化只在**所有请求日都有完整股票池有效收益**时调用 `evaluate_factor_portfolios`；否则结果标为“数据不足”，没有曲线。该曲线是等权目标组合的研究诊断，不是含费用/成交的回测净值。
5. 结果包含因子 ID/版本、完整输入和输出来源身份、区间/股票池/参数、覆盖率、逐日 IC、汇总、可选分组诊断与确定性的内容 SHA-256。相同输入重复运行的结构和摘要一致；不同因子版本、收益口径或来源不能共享摘要。输出对象不包含生成时钟、随机数或用户文案。

## 实现步骤与验收

1. 在 `tests/unit/test_factor_result_assembly.py` 写手算 3 股 × 2 期的红测：值、IC、3 组收益与复利、缺数覆盖率以及相同输入摘要。直接复用现有 `FeatureCatalog`、`FactorDefinition` 和计算模型。
2. 在 `src/rquant/factor/result.py` 实现有界 Pydantic 合同与纯组装函数，在 `src/rquant/factor/__init__.py` 暴露入口。无 I/O、无 Web/Serving/PageControl/行情 SDK 导入；后续适配器不必重新写统计公式。
3. 聚焦拒绝用例覆盖：漏/重/越界股票或日期、未来可用时间、混合结束时刻、窗口重叠、非有限或低于 -100% 收益、来源身份缺失；缺数路径验证 IC 可部分算、分组曲线停用且没有伪零。
4. 运行新增与直接相关因子测试、Ruff、diff 检查；真实收集增加的节点按仓库固定清单规则登记。更新 `docs/plans/2026-09-27-react-platform-progress.md`：仅写“本地结果组装”，明确仍缺同源 PIT/复权收益适配、定义持久化、Lab 任务/封存、Serving 和 React 因子页。最终候选独立审查只覆盖本片和直接依赖。

## 后续接线顺序

在本片冻结后，分别接：同一不可变研究快照的 PIT 特征与复权后续收益适配 → 受控因子定义及 Lab `factor_eval` 提交 → 任务产物封存与同代 Serving 索引 → React 因子库、参数、结果和跟踪。每一步都必须有真实数据和行为证据；原型的随机 IC/收益值不能进入产品页面。生产迁移、服务配置及切流按项目单独授权边界处理。
