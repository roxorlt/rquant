# 池子画布：真实数据与编辑闭环

**目标**：把原型中的池子画布变成可查看、可编辑、可验证的 React 功能，并在相应能力通过验收后逐步退役旧 Streamlit 画布。原型里的演示数据和模拟成功提示不能进入正式页面。

**分级**：查看阶段为普通任务，涉及多个前后端模块和用户可见行为；写入阶段为高风险任务，因其改变 PageControl 命令、池子定义与下一次筛选结果，开始实现前须冻结单独的失败模型和可执行验收标准。

## 数据与职责

- **筛选与发布**：既有筛选流程负责计算候选池。`screen_bounds` 给出每个池的历史范围与累计行数，不能当成最新成员数；`canvas_hit` 只发布全局最新交易日的成员，`canvas_diagnostic` 目前通常只有最终命中步。网页仅从同一个已验证的 Serving 数据代读取，不直连主库或画布文件，也不编造缺失的中间漏斗。
- **画布定义**：`canvas_definition` 已发布名称、描述和池子引用。它没有条件节点、节点位置或池子依赖的完整定义；页面不得把“引用关系”伪装成真实的规则依赖。对无法还原的节点明确说明当前可查看范围。
- **命令写入**：画布、池子和引用关系的修改走 PageControl，完成回执表示命令已受理；只有后续 Serving 代发布了目标版本，页面才显示“已生效”。前端不得直接写文件或数据库。
- **页面 API**：负责把发布表映射为有界、类型化的画布列表、节点/漏斗和成员响应。内部 `command_id`、hash、路径及原始规则表达式只在必要的详情或悬停说明中出现，不放正文。

## 阶段与验收

### 1. 已发布池子可视化

1. 一个画布展示已发布的池子节点及有证据的连接；点节点可看到该池的交易日、最新成员数、已发布的命中步骤和成员表，点成员打开已有个股详情。只有最终命中时只写“最终命中”；无数据、数据代不可用、池子引用失效和不同交易日均有明确状态。
2. 同一屏的数字来自同一 Serving 代；成员列表有界且数量截断可见，不能把旧日成员误称为今日结果。节点和成员支持键盘操作；窄屏可完成选择、看漏斗和打开个股详情。
3. 沿用 React Flow + dagre 和现有 UI 组件，节点文字用短中文；解释性内容放 Tip。画布之外提供等价的可访问池子列表，避免仅靠拖拽或视觉连线理解关系。
4. 以合成发布代覆盖列表、引用、日期、漏斗、成员、截断/不可用；通过 OpenAPI→TypeScript、前后端聚焦回归、桌面及 390px 验证。

### 2. 规则与依赖编辑

1. 在独立失败模型中明确命令幂等、版本冲突、非法依赖/环、半途失败、发布延迟和回滚边界。补足 `save_user_pool_v2` 的依赖与延后天数，并保留旧命令兼容性。
2. 编辑条件、参数、池子名和依赖时先预览差异与预计命中变化；确认后交给 PageControl。响应区分“提交中 / 已受理待发布 / 已生效 / 失败”，重复点击不会重复写入。
3. 新增、删除或修改节点必须在发布代中可读回；不能仅更新浏览器内存。错误和冲突保留用户草稿，且不显示模拟成功。

### 3. 一句话改池子与入池记录

1. 自然语言先解析成可检查的规则差异，再由用户确认写入。解析不确定、不支持或服务不可用时明确提示，不静默猜测。
2. 逐日成员比较形成入池/离池记录与入池价；页面展示入池时间、入池价和日 K 标记，缺少可靠历史时不编造。该数据由发布链路产出，图表与成员表使用同一时间口径。

## Streamlit 退役门

每阶段记录与旧 `/canvas/` 实际能力的映射及线上 Serving 数据代证据。只有 React 完整承接该单元的查看与操作、生产读写路径验收通过、且获得基础设施变更所需的单独授权，才停止对应 Streamlit 入口；在此之前保留旧服务与回滚路径。
