# 脉搏 Push 手机端分块排版设计

## 目标

让 30 分钟脉搏在 PushDeer 手机端可以按信息组快速扫读，同时保持标题摘要、全部字段、
数量上限、槽位增量口径、数据源标注和通知路由不变。午间战报不在本次范围内。

## 根因

`render_pulse()` 当前把四类内容分别拼成超长单行：市场温度使用四个管道字段，
新晋涨停、题材热度和放量异动又把多个对象用空格或管道连续拼接。PushDeer 在窄屏自动折行后，
字段与对象边界消失，今天 10:30 的 8 只新晋涨停、5 个题材和 5 只异动尤其难读。

## 方案选择

- 只把管道替换为换行：改动最小，但对象列表仍挤成一团。
- Markdown 表格：桌面规整，但 PushDeer 手机端渲染和横向滚动不稳定。
- 分节标题加逐项 bullet：行数略多，但字段边界稳定，且与爆量通知的新格式一致。

采用第三种方案。正文结构为“市场温度 / 新晋涨停 / 题材热度 / 放量异动”四节；空列表继续
省略对应节。市场温度拆成两行，新晋涨停、题材和异动各对象独占一行。降级短讯保持原样。

## 验证

新增一个包含全部四节的渲染契约测试，先证明旧格式失败，再实现最小渲染调整。随后运行
`tests/unit/test_midday_briefing.py`、相关通知测试、Ruff 和全量 CI。发布使用新版本
`v0.26.9`，15:15 受控部署任务改为这一精确标签。
