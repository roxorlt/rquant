# 任务与调度：运行记录与日志

接续 [任务与调度总览](2026-09-28-task-schedule-overview.md)，对应 v2 C13.2。原型里的「日志」要能查看真实记录；研究任务的生命周期事件和 systemd 的运行日志来自不同权威，分别显示「任务进展」与「运行日志」，不能把演示文本或上次状态伪装成日志。

**分级：高风险。** systemd journal 与研究任务的自由文本原因可能含凭据、内部路径或其他不宜在网页展示的信息；日志读取还可能被任意 unit、时间范围或高频请求拖垮运维服务。

## 信任边界与不变量

- systemd 边界是 `受签安装清单中的确切 service → 独立运维服务只读 journal → 封闭事件投影 → Web API → React`。网页进程、Serving 构建器和 `ops_status` 的 60 秒采集均不运行 `journalctl`。研究任务边界是 `同一 Lab 只读事务中的任务与事件 → 有界只读发布 → 同一 Serving 数据代 → Web API → React`；Web 不直读 Lab SQLite。两条来源的时刻、身份和错误独立，不能拿 Serving 时间冒充 journal 更新时间。
- 用户只能选择受签清单中已安装的**确切 service**，服务端再次核对清单摘要与 host/boot；不按 `rquant-` 前缀接受新名称，不拼 shell 命令。运维服务仅以固定路径和 argv 调用 `journalctl`，固定当前 boot、`--no-pager`、JSON 输出、确切 `_SYSTEMD_UNIT` 匹配；禁止 follow、通配符、自选路径、任意 journal 字段。每次最多 500 条、256 KiB、5 秒，每条消息最多 4 KiB；`since` 必须是带时区时间且不早于服务端当前时刻前 7 日，`level` 只允许标准严重性枚举。每条须带 journal 自身不透明 `__CURSOR`、`_BOOT_ID`、时刻和级别，且 `_BOOT_ID` 等于本次请求绑定的 boot；缺失、超时、截断、非法 UTF-8、输出结构或单位身份不符时整页不可用。首页按最新到最旧，下一页从末条 journal cursor **严格向更早记录**读取并排除边界条；时间相同仍按 journal cursor 保证不重不漏。服务端签发的页游标绑定 unit、boot、清单摘要、过滤条件及 `__CURSOR`；轮转使游标失效、重启或身份不符时返回 409 并清空旧页。systemd 的 `journalctl` 把 `--since` 与 `--cursor` 视为互斥：首页只带 `--since`，续页只带 `--cursor`，服务端再按游标签名绑定的时间下界截断；见 [systemd 源码](https://github.com/systemd/systemd/blob/main/src/journal/journalctl.c)。Linux 环境须验证反向游标的包含性和轮转行为后才能启用。
- 原始 journal `MESSAGE` 是不可信自由文本，**默认不返回**，关键词正则脱敏不能作为保密边界。只允许按固定 `MESSAGE_ID`/rQuant 事件码与封闭字段类型白名单解析已登记的结构化事件，由服务端用固定中文模板生成文案；未知事件、自由文本异常、堆栈、跨行消息或含未登记字段的记录只保留时间/级别并显示「该条内容暂不可显示」。不可把原始 `MESSAGE`、命令 stderr 或未知字段送入 Web API、错误、诊断日志或浏览器；固定模板参数仅可来自经过范围验证的数值/枚举，不能拼入原文。首批给 `rquant-daily.service` 和 `rquant-backup.service` 接入受控结构化发射器：每个服务至少发布 `run_started`、`run_succeeded`、`run_failed` 三个封闭事件码，服务端分别渲染「任务已开始」「任务已完成」「任务未完成」；仅允许整数耗时与退出码等有界参数，错误文本始终隐藏。其余清单 service 逐个接入相同受控协议；某个服务未通过正常/失败两条真实发射路径核验前，该服务的日志按钮不可启用，不能出现只有隐藏行的“可用日志”。React 按纯文本呈现，不使用 HTML 注入。日志请求须有固定频率和并发上限，拒绝时给出重试提示，不影响 10 秒健康心跳或 Serving 发布。
- Lab `lab_event.reason` 是自由字符串，不能直接进入网页。Lab 读取器在同一只读 SQLite 事务中读取有界**已发布 job 集**及其事件；逐条验证 job ID、单调 event ID/version、事件时间和最终状态与该 job 版本匹配，再将同一快照原子发布为同代只读表，失配整项不可用，不能由独立查询拼接。事件类型按封闭中文表映射，未知类型只显示「状态已更新」，不显示原始 reason、request ID、fencing token 或内部路径。每个任务最多显示最近 500 条；超过时明确「仅显示最近记录」，不能把截断称为全部历史。请求的任务若不在已发布集合中，只答「当前数据未包含该任务」，不推断权威库里不存在；无可信事件发布、零事件、未包含和来源损坏分开表示。任务 ID 与游标均绑定同一 Serving 数据代，换代清空旧抽屉。
- 当前 `current_user()` 只解析可被直连请求伪造的头，**不能单独授权日志**。启用前，必须让 Web 只接受受控 nginx ingress 的连接（例如受限 Unix socket），由 ingress 覆盖身份头，并由服务端用固定管理员名单/可信角色来源再次校验；身份缺失、角色不符或入口未证实一律拒绝。Web 到专用运维服务的 Unix socket 还须限制文件权限并核验 peer credentials，只接收受控 Web 进程，直连 socket 的其他本地进程拒绝。任何一段认证尚未安装时 endpoint 与按钮均不可用，不能只靠按钮隐藏。单元日志与研究记录各自有独立来源状态；一个不可用不抹掉另一个。页面标题明示「本机本次开机以来的服务日志（含手动运行）」；逐条校验 boot，不把服务全部消息说成 timer 上次触发的日志。若要按某次运行筛选，只能由 C13.1 可信触发回执的 `InvocationID` 精确绑定，否则不提供该入口。正文仅显示中文任务名、上海时间、级别与封闭文案；技术代号只放可点按的提示。抽屉支持时间和级别过滤、关闭后恢复焦点，加载、空、错误、截断和换代均可理解，桌面和 390px 可操作。

仓库已有 `web.ingress.private_web_ingress_socket` 与 `RQUANT_WEB_INGRESS_SOCKET`，可复用其受限入口；现有 `deploy/systemd/rquant-web.service` 仍显式绑定 `127.0.0.1:8768`。因此本地 API 实现不能把“支持 Unix socket”误记为“线上入口已受信”。实际切换 nginx、systemd 与目录权限须形成候选并取得项目规定的单独授权，随后在 Linux 验证。

## 服务日志接线顺序

1. 运维服务客户端和 Web API 只交换有类型的 `JournalPage`。Web 的服务日志接口先复核受限入口和管理员身份，再校验确切 service 是否同时属于已签安装清单与已完成正常/失败发射验收的集合；这个集合默认空，配置了清单本身不等于可展示。没有独立运维 socket 或验收标记时，接口返回不可用，任务列表不出现服务日志按钮。
2. 接口输入限于 `since`、`level`、`page_size` 和签名 `cursor`；服务端继续限制 7 日、500 条与固定 boot，不接受任意 journal 查询。首次与续页使用同一组过滤条件；游标失效返回 409。授权读取只记封闭的访问审计（操作者、服务、结果类别和时刻），不进入命令 outbox，审计中也不得含原始日志、游标或异常文本。服务日志错误不影响研究任务进展、任务总览和健康心跳。
3. React 的研究任务「进展」与定时任务「运行日志」分别开启各自抽屉。前者依赖同一 Serving 数据代；后者明确标注本机本次开机的范围，不假称某次定时触发的日志。两者都只显示封闭中文事件，换代或权限撤销立即清旧内容。

2026-09-28 对现有 Linux 主机做了**只读** journalctl 语义检查：systemd 255 的 `rquant-daily.service` 当前 boot 样本中，反向 `--cursor` 续页会先包含边界记录一次；与 `--since` 同用返回非零。读取器已排除边界并在服务端维持时间下界。`/proc/sys/kernel/random/boot_id` 是带连字符的 36 字符 UUID，而该版 journalctl 的 `--boot=` 只接受 [32 位无连字符 ID](https://www.freedesktop.org/software/systemd/man/255/journalctl.html)，JSON `_BOOT_ID` 也为 32 位；读取器已定向修正归一化与三项真实标准元数据白名单，聚焦测试通过。尚未验证修正代码在 Linux 实机的完整读取、日志轮转、结构化事件真实发射、安装后的 socket 权限与端到端 API，故不开放服务日志入口。

## 验收与发布边界

1. 合成日志覆盖确切白名单、未安装或恶意 unit、旧 boot、同一微秒多条记录、轮转、时间与级别过滤、倒序稳定分页、500 条与字节/时间上限、非法 JSON/UTF-8、受控失败。同 service 多 invocation、手动运行、旧 boot 混入不能误归属于 timer。未知字段、裸 token、赋值、Bearer、带 key 参数的 URL、异常堆栈与跨行文本均不能出现在 API 响应、错误、诊断或浏览器 DOM；已登记结构化事件才显示固定中文文案。
2. 合成 Lab 事件覆盖同事务任务/事件、读途中新事件或任务换代、缺行、损坏、同 ID 旧版本、未知事件、恶意 reason、截断、任务缺失、未发布与 Serving 换代。鉴权测试覆盖伪造头、缺头、非管理员与直连运维 socket。日志抽屉通过键盘和 390px 聚焦验证；只运行直接相关的聚焦回归，最终候选一次独立高风险审查。
3. 运维日志服务/权限/安装、真实 journal 游标与受控速率，以及研究事件的新 Serving 投影均在本地候选与相应环境核验后才能启用。首批 `rquant-daily.service`、`rquant-backup.service` 必须在合适环境实测正常和失败路径均能发出已登记事件并显示固定文案；此后逐服务验收，不能因清单里有名称就开放日志按钮。涉及生产 service、systemd、权限或发布配置的变更形成具体候选并取得单独授权；未接通时不显示可点击的「日志」按钮。
