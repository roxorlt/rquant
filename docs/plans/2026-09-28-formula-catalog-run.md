# 公式目录批量运行：第一切片

## 定位与边界

本切片在离线进程中，对**已核验历史投影内的股票目录**逐只运行受限通达信公式，得到有界的命中、不命中和未知统计。它是 C4.5 全市场运行的计算基础，**不把目录等同指定历史日的完整 A 股市场**：当前 `stock_basic` 由 `list_status=L` 逐日 `INSERT OR REPLACE`，旧行不会因退市删除，也没有逐日完整名单回执。本切片的范围标记固定为“历史投影收录的股票”，不得在 API 或页面称作“全市场命中数”。

任务分级：高风险。公式文本不可信，遍历历史行情有耗尽 CPU/内存的风险；数据代混用或目录漏项会产生错误的研究结论。此次只修改离线历史投影读取和公式批量计算，不接 Web 同步请求、PageControl、生产任务、主库写入或发布。

## 方案与验收

1. `VerifiedFormulaHistoryProjection` 增加一次有界的目录快照读取：同一已固定的不可变 SQLite 代、同一 `expected_identity`，从 `listing` 取得最多 10,000 条代码及上市日；超过容量明确失败，不能截成前 10,000 条。股票代码须是规范 A 股代码，重复或坏日期使本次运行失败。上市日晚于目标交易日的行明确排除；上市日缺失者保留并归“未知”，不能被当作未命中。目录读取仍受文件身份复核、只读连接和 SQLite 步数上限约束。
2. 新建离线公式目录运行器。运行前固定目录代和已收盘日期，解析公式一次；逐只读取现有 `formula_history`，复用纯 `evaluate_formula` 的真假/未知语义。每次仅持有单股历史并施加目录数量、总运行时间及已有单股求值预算。单股历史超过预算记为未知；数据代变化、目录读失败或整体超时使**整次运行失败**，不交付部分命中。运行结束再次复核目录代。
3. 返回有类型摘要：日期、目录范围、代身份、目录总数、上市后候选数、未来上市排除数、命中/未命中/未知数、未知原因计数，以及有界的命中代码。各计数必须守恒；“未知”不能算作“未命中”。技术代号只供内部产物，之后用户界面显示中文覆盖说明。
4. 用合成不可变投影做聚焦红绿验证：命中、未命中、缺日、缺上市日、未来上市、公式递归所需全史、目录超限、单股超预算、代际切换与坏输入。运行器只接受显式投影根和时间，不打开 `.env`、网络或主 DuckDB。相关 Ruff 与 diff 检查通过；最终候选一次独立审查。

## 冻结的威胁/失败模型

- 资产：行情事实、目录范围、来源代、计算结果。信任边界为离线发布者写入的不可变投影与只读批量运行器；公式文本仍是不可信输入。
- 失败路径：目录只取前 N 导致假零结果、历史停牌/退市混入后误作未命中、同次运行跨投影代、耗时或历史量失控、公式错误被吞掉后交付部分结果。
- 不变量：每条目录记录恰好进入“未来上市排除”或“上市后候选”；每个候选恰好进入命中/未命中/未知。任何全局来源/时间/公式错误均不返回摘要；已知旧目录边界必须在摘要中显式标明，不宣称完整市场覆盖。
- 排除项：历史上市状态权威、可证全市场分母、持久任务/产物、Serving/Web/React 按钮、正式数据代、Streamlit 停用。下一切片须引入逐日完整名单及状态证据，再把真正全市场结果接入离线任务、受控发布与页面。
