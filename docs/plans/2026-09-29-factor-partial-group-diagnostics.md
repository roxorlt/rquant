# 因子检验：部分有效样本的分组诊断

**目标**：固定股票池中个别股票的因子或后续收益缺失时，仍可用同一决策日已成熟、可见的有效配对样本计算分组累计收益和目标权重变化，同时把缺口明确交给上层展示。

**任务分级**：普通任务。仅修改纯因子结果/组合诊断与聚焦测试，改变研究结果的可用状态，但不触及生产写入、鉴权、共享发布契约或服务部署。最终候选安排一次独立审查。

## 口径与边界

1. `FactorResearchRequest` 仍须拥有固定池子 × 请求日期的完整事实网格；缺值保留原缺失原因，不补值、不把缺值记为零。上游的 PIT、同源、收益成熟和窗口不重叠约束保持不变。
2. 每个请求日有至少 3 个有效因子/收益配对，才可生成跨完整请求日期的 3 组诊断；任一日不足 3 个时，整个区间的组合诊断仍为 `insufficient_data`，不跳过那天或拼接不连续曲线。5/10 组不足样本的日期继续显示现有 `insufficient_samples`，不得伪造组收益。
3. 有组合诊断且所有日期的有效数等于预期数时，状态为 `available`；有诊断但至少一天部分覆盖时，状态为 `available_partial`。逐日 `coverage` 继续给出分母、有效数及缺失原因。供 UI 显示的解释是“部分股票缺数据，曲线仅基于有效样本”；不在纯计算层加入文案。
4. `evaluate_factor_portfolios` 接受固定股票池的非空有效子集，并继续要求每一决策日共用决策时间和收益结束时间、收益不小于 -100%、相邻收益窗口不重叠。目标权重变化仅是等权目标持仓差异，不代表实际成交量或含成本回测。
5. 结果 `sha256` 覆盖新状态和真实分组诊断；相同事实行排列变化仍得到同一内容摘要。其余 API 行为保持。

## 执行与验收

1. 先新增聚焦失败用例：4 股 × 2 日，每天只缺一股且有效数为 3，手算分组收益、复利与目标权重变化；检查 `available_partial`、覆盖率/原因和输入/输出摘要稳定。另测一日只有 2 对时仍无曲线，完整池子仍为 `available`。
2. 在 `portfolio.py` 放宽“每日期必须覆盖整个池子”的限制，但保持对子集、时点与窗口的一致性校验。在 `result.py` 以逐日有效数决定是否组装诊断和状态。
3. 更新此前把任意缺值都视为禁用曲线的测试断言，只改变满足 3 对有效样本的情形；不弱化时间或来源拒绝用例。
4. 运行直接相关因子测试、Ruff 和 diff 检查；在累计分支集成后更新固定测试清单及进度文档。审查限本 diff 和直接依赖。

**范围外**：Lab 任务、Serving 投影、React 因子页、真实成交/费用模拟、生产迁移或切流。它们沿既定 C3.2/C3.3 顺序继续推进。
