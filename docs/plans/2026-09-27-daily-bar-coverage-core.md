# 日线覆盖率审计核心计算

> 对应 v2 C1.2 的第一段计算能力。完整 C1.2 还包括质量异常、Lab 任务、S3 发布、网页图表与受控手动运行；本增量不把计算库等同于已上线的数据审计。

## 分级与验收

**普通任务**：新增只读、纯计算的日线覆盖率模型与聚焦测试，不改数据库、生产数据、调度或网页。输入为显式审计区间、完整 SSE 日历与从某个已核验只读快照汇总出的逐日行数；输出每个月的应有开市日、实际有数据日、覆盖率和按交易日顺序合并的缺口区间。人为删去中间若干交易日的合成输入必须准确定位缺口，不把休市日、尚未到达采集时点的今天或没有日历证据的日期判成缺失。

## 边界与行为

1. 计算函数不打开 DuckDB、不拉外部行情、不读 `.env`；调用方未来负责从单一只读快照聚合 `daily_bar` 行数并传入所审计的最后一个**已应完成**交易日。源身份随输入输出传递，计算不得混合两个快照。
2. SSE 日历必须覆盖审计范围内每一个自然日，日期唯一且有开闭状态；缺日期、重复、超范围矛盾或输入未排序时拒绝计算并给调用方可识别的错误。日线逐日计数须非负且唯一；有数据的休市日记为异常证据，不能提高覆盖率。
3. 月度覆盖率以 `实际有数据的开市日 / 应有开市日` 计算，并保留分子、分母；没有开市日的月份标记为“无应有交易日”，不造 100%。缺口按连续的**交易日**合并，周末或节假日不打断同一缺口；输出起止日和缺失交易日数。
4. 只判断全市场日线表某交易日是否完全缺失，不用是否有某只股票的日线推断停牌或部分股票缺口，也不把行数变化、价格跳变、零成交量、空值比例误称已完成。本计算由聚焦合成测试验证首尾缺口、跨月缺口、休市日、空月、日历破损和来源一致性；最终候选按普通任务做一次独立审查，不扩成全库审计。
