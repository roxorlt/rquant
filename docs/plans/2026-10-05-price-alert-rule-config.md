# 到价规则配置实施方案

**目标：** 在「盯盘与告警」页面完成到价规则的新建、编辑、启停和删除。

**做法：** 页面读取同一批已核验的规则和名单。写入走现有 PageControl 私有通道，复用规则仓储、版本校验和原请求恢复。只加网页适配和编辑抽屉。

**技术：** Python / Pydantic / FastAPI，既有 SQLite 与私有 Unix socket，React / TypeScript。由当前 Codex 原生实现者实施；不调用其他模型。

**分级：高风险。** 本片新增登录用户到规则写入的网页边界，涉及用户隔离、并发版本和未知回执恢复。审查限以下边界。

**状态：待 root 冻结和独立 SPEC 结论。** 当前仅写本方案与来源锁；未改产品或运行产品测试。基准为 `f459d6d4d8f34235a06ff89e7ba0b215355820c1`。工作树与身份记录见 `data/verification/price-alert-config-20261005/source-lock.json`。

## 1. 交付范围

- 「告警规则」表、新建入口、编辑抽屉、启停开关和删除确认均接真实配置命令。
- 字段沿用已有合同：股票、名称、级别、价格不低于 / 不高于、阈值、上海时间窗口及启用意愿。新建只能选择本人当前有效盯盘股票。
- 价格用十进制文本传输，保留已有精度，不经二进制浮点改值。新操作写入前须通过原价格投影的完整候选校验：正有限 Decimal，`abs(adjusted) <= 64`、数字数不超过 64、规范十进制文本长度不超过 128。不得舍入或限成两位小数。时间保留原秒与精度；新建默认 09:30–14:57，起点必须早于终点。
- 页面显示自己的配置、名单绑定原因及操作结果；不返回另一人的规则、名单或回执。
- 完成本片只记价格规则**配置**可用。报价评估、其他条件/范围、频率、通知、测试推送、推送模式和旧 monitor 对照继续后续 M12。

## 2. 已有能力与单一权威

| 现有入口 | 本片用途 |
|---|---|
| `PriceAlertRuleRepository` | 保持唯一规则写入；同事务名单核验、版本比较、删除墓碑，每用户最多 100 条未删除规则 |
| `SavePriceAlertRule` / `SetPriceAlertRuleEnabled` / `DeletePriceAlertRule` | 保持原命令字段、内容身份与结果合同 |
| `PriceAlertAdmissionClient.submit/lookup/resume` | 保持跨用户校验、精确查询和仅续跑已存在命令 |
| `current_user` / `require_csrf` | 复用已验证代理身份、JSON 和同源限制 |
| 规则 / 名单投影模型与校验器 | 复用内容摘要、唯一键、来源时刻、同代及完整容量校验 |
| 名单页面的请求日志与恢复写法 | 沿用先保存原请求、再发送、未知结果继续核对的方式；旧名单日志不变 |

Web 只读已发布数据，不直连 PageControl SQLite、主 DuckDB 或 `.env`。本片不建第二份服务端规则账本、任务系统、评估器或通知系统。

## 3. 信任边界和必须保持的事实

**资产：** 本人的规则和名单、版本/墓碑、原命令身份、效果与终态回执、页面当前草稿及保存确认。

**身份链：** 浏览器 → 受信代理 → 私有 Web ingress → 已验证登录用户 → 独立 Web UID → 现有价格规则私有通道 → PageControl。用户身份只由这条链产生。JSON、query、cookie、转发头不能指定 owner、文件路径、UID/GID 或凭据。

**默认关闭：** 没有已验证入口，拒绝私有读取。价格写通道未配置或身份不满足原合同，显示「规则操作暂未开放」。不退回普通 TCP、裸用户头或同 UID 信任。读能力与写能力分别说明，不能仅凭页面有数据就开放写入。

**版本：** 新建使用空预期版本；编辑、启停、删除使用精确已读版本。删除保留原墓碑。新建、重绑或启用在 PageControl 原事务中再核本人、股票、名单版本与到期时间；停用和删除仍可在名单失效后进行。禁用规则的同绑定编辑沿用现有仓储行为。

**原请求：** 用户确认一次操作时冻结 ID、请求时刻、动作和完整内容。页面记录读取时的数据代，供新操作检查及后来发布确认；它不加入现有领域命令的内容身份。恢复时所有原字段保持不变，不能把当前名单版本、规则版本或新数据代塞进原请求。

**写入结果：** 准入前拒绝不能产生规则、效果或新命令。已受理的业务拒绝保留原命令和失败回执，不改规则、不记成功效果。并发变化由现有事务/CAS 决定。成功须验证命令 ID、请求时刻、动作、规则 ID、精确结果版本、删除与启用值；回执错配视为待核对。

**来源：** 一次读取借用一个固定数据代，核验规则状态、规则事实和名单事实。未知、缺表、损坏或超容量不解释为空。复用现有 10,000 条全局投影上限、100 条本人未删除规则上限和 500 个有效名单成员上限，不截断为健康。

## 4. 薄网页接口

路径统一在 `/api/v1/monitor/price-rules` 下；接口类型来自 Pydantic，root 生成 OpenAPI 与 TypeScript。

| 方法 / 后缀 | 输入与结果 |
|---|---|
| GET 根路径 | 返回本人未删除规则、同代本人名单选择项、来源状态、短中文原因、读写能力；可信零行明确为空 |
| GET `/head?rule_id=...` | 返回本人精确规则 head，包括缺失、墓碑和更高版本；ID 按原合同作有界字符串，参数正确编码，不解释为文件路径，不暴露别人的同 ID |
| POST `/commands` | 严格、有界、无 owner 的原请求；动作为 `save` / `set_enabled` / `delete` |
| POST `/commands/resume` | 携带完整原请求；只查询或续跑已存在命令，未知 ID 不创建命令 |

请求最大 8 KiB，复用严格 JSON 解析，拒绝重复键、额外字段、坏时间、非有限价格及错误动作字段。服务端验证当前登录身份和 CSRF；正文只给短中文原因，技术诊断进服务日志。

**提交顺序：**

1. 先由原命令精确查回执。存在时按原请求恢复，不先要求当前数据代等于旧代。
2. 查无原命令时，才核验新操作的当前数据代、规则版本、所需名单状态与能力，并以原 `PriceAlertRuleProjectionRow.from_entry(候选)` 校验完整配置能发布，包含原规范文本往返校验，不能只查 `_bounded_threshold`。有限但指数、数字数或规范文本长度越界也须在 `submit` 前拒绝，命令/效果/规则不得新增；保持精确值，不改仓储、投影或 CAS。提交前再核当前指针。已有命令仍按第 1 步恢复，不受这项新操作预检阻断。
3. 原通道提交。失联或坏回执时再查原命令；仍无法确认则保留原请求。若检查与提交间发生变化，权威事务仍会拒绝旧版本。
4. 新操作预检拒绝后，再查一次原命令以接住并发提交；已有原命令继续恢复，不造新 ID。

`resume` 可以跨数据代、名单变化或来源暂时不可读恢复原回执。未找到、失联和确定版本冲突须区分；前两者不能自动提交另一条命令。

## 5. 页面状态和完成确认

| 事实 | 用户看到 / 可做 |
|---|---|
| 规则来源未发布、未启用或不可用 | 「规则暂不可用」及短原因；不能当成「暂无规则」 |
| 来源可信且本人零条 | 「还没有到价规则」；名单可用时可新建 |
| 名单可信但缺失、移出或到期 | 「已移出盯盘」或「盯盘已到期」；可停用、删除，重新绑定须新操作 |
| 移出再加入，名单版本已变 | 「盯盘已更新，请重新选择股票」；旧规则不自动恢复 |
| 禁用 | 开关保持关；状态「未运行」，原因放提示 |
| 设置启用且绑定有效 | 开关表示已保存设置；没有评估证据时状态仍「未运行」，提示「行情评估接通后才会提醒」 |
| 已入队 / 处理中 / 回执未知 | 「等待处理」/「正在处理」/「状态待核对」；使用原请求核对 |
| 写入成功，页面尚未确认 | 「设置已写入，等待同步」；不显示保存或启停完成 |
| 后续精确版本和内容确认 | 「已保存」/「已启用」/「已停用」/「已删除」，表示配置完成；名单作用范围另显示 |
| 当前规则版本更高 | 「规则已更新」；显示当前权威设置，旧回执不能覆盖当前规则或锁住新的合法操作 |

**发布确认条件：** 回执成功且有完成时间；当前数据代新鲜、无校验降级，指针仍指向本次借用代；不是原请求读取的代，且生成时刻严格晚于完成时间。该代规则和名单来源均可信。本人精确 rule ID/version 与回执一致：保存须逐字段等于规范化原配置，启停须精确启用值，删除须精确墓碑。任何一项缺失都继续等待，不能用行消失代替删除证明。名单后来到期或换版属于作用范围状态，不伪称配置写入失败。

**请求日志：** 发送前保存完整原请求，按当前登录用户与命令 ID 分开。每条规则最多一个未决操作，每用户最多 100 个未决操作；达到上限先核对原请求，不丢弃未知或待同步条目。浏览器存储失败时不发送新操作。刷新、多标签或切股票后仍能找到原请求。换用户不能显示或续查前一用户的日志。

**迟回执：** 回复只更新匹配原用户/命令的记录。改写编辑抽屉还须匹配当前用户、编辑会话、规则 ID 与读取版本。保存 A 后切到 B、新建另一个草稿或退出登录，A 的迟回执都不能改动当前草稿或弹出错误成功提示。

**界面：** 表格用 `DataTable`，抽屉/确认框用现有封装。级别和原因由 API 给中文名。正文不显示 owner、技术状态串、ID/hash、M 编号或内部服务名。必要说明用 `Tip`，支持悬停、聚焦和手机点按。1440 px 下表格清楚；390 px 下保留名称、股票、开关和操作，次要列收起。使用两位价格常用格式和相对时间，完整值可在详情核对。标签、焦点回到入口、Esc 关闭、删除确认和未保存草稿保护均可用键盘操作；加载用骨架屏，空态和错误有可执行去处。
