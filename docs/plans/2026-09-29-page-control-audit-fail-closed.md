# PageControl 共享审计快照失效时阻止公式池新权威

**分级：高风险。** 这影响公式池运行结果与保存命令的来源绑定，错误地发布新 Serving 代会使公式池事实失去可信依据。

## 冻结失败模型

- 资产是已发布的公式池定义、运行结果及其 PageControl 保存回执；信任边界是同一 SQLite 审计快照到新的 Serving 权威。
- 已复现路径：PageControl 审计库出现 WAL sidecar 后，共享快照无法安全进入；通知发布器将异常当作盯盘附属来源暂不可用，剔除公式池投影，却仍可生成新的每日权威。
- **不变量**：只要启用了公式池来源，任何共享审计快照无法进入、读取或安全退出，都必须阻止新的 Serving 权威发布，并保留旧代。不能用上一代投影、空投影或“来源不可用”替代公式池的来源绑定。
- 未配置公式池来源时，现有名单、确认和价格规则的有界降级可继续，但必须保留各自的未知状态。修复只触及这一错误分流，不改变数据库、生产配置或通知通道。

## 验收

现有 `test_page_control_wal_revocation_blocks_new_daily_authority` 在 CI 红、修复后绿；另聚焦验证无公式池时共享快照失效仍按原设计降级，并运行直接相关投影回归。独立终审只核对这一冻结边界及修复引入的回归。
