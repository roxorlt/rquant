# 每日池子排名：核验后发布当前结果

## 范围与分级

本片接在已审查的 `screen-run-receipt/v3` 持久回执之后，让池子页显示**最近一次当前规则下的日终排名名次和分数**。来源是固定只读 DuckDB 副本中同一个冻结连接/事务内的 `screen_run_receipt` 与 `screen_result`；Serving 把核验结果封入同一个数据代，Web 在该代内给池子成员，React 只在整组证据可信时显示。未发布的历史日期、按分回测权重和旧 v1/v2 结果仍无可信排名，留待后续片。

**高风险**：排名回执和池子成员是共享生产数据契约，错误连接会把篡改行或旧规则的分数当成当前事实。冻结基线 `3f1a17bf`。本片只读副本、Serving/Web/React 与测试；不运行生产迁移、不写主库、不改生产配置、不部署或停 Streamlit。

## 威胁与失败模型

- **可信源**：回执自身的 `result_version` 由模型核验；同一冻结数据库连接中的成员代码、收盘价、名次、分数分别重算成员摘要、价格摘要和 v3 排名摘要。完整组与回执的日期、池名、命中数、定义版本绑定。旧合同只保持原有行为；不能从定义中的排名参数反推实际分数。
- **失败路径**：Serving 仍只给 v2 核验价格，令合法 v3 入池价变未知；v3 分数/名次行被改而成员集合未变；缺新列或 `rank_digest`；部分成员有排名、重复/断档名次、NaN/Inf/越界分数；最新日有坏回执却回退旧日；当前定义版本变更后还显示旧排名；数据代换代后沿用旧分数；网页只按视觉排序却把临时分数写成事实。
- **不变量**：v3 的成员、价格、排名三摘要均用持久行验证，且通过 1..N、唯一代码、有限 0..100 分、零命中空摘要；任一失败使该池当前 ranked 结果整体不可用，绝不发布部分名次/分数。合法 v3 的价格证明应和 v2 一样供入池价计算。`current_definition`、最新交易日和同代 `result_version` 三者均满足才可在当前池子的成员表显示排名；旧 v1/v2 或缺排名事实显示“暂无可信排名”，不伪造零分或首名。Web 在核验同代完整有界成员组之后，才按可信名次选出展示的前 100 只，保留完整成员数及截断提示；旧 v1/v2 沿用代码序。Serving 代更换时 React 清掉旧详情；网页正文用“名次”“评分”，技术摘要只在悬停详情或不显示。
- **边界**：此片仅是日终当前结果的展示；不是历史调仓时点的冻结定义授权，不能把页面数据直接喂给按分回测。生产 v16 表迁移、真实副本、Serving 代和页面切流须另外验收和授权。

## 契约选择

1. 在现有有界只读投影中核验 v3；`screen_run_receipt` 投影继续含旧字段，若增加可信排名可用性标记，必须由核验者给出。成员展示沿现有 `canvas_hit`/池子 API 的同代通路承载可选 `rank_position` 与 `ranking_score`，不建第二个独立数据源，也不让浏览器指定回执摘要。发布器先核整个池子，再输出所有成员排名；零命中保留“已跑、无成员”，不显示排名表。
2. 旧 v1/v2 的回执、价格、成员、API 及 React 语义保持兼容；旧副本缺 v16 列可读。新 v3 缺列或坏摘要时给出不可用状态，不吞为可信零。后端按当前定义与结果版本核对后才把可选排名字段提供给当前池子，页面按名次升序展示截取后的前 100 只。

## 验收

1. 合成同库 3 股 v3 回执从写入到 Serving→Web→React 显示准确 1..3 名与持久分数；合法 v3 的入池价恢复可信。零命中明确显示“本次没有成员”。旧 v1/v2 与缺列旧副本不产生排名，同时保持原价格/成员行为。
2. 改单股分数/名次/价格、删行、重复或断档名次、坏 `rank_digest`、旧定义、过时日、发布中换副本或换 Serving 代，都不能显示旧或部分排名；范围内红绿测试覆盖原因和一致空态。另构造代码序最后一股排名第 1 的 101 股核验组，必须展示第 1 名、保留总数并显示截断提示，不能先按代码截 100 股再在页面排序。桌面/390px/键盘检查名次排序、tooltip、未知状态。
3. 聚焦 Python/Web 测试、OpenAPI 产物、前端 check/build/verify dist、固定清单增量与相关浏览器用例通过；最终候选一次独立范围内审查。P2 只有可复现违反本计划才阻断。
