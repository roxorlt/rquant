# 公式池逐日重算与结果证据

## 范围与分级

接续公式池定义的可信保存核心，先实现**单只公式池、单个已收盘交易日**的受信离线重算、不可变每日结果与读取核验；批量调度、Web/React、生产数据与切流留给后续切片。高风险：错用保存当天的旧命中、不同定义版本或不同日期的行情，会生成看似有效的池子成员。

## 验收

1. 受信调用仅指定公式池名称、定义版本和目标交易日。运行时从私有定义存储重读并固定公式原文与语法合同版本；使用目标日新归档的完整 A 股名单和对应日期的历史投影，不能把创建证据中的来源身份或命中名单当成新一日输入。缺目标日来源、语法版本不支持、日期未收盘或任一来源换代时拒绝，不生成成功结果。
2. 复用现有公式市场求值与持久任务的单活动、租约和幂等能力；逐日重算的请求身份由池名、定义版本、交易日及两来源身份组成。同一身份重试只得到同一任务/结果；不同定义版本或来源身份不得借旧任务冒充新结果。结果须把池名、定义版本、交易日、任务与封存结果摘要、两来源身份、命中/未命中/未知数、未知原因及成员摘要绑定。
3. 只有完整成功、计数守恒且封存结果可重新核验时，才写一次不可变的每日结果；零命中是可信结果，失败或未知原因不能伪装成零命中。重试不覆盖旧文件，不悄悄替换同池同日已发布的不同版本；冲突保留证据并拒绝自动选择。读取接口按精确池名、定义版本和交易日复核所有引用，再返回成员与计数。
4. 使用合成的连续两个收盘交易日验证每日独立成员、定义版本和来源身份；覆盖缺当日名单/行情、来源换代、公式版本不符、任务中途失败、结果损坏、重复提交与同日冲突。运行聚焦测试、Ruff、diff 检查，并做一次独立终审。本片不修改生产主库、定时器、服务配置或旧规则池行为。

## 冻结失败模型

- 资产：公式池定义版本、交易日与完整来源、封存任务结果、每日成员和未知计数。
- 边界：受信调用→私有定义与目标日两来源→持久公式任务→不可变每日结果；后续只读发布只能消费已核验结果。
- 失败路径：创建日命中被重复使用；旧定义或错误日期与新来源混合；任务回执先于结果落盘；失租约/损坏产物被当成功；同日不同版本静默覆写；缺来源沿用前日成员。
- 不变量：每个成功的每日结果只能来自同一固定定义版本在目标日两份完整来源上的一次可核验成功运行；失败不发布成员；未知数量与原因保留；旧规则池不变。
- 排除：Web/React 保存按钮、批量定时调度、Serving、生产配置/数据、Streamlit 停服。
