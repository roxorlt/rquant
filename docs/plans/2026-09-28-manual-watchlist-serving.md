# 手动盯盘名单：同代只读发布

接续 [名单状态](2026-09-28-manual-watchlist-authority.md)与[原子命令](2026-09-28-manual-watchlist-command.md)，对应 v2 C4.8。将 PageControl 单库中的名单版本以有界快照封入 Serving 数据代，供后续网页只读 API、按钮状态和告警范围使用。本片不启用网页写入、按钮或旧 monitor 切换。

**分级：高风险。** 错代、部分读取、过期状态或跨用户泄漏可能导致误显示与未来误告警；以下为本片冻结模型，终候选仅做一次独立审查。

## 威胁与失败模型

- 资产与信任边界：已激活的 PageControl SQLite 名单是唯一手动名单权威；Serving 发布器只从其现有只读审计快照读取，不自建第二份可写状态，不修改 PageControl 库；页面和新告警角色以后只读同一个 Serving 数据代。`owner_id` 随投影保留，未来网页 API 必须按经认证的用户过滤；本片不开放读取接口。
- 失败路径：未激活/旧库与真实空名单混淆；表结构或行损坏、超容量、读时换代、写命令进行中；来源失效后沿用上一代名单；在发布时固定的“有效”标志越过到期时刻仍被信任；一名用户的行混入另一名用户的结果。
- 不变量：未激活或来源不可用只产生明确不可用状态，绝不作为可信空名单；已激活的零行可证明为空。名单行与行数/摘要从同一审计快照取得、稳定按 `(owner_id, ts_code)` 排序且有总数和字节边界；墓碑与过期行保留版本，供后续精确按钮状态及 CAS，字段输入必须经类型与约束核验。投影只发布 `deleted` 与 `expires_at` 事实，**当前是否有效由消费端在自己的可信观察时刻判断**，不缓存成永不变的布尔值。来源失效的旧名单须从回退数据代撤去。
- 排除：本片不提供登录用户过滤后的 Web API、不做 React 交互、告警评估、生产表激活或服务器发布；不触及 `.env`、真实凭据或生产库。

## 验收

1. 从现有 `_ReadonlyPageControlAuditReader.snapshot()` 事务读取激活标记和名单，验证表结构、唯一身份、行约束及有界总量；未激活、已激活空行、坏表/坏行/超限各有不同且安全的结果。读取仅用当前 PageControl 权威路径，无直连 DuckDB 主库。
2. 新的 Serving `manual_watchlist_state` 与 `manual_watchlist` 投影按现有固定契约登记，状态行包含激活时刻、行数与行摘要，只有可信激活时才配套名单表；快照和发布器验证配套关系及摘要。PageControl 读取不可用时回退逻辑撤销旧名单投影，不发布旧成员。
3. 离线合成 PageControl→Serving 测试覆盖零行、活跃/到期/墓碑及版本、不同用户、变更后的新数据代、损坏/超限、来源不可用撤表；相关聚焦测试、Ruff 与 diff 检查通过。正式数据代、真实负载和生产权限留待后续验收，台账继续标「部分且未发布」。
