# 公式结果保存与池子画布呈现

## 范围与分级

把已完成的全市场公式任务、受保护的保存命令和公式池只读 API 接成可用的 React 路径：在选股结果保存可重算公式池，在「全部池子」看到定义、最近成功日和命中成员。普通任务：改变用户可见交互，不改变领域计算、鉴权、生产配置或写入裁决。风险在于把不明回执当成功、把旧代结果挂在新定义上，或显示不存在的自动更新与收益数据。

## 验收

1. 仅对当前数据代中**成功且结果可读**的所选公式任务提供「保存为池子」。输入简短池子名称，确认前能看清本次公式、交易日和命中/未知数；内部任务 ID、摘要、来源代及语法代号不进入正文。名称格式与后端一致，重复名称给出可行动的中文提示，不抹掉用户输入与当前结果。
2. 保存请求使用 Web 已生成的类型、`expected_version: null`、唯一命令 ID 和请求时刻；网络不明或回执未完成时保存原请求供原样重试，不能换命令 ID 造成双写。只有 `succeeded` 且返回精确池名/版本时说「已保存」；要说「可在池子画布查看」还须只读 API 在同一或更新的 Serving 代出现该版本。页面刷新或关闭再打开仍能续查不明请求；失败不丢批量结果。
3. 池子画布的「全部池子」同时展示旧规则池与公式池，两类节点和详情有清楚的用户名称。公式池展示公式、最近成功运行的**真实日期**、命中/未命中/未能判断和分页成员；尚未运行、可信零命中、结果未发布、读取失败、旧数据代分别有简短中文状态。成员可打开个股详情，不推算未发布的入池价、涨幅或今天的成员；规则池原有编辑与画布引用不误用于公式池。
4. 保存、列表和成员请求遵守 `useServingQuery` 的同代缓存规则；当代切换时清除旧成员与游标并从第一页读。桌面、390px、键盘焦点与提示可用；长公式和中文池名不会撑破布局。文案与信息层次遵守 `web/AGENTS.md`，`findJargon()` 检查正文。
5. 以合成 Serving 响应覆盖成功/不明/冲突保存、版本待发布、未运行/零命中/未知、分页换代与坏成员；运行相关 Vitest、类型检查、构建/产物校验及桌面/390px 浏览器路径，候选做一次独立终审。

## 边界

- React 只负责命令会话、展示与导航；Web/PageControl 判定保存，Serving+每日结果判定可显示的事实。公式池仍保存可重算定义，不把一次命中代码当静态池。
- 自定义画布的公式池挂接、逐日自动调度及入池价等证据链是后续切片；本片如实显示可用状态，不承诺尚未接通的自动运行。生产入口和 Streamlit 退役另按项目规则验收与授权。
