# 公式批量选股的 React 交互

## 范围与分级

在现有「公式预览」抽屉中接入已审查的批量命令与只读任务接口，并保留单股预览。普通任务：改变用户可见操作和状态，但不触碰计算、生产配置或池子写入。本片只在 Web 只读接口完成后实施。

## 交互与验收

1. 公式文本是共同输入。「检查公式」通过后，用户可单股预览或选择已收盘日期运行批量筛选；修改文本即撤销本次检查/单股预览资格。批量结果始终附自己的公式与日期，不把旧任务显示成当前输入的结果。页面正文不出现任务 ID、来源摘要、Serving/worker 等内部词。
2. 批量运行是较重操作：点击后显示简短确认，说明会用所选日期的数据检查全部已归档 A 股、完成后可回来查看。提交期间防重复点击；服务端冲突、来源不可用和状态待确认分别给出能执行的下一步。命令成功回执先显示「已提交」，在 Serving 尚未发布新任务的间隙不倒退成「没有任务」。
3. 「最近运行」可重新进入先前任务。排队、运行、失败、成功、数据过期和结果无法读取各有真实状态；活动任务适度刷新，离开再回来通过任务列表恢复，终态停止轮询。失败可在确认后用新命令重试；不得把重试当作原任务成功。
4. 成功结果展示市场总数、命中、未命中、未能判断和按原因汇总的未知数量；只展示服务端真实提供的命中代码，分页按受控游标前进。日期、公式或数据代变化时不沿用旧游标。可以点击代码打开股票详情；无命中与结果未就绪分开。结果损坏时不展示成功摘要或历史缓存。
5. 桌面、390px、键盘和触屏实走：确认、提交、离开/返回、失败重试、结果翻页、改公式后的状态隔离。文案短，技术细节只在提示或详情中。运行命令与单股预览分别有聚焦测试；前端检查、构建、产物验证与浏览器路径按 `web/AGENTS.md` 执行。

## 设计约束

- 页面只通过 `@/api/*` 的生成类型取数和提交；不复制 OpenAPI 类型，也不直接连任务库或产物文件。
- 暂无可信「该日期可批量运行」目录时，不把单股预览日期误标成批量可用日期。可显示用户所选已收盘日期并让命令做最终校验；拒绝时说明具体原因，后续以独立来源可用性接口补足提前提示。
- 保存为公式池子属于下一段，须先有可重算的池子合同；本片不放一个只能保存静态命中名单的假按钮。
