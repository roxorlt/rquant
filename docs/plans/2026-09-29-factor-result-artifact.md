# 因子检验：单文件不可变研究产物

对齐 v2 C3.2 的 Lab 产物链第一片：把已通过同源快照准入和历史适配的 `HistoricalFactorResearch` 封存成一个内容寻址的规范 JSON 文件，并可只读复核。后续任务 runner 才负责调度、Parquet 图表表、Serving 索引与 React 展示；本片不声称「运行检验」按钮已可用。

**任务分级：高风险。** 已封存研究结果会被后续任务回执和页面引用；覆盖、半写或错配来源会破坏可复算性，因此先冻结失败模型。

## 冻结失败模型

- **资产与信任边界**：冻结来源回执、完整请求、结果、代码修订、产物内容摘要与目标文件。信任边界为已准入的内存研究结果 → 私有本地产物目录 → 未来 Lab/Serving 的只读消费者。写进程与目录拥有者可信；不把文件名或 JSON 内的路径当作任意文件读取权限。
- **失败路径**：请求/结果或来源摘要错配；生成过程中崩溃只留临时文件；A 已 rename 尚未同步目录时 B 命中同一目标并误报成功；同一摘要重试或不同内容占据同名文件；根目录或中间目录是符号链接/被换代、终点是符号链接/非普通文件；读取时文件被换掉或截断；超大载荷耗尽内存；JSON 被改写但文件名仍旧；旧 schema 被误认。
- **不变量**：封存前验证整个 `HistoricalFactorResearch` 与三者配对，并从冻结请求重算纯结果逐字段比较；代码修订显式入摘要。规范字节有固定 128 MiB 上限。最终文件只在全部字节写入、同步且复读通过后以 no-replace 原子出现，随后同步目录；**无论是本次新建还是已存在同内容目标，返回成功前都须同步已核验的普通文件及其父目录**。重试只复用相同且已核验的内容，不覆盖已存在文件。读取只接受固定前缀、规范 JSON、匹配文件名/内容摘要的普通文件；缺失或损坏拒绝，不返回部分研究。临时残留不进入读取索引。所有调用需要显式绝对产物目录，不猜生产路径。
- **排除项**：此片不证明历史数据当时实际采集或可成交，不给 JSON 加签；同一可信 Unix 用户直接同时改写产物与摘要超出本片的物理权限边界。没有 Parquet、任务队列、Web/Serving/React、生产创建/迁移/发布或 Streamlit 切流。

## 合同与实现

1. 新 `FactorResearchArtifactV1` 包含 `schema_version=1`、40 位小写代码 commit、完整 `HistoricalFactorResearch` 和 `content_sha256`；内容 SHA 对不含自身的规范 JSON 计算。`research.result.sha256`、规范请求摘要、来源回执摘要均要在重新构造时复核，不能只信内存对象冻结标记。发布器还应从 `research.request` 重算 `assemble_factor_research_result` 并与传入结果精确比较；它不重新读取或证明历史来源租约。
2. `publish_factor_research_artifact(research, code_revision, root)` 先在内存完成全部验证和限额，再打开**预先创建**的私有根目录：参数必须是规范绝对路径，从 `/` 逐组件以目录 FD 和 `O_NOFOLLOW` 打开，不接受任何符号链接；根必须是当前 Unix 用户所有、mode `0700`，开始和返回前重开核对物理身份。只在该 FD 下创建 mode `0600`、单链接的独占临时普通文件；临时文件 fsync 且复读通过后以 no-replace 语义发布固定名称 `factor-research-v1-{sha}.json`。新建与 EEXIST 分支均核验最终普通文件的完整规范字节、owner/mode/单链接，并在**返回成功前** fsync 最终文件和根目录。若 A 停在 rename 后目录同步前，B 只有自己完成最终文件与目录同步后才能成功；A 的同步失败不能让未经持久化的成功回执流出。不同或不可信目标拒绝且不覆盖；失败时仅按本次独占临时文件的 FD/名称身份清理，不删既有目标。
3. `load_factor_research_artifact(root, sha256)` 同样先逐组件打开并核验私有物理根，仅接受 64 位小写摘要并在根 FD 下打开由它构造的**直接子文件名**，不接受任意完整路径、`..`、同前缀兄弟路径或外部同名文件。以 `O_NOFOLLOW` 有限读取，核对最终普通文件的 owner/mode/单链接、前后文件与根身份；严格拒绝非规范 JSON、坏内容摘要、坏嵌套来源/请求/结果、错误文件名或 schema。缺失或根换代时拒绝，不落到其他路径。
4. 只依赖现有 `rquant.factor` 类型、规范 JSON/private_fs 工具与标准库，不修改策略 Lab 作业合同或现有共享产物协议。发布结果返回有类型的摘要/文件名/字节数，后续任务回执可引用。

## 红测与验收

先用已知小型同源研究样本测试往返与同内容重试；换代码修订应变更 ID。注入写前失败、临时残留、目标占位/符号链接、读取截断/改字节/错名、坏嵌套摘要和降低测试限额后的超限输入；检查目标不被覆盖、临时文件不被当作已发布。设置并发停点：A 在 rename 后、目录 fsync 前暂停，B 同摘要重试必须先完成自己的文件与目录同步才可成功；目录 fsync 故障后下一次同内容重试能补齐持久化再成功。非私有/符号链接根、中间目录重定向、同前缀兄弟路径、目录换代和外部同名文件一律拒绝且不触及外部路径。只跑新产物及直接因子依赖的聚焦测试、Ruff、diff。先由独立 reviewer 审此 SPEC，最终候选再审一次；阻断按项目高风险上限定向修复。

后续顺序：Lab `factor_eval` 有类型提交/只读 runner → 把已封存 JSON 转成同身份 Parquet 表及索引 → Serving 同代发布 → React 真实运行/结果。每片都更新能力台账，不把本片当作整页完成。
