# 集合竞价跳空高开策略量化与扩展设计

## 1. 策略背景

这是一条独立于 Pool1 / Pool2 N 字战法的集合竞价策略。原始条件来自同花顺动态分组：

> 今天的跳空高开，今天的竞价量 / 近 5 日的区间日均成交量 = 0.15 到 5，今日未涨停，股票简称不包含 st。

2026-06-26 9:27 左右，同花顺筛出 4 只：`605366`、`002253`、`002289`、`301051`，盘中观察 3 只上板。这条现象值得量化，但不能直接把当天 3/4 当成策略胜率，需要用历史集合竞价数据逐日回放。

## 2. 当前可量化定义

当前代码实现为 `rquant auction-gap-replay`，对应配置模型为 `AuctionGapConfig`。

基础入选条件：

- 信号时间：开盘集合竞价成交数据，当前用 Tushare `stk_auction` 的 `open_realtime`。
- 跳空高开：
  - `close` 口径：竞价成交价高于前一交易日收盘价。
  - `strict_high` 口径：竞价成交价高于前一交易日最高价。
- 竞价量比：`auction_vol / 近 5 个交易日日均成交量`，日线成交量按 Tushare 的“手”转换为“股”，即 `daily_vol * 100`。
- 竞价未涨停：竞价价小于当日涨停价，默认留 `0.01` 元容差。
- ST 过滤：
  - `case_insensitive`：大小写不敏感过滤 `ST` / `*ST`，这是 rQuant 默认的严格风控口径。
  - `literal_lower`：只过滤小写 `st`，用于近似同花顺这次动态分组的可能口径。
  - `none`：不做名称过滤，仅用于排查数据口径。

基准交易假设：

- B 买入：集合竞价成交价视作入场价。
- S 卖出：基准用次一交易日开盘价离场。
- 这个离场口径不使用次日盘中未来数据，符合 A 股 T+1 限制，也能快速判断“今天打进去，隔夜到次日开盘是否有正收益”。
- 输出 CSV 额外保留当日最高、当日收盘、次日最高、次日收盘等结果列，用于后续设计更细的次日盘中 S 策略。

## 3. 口径校准

2026-06-26 用 Tushare 临时拉取 `stk_auction` 做校验时，4 只同花顺样本中只匹配到两只：

| 代码 | 名称 | 竞价价 | 竞价量 / 近 5 日均量 |
|---|---:|---:|---:|
| 301051.SZ | 信濠光电 | 18.36 | 0.1823 |
| 605366.SH | 宏柏新材 | 13.59 | 0.1740 |

`002253.SZ` 和 `002289.SZ` 在本地 `stock_basic` 中分别是 `*ST智胜`、`*ST宇顺`，且这次 Tushare 当日竞价结果没有返回它们。因此这里至少有两个需要继续校准的点：

- 同花顺“股票简称不包含 st”可能是字面小写匹配，没有排除大写 `ST` / `*ST`。
- Tushare `stk_auction` 与同花顺动态分组在样本范围、停复牌、ST 名称更新时间或竞价快照时点上可能存在差异。

结论：回测主口径应该先用 rQuant 严格 ST 风控，另保留 `literal_lower` 口径用于复现同花顺现象。

## 5. 上板与不上板的差异

严格 ST 过滤样本中，当日上板和未上板样本呈现这些差异：

| 特征 | 未上板均值 | 上板均值 |
|---|---:|---:|
| 竞价量 / 近 5 日均量 | 0.2920 | 0.3216 |
| 竞价成交额 | 5910 万 | 8860 万 |
| 竞价换手率 | 0.90% | 1.20% |
| 跳空幅度 | 5.36% | 6.83% |
| 距离涨停价 | 7.12% | 4.44% |
| 次日开盘收益 | -4.70% | 7.25% |

最重要的分叉不是“当天最高能不能冲一下”，而是“当天能不能封板”。没有上板的样本，次日开盘平均亏损约 `-4.70%`；上板样本次日开盘平均收益约 `7.25%`。因此这条策略后续优化目标不应只追求入选数量，而应提高“当日封板概率”和“封板后的次日溢价质量”。

## 6. 初步过滤方向

目前用网格阈值做了第一轮粗筛，较有希望的方向是：

- `跳空幅度 >= 10%`
- `竞价量 / 近 5 日均量 >= 0.15`
- `距离涨停价 <= 5%`

这个组合历史样本约 `63` 笔，当日上板率约 `55.56%`，次日开盘胜率约 `58.73%`，次日开盘平均收益约 `0.69%`，中位收益约 `2.81%`。

注意：这不是最终策略，只是候选方向。样本数还偏小，需要 walk-forward 验证，避免对历史过拟合。

## 6.1 分钟数据覆盖策略

当前分钟线主要按 Pool1 / Pool2 补过 90 日上下文，因此不能用这些分钟线覆盖率去判断集合竞价策略。集合竞价跳空是全市场候选，必须补它自己的分钟 replay 窗口。

不建议一开始补全市场全历史分钟线。原因：

- 全市场 90 个交易日约为 `股票数 * 90 * 241` 行，按 5500 只股票粗估约 1.2 亿行。
- 从 2025-01 到 2026-06 约 345 个交易日，粗估约 4.5 亿行。
- 这些数据会明显增加本机和云端 DuckDB / Parquet 的存储、备份、同步和查询压力。
- 对当前问题来说，大量全市场分钟线并不会直接转化为策略有效样本；真正需要的是“候选出现后的 B/S 窗口”。

因此当前采用三层路线：

1. 策略候选窗口回补：
   - 先用日线和集合竞价生成候选；
   - 再只回补候选从信号日到退出窗口的分钟线。
   - 当前 `2025-01-16` 至 `2026-06-24` 严格 ST 口径有 2236 个候选，对应 2236 次分钟请求。

2. 对照样本 / 负样本回补：
   - 为了避免只看入选样本，可按同日同板块、同市值/成交额分层抽取未入选样本；
   - 这比全市场回补更节省，也更适合做分类模型。

3. 全市场滚动特征仓：
   - 如果后续策略越来越多，再考虑只维护最近 60/90 个交易日的全市场分钟“特征结果”，而不是永久保存全量原始分钟。

可用命令：

```bash
UV_CACHE_DIR=/private/tmp/rquant-uv-cache uv run rquant auction-gap-minute-backfill \
  --start-date 2025-01-16 \
  --end-date 2026-06-24 \
  --gap-mode close \
  --st-filter case_insensitive \
  --max-hold-days 1 \
  --dry-run
```

## 7. 下一步需要的次日 S 策略

第一版已经保留“次日开盘卖出”作为最干净的无未来函数基准，同时新增了一条更真实的分钟回放路径：

- 9:25-9:30 的集合竞价条件只生成观察候选，不直接 B。
- B 日开盘后等待 1 分钟因子确认：
  - 开盘后累计低点不明显跌破竞价价；
  - 当前价站上竞价价和当日 VWAP；
  - 累计高点向涨停价推进到配置阈值；
  - 同分钟历史基准、累计进度基准、日内加速度作为 B 信号明细和后续优化特征；
  - 信号确认后用下一分钟开盘价成交，避免同一分钟“看到 high/low/close 后按当前价买”的乐观假设。
- S 日先看次日集合竞价是否明显转弱：
  - 次日竞价价低于入场价，或相对 B 日收盘明显低开，按开盘价退出；
  - B 日封板强度高时，对次日轻微弱竞价更宽容；
  - 若竞价不弱，再进入分钟线扫描。
- 次日分钟扫描使用：
  - T+1 门禁；
  - 普通止损、移动止盈；
  - 次日早盘 VWAP 破位退出。
  - S 侧同样记录同分钟历史基准、累计进度基准、5/10 分钟加速度。

关于 9:30-9:32：

- 这个边界不是策略真理，而是一个可调的工程初值。
- 开盘前几分钟有显著的集合竞价延续、隔夜信息释放、撮合积压释放和成交额峰值，和普通盘中分钟不属于同一分布。
- 当前做法是把 9:30-9:32 标记为 `opening_segment`，不参与普通 5/10 分钟滚动加速度计算。
- 后续应把边界参数化，在 walk-forward 中比较 `9:30`、`9:30-9:31`、`9:30-9:32`、`9:30-9:34` 等口径，而不是手工认定 3 分钟最优。

这条路径可用：

```bash
UV_CACHE_DIR=/private/tmp/rquant-uv-cache uv run rquant auction-gap-minute-replay \
  --start-date 2025-01-16 \
  --end-date 2026-06-24 \
  --gap-mode close \
  --st-filter case_insensitive \
  --max-hold-days 1 \
  --output /private/tmp/rquant-auction-gap-minute.csv
```

后续还要继续做两层：

1. 次日 1 分钟回放退出：
   - 当前已有次日竞价转弱、早盘 VWAP 破位、移动止盈；
   - 后续要加入次日集合竞价量比、同分钟历史基准、开盘 5/10 分钟承接强度。

2. 封板质量分层退出：
   - 当前已记录首次触板时间、触板分钟数、收盘是否封板；
   - 后续要加入炸板次数、回封时间、封板后成交衰减等更细特征。

这部分需要把集合竞价策略接入现有 `minute_replay` / `paper` 的分钟退出引擎，而不是只看日线 OHLC。

## 8. 平台扩展结构建议

未来 rQuant 要支持“我又描述了一条新策略，然后快速回测、拟合、调优”，核心结构应该分成五层。

### 8.1 策略规格层

每条策略用一个 `StrategySpec` 描述，而不是把逻辑散落在 CLI 或 dashboard：

- `strategy_id`：如 `auction_gap_open`、`n_shape_pool_attack`。
- `universe`：全市场、Pool1、Pool1+Pool2、创业板强势池等。
- `signal_time`：9:27、9:31 后逐分钟、17:00 收盘后等。
- `feature_dependencies`：需要哪些表和字段。
- `candidate_filter`：候选过滤条件。
- `entry_rule`：买入触发与成交价。
- `exit_rule`：T+1 门禁、止损、止盈、移动保护。
- `label_rule`：当日上板、次日溢价、3/5/10 日最大收益等标签。
- `search_space`：哪些阈值允许自动搜索。

### 8.2 特征仓库层

把策略用到的因子变成可复用特征，不跟某条策略绑定：

- 日线特征：涨停价、ST、板块、位置百分位、连板、均线、波动。
- 集合竞价特征：竞价量比、竞价金额、竞价换手、跳空幅度、距涨停。
- 分钟特征：同分钟历史基准、累计成交额进度、短线爆量、VWAP、回撤。
- 90 日价量分布：POC、value area、上方压力、下方支撑。
- 市场环境：涨停家数、炸板率、连板高度、指数状态、题材强度。

关键约束：所有特征必须带 `asof_time` 或清晰的信号时点，保证回测时只使用当时已经可见的数据。

### 8.3 回放引擎层

统一流程：

1. 按交易日和信号时间生成候选。
2. 只读取当时已可见数据计算特征。
3. 按 entry rule 生成 B。
4. 按 A 股 T+1 和 exit rule 生成 S。
5. 生成收益、回撤、胜率、上板率、隔夜溢价、样本明细。

这样新策略只需要补 `StrategySpec` 和少量特征，不需要重写整套回测。

### 8.4 自动优化层

人工勾选策略组合太低效，应改成自动化：

- 阈值网格：如跳空幅度、竞价量比、距涨停、竞价金额。
- 特征权重：把多个特征合成分数，每天取 top1 / top2 / top3。
- walk-forward：只用过去训练，未来验证，避免上帝视角。
- 消融实验：逐个加入或移除特征，看是否真有增益。
- 稳健性约束：收益为正、样本数足够、最大回撤可接受、不同月份不过度集中。

### 8.5 Strategy Lab 页面层

Streamlit 上应该新增一个“策略实验室”入口，把策略研究变成可视化工作台：

- 选择策略：N 字战法 / 集合竞价跳空 / 未来新策略。
- 选择数据范围和样本池。
- 勾选特征和过滤器。
- 查看训练区间、验证区间、walk-forward 结果。
- 查看每天 topN 入选名单、成功样本、失败样本。
- 一键导出策略配置，用于盘中监控和模拟盘。

最终结构是：策略研究、自动优化、盘中推理、模拟盘复盘都吃同一份策略规格和特征定义，避免每来一个新想法就复制一套脚本。
