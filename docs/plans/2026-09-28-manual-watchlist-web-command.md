# 手动盯盘名单：网页命令与发布核对

接续 [可信写入入口](2026-09-28-manual-watchlist-admission.md)和[原型交互](2026-09-28-manual-watchlist-ui.md)。本片把经过登录与同源校验的单股操作交给私有 PageControl 通道。名单的权威写入与网页可见的数据代分开；按钮的最终状态仍须读下一代名单确认。

**分级：高风险。** 页面命令改变未来监控范围。资产为当前用户的名单、CAS 版本和原命令回执；信任边界依次为私有 Web ingress、认证身份、私有 Unix socket、PageControl SQLite 与只读 Serving。跨用户头注入、请求重放、响应丢失、旧数据代、权限错误、容量满、版本冲突和写入后尚未发布是本片的失败路径。

## 合同

- `POST /api/v1/watchlist/commands` 只在私有 Web ingress 和显式配置的独立名单准入 socket 下启用；严格 JSON 小体积限制、`require_csrf`、请求身份校验。浏览器只提交原命令 ID、UTC 请求时刻、所依据的 Serving 数据代、股票代码、加入/移出、CAS 版本，以及加入时可选的来源、价格位和到期时刻；绝不接收 owner 或通用 PageControl 命令结构。Web 依据认证身份构造领域命令，PageControl 再对 owner 做独立比对。
- 新命令需当前单代名单可用，且操作所据单股状态与提交的 CAS 版本一致；无法确认当前状态时拒绝新命令，不把未知按空名单处理。Web 校验只负责用户体验，PageControl SQLite CAS 仍是并发最终裁决。准入通道提供按 owner、命令 ID 和完整内容核验的只读原命令查询；已存在但未终结的命令可以仅按原记录恢复处理。相同 ID、相同内容的原命令可以在换代、响应丢失或重启后续查；相同 ID、不同内容返回冲突，查询和恢复绝不生成第二次副作用。
- `generation_id` 只用于 Web 对**新命令**核对所据名单数据代，不写入 PageControl 领域命令或其幂等摘要。已有原命令按持久命令的 owner、动作、股票、CAS、参数、ID 与请求时刻精确核对，可跨代续查；浏览器仍保留原请求体，不在重试时换数据代或命令 ID。
- 端点用有类型回执区分「正在处理」「已保存，正在同步」「版本已变化」「名单已满」「失败」「状态待核对」。传输超时或响应无效时只报告不确定并要求保留原命令重试；不能重新生成 ID。PageControl 成功回执返回股票、动作和新版本，**不**直接等同「已加入/已移出」。只有随后单个有效 Serving 数据代的当前用户单股状态与版本和动作吻合，页面才呈现最终状态。
- 任何入站错误和回执只给用户可行动的简短中文文案；技术错误写服务端日志。接口不开放批量原子语义，选股器批量功能在前端逐只命令、明确范围与逐只结果基础上实现。

## 验收

离线红绿测试覆盖私有配置缺失、伪造 owner/普通 TCP、CSRF、跨用户、坏 JSON 与超长请求、未激活或缺失/陈旧 Serving、新命令旧版本、响应丢失原 ID 恢复、异内容同 ID、PageControl 已写但 Serving 未更新、容量和 CAS、错权限或错 UID 的 socket。保持现有名单 GET、Ack 与 PageControl 通用接口聚焦回归。终候选按冻结范围做一次独立审查；本片不改生产配置、不激活生产名单、不开放 React 按钮或停用 Streamlit。
