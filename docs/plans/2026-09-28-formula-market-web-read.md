# 公式批量任务的网页只读查询

## 范围与分级

本片让 Web 从**同一个已校验 Serving 代**读取公式批量任务、状态和成功产物，提供有界列表及命中代码分页。Web 不连接任务 SQLite、行情主库或研究投影，不执行公式，也不写任务。高风险：跨代拼接任务与结果、错误文件或不完整结果显示为成功，会误导选股判断。

## 验收

1. 新增有类型的任务列表与详情接口。一次请求仅借用一个 Serving 代，并校验 `formula_market_job_state`、`formula_market_job`、`research_artifact_index` 三表完整、同源、同 `available_at`，行数与 manifest 一致；旧数据代无表、来源未配置、无任务和不可读分别有清楚状态。列表最多返回最近 100 条，正文用简洁中文状态；技术身份留在结构化字段供程序校验，不作为页面文案。
2. 详情按任务 ID 在同代查找。排队、运行、失败只返回状态及可行动提示；成功必须有同任务、同来源、同请求摘要的索引，固定的只读结果目录内文件再经安全打开、长度、SHA256 和域模型核验。结果目录只从可信 Web 本地配置注入，浏览器不能传路径。未配置目录或任何核验失败时绝不返回命中名单或伪称成功。
3. 命中代码分页每页 1–100 条，按封存结果顺序稳定读取；游标至少绑定 Serving 代、任务 ID、产物摘要与偏移。游标与当前代或任务不符时要求刷新，绝不接到新一代结果上。摘要给出市场总数、命中/未命中/未知及未知原因计数；未知原因有用户可读中文名称。没有逐只未知代码的数据，不编造逐只列表。
4. 使用本地合成 Serving 代和私有结果目录走真实 FastAPI 路由，覆盖排队→成功、跨代游标、损坏/替换文件、同代状态与索引错配、未配置目录、空/旧代；生成 OpenAPI 与 TypeScript 合同，跑聚焦 Python 和 TS 类型检查。生产服务权限与配置单独验收，本片不改 `deploy/` 或线上。

## 冻结失败模型

- 资产：任务身份、公式与日期、两来源代、成功摘要、命中集合。
- 边界：Serving 只读代→Web；受控私有结果目录→Web；Web→浏览器。来源身份只来自可信配置和 Serving，HTTP 只接任务 ID 与有界分页参数。
- 失败路径：Serving 代更新期间拼接旧任务与新索引；游标复用到另一产物；结果文件损坏/被换/消失；成功任务缺索引；目录未授权而 API 仍显示成功；Web 错把未知算成未命中。
- 不变量：所有显示的成功数字和代码来自同任务、同产物、同一 Serving 代；失败与部分计算没有成功结果；Web 对任务库和产物目录没有写路径。
- 排除：React 页面、保存池子、正式 worker 调度、生产目录/权限、上线切流、真实约 10 GB 负载。这些分别后续验收或单独授权。
