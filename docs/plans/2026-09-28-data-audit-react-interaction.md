# 数据审计：React 运行与结果交互

本片接通可点击原型「数据中心 → 运行数据审计」。用户已确定原型是最终使用路径，旧 Streamlit 不再扩功能；页面按 `web/AGENTS.md` 的中文文案与交互原则实现。服务端任务、报告和 Web 读写合同分别承担状态、证据和访问控制，React 只处理操作与展示。

## 交互选择

选用数据中心内的轻量日期表单与较重确认框，保持用户在当前数据集和报告上下文中。另开完整页面会增加导航和跨页状态；只用弹窗会让长时间运行的结果缺少可持续查看的位置。表单默认上次审计的起始日，首次可从 2024-09-01 开始；结束日取上海时间最近一个已收盘日期。日期可改，按服务端支持的 1–3660 天校验。确认文字说明：将只读核对所选期间，可能耗时较长，不会执行回补或写日线。

## 状态与数据流

点击确认前把包含原命令 ID、请求时间与日期的请求存入浏览器记录，再 POST 受保护接口。只有核验过的入队回执才显示「已排队」；响应超时、未知或待确认时保留原请求并提供「继续核对」，刷新后也能恢复。确定失败可重新编辑日期。任务状态、最近成功报告和最多 20 条安全事件从同一次 Serving 数据代读取；只有最新任务 ID 与本次命令一致时才把投影状态归属本次。旧数据代或尚未发布时，任务进度标明不可用，不根据旧报告猜测成功。

结果区把「本次审计」与「上次报告」分开。排队、运行、失败和成功分别给短中文状态与下一步；最新失败不撤掉上次成功报告，但上次报告显示完成时间与截止日，始终保留「采集完成未确认」。质量问题为零只表示实际完成检查的日期没有观察到问题，未评估日期仍明确显示。原始路径、任务 ID、哈希、错误码和服务名不进入正文；有帮助的解释放提示。没有报告时仍能看到运行入口和任务状态。

## 验收

- 桌面、390 px、键盘和触屏可完成日期编辑、确认、提交、刷新后原命令续查及结果查看；焦点与按钮禁用状态清楚。
- 合成 Serving 数据代覆盖空任务、排队、运行、最新失败但有旧报告、成功未发布、同代成功可见、换代与来源不可用；只在确证入队后显示「已排队」。
- 页面正文通过内部术语检查；数字、时间、百分比和空态遵守既有格式。前端检查、构建、产物校验及相关浏览器路径通过后，才记本地候选完成。

正式任务进程配置、生产副本负载、生产完成身份链、切流和旧服务停用另按项目门禁处理。
