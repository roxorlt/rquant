# 任务与调度总览：受信状态来源

接续已合入的研究任务队列页面，完成 v2 C13.1 的定时任务、常驻服务和资源概况。原型最终还包含日志、立即运行及研究任务控制，分别由 C13.2–C13.4 接续；本片不展示无行为的操作按钮。当前 `runtime_health` 有常驻 role 的心跳，`lab_jobs` 有研究队列；`workload_evidence` 每 5 分钟采集内存，但没有 CPU 用量；仓库尚无 `unit_status` 或 `scheduled_units` 发布源。页面不能据代码里的 timer 文件猜测服务器运行状态。

**分级：高风险。** 定时任务状态会成为运维判断依据，且状态采集接触共享的运行时健康与 Serving 发布链。实现前冻结以下信任边界；生产 unit、权限、发布及切流仍需按项目规则单独授权。

## 资产、失败路径与不变量

- 资产：固定允许查看的 rQuant timer/service 集合、主机 systemd 的只读状态、既有运行时心跳与 5 分钟资源采样、同一 Serving 数据代、网页操作员。边界为 `systemd → 有界只读采集 → 受信快照 → Serving → Web API → React`。浏览器和 Web 进程不执行 `systemctl`，不接收可指定任意 unit 的采集参数；采集进程不读取 journal、`.env` 或主库。
- 失败路径：任意 unit 名注入命令；`systemctl` 卡住或输出过大；timer 已禁用却显示“正常”；一次服务运行失败却被当前 timer `active` 掩盖；UTC/上海时间混用；一次采样缺失或过期却沿用旧绿色状态；资源占用把历史峰值冒充当前；不同 Serving 数据代拼接；状态采集失败拖垮既有 runtime-health 发布。
- 只从固定白名单以 argv 调用只读系统命令，不用 shell；单 unit、总时间、输出字节和 unit 数都有上限。每个 timer 与其对应 service 分开取证：下一次触发由 timer 属性决定，上次结果与耗时由 service 的同一次执行证据决定，缺字段显示未知，不反推为成功。动态模板实例只能来自安装清单中明确允许的身份，不按前缀扫描后自动纳入。
- 采集结果带采样时刻、主机/启动身份、unit 集合版本及每条证据；固定快照一次完成后才整体发布。任一系统命令失败仅使本类来源不可用，不能污染既有心跳或研究任务数据。Serving 对来源身份、行数和时间做封存核验；Web 的 `/tasks/units` 和 `/tasks/resources` 只读同一借用代，换代后旧游标/缓存失效。
- 现有 `RuntimeServiceHealth` 负责常驻 role 状态，不把 timer 的 `inactive` 一概解释为服务异常。休市、等待开盘和已收盘按 `web/AGENTS.md` 的五态规则表达。资源卡片先使用已核验的 `workload_evidence` 最近采样与原采样时间，只显示实际具备的内存指标；CPU 未有可信采样时明确不可用，不能用配额或 reservation 冒充已用 CPU。任何资源或单元状态过期都显示更新时间与“暂无法确认”。
- API 只给中文显示名、上次/下次时间、耗时、结果、状态和必要原因；技术 unit 名留在提示或详情，不进入正文。React 在同页保留现有研究队列，增设定时任务和运行状态分区；桌面与 390px 均能读上次/下次及状态，加载、无来源、过期、失败有不同反馈。C13.2–C13.4 未实现前，不出现可点击但无真实回执的日志、立即运行和暂停按钮。

## 实施与验收

1. 先定义有类型的只读状态快照和固定 unit 清单，使用可注入的系统命令适配器在 Linux 合成回放中证明时区、禁用、成功、失败、运行中、缺字段、超时、超长输出和异常 unit 标识的行为。采集不得修改 systemd 状态。优先复用既有健康发布周期；若必须新建常驻服务，先给出生命周期、权限与资源隔离的证据再决定。
2. 将 `scheduled_units` 与已有常驻 role/资源证据封入 Serving；旧代或没有来源时返回明确不可用，不制造“0 个任务”。`/tasks/units`、`/tasks/resources` 使用 Pydantic → OpenAPI → TypeScript 合同，固定小列表无需无界分页。现有 `/tasks/jobs` 的数据代、计数和分页行为保持。
3. 任务页按原型的“定时任务 + 研究任务队列”路径展示，状态和短文案按 `web/AGENTS.md`；定时任务操作留待 C13.2/3 接通后出现。验收覆盖同代读取、换代、时区、空态、stale、错误、键盘和 390px。只跑直接相关 Python/Web/浏览器聚焦回归，最终候选安排一次独立高风险审查。
4. 正式服务器 systemd 属性、服务用户读取权限、采集开销、资源样本新鲜度和约 10 GB 副本共存情况必须在受控环境单独验证；涉及 `deploy/systemd/`、权限或 Serving 发布配置的变更先提交具体候选并取得单独授权。未满足时本片只能记本地候选，不能称任务总览上线。
