# v0.17.0 首次部署前数据初始化

> 适用版本：`v0.17.0`
> 原因：目标版本的 production preflight 严格要求 migration v8 和上一交易日的
> `stock_suspend_coverage`。不能直接运行发布器，否则目标版本 preflight 会失败并自动回滚。

## 原则

- 只在 15:10 后、monitor 和其他写任务停止后执行。
- 用目标 tag 的临时 worktree 运行新 CLI，生产 checkout 仍保持旧版本，初始化失败不切代码。
- 历史名称/ST 与停复牌先 dry-run/回补；涨停池修复必须人工核对 plan ID 后显式 apply。
- 初始化完成、只读副本刷新且目标版本 preflight 通过后，才运行受控发布器。

## 云端命令

```bash
set -e
cd /home/lighthouse/rquant

# 在停止任何服务前先取得并验证目标 tag。
git fetch --prune origin main --tags
git rev-parse --verify 'refs/tags/v0.17.0^{commit}'

restore_rquant_timers() {
  sudo systemctl start \
    rquant-daily.timer \
    rquant-monitor.timer \
    rquant-surge-watch.timer \
    rquant-replica-sync.timer \
    rquant-backup.timer \
    rquant-kpl-snapshot.timer
}

trap 'echo "v0.17.0 bootstrap failed; restoring timers" >&2; restore_rquant_timers' ERR

sudo systemctl stop \
  rquant-daily.timer \
  rquant-monitor.timer \
  rquant-surge-watch.timer \
  rquant-replica-sync.timer \
  rquant-backup.timer \
  rquant-kpl-snapshot.timer

sudo systemctl stop \
  rquant-monitor.service \
  rquant-surge-watch.service \
  rquant-replica-sync.service \
  rquant-backup.service \
  rquant-kpl-snapshot.service

git worktree remove --force /tmp/rquant-v017-bootstrap 2>/dev/null || true
git worktree add --detach /tmp/rquant-v017-bootstrap v0.17.0
ln -sfn /home/lighthouse/rquant/.env /tmp/rquant-v017-bootstrap/.env

cd /tmp/rquant-v017-bootstrap

PYTHONPATH=/tmp/rquant-v017-bootstrap/src \
  /home/lighthouse/rquant/.venv/bin/rquant security-status-backfill \
  --start-date 2026-04-01 --end-date 2026-07-14 \
  --source-as-of 2026-07-15 --dry-run

PYTHONPATH=/tmp/rquant-v017-bootstrap/src \
  /home/lighthouse/rquant/.venv/bin/rquant security-status-backfill \
  --start-date 2026-04-01 --end-date 2026-07-14 \
  --source-as-of 2026-07-15

PYTHONPATH=/tmp/rquant-v017-bootstrap/src \
  /home/lighthouse/rquant/.venv/bin/rquant suspension-backfill \
  --start-date 2026-04-01 --end-date 2026-07-14

# 先记录输出中的 plan_id；不要跳过人工核对。
PYTHONPATH=/tmp/rquant-v017-bootstrap/src \
  /home/lighthouse/rquant/.venv/bin/rquant zt-pool-repair

# 把 <PLAN_ID> 替换成上一步输出的 64 位值后执行。
PYTHONPATH=/tmp/rquant-v017-bootstrap/src \
  /home/lighthouse/rquant/.venv/bin/rquant zt-pool-repair \
  --apply --plan-id <PLAN_ID>

sudo systemctl start rquant-replica-sync.service
sleep 5

PYTHONPATH=/tmp/rquant-v017-bootstrap/src \
  /home/lighthouse/rquant/.venv/bin/rquant data-audit \
  --start-date 2026-04-01 --as-of 2026-07-14

PYTHONPATH=/tmp/rquant-v017-bootstrap/src \
  /home/lighthouse/rquant/.venv/bin/rquant preflight

cd /home/lighthouse/rquant
git worktree remove --force /tmp/rquant-v017-bootstrap

bash scripts/deploy-production.sh --target v0.17.0 --dry-run
bash scripts/deploy-production.sh --target v0.17.0

# 先完成一次性任务，再恢复周期调度，避免多个任务同时抢 DuckDB。
sudo systemctl start rquant-backup.service
sudo systemctl start rquant-replica-sync.service
restore_rquant_timers
trap - ERR

systemctl list-timers --all 'rquant-*' --no-pager
systemctl status rquant-dashboard.service rquant-nl-screen.service --no-pager -n 8
```

`data-audit` 只有 P0 为 0 才返回 0。任何一步失败都应停在旧代码版本排查，不应使用
`set +e` 继续发布，也不应临时放宽 production freshness。

命令已在失败时自动恢复 timers。发布成功后先依次完成一次性备份和副本同步，再恢复周期调度；
不要同时启动全部写服务，避免重演 v0.15.0 首次恢复时的 DuckDB 锁竞争。
