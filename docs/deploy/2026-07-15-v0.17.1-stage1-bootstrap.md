# v0.17.1 Stage 1 状态修复与首次部署

> 适用版本：`v0.17.1`
> 前置状态：v0.17.0 首次部署已被 `data-audit` 的两个历史状态 P0 阻断，生产仍运行
> v0.15.0；全量历史状态与停牌覆盖已经回补，休市日涨停池修复计划为空。

## 原则

- 只在工作日 15:10 后执行，先停周期任务、watchdog 和盘中写服务。
- 所有失败即停逻辑放在子 shell；失败只结束命令块，不退出交互 SSH。
- 第一阶段只做备份和只读预演，不迁移 schema、不回补、不清理数据；备份另存为带时间戳的
  不可覆盖恢复点。
- 第二阶段先再次备份，再部署可同时读取旧、新状态的兼容代码；之后才执行 v9 迁移与
  unknown/冲突键重算。`data-audit` P0 必须为 0，主副本摘要一致且 preflight 通过后才恢复调度。
- v9 数据写入后不要单独回滚到 v0.15.0；需要回退时必须同时恢复第二阶段打印出的
  `v0.17.1-pre-apply-*` 数据库备份。
- 涨停池计划为空时不 apply；非空时必须使用第一阶段人工核对过的 plan ID，CAS 不匹配即停。

## 第一阶段：预演和计划

不要在交互 shell 顶层执行 `set -e`。整段粘贴执行：

```bash
set +e
(
  set -Eeuo pipefail

  ROOT=/home/lighthouse/rquant
  TARGET=v0.17.1
  WORKTREE=/tmp/rquant-v0171-bootstrap
  TIMERS_STOPPED=0

  restore_rquant_timers() {
    sudo systemctl start \
      rquant-daily.timer \
      rquant-monitor-watchdog.timer \
      rquant-monitor.timer \
      rquant-surge-watch.timer \
      rquant-replica-sync.timer \
      rquant-backup.timer \
      rquant-kpl-snapshot.timer
  }

  cleanup_worktree() {
    cd "$ROOT"
    git worktree remove --force "$WORKTREE" 2>/dev/null || true
  }

  on_exit() {
    rc=$?
    trap - EXIT
    trap '' HUP INT TERM
    set +e
    cleanup_worktree
    if (( TIMERS_STOPPED )); then
      if ! restore_rquant_timers; then
        echo "timer restore failed; inspect systemctl state immediately" >&2
        rc=1
      fi
    fi
    if (( rc != 0 )); then
      echo "v0.17.1 preview failed (exit=$rc); timers restored" >&2
    fi
    exit "$rc"
  }

  verify_backup() {
    local started_epoch=$1
    "$ROOT/.venv/bin/python" - "$ROOT/backup/latest.json" "$started_epoch" <<'PY'
import json
import sys
from datetime import datetime
from pathlib import Path

metadata = json.loads(Path(sys.argv[1]).read_text())
started_epoch = int(sys.argv[2])
snapshot_epoch = int(datetime.fromisoformat(metadata["snapshot_at"]).timestamp())
assert metadata["source"] == "main"
assert metadata["source_lag_seconds"] == 0
assert metadata["verified"] is True
assert metadata["table_count"] > 0
assert snapshot_epoch >= started_epoch
print("BACKUP_METADATA", metadata)
PY
  }

  preserve_backup() {
    local label=$1
    local stamp destination
    stamp=$(date -u +%Y%m%dT%H%M%SZ)
    destination="$ROOT/backup/${label}-${stamp}"
    cp -- "$ROOT/backup/latest.duckdb.gz" "${destination}.duckdb.gz"
    cp -- "$ROOT/backup/latest.json" "${destination}.json"
    echo "PRESERVED_BACKUP=${destination}"
  }

  assert_outside_market_window() {
    local weekday hour_minute
    weekday=$(date +%u)
    hour_minute=$(date +%H%M)
    if (( weekday <= 5 )) \
      && [[ "$hour_minute" > "0914" && "$hour_minute" < "1511" ]]; then
      echo "refusing production mutation during 09:15-15:10" >&2
      return 1
    fi
  }

  trap on_exit EXIT
  trap 'exit 129' HUP
  trap 'exit 130' INT
  trap 'exit 143' TERM
  assert_outside_market_window
  cd "$ROOT"

  git fetch --prune origin main --tags
  [[ "$(git cat-file -t "$TARGET")" == "tag" ]]
  TARGET_SHA=$(git rev-parse --verify "refs/tags/$TARGET^{commit}")
  git merge-base --is-ancestor "$TARGET_SHA" origin/main
  echo "TARGET_SHA=$TARGET_SHA"

  TIMERS_STOPPED=1
  sudo systemctl stop \
    rquant-daily.timer \
    rquant-monitor-watchdog.timer \
    rquant-monitor.timer \
    rquant-surge-watch.timer \
    rquant-replica-sync.timer \
    rquant-backup.timer \
    rquant-kpl-snapshot.timer

  sudo systemctl stop \
    rquant-daily.service \
    rquant-monitor-watchdog.service \
    rquant-monitor.service \
    rquant-surge-watch.service \
    rquant-replica-sync.service \
    rquant-backup.service \
    rquant-kpl-snapshot.service

  cleanup_worktree
  git worktree add --detach "$WORKTREE" "$TARGET"
  ln -sfn "$ROOT/.env" "$WORKTREE/.env"

  TARGET_VERSION=$(PYTHONPATH="$WORKTREE/src" "$ROOT/.venv/bin/python" -c \
    'import rquant; print(rquant.__version__)')
  [[ "$TARGET_VERSION" == "${TARGET#v}" ]]
  echo "TARGET_VERSION=$TARGET_VERSION"

  BACKUP_STARTED=$(date -u +%s)
  RQUANT_BACKUP_SOURCE=main \
    RQUANT_BACKUP_PROJECT_DIR="$ROOT" \
    "$WORKTREE/scripts/backup-snapshot.sh"
  verify_backup "$BACKUP_STARTED"
  preserve_backup "v0.17.1-preview"

  DUCKDB_READONLY_PATH="$ROOT/data/rquant.duckdb" \
    PYTHONPATH="$WORKTREE/src" "$ROOT/.venv/bin/rquant" \
    security-status-backfill \
    --start-date 2026-04-01 \
    --end-date 2026-07-14 \
    --source-as-of 2026-07-15 \
    --dry-run

  # 第一阶段保持只读，只核对已经完成的停牌覆盖和涨停池计划。
  PYTHONPATH="$WORKTREE/src" "$ROOT/.venv/bin/python" - <<'PY'
from datetime import date

from rquant.data_quality import build_limit_up_pool_closed_day_repair_plan
from rquant.storage.duckdb import DuckDBStore

path = "/home/lighthouse/rquant/data/rquant.duckdb"
with DuckDBStore(path, read_only=True) as store:
    suspension = store._conn.execute("""
        SELECT count(*), min(trade_date), max(trade_date)
        FROM stock_suspend_coverage
        WHERE source = 'tushare'
          AND coverage_state = 'complete'
          AND trade_date BETWEEN DATE '2026-04-01' AND DATE '2026-07-14'
    """).fetchone()
    print("SUSPENSION_COVERAGE", suspension)
    assert suspension == (70, date(2026, 4, 1), date(2026, 7, 14))
    plan = build_limit_up_pool_closed_day_repair_plan(store)
    print(plan.model_dump_json(indent=2))
    assert plan.status != "blocked"
PY

  cleanup_worktree
  restore_rquant_timers
  TIMERS_STOPPED=0
  trap - EXIT HUP INT TERM
  echo "PREVIEW_DONE"
)
PREVIEW_EXIT=$?
echo "PREVIEW_EXIT=$PREVIEW_EXIT"
```

预期：`TARGET_VERSION=0.17.1`；状态计划约 218 个键、69 个交易日、82 次逻辑 API
调用；停牌覆盖无缺口；涨停池 `before_count=0`。记录实际 `before_count` 和 `plan_id`，
只有 `PREVIEW_EXIT=0` 才进入第二阶段。

## 第二阶段：修复、审计和部署

先把第一阶段的结果写入两个环境变量。当前空计划应使用：

```bash
export RQUANT_REPAIR_PLAN_COUNT=0
unset RQUANT_REPAIR_PLAN_ID
```

如果 `before_count` 非 0，则改成实际数量和 64 位 plan ID。随后整段粘贴执行：

```bash

  TARGET=v0.17.1
  WORKTREE=/tmp/rquant-v0171-bootstrap

  restore_rquant_timers() {

  preserve_backup() {

  trap 'exit 130' INT

  if (( RQUANT_REPAIR_PLAN_COUNT > 0 )); then
    [[ "${RQUANT_REPAIR_PLAN_ID:-}" =~ ^[0-9a-f]{64}$ ]]

  git fetch --prune origin main --tags
  [[ "$(git cat-file -t "$TARGET")" == "tag" ]]
  TARGET_SHA=$(git rev-parse --verify "refs/tags/$TARGET^{commit}")

    rquant-daily.timer \
    rquant-monitor-watchdog.timer \
    rquant-monitor.timer \

    rquant-replica-sync.timer \
    rquant-backup.timer \

    rquant-daily.service \
    rquant-monitor-watchdog.service \
    rquant-monitor.service \
    rquant-surge-watch.service \
    rquant-replica-sync.service \

  RQUANT_BACKUP_SOURCE=main \
    RQUANT_BACKUP_PROJECT_DIR="$ROOT" \

  cleanup_worktree
  cd "$ROOT"
  bash scripts/deploy-production.sh --target "$TARGET" --dry-run
  bash scripts/deploy-production.sh --target "$TARGET"

  [[ "$(git describe --tags --exact-match)" == "$TARGET" ]]
  [[ "$(git rev-parse HEAD)" == "$TARGET_SHA" ]]

  # 发布器可能重启原本 active 的服务；数据迁移前再次确保所有写者静默。
  sudo systemctl stop \
    rquant-daily.service \
    rquant-monitor.service \
    rquant-surge-watch.service

  .venv/bin/rquant \
    security-status-backfill \
    --start-date 2026-04-01 \
    --end-date 2026-07-14 \
    --source-as-of 2026-07-15

  # 再计算一次当前计划并与第一阶段记录做一致性校验。
  .venv/bin/python - <<'PY'
import os

from rquant.data_quality import build_limit_up_pool_closed_day_repair_plan
from rquant.storage.duckdb import DuckDBStore

expected_count = int(os.environ["RQUANT_REPAIR_PLAN_COUNT"])
expected_id = os.environ.get("RQUANT_REPAIR_PLAN_ID")
with DuckDBStore(
    "/home/lighthouse/rquant/data/rquant.duckdb",

    plan = build_limit_up_pool_closed_day_repair_plan(store)
print(plan.model_dump_json(indent=2))
assert plan.status != "blocked"
assert plan.before_count == expected_count
if expected_count > 0:
    assert plan.plan_id == expected_id
PY

    .venv/bin/rquant zt-pool-repair \
      --apply --plan-id "$RQUANT_REPAIR_PLAN_ID"

    --start-date 2026-04-01 \

from datetime import date

from rquant.storage.duckdb import DuckDBStore

path = "/home/lighthouse/rquant/data/rquant.duckdb"
with DuckDBStore(path, read_only=True) as store:
    coverage = store.stock_status_coverage(
        date(2026, 4, 1),
        date(2026, 7, 14),
    )
    print("STATUS_COVERAGE", coverage.model_dump(mode="json"))
    assert coverage.expected_count == 379_658
    assert coverage.persisted_count == 379_658
    assert (
        coverage.missing_count
        + coverage.unknown_count
        + coverage.conflict_count
        + coverage.invalid_count
    ) == 0
    suspension = store._conn.execute("""
        SELECT count(*), min(trade_date), max(trade_date)
        FROM stock_suspend_coverage
        WHERE source = 'tushare'
          AND coverage_state = 'complete'
          AND trade_date BETWEEN DATE '2026-04-01' AND DATE '2026-07-14'
    """).fetchone()
    print("SUSPENSION_COVERAGE", suspension)
    assert suspension == (70, date(2026, 4, 1), date(2026, 7, 14))
    closed_pool = store._conn.execute("""
        SELECT count(*)
        FROM limit_up_pool_daily AS pool
        JOIN trade_calendar AS calendar
          ON calendar.exchange = 'SSE'
         AND calendar.cal_date = pool.trade_date
        WHERE NOT calendar.is_open
    """).fetchone()[0]
    print("CLOSED_DAY_POOL_ROWS", closed_pool)
    assert closed_pool == 0
    migration = store._conn.execute(
        "SELECT max(version) FROM schema_migration"
    ).fetchone()[0]
    print("SCHEMA_MIGRATION", migration)
    assert migration == 9
PY

  # 保存修复完成后的精确恢复点，再刷新只读副本。
  BACKUP_STARTED=$(date -u +%s)
  RQUANT_BACKUP_SOURCE=main "$ROOT/scripts/backup-snapshot.sh"
  verify_backup "$BACKUP_STARTED"
  preserve_backup "v0.17.1-post-repair"
  sudo systemctl start rquant-replica-sync.service
  REPLICA_SYNC_STATUS=$(systemctl show rquant-replica-sync.service \
    --property=ExecMainStatus --value)
  echo "REPLICA_SYNC_STATUS=$REPLICA_SYNC_STATUS"
  [[ "$REPLICA_SYNC_STATUS" == "0" ]]

  # 恢复调度前门禁：主库和副本必须为同一状态代际，不能让 preflight 偷读旧副本。
  .venv/bin/python - <<'PY'
import duckdb

signatures = {}
for label, path in (
    ("main", "/home/lighthouse/rquant/data/rquant.duckdb"),
    ("replica", "/home/lighthouse/rquant/data/rquant_ro.duckdb"),
):
    conn = duckdb.connect(path, read_only=True)
    row = conn.execute("""
        SELECT count(*),
               count(*) FILTER (WHERE is_st IS NULL),
               count(*) FILTER (WHERE conflict_reason IS NOT NULL),
               bit_xor(hash(
                   ts_code, trade_date, name, is_st, name_source,
                   st_source, available_at, ingested_at, conflict_reason
               ))
        FROM stock_status_daily
        WHERE trade_date BETWEEN DATE '2026-04-01' AND DATE '2026-07-14'
    """).fetchone()
    migration = conn.execute(
        "SELECT max(version) FROM schema_migration"
    ).fetchone()[0]
    signature = (*row, migration)
    signatures[label] = signature
    print(label, signature)
    assert row[:3] == (379_658, 0, 0)
    assert migration == 9
    conn.close()
assert signatures["main"] == signatures["replica"]
PY

    rquant-nl-screen.service \
    rquant-monitor.service \
    rquant-surge-watch.service \
    rquant-replica-sync.service \
    --property=Id,ActiveState,SubState,Result,NRestarts
```

成功门槛：`ROLLOUT_EXIT=0`，版本为 `v0.17.1`，SHA 等于目标 tag，preflight 全部通过；
主库和副本均输出相同的 `(379658, 0, 0, <摘要>, 9)`；七个恢复的 timers 有下一次触发时间。
任何失败都停止后续步骤并恢复 timers，不要在失败后手工跳过审计或 preflight。
