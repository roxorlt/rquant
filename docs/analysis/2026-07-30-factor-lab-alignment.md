## 三、Tushare `rt_k` 权限实测（2026-07-30 16:2x，盘后）

用 `.env` 中两个 token 分别调 `pro.query("rt_k", ...)` 与 `pro.query("rt_min", ...)`：

| Token | `rt_min`（分钟 RT） | `rt_k`（L1 盘口快照） |
|-------|--------------------|----------------------|
| `TUSHARE_TOKEN_MAIN` | ✅ 正常返回 | ❌ 「没有接口(rt_k)访问权限」 |
| `TUSHARE_TOKEN_BACKUP` | ❌ 无权限 | ❌ 无权限 |

**结论**：

1. 此前「tushare 已付费」指的是**分钟 RT 包**（`rt_min` / `rt_min_daily`，挂在主 token 上，当前有效）。
2. `rt_k`（doc_id 372，买一/卖一价量 + 成交笔数，¥200/月）是**独立权限，尚未开通**。
   VP 规格书 §8.4 推荐它做封单监控的结论不变，但需要单独付费。
3. 规格书 P0 列的付费前三项实测（实际刷新频率、盘口字段是否需显式 fields、封板时买一价==涨停价）
   只能在**开通权限后的交易时段**做——权限本身就是第一道闸，前置动作从「实测」改为「决定是否开通」。
4. 分钟 RT 包 2-4 周续费评估窗口仍在进行中（见 memory `tushare-intraday-facts`），
   续费决策可与 `rt_k` 开通决策合并考虑。

## 四、A 股 L2 逐笔数据外部 API 调研

调研核心问题：哪些渠道能在自有服务器（macOS / 腾讯云 Linux）上通过外部 API/WebSocket
拿到 L2 逐笔成交 + 逐笔委托。**结论：用户的印象成立——「个人可购 + 外部 API + 真 L2 逐笔 +
数千元/年」四个条件同时满足的渠道不存在**，根源在监管侧：沪深 L2 由上证所信息网络 /
深圳证券信息公司独家授权，分「展示型」与「非展示型（数据接口）」两类许可，后者只签机构合同
（上证所展示许可仅牌照费 35 万/年起）。个人合法路径只有两条：券商展示型终端（只能看不能导出）、
或挂靠券商柜台系统在其客户端/托管环境内消费。

### 4.2 对 rQuant 的推荐排序

1. **榨干现有免费 L1**：3 秒级快照（mootdx / Tushare 分笔 / iTick）足够做「近似订单流」因子原型
   （快照间量价差分、大单撕裂等），先证明因子有效再讨论花钱升粒度；
2. **迅投研专业版（约 ¥4,978/年）是预算内唯一值得考虑的付费升级**：交易所授权级干净 L1 tick
   历史（回补至 2018）+ 官方 Linux SDK，可替代爬虫源做因子回测底座。购买前必问客服：
   个人能否开 L2、Linux 版函数是否放行；
3. **不要为 AllTick/iTick 的「逐笔」二字付费**——A 股侧它们都是 L1；
4. **真 L2 的中期路线**（因子在 L1 上证明价值后再说）：Windows 云主机 + 券商 QMT VIP 行情 +
   自写 proxy 转发（数百元/月级，牺牲架构洁癖），或资产达标后走华鑫 TORA / 中泰 XTP。

### 4.3 落地决策（承接 D2）

真逐笔现阶段不可得 → **按用户既定 fallback 执行：用分钟线（以及竞价、3 秒快照等能拿到的
更小时间窗数据）做「按形态不等权分摊」的近似 VP**。vp/engine 已有均摊算法 U，
后续在对照实验框架下增加形态加权分配算法（W）即可，算法切换纪律遵守 vp/sandbox 既有约定
（对照实验做完前不得因收益更高而切换）。
