# Pool 信号目标函数重构：从次日涨停到后续溢价（2026-06-25）

## 结论先行

只看“次日涨停”会漏掉一大批有效目标。更合理的目标函数应改成：

- 入池后 1 / 3 / 5 / 10 个交易日内的最大溢价。
- 盘中上攻信号触发后 1 / 3 / 5 / 10 个交易日内的最大溢价。
- 次日涨停只是强标签之一，不再是唯一目标。

这仍然属于项目边界内的“条件筛选 + 实时监控 + 告警”，不涉及下单。

## 样本口径

- 数据库：`data/rquant.duckdb`，只读连接。
- 样本：`n-shape-pool1` / `n-shape-pool2` 入池记录。
- 日期：2026-04-16 至 2026-06-24。
- 总样本：661 条，393 只股票。
- 溢价口径：
  - 入池后溢价：`max(high[T+1..T+N]) / close[T] - 1`。
  - 突破 T 高后溢价：`max(high[T+1..T+N]) / high[T] - 1`。
  - 强承接后溢价：`max(high[T+1..T+N]) / open[T+1] - 1`。
- 由于历史没有分钟级触发价，突破 T 高和强承接使用日线代理。

## 监控策略调整

### 删除盘中回踩提醒

旧的 40 / 30 / 20 / 强止 / 弱止档位不再作为盘中提醒事件。它们的问题是：

- 对“找上攻目标”是弱信号甚至反向信号。
- 容易把注意力拉到回踩低吸，而不是识别强势资金回流。
- 历史上触发回踩档位后的次日收盘涨停率明显更差。

保留强止 / 弱止作为 Pool2 退出风控参考，但不再发盘中价格档位通知。

### 新目标

盘中监控改成只发上攻信号：

- `attack_open_strength`：开盘 2%~4%。
- `attack_strong_carry`：盘中低点不破 T 日收盘，且当前价不弱于 T 日收盘。
- `attack_break_high`：实时最高价突破 T 日高点。
- `attack_near_limit`：距离涨停价 1.5% 内，且已经突破 T 高、承接未破。

后续复盘不再只统计“信号后是否涨停”，还应统计：

- 信号后 1 / 3 / 5 / 10 日最大溢价。
- 信号后 1 / 3 / 5 / 10 日收盘收益。
- 最大溢价是否达到 3% / 5% / 8% / 10%。
- 达到最大溢价前是否发生回撤，比如信号价下方 -3% / -5%。

## 下一轮实现建议

1. 新增 `monitor_attack_event` 或扩展 `monitor_event` 字段，记录信号价、T 高、T 收盘、次日涨停价、距离涨停价、实时最高价、实时最低价。
2. daily 17 点后生成一张 `attack_event_outcome` 复盘表，按 1 / 3 / 5 / 10 日更新未来最大溢价。
3. 策略排序从二分类改成多目标：
   - `next_day_limit_up_score`
   - `forward_premium_score`
   - `risk_of_failed_breakout`
4. 在日报中把候选拆成：
   - 强承接目标：优先级最高。
   - 突破 T 高目标：高召回，等待承接确认。
   - 临近涨停目标：短线临门观察。

这会把 rQuant 从“找次日涨停”升级成“找池子里真正有后续溢价的资金回流目标”。
