# L2数据源股票列表订阅与原始批次接口

本接口保存L2数据源市场响应的原始批次，不写分钟表、全景快照或生产数据库。HTTP 管理股票列表和游标补取；独立 API 的 WebSocket 向下游发送已提交批次。2026-10-19，20股全部60路已通过部署前持续验收，核心版本 `v0.34.0` 已部署，服务监听服务器 `127.0.0.1:8771`。生产采集器随后因解码错误停止，API 仍可读取已提交缓存；当前不代表实时服务可用。本次大行数成交推送修复仍须完成新的实盘验收和正式发布。当前生产容量策略为20股。100 是代码上限，不是已测容量或数据源最大值。更大规模须逐级实测。

每股注册成交明细候选 `4013`、买委托 `4027`、卖委托 `4027` 三流，共用外层 `2357`，按已发页面关联。既有两股六流实验证据不替代本次批量容量认证。保留原始响应头、字节、字段值、style 与 SHA256；成交粒度、数量单位、交易所身份、全日完整覆盖、缺口补齐和会话续期仍未认证。

## 启动

使用 Python 3.11+。先创建 owner-only 的 state 父目录；以下路径均为占位符，私有输入内容不得进入 HTTP、命令参数或源码。

```sh
uv run python -m rquant.l2 \
  --cache-root /absolute/private/state/cache \
  --control-root /absolute/private/state/control \
  --capacity-file /absolute/private/state/capacity.json \
  --bootstrap-file /absolute/private/inputs/bootstrap.bin \
  --order-template /absolute/private/inputs/order-template.bin \
  --trade-template /absolute/private/inputs/trade-template.bin \
  --resident --max-reconnects 0

uv run python -m rquant.l2.api \
  --cache-root /absolute/private/state/cache \
  --control-root /absolute/private/state/control \
  --capacity-file /absolute/private/state/capacity.json
```

API 固定监听 `127.0.0.1:8771`，无 host/port 覆盖参数或在线文档端点。仅显式传入 `--control-root` 才启用订阅控制；不传时保留缓存 GET 和 WS。既有平台 Web 仍只有缓存 GET，不暴露 WS 或写控制。调用方限同服务器或已有授权 SSH 边界，不应将无鉴权市场接口公开监听。

`--capacity-file` 是管理员提供的只读认证策略，包含 `max_symbols`、`source_tree`、`acceptance_sha256`；生产组件由部署器从验收证据生成。离线开发可显式使用 `--max-symbols`，默认 20、硬上限 100，与 `--capacity-file` 互斥；HTTP 请求不能修改容量。

在控制模式下，持久化 desired 列表是唯一股票来源，不自动注入两只默认股票。采集器先取得单缓存写锁；空列表时等待，不读取会员输入或建立上游连接。首次非空后只建立一个连接，一个 reader 同时处理待发种子和推送。每股种子完成后被动接收，HTTP GET 不重查上游，重复 POST 不重新入队已有股票。

`--resident` 与 `--duration-seconds` 互斥，只取消人工结束期限；EOF、协议、鉴权或关联错误仍停止。默认零重连；显式最多两次、间隔至少 60 秒的重连只适用于传输错误，次数不随新 epoch 重置。重启或断线先持久记录缺口，新种子不会清除缺口。SIGINT/SIGTERM 关闭连接，不自动续期会话。

## 股票列表控制

```http
POST /api/v1/l2/subscriptions
Content-Type: application/json

{"symbols":["600000","000001"]}
```

股票代码必须为以 `0`、`3` 或 `6` 开头的六位 ASCII 字符串，保留前导零；单请求最多 100 项。服务端按首次加入顺序去重，并原子追加到所有调用方共享的并集，不替换他人列表，不提供退订或租约。多请求并发合并时不会丢失已受理股票。

新增股票返回 202，表示已持久排队；已全部存在返回 200，revision 不变、`added` 为空。下面仅是结构示例，不代表已有市场数据或容量认证：

```json
{"revision":1,"symbols":["600000","000001"],"max_symbols":20,"added":["600000","000001"]}
```

非法代码、空列表、数字类型或额外字段返回 422。并集超过管理员总容量返回 429，整个请求拒绝，不部分写入。控制文件不安全或损坏返回 503 和固定错误码；错误不会包含私有内容或路径。API 不读取会员输入，也不导入或启动采集器。

```http
GET /api/v1/l2/subscriptions
```

返回 `desired`、`runtime`、`runtime_current_epoch`、`status`。desired 包含持久 revision、完整列表和容量。runtime 是有界持久快照，包含 epoch、已处理的 desired revision 和每流状态：`queued`、`sent`、`seeded`、`no_data`、`first_push_observed` 或 `failed`。它只在状态转换时更新，可能暂时落后于 desired；不表示每流最后行情时间。只有 `runtime_current_epoch=true` 时才属于当前状态的 epoch，旧 epoch 的种子不能证明当前已就绪；停止或 gap 也须结合 status 判断。此 GET 不扫描历史批次。

## 统一排队与频控

本实现的上游业务请求每包只包含一个标的和一个数据流。20股需要60次启动查询，另有一次会话发送，之后被动接收。一个连接通过多个注册页面交错接收多股三流。上游多标的封包尚未验证，不能据此断言数据源全部协议的单包上限就是一股。

所有调用方共享单采集器队列，下一业务发送开始距上次发送完成至少 1 秒。重复已有列表不会新增业务请求。生产组件使用每类一页，100 股相应最多 300 次业务请求，另有一次初始会话发送。多个 agent 共用磁盘缓存和唯一采集器；HTTP GET 与 WS 读取都不增加上游查询。

`--trade-pages 3 --order-pages 3` 可显式增加启动时的有限回溯，每类最多三页。已有同日三页证据；任意日期、跨日、整日完整历史未认证，不应把分页当作自动缺口补齐。

上述一秒节奏是本采集进程的本地节流，不是数据源配额。没有账号全局、跨机器配额协调、分布式限流或 API QPS 限流。容量与读取性能必须实测，不能用一次成功种子或 `ispush=1` 证明持续订阅。

## 只读缓存与双消费者

```text
GET /api/v1/l2/status
GET /api/v1/l2/batches?after_sequence=0&limit=128
```

每个消费者独立保存全局本地游标，初始为 0；本地批次从 1 连续编号。`limit` 默认 1、范围 1–128，同时受 12 MiB 批次内容预算约束，实际可能少于 limit。股票和类型通过每批 `binding` 在客户端筛选，游标覆盖所有股票，不能自行跳过未消费序号。未来游标返回 400。

处理完整页并提交自身消费结果后，将返回的 `next_sequence` 用于下一次请求；不要使用 `status.last_sequence` 跳到末尾。空页保留游标后等待。处理失败从最后已提交游标重读。每个 agent 独立持久保存自己的游标。HTTP OpenAPI 结构见 [l2-openapi.json](l2-openapi.json)。

缓存未创建时 `/batches` 返回 `{"batches":[],"next_sequence":0,"status":{...}}`，status 为 `unconfigured`。市场批次包含 `binding`、epoch、`delivery`（seed 或 candidate_push）、接收时间、请求 ID、会话 FD 序号、原始响应与表字节、SHA256 及 typed raw table；小数保持字符串。原始相同行、值变化和重复响应都保留，不按 ID 去重、不分钟化。

已识别的成交 sentinel 推送可包含最多4096行。超过500行时，必须同时满足成交类型、已注册页面关联、固定推送头和 `candidate_push`；种子、普通请求响应和委托仍最多500行，委托种子的原有更低限制保持不变。这是本地解码边界，不是源端每批数量承诺。单缓存批次仍受8 MiB预算限制，HTTP与WS每页仍受12 MiB预算限制。完整响应、表字节、行数及SHA256均须通过校验，不截断或跳过超限批次；失败时停止采集并保留缺口。

`binding` 只证明已注册请求/页面关联，空标题表不独立证明股票或交易所身份。本地序号和 vendor ID 都不是交易所全局唯一标识。本地接收时间候选不同于源事件时间；`source_freshness` 保持 `unknown`，显示时间和数值时间为候选值。`last_market_received_at` 只由实际已提交市场批次刷新，心跳、控制帧、GET 不刷新；种子较新也不证明源事件实时。缓存超过 60 秒或连接已停止/阻断时 stale 为真。

传输时间与帧处理结果合并为一次原子状态写入。市场批次仍先完整提交；控制包和心跳仍保存计数。关联、解码或缓存错误仍关闭连接并标记 gap。状态文件本身无法写入时返回 `cache_error`，不能把内存状态当作已落盘证据。15 秒种子等待和上游频控不变。

缓存以 `batches/.head` 硬链接原子发布最新批次。每次 HTTP 或 WS 读取先固定已发布序号 H，再验证所选连续批次和 H 的路径、文件类型、原始字节、SHA256 及模型。即使写入继续，该页也不超过 H。读取工作量受页大小约束，不随全部历史增长。

尾部读取不再逐次检查未选中的旧历史。旧批次缺失、路径不安全或内容损坏，会在请求该批次、采集器恢复时的完整审计或停止后的完整验收中报错。没有 `.head` 的旧缓存使用完整审计慢路径；只有持写锁且完成全部审计后才能补建或更新发布点。已有但损坏、来源不符或指向无效批次的 `.head` 不会触发静默回退。

每次追加先检查服务用户可用磁盘：保留 5 GiB，加上按文件系统块取整的批次和 SHA 文件空间，以及 1 MiB 元数据预算。不足或磁盘统计无效时，在新批次分配前返回 `cache_io`；采集器按现有错误路径停止并记录缺口。这不是跨进程空间预留，也不删除历史数据。健康追加保留原有四次批次 fsync，发布点使用已有父目录 fsync。

## WebSocket 下游推送

原生 agent/服务端客户端使用以下地址。不要发送 Origin header；浏览器握手一律拒绝。

```text
ws://127.0.0.1:8771/api/v1/l2/stream?after_sequence=0&limit=1
```

参数与 HTTP 游标同义：`after_sequence` 默认0，`limit` 默认1、最大128，仍受12 MiB页预算限制。参数须为不超过20位的 ASCII 十进制整数。额外参数、重复参数、非法值和未来游标都拒绝。WS 不接收股票列表或其他应用数据，订阅修改仍使用 HTTP POST。

每条文本消息是现有 `BatchPage` JSON：`batches`、`next_sequence`、`status`。先按序重放游标之后的批次，再跟随新提交批次。服务端只在发送成功后推进发送游标；客户端只有处理完整页并提交消费结果后，才持久保存 `next_sequence`。断线后用最后已处理游标重连，或用 HTTP 补取。消息可能重放，不承诺 exactly-once。

API 每0.2秒检查本地缓存，有数据即发送；空闲时每5秒发送空 `BatchPage`。心跳不改变游标或市场接收时间。采集器停止后，消息保留真实的 stopped/stale/gap 状态，不能把 WS 连接存活当作源行情正常。此实现按连接独立读取同一磁盘缓存，不是内存广播中心。

API 最多接纳8个 WS 连接。每连接仅一页在途，发送超时5秒；缓存读取在事件循环之外执行。断连时等待收发任务和在途读取结束，再释放名额。非法参数、Origin或满额连接在握手阶段被拒绝，实际 Uvicorn 通常返回 HTTP403，并不是客户端收到 WS close frame。连接建立后的未来游标或应用数据以1008关闭，发送超时以1013关闭，缓存故障以1011和固定原因关闭。慢端不增加上游发送；断线客户端从自己的持久游标恢复。

服务端固定使用锁定的 websockets backend，入站消息上限1024字节、队列上限1。客户端应允许至少16 MiB消息，接收超时大于5秒，并禁用代理环境继承。8连接是代码保护上限，不是已经测定的并发容量；真实负载仍须验证。

## 持久性与部署

每个缓存只有一个写者。批次 JSON 与整份内容 SHA 先写私有临时目录，fsync 后原子重命名到连续序号目录，再原子发布 `.head`。坏批次、缺号和不安全文件类型显式失败。写者恢复时核验完整前缀；HTTP 和 WS 固定已发布 H，检查 H 与所选有限批次。没有 `.head` 的旧缓存使用完整审计慢路径。异常保留最后完整提交，gap 不代表已补齐。

独立组件使用 `/home/lighthouse/rquant-l2-rel/current`；state 下 `control` 为 API 唯一写控制目录，`capacity.json` 只读，`cache` 由采集器唯一写。会员输入为独立私有目录，API 无权读取。目录 0700、私有文件 0600；组件不切换既有 Web current、不触碰生产数据库。

部署唯一入口为 `scripts/deploy-production.sh --component l2`，先核 main 精确提交、完整 CI、正式制品 digest、源树和实际容量验收。生产首次 desired 仅取已验证列表前20股，即使认证容量更大也不自动订阅全部。当前已部署核心为 `v0.34.0`，main 提交 `8e8ba860115eb285c6336f4cc4e5b14eb1afd7e3`；更大列表不会绕过当前容量策略。

新版本部署需要 `rquant-l2-acceptance-v3`，保留原有全部门禁。先验证20股全部60流：最后种子后有共同90秒窗口，各流有种子后的向前新 ID、至少60秒跨度、三个30秒桶和窗口最后60秒至少两批向前数据。双 HTTP 和双 WS 消费者都须完整读至最终缓存头，四条哈希链分别等于缓存导出链。两个 WS 消费者还须各自在共同窗口的前、中、后三段收到实际向前数据，lag不超过5秒。种子、心跳、同 ID 值变化或窗口后补取不算该窗口新事件。所有连接、接收、游标、哈希或关闭错误均阻断；不能用 HTTP-only 证明放行 WS。

升级先受控停 API，再重读最新并集后改容量。回滚不恢复旧 desired 快照；若已受理并集超过旧认证容量，保留新 desired/policy/cache，两服务保持停止并报告回滚未完成，不丢 202、不扩大旧容量或自动重登。操作和回滚约束见 [受控发布说明](production-release.md#l2-独立组件)。

盘中消费者使用本接口。盘后训练和回测读取独立历史文件。归档候选复用现有 R2 客户端，独立完成日终导出、上传校验和按接收日期恢复；不接入实时收发路径，不删除本地缓存。

归档版本 `v0.35.1` 的 timer 已安装，计划工作日17:20运行；首次真实日终归档仍待执行。归档使用独立发布版本。旧版仍可读取已有不超过500行的缓存；读取新增的大行数成交批次前，归档也须完成兼容版本的独立验证与升级。核心修复不会自动升级归档。操作与数据限制见 [归档和恢复](l2-archive.md)，整体数据路径见 [架构说明](l2-architecture.md)。
