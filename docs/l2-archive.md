# L2 日终归档与历史恢复

## 1. 目的与状态

本组件将已接收的 L2 原始市场批次存入项目现有 R2 bucket。盘后任务负责归档。监控服务继续使用实时缓存 API。训练和回测读取独立历史文件。

本组件独立于实时服务发布。2026-10-19，常驻核心为 `v0.35.2`，归档 `v0.35.3` 已独立部署，timer已启用；已完成实际归档和按日期恢复的一致性检查。实际状态以部署回执和云端unit状态为准。它不表示源端全日数据完整。

本分支提出20 MiB单记录字节预算，尚未启用。新候选必须单独通过锁定Linux环境、现有384 MiB归档进程预算、真实R2完整往返和正式发布门禁。不得使用现行归档的证明替代新源码树验收，也不得为归档重启核心。

## 2. 数据范围

归档包含完整的 `RawL2Batch`。每批保留原始字段、原始响应、股票与数据流绑定、epoch、接收时间和本地批次序号。

日期采用 `Asia/Shanghai` 的接收日期。它不是已经认证的交易所业务日。归档不转换数量单位，不推断成交粒度，不去重源事件，也不重新编号。

归档只覆盖实际接收并完整提交的批次。源端缺口、停止状态和覆盖范围限制会留在清单中。归档不能补回未采集的数据。研究使用前，应检查缺口、覆盖范围和字段语义。

## 3. 文件与提交方式

生产前缀固定为 `l2/v1/rquant`。验证数据使用独立的 `l2/v1/_acceptance/<随机编号>` 前缀。归档不访问既有 L1 快照前缀。

| 对象 | 作用 |
| --- | --- |
| 压缩 JSONL 分片 | 保存完整原始批次。对象名绑定接收日期、原序号范围和 SHA256。 |
| 不可变日期清单 | 记录该日期的分片、大小、SHA256、批次数和原序号范围。 |
| `catalog.json` | 指向已提交日期清单，记录远端进度和源状态。 |

每轮开始时固定末批序号 `H`。本轮只处理到 `H`。之后提交的新批次留给下一轮。

当前缓存通过 `.head` 发布末批。归档不把发布点当作批次，也不持有缓存写锁。归档逐批验证本次新增区间的原始数据和 SHA256，再发布远端进度。新区间缺批、损坏或类型错误会阻断发布。没有 `.head` 的旧缓存使用只读兼容路径，不补建发布点。

任务按以下顺序发布归档：

1. 读取完整提交的批次，验证原始模型和连续序号。
2. 生成确定性的 JSONL 和 gzip 分片。
3. 上传分片，检查 HEAD 大小和 SHA256 元数据。
4. 重新下载分片，检查实际字节、SHA256、gzip 和原始模型。
5. 上传并验证日期清单。检查所有清单的序号范围覆盖本轮前缀。
6. 使用条件写入发布目录，再下载核对目录。
7. 写入本机成功回执。

新对象使用 create-only 条件。目录更新使用上一次已验证的 ETag。ETag 只控制并发写入；内容校验使用 SHA256。上传结果不明时，任务不会回写旧目录。

远端目录是唯一进度记录。本机成功回执丢失不会丢掉远端进度。没有新数据且持久状态不变时，重跑不上传对象。已存在的不可变对象必须核对通过，才能复用。

已有远端目录、清单或分片损坏时，任务失败。任务不会自动创建空目录来掩盖缺失，也不会静默覆盖坏对象。首次目录初始化只允许由受控首次部署执行；升级不重新初始化。

## 4. 自动运行

| 项目 | 固定值或行为 |
| --- | --- |
| timer | `rquant-l2-archive.timer` |
| service | `rquant-l2-archive.service` |
| 执行时间 | 工作日17:20，上海时区 |
| 补触发 | `Persistent=true` |
| 盘前和盘中保护 | 工作日07:00–16:30先延期，不读取缓存或访问 R2 |
| 单次最长时间 | 2小时，不自动重启 |
| CPU / 内存 | CPU配额20%，内存上限384 MiB，低 CPU 和 I/O 优先级 |
| 输入 | 只读核心缓存，不持有行情会话 |
| 本地状态 | 独立任务锁、临时文件和最后一次运行回执 |

07:00开始延期，是为了让最长2小时的补跑也不会跨入09:00保护窗口。17:20正常归档。一次未完成的归档，后续运行从远端进度继续。

R2 凭据只由归档受控进程加载现有 `/etc/rquant-r2.env`。凭据不进入源码、命令参数、回执或 API。归档不使用 Web 环境文件，不读取行情会员输入。

## 5. 查询和恢复

运行环境为 Python 3.11+。下列命令供服务器作业和 agent 使用，应在已通过受控 EnvironmentFile 加载 R2 权限的进程中执行。不要将密钥拼入命令。

列出可恢复的接收日期：

```sh
python -m rquant.l2.archive list
```

检查目录、清单和已引用对象的大小与 SHA256 元数据：

```sh
python -m rquant.l2.archive check
```

恢复一天到一个尚不存在的绝对路径：

```sh
python -m rquant.l2.archive fetch \
  --date 2026-10-19 \
  --dest /absolute/research/l2/2026-10-19
```

恢复成功后，目录包含：

```text
2026-10-19/
  batches.jsonl
  receipt.json
```

恢复程序重新下载目标日期的分片，并检查大小、SHA256、解压上限、模型、日期、epoch、原序号和批次数。全部检查通过后，才原子发布新目录。已有目标目录不会被覆盖。恢复不依赖本地归档回执。

`batches.jsonl` 每行是一批完整数据。跨日期的本地序号可能交错，因此单日文件可以含有原序号间隔。不要重新编号，也不要将单日子集当成从1开始的完整实时缓存。

Python 调用方可复用 `rquant.l2.archive` 的 `list_archive`、`check_archive` 和 `fetch_archive`。客户端复用 `research.snapshot_archive.R2.from_env()`。这条路径直接读取历史对象，不发起上游行情查询。

## 6. 边界和失败处理

| 情况 | 行为 |
| --- | --- |
| 上传失败或结果不明 | 不报告成功；下次重新读取远端目录，不回滚旧目录。 |
| 条件写入冲突 | 停止本次发布，重新核对远端状态，不降级为无条件写入。 |
| 目录、清单或对象缺失 / 损坏 | 失败并保留本地数据，不自动重建历史。 |
| 本地源被截断或边界身份改变 | 拒绝推进，不将新源接到旧归档后面。 |
| 恢复校验失败 | 不发布目标目录。 |
| 归档进程失败 | 不重启或停止实时 API、采集器或既有 L1 任务。 |

候选单记录连同LF最多20 MiB。单分片仍最多32 MiB解压数据，压缩下载最多33 MiB；一条完整记录不能拆分到两个分片。目录和日期清单各最多8 MiB。恢复总输出默认最多64 GiB，可通过 `--maximum-output-bytes` 显式缩小或设置当前作业预算。超过边界即失败，不截断数据。

同一生产前缀只允许一个写入主机。本地任务锁不提供跨主机协调。首批和末批 hash 用于核对可信 append-only 源边界；它们不证明任意旧中间批次没有被外部修改。

本组件不删除本地缓存或远端对象，不更改 bucket 生命周期。长期可恢复性仍依赖 bucket 保留策略、凭据可用性和定期恢复检查。一次上传成功不能保证永久保存。

## 7. 发布与回退

归档使用独立的 `/home/lighthouse/rquant-l2-archive-rel/current` 和 `/home/lighthouse/rquant-l2-archive-state`。核心服务的 release、缓存和控制目录不切换。

部署入口：

```sh
bash scripts/deploy-production.sh --component l2-archive \
  --target FULL_COMMIT_SHA \
  --artifact /absolute/release/source.tar \
  --archive-proof /absolute/evidence/proof.json \
  --archive-proof-sha256 PROOF_SHA256
```

部署器验证 main 精确提交、完整 CI、正式制品、源码树、实际 R2 往返证明，以及已正式部署的核心20股证明。R2 合成往返证明与真实行情容量证明各自绑定自己的源码树，不能互相替代。

激活失败时，只回退归档 release 和两项归档 unit。已上线采集器、API、股票列表、容量策略和缓存保持其当前状态。升级遇到远端目录缺失时必须失败，不能初始化。

回退入口仅接受已记录的上一归档版本：

```sh
bash scripts/deploy-production.sh --component l2-archive \
  --target PREVIOUS_FULL_COMMIT_SHA --rollback
```

实际部署记录、恢复证明和最终运行状态在验收完成后更新。接口与数据路径分别见 [接口说明](l2-interface.md) 和 [架构说明](l2-architecture.md)。
