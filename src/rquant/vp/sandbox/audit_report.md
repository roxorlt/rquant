# 风险审计报告

规格 §7.2：**每次实验后必跑这份清单**，不是抽查。每次审计往下追加一节，不覆盖旧节。

审计角色与做实验的角色分开：任何一次「收益提升」的实验，先回答第一个问题——
是不是因为成交规则被放松了？

## 清单模板（复制整段，逐条打勾并写证据）

```markdown
### 审计 A-{编号} · 实验 {experiment_log.csv 的 id} · {日期}

- [ ] 未来函数：有没有用到 `available_at` 晚于决策时刻的数据？
- [ ] 前复权导致的历史改写？
- [ ] 幸存者偏差：股票池是不是用了「今天还在市」的名单回测历史？
- [ ] 停牌股是否被当作可成交？
- [ ] 涨跌停是否被当作可成交？
- [ ] 成交价是不是用了信号当根 K 线的收盘价？
- [ ] 成本是不是被调低了？
- [ ] 单票仓位是否超过容量限制（规格 §5.4）？
- [ ] 收益是否集中在极少数样本？
- [ ] 实验次数是否已超过多重检验阈值？

**结论**：{通过 / 有条件通过 / 不通过}
**证据**：{每条打勾的依据，指到具体代码行或输出文件}
```

## 打勾规则

- 打勾必须给证据，指到具体代码行或输出文件；「看过了没问题」不算证据。
- 任何一条不通过，实验结论作废，在 `experiment_log.csv` 的 `verdict` 写
  `audit_failed`，不要留着「等有空再查」。
- 引擎版本变了要重跑历史实验，重跑后的审计另起一节，注明触发原因是引擎变更。
